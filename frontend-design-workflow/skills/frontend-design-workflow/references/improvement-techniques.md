# 定向优化技巧

2026-10-16 改编：daymade 两包、taste 固定版本的专项方法与 emil-design-eng；归属、固定版本、许可和改动见[声明](../licenses/ATTRIBUTION.md)。原文中的数值与绝对偏好在这里作为有条件的经验，不证明普遍效果。

目录：1 结构阅读（layout/typeset）→ 2 视觉表达（colorize）→ 3 调性（bolder/quieter/distill/delight/overdrive）→ 4 交互（animate/clarify/emil）→ 5 使用质量（adapt/harden/optimize）→ 6 评审精修（critique/audit/polish）。按问题读取对应节，不执行原命令工作流。

## 1. 结构与阅读

### 布局、分组、密度与层级（layout）

所有信息同样醒目、行列难比较时，先确定用户要找的内容。用最少的间距、字重和位置形成阅读次序；不够再增加字号/色彩对比。眯眼检查主信息、第二层和分组，只是启发式，仍需实际界面与操作。

- 复用一致间距刻度；自建时用角色 token，如 `--space-xs`，避免任意值。兄弟间距可用 `gap`，流动留白可用 `clamp()`。来源例子：相关项 8–12px，独立章节 48–96px，不能将营销页间距直接套入高密后台。
- 一维条目/导航/按钮组优先评估 Flex；需要协调行列时用 Grid，可用 named areas；自适应卡组例子 `repeat(auto-fit,minmax(280px,1fr))`。按内容实际最小宽度调整，别让 280px 加边距在小屏溢出。
- 重复容器造成竞争时，尝试用标题、间距、对齐或分隔代替部分卡片；独立操作与明确归属需要卡片时保留。嵌套也按信息关系判断，不移植来源“一律禁止卡片”的审美禁令。
- 覆盖层以职责区分下拉、sticky、modal/backdrop、toast、tooltip 的顺序，复用项目层级；不要为对齐问题盲加 z-index。光学位置只有实际看出偏差才微调。

**候选：减少卡片容器。** 预期减少边界干扰；适用于重复包裹或视觉拥挤。先在代表区域比较分组可辨性、信息查找和动作归属，再决定是否推广；去框可能让关系更模糊。来源为两包内容优先与 taste layout/distill；尚无普遍效果结论，可试用并保留无明显改善或副作用。

### 字体、行长与数字（typeset）

标题/正文/辅助难辨时，先梳理职责。来源用 caption、secondary、body、subheading、heading 五级，1.25/1.333/1.5 比例为示例，不要求每页五级。字重可用400/500/600/700 中必要的 3–4 种。已有系统字体有效时保留，个性不等于每次下载字体。

- 应用界面可用稳定 rem 字阶；营销标题可 `clamp()`，正文保持可预测大小。来源建议正文约 1rem，正文行高 1.5–1.7、标题 1.1–1.2，行宽 45–75 字符（`max-width:65ch`）；中文字符宽度、字体和密度须实看，不能把 ch 当精确中文字数。
- 数据对比用 `font-variant-numeric:tabular-nums`；大标题可试微收字距，小型大写标签可适当放开，保留语言本身的阅读性。检查长名称、金额、缺字回退、200%缩放，不截掉决策信息。
- 新字体确有必要时只加载所用字重，核对许可、字形覆盖和回退；`font-display:swap` 与度量相近回退是候选，仍须测加载位移。不要把某字体名称直接判为缺陷。

## 2. 视觉表达

### 颜色、图像与组件（colorize 与两包）

先找颜色要表达的角色：品牌、主次操作、状态、类别、阅读层级或导航。来源示例是中性色外 2–4 色、强调元素 60/30/10 的相对分配；它不是整页面积公式或品牌约束。小范围颜色可胜过全页加彩。

- 成功/警告/错误等沿用项目语义，标签同时有文字/图形，不只靠红绿；图表类别和数值颜色要对应真实数据与可辨关系。
- 可尝试暖/冷轻染背景，例如 `oklch(97% .01 60)` / `oklch(97% .01 250)`；实际浏览器支持、渲染颜色和对比须检查。纯黑、纯白、灰色、渐变都可在合适场景使用，来源的禁令不作为共同规则。
- 主要动作可保留实心品牌色，次要动作以边框或文字减弱；危险操作保持清楚。相同职责组件统一高度、padding、圆角、边框、图标尺度；不同职责允许不同层级。
- 图标与相邻文字光学对齐、保持同族；装饰图像服务内容，真实资产核对许可；图片预留尺寸/比例并保留适当替代文本。品牌标记不凭记忆仿造。多图先分配用途，避免无意义重复和不相干照片。

检查最终组合的文字、按钮和状态对比，不以十六进制表或色彩感觉代替；常规正文 4.5:1、符合大字条件的文本及必要控件边界 3:1 是常见检查基准，按项目适用标准判断。状态、主次动作、焦点在窄屏与不同内容下仍应可辨。

## 3. 调性调整与效果候选

### 更大胆 / 更克制（bolder、quieter）

方向平淡时选一个主要焦点，调高一种或几种关联对比；不要让所有对象同样抢眼。来源 bolder 例子：主次尺度 3–5 倍、900/200 字重、100–200px 大间隔、70/30 或80/20 构图、纹理/厚边框/跨格图形、50–100ms 入场间隔。这些适合特定展示语境，高密业务界面可能不适用；仍需完整内容、可读性和性能。

过刺激时保留有效焦点，逐项减少饱和度、字重、尺度差、边框/阴影/模糊或装饰动效。quieter 原例是降至原饱和度约70–85%、900→600/700→500、装饰移动从40px降至10–20px、中性色主导加约10%强调。不要为了安静把文字全部变小变浅，或消除功能提示。

先比较阅读与主要任务是否更顺畅；没有真实用户观察时，只能描述视觉关系和运行现象，不能宣称更有记忆度或转化提升。

### 删繁就简（distill）

从用户完成任务必需的信息与动作出发，合并重复表达，删除无职责装饰，缩短文案但保留判断条件。来源例子：1–2 主色加中性、1 字体族、3–4 字号、2–3 字重、一套间距；根据项目规范取必要部分。

渐进披露须仍能发现与到达功能，不能借“简化”删除已要求的功能、数据或恢复路径。减少弹层/步骤或整合操作前核对行为授权；局部美化可先收敛样式、重复容器和死 CSS。检查首用者是否仍理解分组，键盘与辅助名称是否保留。

### 趣味与高表现（delight、overdrive）

在与品牌和用户情绪相符的成功/首次使用/等待时刻，可试轻量插图、明确的成功反馈或短暂动效。来源 delight 建议小于1秒且可跳过，按钮按下可下移2px、hover上移2px；声音需适用授权/用户选择且可静音。错误场景优先具体恢复，不让玩笑遮蔽原因。检查重复使用是否烦扰、是否拖慢动作、减少动效与性能。不要为此新增彩蛋、主题或依赖。

技术高表现先明确目的和成本，再在授权方向内试代表对象。overdrive 例子包括触发源到弹层的 View Transitions、CSS scroll timeline、`@starting-style`、Canvas/WebGL、Worker/OffscreenCanvas、虚拟列表、WAAPI 等。它们是候选工具，不保证当前浏览器支持或性能；先功能检测，提供有效静态/原有路径，目标环境实测，避免多个竞争效果。原文“60fps、低于50则简化”是其预算建议，不替代当前测量，也不授权安装库、WASM、后台或设备权限。

## 4. 交互、动效与文案

### 明确动作和恢复路径（clarify）

按钮说明动作：“保存更改”而非“确定”；同一操作在按钮、进度与结果中使用相同术语。字段有持久标签，说明格式与必要原因，placeholder 不是唯一标签。错误具体说明问题及下一步，尽可能保留输入；例如“请输入包含 @ 的邮箱，如 name@example.com”，权限不足说明如何申请权限，不只写403。

空态区分首次、无搜索结果、权限不足；分别说明会出现什么、如何创建/调整查询/获得访问。成功反馈说明完成了什么与后续影响；加载时间仅有实际依据时给估计，不凭空承诺30–60秒。危险确认写清具体对象、后果和动作名；不为每个普通动作增加确认。来源幽默或固定用语须适配品牌与情绪，先保留可理解和可恢复性。

### 目的、时长与打断（animate、emil-design-eng）

缺反馈或状态跳变时，先决定动效是否比即时状态更有帮助。高频键盘动作通常适合直接响应；偶发弹层可用短过渡，首次/低频场景允许更有表现力。动作不能等装饰播完才可用。

- animate 原例：按压100–150ms，状态200–300ms，布局300–500ms，入场500–800ms，退出约入场75%；emil 原例：按压100–160ms、tooltip125–200ms、下拉150–250ms、弹层200–500ms；这些是不同场景经验，选择最短且清楚的反馈，不统一套值。
- 可试 ease-out `cubic-bezier(.25,1,.5,1)` / `(.22,1,.36,1)` / `(.16,1,.3,1)`；emil 例 `(.23,1,.32,1)`、屏内移动 `(.77,0,.175,1)`、drawer `(.32,.72,0,1)`。弹跳等效果按用户方向和语境选择，不成为审美禁令。
- 简单状态可用 CSS transition，需编排/动态控制时评估现有 WAAPI 或项目库；避免 `transition:all`，明确属性。频繁反向动作要检查能否从当前位置顺畅继续，不能笼统认定所有 keyframe 无法打断。
- 尽量用 transform/opacity 降低布局开销，但 GPU/合成不保证自动发生，真实页面测量。`will-change` 只在确有需要时使用。不要将原文关于 Motion shorthand、硬件加速或浏览器支持的经验当本环境事实。

### 具体交互例子（保留为候选）

需要以下问题时读 [emil 原样全文](materials/taste/emil-design-eng/original.md) 查代码与限制，遵循公共入口的参考用途边界：

- 按压反馈可 scale(.95–.98)，常例 .97 /160ms；入场可从 .95 加透明度代替scale(0)。popover 从触发位置展开，居中 modal 仍从中心；tooltip 初次延迟，相邻连续查看可跳过等待。
- 两状态 crossfade 重影时可试 blur(2px)+opacity(.7)，模糊耗费须测，不能靠大量 blur 掩盖问题；`@starting-style` 需核对浏览器支持并保留无动画路径。
- `translateY(100%)` 相对元素自身高度；3D preserve-3d/orbit 原例以72px深度旋转，只有相关视觉目的才选。`clip-path:inset()` 可用于标签色块、比较图、揭示等；hold-to-delete 原例按住2s linear、释放200ms ease-out，是交互候选，不能自行替换已批准危险操作契约。
- 拖动可按距离或速度判断，原例阈值约 .11px/ms；需在设备中校准、处理 pointer capture、多指和边界阻尼。直接更新 transform 与继承 CSS 变量的成本要测，不一概宣布哪种更快。
- 交错入场原例30–80ms（animate 来源100–150ms），需适配列表长度，不阻断交互。hover 运动可限于 `(hover:hover) and (pointer:fine)`；减少动效保留可理解状态，移除非必要位移。慢放2–5倍或逐帧可帮助定位时序，不代表真实速度体验已验证。

## 5. 使用质量

### 屏幕、设备与内容适配（adapt）

按目标设备、输入方式、连接和使用情境调整，不只是缩小。断点可从内容开始挤压处决定；来源320–767 /768–1023 /1024+只是例子，非固定合同。手机堆叠、桌面并列、平板主从视图均按内容选择，不因适配隐藏核心功能。

触控可参考至少44×44px目标，避免依赖 hover；字体常从16px正文起验证，允许缩放。容器查询、Flex/Grid、clamp 和 responsive images 按现有环境选用。打印只在需求相关时考虑合理分页、展开必要信息、弱化交互与有限配色；邮件原例600px单栏、inline CSS/table 兼容需实际目标客户端验证，不默认成为普通网页要求。

### 极端内容、状态和恢复（harden）

检查真实或拟真长标题、100+字符、空内容、大数字、CJK、emoji、RTL、译文和大量条目。源例给翻译预留30–40%扩展，使用 `margin-inline-start` / `padding-inline` 等逻辑属性，日期/数字可用 `Intl`；仅在项目需要国际化时实施。

- Flex/Grid 收缩可设 `min-width:0`；长词可 `overflow-wrap:break-word`；必须保留的信息完整换行。省略单行、三行 clamp 只适用于允许截断且仍有访问全文路径的对象。200%缩放时容器随内容扩展。
- 关注实际存在的加载、刷新、分页、空/无结果、校验错、网络失败、权限、禁用、成功；错误就近具体表达并保留输入。401/403/429等处理沿用产品约定，不由美化任务修改鉴权或新增离线能力。
- 异步防重复提交、竞态、乐观更新/回滚、清理监听/计时器和取消请求，须有相关问题与授权，不能为“完善”叠加机制。长列表可评估分页/虚拟化，具体实现并非本 Skill 已提供的通用算法。
- 来源 debounce搜索300ms、throttle滚动100ms为候选；先量化卡顿与可接受响应，别给即时简单筛选平添延迟。导览/首次状态用即时价值和可跳过引导，不强制漫长问卷。

### 有依据的性能优化（optimize）

先测本次慢在哪里，再选择对应改动，同条件比较。图像按显示尺寸提供 WebP/AVIF/srcset 等候选，来源80–85%质量为初试值，实看可接受损失；首屏关键图不盲目 lazy load，离屏资源可按需加载并预留比例避免位移。

检查不必要 JS/CSS/字重/第三方请求、交替读取offsetHeight与写样式导致的重复布局；可批量读后批量写。独立区域 containment、长内容 content-visibility、虚拟化、memo 等只有测出相关瓶颈才选，不无条件增加缓存、服务工作线程、CDN、库或后端变更。

来源列出 LCP<2.5s、INP<200ms、CLS<.1 及旧 FID<100ms 等指标示例；它们不是本 Skill 新增的固定发布门槛。按项目当前指标和设备/网络测实际变化，记录工具、条件和限制。FPS、节点数、资源数或 Lighthouse 分数只能说明各自测量，不能推出用户效率或全局性能无退化。

## 6. 评审与精修

### 找到真实影响（critique、audit）

先明确界面的主要任务，结合实际页面与相关实现判断阅读顺序、操作可发现性、信息分组、状态、可理解性和恢复。必要时分别从熟练用户、首次用户或相关辅助需求视角走查；模拟 persona 只辅助发现问题，不能称真实用户测试。

每项发现给具体对象/位置、观察依据、用户影响、建议动作和验证办法。可按任务阻断、显著困难、可绕过不便、细节区分优先级，不凑固定问题数。启发式评分/“像AI”判断不构成缺陷证据或完成标准；不以缺少暗色模式、memo、动效等未要求能力阻断交付。

多步骤表单或跨页面决策时，检查 critique 认知负担参考中的两种具体问题：

- **跨步骤上下文（Memory Bridge）：** 后一步需要用户记住前一步的信息时，让必要上下文持续可见，或在需要处再次呈现。例如确认页显示本次已选方案、金额及影响判断的条件，而非要求用户凭记忆确认。用实际任务检查能否在当前步骤核对这些条件，并保持返回修改后的信息一致。
- **决策信息并置（Context Switch）：** 同一次决策需要跨页面、标签或弹窗收集信息时，将必要信息放在当前决策位置，减少往返。例如比较报价时并列呈现总价与对应交付限制，而非只列价格、把限制藏在另一标签。检查用户能否在同处完成比较；保留信息来源与完整内容，不因合并而丢失判断条件。

原 critique 的双视角、Nielsen十项及情绪路径也可在相关任务作为检查线索；audit 的可访问性/性能/主题/响应式/反模式按本次实际范围检查，不执行 npx 检测器/overlay/后台服务或自动子代理，不额外创建统计账本。发现后建议与实施授权分别判断。

### 沿用系统、收尾一致性（polish）

功能已成立后，核对现有 token/组件、相同职责的对齐/间距/字阶/圆角/颜色、按钮状态、标签与术语、图像比例/替代文本、表单焦点及长内容。源例45–75字符行宽、150–300ms过渡、触区44px用于适用时比较，不机械新增全部状态。

检查渲染与实际操作；只有看出光学偏差才调整，不猜测微移。复用已有组件，删除本轮造成的死CSS/孤立组件/重复token；无新增机制时不为“整洁”扩大重构。每轮只修能解释影响的问题，最终按[验证参考](validation-and-feedback.md)交付证据和剩余限制。
