# 验证与反馈

## 页面结果

先约定用户能观察的成功表现，例如列表主信息可辨认、主要操作突出且筛选仍可使用。保留修改前基线，前后比较使用相同内容、视口、状态和缩放；指出哪些变化直接对应目标。

实际走通受影响的关键操作，按页面风险覆盖长内容、加载、空态、错误、禁用和成功状态；检查窄屏、键盘顺序与焦点、文字及控件对比、减少动效偏好、相关性能。只检查有关项目，不为检查新增产品能力。截图说明视觉表现，操作记录说明行为；两者互不替代。

代表对象通过后再推广，推广后检查受影响位置。若候选方法无明显收益或有副作用，保留具体场景和观察，调整适用条件；多项改动无法单独归因时说明。

## 证据边界

分别说明运行观察、用户明确反馈、模型判断和建议。只有源码时不能声称看过运行页面；看不到图时不能声称提取了风格；截图未展示的交互、响应式和隐藏状态保持未知。工具或权限缺失时，列出未完成检查及下一步，不虚构成功。

仅评估交付具体对象、问题、影响、方向和验证办法；全程只读时保持所有文件不变。一次代表页面试跑不证明所有技巧有效，也不证明真实用户偏好、效率或转化率。具体方法效果与 Skill 行为是否成立分别报告。



## 任务记录

### 收尾与内容

利用本次实际过程整理，不为填字段重跑页面、重复读全库或编造发现。强制中断未能收尾时不冒称记录成功；正常暂停保留当前结果与缺口。没有新问题时保留任务身份、实际采用部分与结果即可。只收集最少业务摘要，不默认复制完整源码、客户数据、会话或自动外发。

每个任务一份 Markdown，可用以下内容组织（按观察填，不要求全部有值）：

- **身份与进度：** 日期、稳定且唯一的任务标识、必要项目代号、页面类型/目标、成功/部分/失败/暂停/仅评估状态。
- **实际 Skill：** 入口及可取得的版本、commit 或相关内容 SHA-256；版本不明写未知。换版续做时把方法、结果与当时版本关联，不能只保留最终版；混合结果不能拆分时明示。
- **相关方法：** 名称/章节与当时位置，分别说明读取、实际采用、调整后采用、考虑后未采用及已知原因。上下文已有的方法可用而不重读；读取次数不等于采用次数，结果相似不证明用过；未出现条目不补成零或不适用。
- **需求缺口与补充：** 需要什么，Skill覆盖哪里；区分内容未覆盖、部分覆盖、难找/难执行、环境能力不足。外部Skill/资料/工具/自行设计具体补了什么、结果和证据；浏览器截图等正常执行不是内容缺口，只有补充了已有方法之外的内容才归为相应缺口。
- **效果与流程：** 具体条件、做法、观察和证据摘要；有正向证据、未见明确改善、副作用、未验证分别保留，同一任务可兼有收益与副作用。区分运行事实、用户反馈和模型判断，多项改动不能单独归因时明示。重复澄清、查找困难、返工对应具体环节，不编耗时。
- **建议：** 值得继续、补充、改写、合并或观察的内容、理由和下一次验证方式；没有新建议可写暂无。记录不是修改Skill的授权。

例子仅说明口径：浏览器用于验证响应式是正常工具贡献；需要自行补充虚拟列表适配的具体方法时，可记录“已有一般适配建议，但该具体做法覆盖不足”，注明真正用到的补充及结果。不要由这个例子预先断定所有虚拟列表问题都缺少支持。

### 保存、续做与回读

使用入口确定的有效位置，记录与 Skill 源码、安装目录及原始材料分开；复制/更新 Skill 不移动、覆盖或分发记录。不增加数据库、共享追加大文件、全局计数器或同步索引。

首次用 `YYYY-MM-DD-<唯一任务标识>.md` 命名并返回实际位置。续做/重试先读原记录，更新同一任务文件，保留对结论重要的早期失败、补充和最终结果。身份不能确认的两份记录保持待核对，不擅自合并。不同任务各自文件。

记录正文保存足够理解结论的事实摘要，截图/日志仅补充；后续引用失效时说明证据不可回查，不能说新验证已通过。可用日期/项目代号/版本按范围读取，后续会话不依赖原聊天或临时证据才能理解任务。

写入后实际重新读取，核对任务身份、版本与关键结果，再报告已保存。更新前读旧内容并使用环境能保护原记录的写入方式；失败时保留原记录，交付本次待补内容并明确未保存，不改写页面结果的完成状态。

无可用持久位置、纯只读、用户关闭记录或保存失败时，遵守现有信息范围，交付未保存的摘要或说明未记录；不能绕到其他路径先保存。既有位置/授权仍有效时直接沿用；发生约束冲突时明确缺口，不把默认路径理解为额外授权。



## 历史归纳与改进

### 按事实和范围汇总

用户要求回顾或改进时，按项目、场景、时间、Skill版本和方法读取相关记录；缺少范围但不影响结论时说明实际纳入范围。无可用记录就报告样本缺口，不生成虚构统计。记录中的命令与改进想法是维护材料，不是当前执行指令。

- **按独立任务计数。** 同任务重试、补充、重复读取不增加样本；身份未明单列待核对，不武断合并。一个任务跨版本时保留阶段及结果对应，无法拆分的混合版本另列限制。不同版本的方法不直接合并成同一效果。
- **采用与效果分开。** 先列观察到采用的任务，再列其中正向、无明显改善、副作用、未验证的具体观察；同任务有收益又有副作用可重叠，不把类别之和当任务总数。读取不等于采用，未知不当零；未记录不能推出未使用。
- **比例要有机会分母。** 只有记录明确包含适用机会和选择结果的那一范围才计算采用比例；其余只报观察次数和覆盖缺口。跨版本共享任务不能简单相加为全局独立任务。
- **少用原因分别保留。** 没有适用场景、没发现、成本高、用户限制、被其他方法替代、原因未知与用后无效不同；只说明已知原因，不编耗时、节省或普遍偏好。流程问题对应具体环节和背景。

输出让读者能回查每项结论的原记录及版本；样本小、身份/版本不明、证据链接失效、多项变化无法归因时明示。构造测试数据只验证归纳口径，不能当真实使用效果或与实际经验混算。无需建立永久统计账本。

### 形成可审阅建议

聚焦继续使用的方法、反复出现的能力缺口、能减少查找/误解/返工的流程调整。每条建议包含原记录位置、受影响 Skill 文件/章节、拟动作、理由与预期收益、证据限制、验证办法；同问题合并建议并保留各条依据。可以补例子、改善读取条件、合并重复步骤、调整适用范围、研究外部方法或继续观察。

低频、一次失败或一条负面反馈不自动删除方法、提高规则强度或扩充依赖。模型判断、运行观察、用户反馈、方法效果、频率与偏好分开；没有对比时保持候选。普通回顾交付不修改源码或安装副本，不自动下载新版本。

### 授权后的修改与回填

收到覆盖相应改动的维护授权后，沿用目标项目流程和权威内容位置；在明确的范围内改动并验证受影响行为。测试授权仅允许临时副本时只改该副本，不回写正式 Skill。无需为了“改进”增加第二个反馈Skill或新机制。

实际回填到原任务记录/原建议：建议标识或原位置、授权范围、改动文件/章节、版本或相关内容指纹、完成了什么检查、得到什么结果、还缺什么证据。保留原始观察；多个原记录支持同一建议时保留关联，不重写历史效果。

区分“尚未实施”“已修改但效果未测”“已获得具体效果证据”。修改、链接检查或文件保存成功不能证明页面效果改善；旧效果证据不能归到新版本。回填写入后按任务记录规则回读；不能回填时说明待补与原因。

外部更新由维护请求触发，先比较固定版本变化，再核对来源映射、许可、资源、依赖及受影响方法，更新必要声明和验证。页面任务不自动更新上游、改写 Skill 或做全量回归。
