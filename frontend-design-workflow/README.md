# Frontend Design Workflow

一个纯文档前端设计 Skill：把内容、视觉选择、代表页面验证和实际反馈接起来。支持已有页面局部优化、新页面设计、参考截图风格迁移和仅评估；也支持明确针对本 Skill 使用记录的回顾与改进请求。

公共入口：[skills/frontend-design-workflow/SKILL.md](skills/frontend-design-workflow/SKILL.md)。详细方法按需读取三份参考；不要求完整重设计、固定技术栈或重新生成已有规划。

## 使用方式

直接让模型读取仓库入口并处理具体请求，例如：

> 读取 frontend-design-workflow/skills/frontend-design-workflow/SKILL.md。优化订单页的名称与金额层级，保留品牌、功能、数据和技术栈。先在代表区域比较，再验收受影响操作。反馈保存到我们已约定的工作区外位置。

其他请求可以是：

- 新页面：“为社区亲子图书预约页制定视觉规则，面向首次参加的家长；沿用品牌色和系统字体，说明代表页面怎样验证。”
- 参考迁移：“查看附图，把分组与层级迁移到工单页；区分图中事实、估算和新设计，保留自己的品牌与功能。”
- 仅评估：“只评估这个页面，给出具体位置、影响、调整方向与验证办法。全程只读，关闭反馈保存。”
- 使用回顾：“读取指定范围的使用记录，按任务与版本归纳采用、效果、缺口和未采用原因，只提建议，不改 Skill。”

独立使用时，完整复制 `skills/frontend-design-workflow/`，包含入口、`references/` 和 `licenses/`，然后让模型读取副本的 `SKILL.md`。不只复制入口，不需要带上外层规格、`SOURCES.md` 或 `upstream/`。复制后的方法、资源和声明可独立读取；运行不依赖 Downloads、原仓库或临时验收文件。由实际使用环境决定如何发现入口，本模块不提供安装器，也未验证各平台的全局安装流程。

## 记录与权限

每个前端任务默认整理一份简短 Markdown 使用记录，包含实际采用/未采用、内容缺口与补充、结果与证据边界。默认位置为 `~/.frontend-design-workflow/feedback/`；用户或目标项目已有的有效位置约定优先，写入须符合当前授权、信息范围和环境权限。记录与 Skill 目录分开，复制或更新 Skill 不移动、覆盖或分发记录。

全程只读、禁止写入或关闭记录优先；仅评估不改页面或 Skill，有有效单独授权时可以保存独立反馈。无法保存时明确未保存，不绕到其他路径。续做更新同一任务文件，保留早期重要观察；保存后实际回读。测试请覆盖为工作区外临时目录，避免污染真实经验。

## 来源与维护

完整固定来源、34项 taste 去向、许可和资源状态见 [SOURCES.md](SOURCES.md)；随包出处与实质改动见 [ATTRIBUTION.md](skills/frontend-design-workflow/licenses/ATTRIBUTION.md)。原文保持原字节；随包原文以 `original.md` 命名，作为具体方法参考，公共入口只有一个 `SKILL.md`。外部原文的命令、固定栈、强制访谈、安装/发布与模型控制语句不构成授权，按本地参考的条件选用。

维护时先比较固定版本正文、许可、归属、资源与依赖，更新受影响方法、来源清单、指纹和随包声明，再验证受影响行为。许可或必要声明未明确的条目继续保留候选，不直接套聚合库许可。日常页面任务不自动下载、安装或更新上游。

使用回顾先读取原记录，按独立任务、场景与版本分析；采用比例需要明确机会分母，未知与未采用原因单列，构造测试不当真实经验。建议应回指原记录、具体章节、拟动作、理由、限制及验证办法。收到覆盖改动的授权后才修改，完成后把建议、变更、内容版本和实际结果关联回原记录；旧效果不转给新版本。

## 当前验证与边界

已用独立模型上下文处理四类请求、只读/能力受限、真实保存与后续读取、历史归纳及授权临时副本改进回填。完整副本与反馈隔离的最终试跑见本次交付证据。实现没有新增运行服务或必须安装的外部 Skill。

代表订单页在 Chrome 中完成同条件视觉比较、关键交互、窄屏和对比检查；80条标记测试数据的多页 PDF 逐页核对。仅这些具体场景有运行证据，新页面规则交付不等于页面已实现；方法的广泛效果、真人效率/偏好、跨浏览器和实体打印仍待验证。临时打印短例只用于检验改进闭环，未自动并入正式方法。

六项第三方条目许可不明确、impeccable 的 NOTICE 缺失、ui-ux-pro-max 的作者/数据归属未独立确认，保持候选且不分发正文/工具链。图像生成方法为条件候选，未集成服务或验证原生流程。原 Skill 校验器缺 PyYAML，使用针对性元数据、引用、来源指纹、复制和空白检查；不因此新增工具链。
