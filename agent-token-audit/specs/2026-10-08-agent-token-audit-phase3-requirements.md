## 1. 核心目标与阶段依赖

在整体分析和消耗解释之上，用户可根据明确价格规则查看已记录用量的估算费用，并在真实来源有对应时间与 usage 时查看 TTFT、生成吞吐和工具耗时。估算金额、实际用量和性能样本各自说明依据与覆盖，不能把估算变成账单结论。

费用估算使用已记录 token 和明确计价配置，不放宽既有“缺失用量不估算”要求。性能依真实来源能力提供，来源未记录时明确不可用及原因，不通过默认零或全未知图表宣称完成支持。

## 2. 费用估算

### 2.1 用户行为与价格依据

用户能够查看和选择价格配置，在原统计范围内按模型、会话或日期查看估算费用及未定价部分。每份估算显示币种、计价单位、规则来源/版本、生效区间、模型及供应商身份、计算范围与覆盖。明确修改价格配置后重新计算的结果与旧估算可辨，旧报告不因打开时间或价格更新而自动改写。

价格绑定来源证实的供应商、完整模型身份及适用时间。别名或映射须有明确配置与依据，不能去掉供应商后把同名模型当成同价。历史记录按照记录所属时间匹配生效规则，不用当前本地时钟价格覆盖全部历史；缺身份、缺价格、时间冲突或规则重叠分别报告。

输入、输出、缓存读取/写入、推理等计价依据来源字段包含关系和价格规则确定，不套用会导致重复计费的统一相加公式；已包含项不能再计一次。套餐额度、折扣、汇率或额外费用无配置或账单证据时不能自行假定。

### 2.2 已定价小计与覆盖

只对计价所需 usage、身份和规则均有依据的部分计价。缺少其中任一项，不填零、不把已定价小计命名为完整总费用。分别显示已定价金额、未定价记录/指标和原因；覆盖分母有依据才给比例，不能以金额覆盖替代用量覆盖。

不同币种分别表达；未确定汇率依据时不合并。模型、日期和会话视图均投影同一计价结果，不再加入总金额。确认价格为零与价格未知可辨；费用保留可复算精度和明确显示精度。

## 3. 性能分析

| 指标 | 依据与限制 |
| --- | --- |
| TTFT | 来源有同一次请求/调用的可信请求起点和实际首 token 时间才计算；注明时间事件定义，不用响应结束时间或调用耗时代替首 token |
| 生成吞吐 | 使用同一次调用的已知输出 token 与可信生成区间；缺首 token/生成结束或输出量的记录不进入计算，聚合以同一有效样本的总输出除以总生成时间，显示单位及样本覆盖 |
| 工具耗时 | 仅展示有明确工具执行身份和起止或直接耗时证据的样本；不把模型调用耗时当工具耗时，不将并行工具时长之和当墙钟跨度 |

零或负时长、时间顺序冲突、未完成记录和缺字段各自说明，不产生无穷吞吐或伪造零延迟。性能样本和 token 统计范围可能不同，展示实际有效样本及排除原因，不能把已计入 token 的所有记录默认当作性能样本。

指标使用固定结果范围及截止点，图表筛选仅改变视图。不同来源有不同时间事件或计量口径时明示，不能据此输出未经控制的 Harness 效率优劣结论。

## 4. 直接验收

| 编号 | 直接验收标准 |
| --- | --- |
| P3-A1 | 用明确测试规则独立复算：输入 1,000,000（含缓存读取 400,000）、输出 100,000、确认缓存写入零；每百万非缓存输入/缓存读取/输出分别为 10/2/20 测试币种单位，费用为 8.8；推理已含输出时不再计价。测试价格不是实际模型价格 |
| P3-A2 | 同名模型不同供应商、规则跨生效日期、缓存写入语义差异、缺价/缺身份/缺 usage、确认零价格、重叠规则及不同币种样例均正确处理；已定价小计和未定价原因可见，不产生伪完整金额 |
| P3-A3 | 两端以真实记录核对能支持的计价身份及性能字段，已计价部分和有效性能样本从原始记录独立复算；未支持项有来源证据与可见原因，构造样例不能冒充真实字段覆盖 |
| P3-A4 | 有首 token、结束和输出样本独立核对 TTFT 与吞吐，混入缺字段、零/负时长和未结束样本后仍只用同一有效集合；用串行/并行工具样例核对工具耗时与墙钟不同，样本覆盖准确 |
| P3-A5 | 真实浏览器查看模型/会话/日期费用、规则依据、未定价部分、性能图与明细；过滤前后合计、范围和截止点不变，配置变更后的重新计算与旧结果可辨 |
| P3-A6 | 实际导出和重载保留价格规则依据、费用与性能状态；隔离来源后旧结果仍展示，不把旧价自动换为新价；原范围重算、明确更新、合法旧报告和两端此前已验收行为无回归 |
| P3-A7 | 来源只读，不改 Harness 或发送埋点请求；普通查询不自动采集或持久保存，导出不含正文/认证信息；两端真实交互及完整安装副本完成相应路径 |

三类性能指标的逐端支持状态须在设计中由真实来源核查确定；无法取得来源证据时保留未决项，不默认为全部支持，也不自动扩大为采集或埋点工程。

## 5. 非目标与设计待定

本期不做账单对账、套餐扣减、自动汇率换算、成本节约或质量保证，不实施持续采集、增量缓存、自动刷新、永久历史库、实时上下文成分拆解或新的 Harness 接入。这些能力按长期独立判断处理。

设计需确定价格配置的最小形式、规则优先级与冲突处理、模型别名依据、历史生效时间、费用精度和报告兼容；逐端核查性能时间事件、配对身份和可用字段。不在需求阶段预设价格服务、配置平台或统一性能埋点，缺字段不得改来源补造。

## 6. Karpathy 精简与自检

基线：已有精确 usage、指标包含关系、归属、固定截止点及两类耗时，二期整体分析和消耗解释提供范围总览和细节；当前没有价格计算或完整 TTFT/吞吐/工具时间接口。

假设与差异：价格规则和新性能字段需要明确依据；估算价格不等于估算 token，性能支持范围依真实记录确认。本需求已批准；具体计价实现和逐端时间事件映射仍待设计，未扩大到采集或对账。

最小方案：价格配置与有依据的有效样本计算复用现有统计结果；自动抓价格、建设历史库或改 Harness 埋点会引入额外职责，当前目标没有要求。价格与性能证据可以分别不足，不以共享机制掩盖覆盖差异。

删除审计：费用、性能及其覆盖保留，自动刷新、缓存、上下文估算和持久采集留在长期候选；不重复二期整体查询与消耗解释明细，也不增加质量或浪费评分。

直接验收：P3-A1–P3-A7 通过独立计价/性能复算、真实字段核对和浏览器/报告/安装回归证明结果，测试规则与真实价格、构造样例与实际覆盖分别披露。
