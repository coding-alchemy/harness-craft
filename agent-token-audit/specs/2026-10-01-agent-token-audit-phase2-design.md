## 1. 问题陈述与现状基线

### 1.1 用户的问题

用户希望回答“这项工作消耗了多少，主要消耗在哪里”。一期已经提供两端统计，但当前会话与统计请求的身份仍依赖运行环境，部分内部调用存在读取或关联缺口，保存报告只有表格，真实交互与分叉验收也尚未全部闭合。

二期要在同一计量口径下改善这些问题：可信证据充分时减少查找 ID 的步骤；把来源已经提供、能够可靠读取和归属的内部消耗补齐；让用户在日志删除后仍能通过网页理解已保存报告。网页查看不能变成一次隐含的新统计。

### 1.2 已读取的合同与源码

本设计对照一期全部已批准行为、A1–A18、二期五项收尾和 P2-A1–P2-A10；现有实现事实来自[CLI](../skills/agent-token-audit/scripts/token_audit/cli.py)、[共用统计](../skills/agent-token-audit/scripts/token_audit/core.py)、[关系归属](../skills/agent-token-audit/scripts/token_audit/relations.py)、[报告读取与输出](../skills/agent-token-audit/scripts/token_audit/formats.py)、[Codex 读取](../skills/agent-token-audit/scripts/token_audit/codex.py)、[ZCode 读取](../skills/agent-token-audit/scripts/token_audit/zcode.py)、[外部行为测试](../tests/test_cli.py)、现有薄 Skill 与安装器。未发现本模块另有 ADR。当前源码基线为提交 `160821efb906397f05dfcb066dce1a3a921d0ceb`。

| 既有接口、行为或限制 | 对二期设计的约束 |
| --- | --- |
| CLI 已有 `sessions`、`turns`、`requests`、`report`、`show`、`recompute` | 保留操作、范围参数、输出格式和退出状态的既有含义；不另建统计入口内核 |
| `--current` 只匹配 `CODEX_THREAD_ID` 或 `ZCODE_SESSION_ID`；薄 Skill 也可传入 Harness 直接提供的可信身份 | 在证据结果中统一这些来源及冲突；不新增“最新文件”兜底 |
| 请求列举已有 ID、时间、来源，ZCode 已支持 `sendText`、`promoted_message_id` 和合成消息排除 | 会话身份与请求身份分别确认；完善等价副本及冲突表达，不用轮次起点替代追加消息起点 |
| Codex 逐调用、唯一回复的 last usage、累计差分是互斥计量路径 | 补读内部调用时先检查重叠，不能把压缩标记或累计量再加一次 |
| ZCode 默认读数据库；显式 rollout 与数据库分开计量，数据库可能只保留最终逻辑请求结果 | 只有明确调用映射才能补入同一小计；跨源重叠不明的已知值独立保留 |
| 关系模块已有后代归属、恢复和可验证继承副本排除 | 收敛到有证据的关系，不增加时间邻近关联；真实行为验收仍必须补齐 |
| 共用聚合已计算整数指标、成对缓存率、调用计数及互斥分组 | 新明细与图表使用同一结果；未知状态、工具报告及未归属量继续保留 |
| 现有 JSON 为 `format_version=1`；可选 `details` 每次只有一个维度 | 新报告保存三个独立维度；旧报告只展示已有维度，不从原始调用猜造缺失视图 |
| `show` 在读取来源前返回，`recompute` 保持范围，`--update` 才改变范围 | 新版加载和网页继承这一隔离，来源删除后仍能展示；不能用旧值冒充重算 |
| 脚本使用 Python 3.9+ 标准库；安装器复制完整 Skill，拒绝覆盖不同内容 | Python 运行依赖保持不变；网页资源随包交付，安装保护继续有效 |

### 1.3 来源观察与尚未证明的事实

2026-10-01 仅只读抽查源结构和关联元数据，没有开展产品验收，也没有导出正文或认证数据。Codex 最近 12 个来源文件包含 `0.159.0` 版本元数据、逐调用 usage、压缩标记、子代理来源和用户消息 `create_time`；逐调用记录仍没有通用的调用性质字段。不能据此认定所有内部调用均能分类，或把所有 `compacted` 标记视为额外模型调用。

ZCode 数据库存在 `assistant_message_id`、`parent_user_message_id`、`trace_id`、`span_id`；rollout 存在 `traceId` 和供应商响应 ID。238 条样例没有请求/attempt 或数据库行 ID 的直接一一匹配；另一次读取的 239 条样例中，trace 均对应多条数据库记录，供应商响应 ID 未直接匹配 assistant message ID。源在增长，两次抽查不是同一快照，不能作为数值对账。字段存在及名称相似不构成映射证明。

数据库还可见 `compact`、`session_title`、`workflow_child` 和重试信息。现有归属逻辑将非 `subagent_child` 的 `parent_id` 解释为分叉，而 `workflow_child` 的关系仍需核实；不能仅凭“有 parent”就按分叉去重，也不能仅凭类型名就归入用户任务。逐类需要的证据及不满足时的行为见第 4.3 节。

## 2. 解决方案

自然语言入口先复用用户已经确定的任务范围；新查询再依据可信上下文确定会话、请求与截止点。两端读取器把源特有身份和调用语义转换为共同证据结果，现有关系归属与统计内核负责去重、筛选和计量。用户仍获得一期六列表格，明确要求时才导出。

新导出的 JSON 使用 `format_version=2`，保存原报告及分组、模型、代理、轮次的独立展示视图。新读取器同时支持合法 v1/v2。网页是随工具交付的离线静态查看器，用户打开页面后自行选择一个 JSON；页面只读取该文件，在内存中切换视图、筛选行和展开来源，不连接 Harness，不扫描日志，不启动 Python 或统计进程。

调用计量、归属和缓存率只在现有 Python 内核中完成。网页使用预先计算的指标绘图，最多执行图形缩放、占比显示和行筛选，不再解析 Harness 字段、合并调用、重算 token 或聚合缓存率。原报告范围、截止点、合计和状态始终可见。

7. 作为报告使用者，我希望等价请求副本合并证据而合成消息及其可靠别名被排除，以便采用正确边界。（P2-A3）

16. 作为会话用户，我希望标题等会话辅助单列且不摊给最近任务，以便保持任务归属准确。（P2-A4）
17. 作为使用后台及多级子代理的用户，我希望后代持续归发起任务且遵守截止点，以便计入正确范围。（P2-A4）
18. 作为内部数据审阅者，我希望后台其他工作和未分类已知量仍可见，以便避免漏掉已经记录的消耗。（P2-A4、P2-A5）

22. 作为报告保存者，我希望导出时保留范围、整数、未知、来源和各展示维度，以便以后独立查看。（P2-A7、P2-A9）

26. 作为视图筛选者，我希望筛选条件与隐藏行可见且原合计保留，以便不把当前可见行误当完整任务。（P2-A8）
27. 作为存在缺口的报告读者，我希望未知不被画成零且占比分母与覆盖明确，以便不误读部分小计。（P2-A8）
28. 作为旧报告用户，我希望 v1 继续可读而缺少的维度明确不可用，以便复用报告而不得到编造明细。（P2-A9）
29. 作为遇到损坏报告的用户，我希望加载明确失败而不残留看似成功的新结果，以便避免采用错误数值。（P2-A9）
30. 作为本地数据所有者，我希望统计源保持只读、普通查询不保存或采集、报告不含正文认证信息，以便安全复用。（P2-A10）
31. 作为部分数据可用时的用户，我希望有效小计、计数或工具报告继续展示，以便在有限证据下仍能做判断。（P2-A5、P2-A10）

## 4. 实现决策

本节定义已批准 V0.1 的技术方案与合同，不规定具体文件拆分、执行顺序或 tickets。

### 4.1 职责、复用与本轮收敛

| 模块 | Interface 与职责 | 复用、新增或替换 |
| --- | --- | --- |
| 自然语言入口与 CLI | 接收明确意图和范围，展示候选、结果及错误；保留一期命令含义 | 复用；消费共同定位结果，不自行计量 |
| Codex/ZCode Adapter | 只读探测来源，返回会话、请求证据、调用/区间、明确关系及源限制 | 补读可靠记录；源字段和版本判断仍留各端 |
| 定位模块 | 接收上下文证据、候选及用户明确选择，分别输出会话与请求的确定结果或选择原因 | 收敛现有分散判断；作为内部 Interface，不新增公共注册协议或一组 CLI 操作 |
| 关系归属与统计模块 | 按已验证调用及关系去重、绑定归属、应用原范围和截止点、计算同一报告 | 复用；补齐内部性质及生成独立视图 |
| 报告读取与输出模块 | 验证 v1/v2，保存相同结果，展示与重算分离，保护来源 | 扩展版本读取，保留现有输出与显式导出合同 |
| 只读网页模块 | 用户选择报告后验证、显示、绘图、筛选及展开 | 新增必要展示；不具有来源读取或统计能力 |

本期涉及身份判断和持久报告合同，先重审现有机制再设计扩展。正常场景中，两端环境身份能与记录唯一匹配、ZCode 入队请求有明确提升关系、单一来源调用可去重；失败场景中，独立 Shell 没有上下文、同 ID 有时间冲突、数据库逻辑请求与 rollout attempt 不同层级、trace 对应多条记录。根因是证据粒度与身份作用域不同，增加更多候选时间规则或把源数量相加不能解决。

比较逐命令添加特殊判断与复用一份定位证据结果：后者让 `sessions`、`requests`、当前报告及自然语言入口获得同样的确定/冲突理由，保留现有操作即可。两端只转换真实证据，共用模块只作决定，不形成包裹旧猜测的另一层实现。报告采用明确新版而不是改变 v1 的必需结构，旧读取分支继续服务已有文件。现有单维 `--detail` 改为使用同一预计算视图，退出旧的独立明细计算路径；不保留两个聚合实现。

### 4.2 会话、请求与范围定位

定位结果分别包含会话身份、请求身份、候选、来源证据、冲突和不可用原因。证据记录身份作用域、关联字段、源位置、时间及其语义；不复制消息正文。状态区分已确定、待选择、证据冲突、不可用和已确认非用户输入。只有可证明对应用户意图的唯一结果才自动采用；没有可靠身份时不能把空结果伪装为“当前”。

| 使用环境 | 采用的证据及默认行为 | 尚需验收的限制 |
| --- | --- | --- |
| Codex 内自然语言入口 | 可验证 Harness 当前上下文或 `CODEX_THREAD_ID` 与记录会话匹配；请求以明确消息关联及其可信创建时间固定 | 桌面/CLI 各自验证实际能传出的身份；同为 Codex 不代表所有启动方式具备相同上下文 |
| ZCode 内自然语言入口 | 可验证 Harness 当前上下文或 `ZCODE_SESSION_ID` 与数据库/日志身份匹配；已确认 `sendText` 的入队时间及明确提升关系确定请求 | 真实桌面路径必须修复后回归；旧格式缺 kind、消息提升关联或环境身份时仍需选择 |
| 独立 CLI | 显式会话/范围或候选选择；命令开始固定默认截止点，带时区显式时间覆盖默认值 | 无上下文的 `--current` 明确失败；默认 Harness 参数语义沿用一期，入口不能自动猜端 |
| 已保存范围的展示或重算 | 保存的确定会话、轮次/时间和代理策略优先，原范围重算沿用旧截止点 | 不以当前环境替换历史范围；仅显式更新重新确定新增范围及截止点 |
| 二期网页 | 只使用报告内保存的身份和边界 | 不提供“当前会话”“当前请求”或新的定位操作 |

支持范围沿用已接入两端的现有运行入口和 Python 运行合同。本轮源抽查来自 macOS；其版本元数据和历史测试版本只是样本范围，不宣称任意 Harness 版本、其他操作系统或所有启动方式已验证。实施验收须逐端、逐入口记录环境与人工步骤；已有路径不能因新增检查未经验证而被默认为不支持。

会话匹配先使用可信明确身份与记录关系，不根据最新文件、目录相同、时间邻近、ID 前缀或模型名称选定。多个可信来源相互冲突时保留所有冲突，交由用户确认；显式选择历史会话是用户范围选择，不要求其等于当前会话。候选提供 Harness、稳定身份、源有则显示的标题、已知时间、能力和冲突原因；无标题不得编造。

请求规范化保留原始 ID 及有明确关系的别名。相同会话、同一请求、同一时间语义的副本合并来源；只有 ID 相同但起点冲突的记录不自动择一。已验证的 ZCode 入队时间与后续提升消息时间属于不同语义：有明确 `promoted_message_id` 时采用入队接收时间，不把稍后的展示时间当冲突；两个入队起点互相矛盾则拒绝自动确定。合成/非用户输入以及可靠关联的别名均排除，不能由用户给出该 ID 就变为合法请求。只有分类未知的旧记录不证明真实用户起点，保留候选及证据限制。

会话已确定不等于本次请求已确定。追加请求使用自身创建/入队起点，不使用共享轮次更早的启动时间。自然语言入口缺少可信起点时列出可用截止点、时间来源及影响，用户选择后记录为明确选择；不得声称已自动排除统计开销。独立 CLI 的显式 `--request-start` 保留调用方提供时间的含义，自动验证程度另外说明，不将一个时间字符串本身当成身份凭据。

确定范围沿用一期：任务限同一用户会话，连续/不连续轮次使用稳定 ID 集合，时间区间为带时区 `[from,to)`。消息不是轮次，范围复用不推进截止点；仅用户明确更新后才重新提交范围。对子代理身份，必须通过明确关系识别当前主会话与后代，不能把后台工作误选为当前用户会话。统计期间固定截止点不移动，结束/usage 时间过滤及无法切分的跨界调用处理保持原合同。

### 4.3 内部调用读取、分类和跨源处理

归一化记录保留已有调用/区间身份、会话/轮次、父子关系、模型、时间、指标及来源；仅补充有证据的调用性质、attempt/结果状态及其依据。代理身份、调用性质与是否重试是不同概念：子代理也可压缩或重试，重试并非必然内部辅助。五类是核查清单，不是可直接相加的五个分组。

| 核查类别 | Codex 的具体检查 | ZCode 的具体检查 | 计入或降级规则 |
| --- | --- | --- | --- |
| 重试与失败 | 逐调用响应身份、失败/取消事件、真实 usage 和累计重叠 | 数据库 `retry_count`、逻辑请求/attempt；rollout 请求/attempt、流式与非流式完成和失败 | 同一 attempt 副本一次；独立 attempt 有 usage 分别计量，保留原调用性质；没有失败 usage 不反推 token |
| 压缩与摘要 | `compacted` 与可读取的响应/usage、上下文及累计区间关联；区分仅标记和真实调用 | `compact` 及实际出现的摘要来源、usage、轮次与结果状态 | 有明确关联则进入内部辅助；已经包含于累计量不能再加。标记无法关联时说明用量可能已计或缺失，不假定全缺或零 |
| 标题与会话辅助 | 检查源是否记录此类模型调用与会话关系；仅有标题文本不构成模型 usage | `session_title`、模型调用身份及会话关系 | 只归会话的调用不摊任务，任务报告单列会话辅助/未归属；完整会话报告按其范围纳入内部辅助 |
| 子代理及后代 | 明确 spawn/parent/root turn、恢复/续接及多级关系 | 启动、后台、完成事件，数据库父会话及调用/工作流的明确关联 | 递归追溯发起任务，跨下一轮仍归原任务；关系缺失或冲突的已知量保留未归属，不能用时间补链 |
| 后台及其他内部工作 | 核对记录类型、调用身份、usage 和明确发起关系 | 核对 `workflow_child`、其他 query source、任务类型、明确工作流/会话关联及 usage | 类型名不证明归属或分叉。可靠新类型只在该端映射；无法分类的已知量保留未分类，不建设全局供应商规则库 |

每个类别分别记录可计量、仅计数、仅工具报告、关联不明、来源未提供的证据，可同时存在多个状态。支持说明包含已核查的来源、版本/结构、身份与字段依据、采用或未采用原因以及缺口；“尚未核查”不能写成“来源未提供”。只有可回源的格式及真实样例才能支持不可补齐结论，不能将当前读取器未实现误写为源能力限制。

默认互斥分组沿用一期：已确认内部性质进入内部辅助，其余已确认常规调用按主/子身份分组，无法确认分类进入未分类。重试/失败状态保留为独立说明，不能让同一调用同时贡献常规组和内部组。会话辅助、任务未归属、继承副本和工具累计报告分别可查看；继承副本不贡献本会话新增量。主代理筛选仍只包含主代理常规调用，保留 A11 的 10 万含义。

ZCode 跨源补齐采用以下合同：

1. 默认读取器核对同一查询可用的数据库、rollout 与关系日志，先验证字段与身份作用域。现有显式 `--database`、`--source` 选择继续表示其计量来源，不被悄悄替换。
2. 数据库行、逻辑请求、供应商响应和 rollout attempt 不能互相冒充。只有源提供明确桥接关系并能验证调用及 attempt、归属和用量覆盖时，才映射到同一真实调用；trace、相近时间、数值相同仅作核查线索。
3. 对已证明同调用的副本合并证据、择一计量；字段冲突只使受影响字段降级，其他可靠量保留。只有能证明独立且没有被现有累计/逻辑结果计入的新增调用，才补入同一小计。补读新来源后沿用一次完整的去重、归属及统计过程，不在合计上追加一个 token 数。
4. 缺少映射时，保持已选计量来源；另一来源中的已知用量和支持状态在内部证据说明中独立显示，并明确“跨源重叠未知，未并入小计”。用户可通过既有来源入口单独核对同一明确范围。不能忽略这些记录，也不能把它们叫作工具报告或混入图表分母。
5. 恢复、分叉与派生工作先验证关系类型。数据库中的非子代理父关系不再一律作为分叉证据；有明确继承及调用身份才排除副本，重新发送继承上下文的新调用正常计入。缺少祖先、关系或累计基线时保留不确定性。

Codex 同样先确认逐调用与累计覆盖。压缩有 usage 但性质或归属不明时，保留已知量与关联限制；累计差分在完整序列上进行后再按集合筛选，不因内部补读退回“先筛选再差分”。不能精确拆分跨轮或跨边界区间时保留已知区间及缺口，不按比例分摊。

若补齐必须依赖新增 Harness 埋点、改造 Harness 或持续采集，列出原始证据、受影响用户行为、可保留量及范围差异供用户决定。本设计不授权这些变化；同时，现有可可靠读取或关联的量仍必须补齐，不能以不支持某些类别为由交付全未知报告。

### 4.4 计量、覆盖与副作用合同

一期七项共同约束继续有效：字段包含关系先验证；缓存读取及已包含推理量不重复加总；缓存率按成对已知字段加权；未知不补零；真实调用去重；来源后补影响重算但旧值不替代新统计；单一用户会话范围与后代归属；来源只读、普通查询不保存采集、报告不含正文认证信息。

字段保留源报告值、推导值、未知、冲突及原因。源报告零但语义未确认继续显示其原值和限制，不作为确认零；仅显式完整的零调用证据才能确认零用量。缺调用总数、记录不匹配或区间粒度不明时不计算调用覆盖率，更不能因“没有发现缺口”报 100%。成对输入的缓存率可以合法为 100%，其与调用覆盖率是不同指标。

直接 usage、调用计数和工具累计报告是独立证据通道。工具累计量不拆输入输出、不与直接 usage 相加；有哪种有效证据就展示哪种，部分结果不被错误吞掉。截止点沿用可信请求起点或用户明确选择；实际读取时间另列，范围固定不保证后补日志后的重算值恒定。

JSONL 只读有限快照，损坏/未完成行标位置和影响；数据库沿用现有只读一致快照机制，临时副本放工作区外并用后清理。导出仍拒绝覆盖源文件、其符号链接/硬链接及已加载报告等输入别名，只在用户明确指定格式和目标时写文件。来源诊断采用元数据白名单，不带请求、回复、错误正文或认证 headers。

### 4.5 报告 v2 与 v1 兼容

采用明确的 `format_version=2`，这是文件合同版本，不是产品发版。既有范围、指标、分组及状态语义不变；新增定位证据、内部来源说明和同时可用的展示视图，使新读取器知道需要验证哪些内容。

| 合同部分 | 保存内容与约束 |
| --- | --- |
| 既有报告主体 | `harness`、`scope`、`input`、`read_at`、`status`、`rows`、`summary`、归一化 `records`、来源、缺口、覆盖、活动状态及独立工具报告；范围保存稳定 ID、时间和代理策略；来源描述保存计量入口及实际采用的补充来源，以便同范围重算复用同一来源选择 |
| `localization` | 本报告采用的会话/请求身份、截止点及其证据、确认方式和剩余限制；仅保存与所选报告有关的证据，不复制全部无关候选 |
| `internal_support` | 第 4.3 节五类的实际支持状态和源证据；未采用来源的可读值独立标注来源与重叠限制，不进入 `summary` |
| `views` | `model`、`agent`、`turn` 三个独立视图，各自保存可用状态/原因、稳定行身份、显示标签及共用聚合所得的完整指标、缓存子集、计数和状态 |
| 既有可选 `details` | 保留 `--detail` 的所选单维结果；新版从 `views` 投影，不再次计算。两个表达同时存在时必须一致，不将其相加 |
| 数值与时间 | token 为非负精确整数或 `null`，指标及比例状态明确；时间带时区。每个值保留覆盖和原因，零不替代未知 |

生成报告时对同一已选、去重和归属后的记录集计算三种视图。模型使用已验证模型身份；代理使用真实代理/会话身份而非模型角色；轮次按所属用户任务轮次归类，后代使用发起轮次。无法分类的量保留未知行。覆盖多个轮次且无法拆分的累计区间在轮次视图中只出现一次，标为“多轮区间，无法拆分”，不得复制到每个轮次。

每个独立视图均是同一报告的另一种分布表达，其可计量部分与原报告可回源对应；未知行、区间和未归属说明不能为追求整齐而省略。视图行划分同一已选记录集，所选指标的分母直接使用保存的 `summary` 对应指标，不在浏览器累加视图行。所有视图指标均传播报告的覆盖限制，不能因该视图全部可读就变成完整调用覆盖。报告没有可靠维度时，保存分类不可用及原因；已有已知量可保留在未知行，不以该行宣称真实分类，也不削弱既有 `--detail` 的未知量展示。

新读取器按格式版本分别验证：

- v1：合法既有报告完整保留原范围、值、状态、来源及已有 `details`；缺少定位证据、内部支持说明或其他维度时明确显示“旧报告未保存”，不读取日志补齐，也不利用 `records` 重新猜分类或聚合新视图。始终展示原报告整体覆盖限制，不能把旧明细的 `known` 字段状态解释为全部调用已覆盖。
- v2：验证主体与新增结构、维度身份、指标状态和理由；有维度投影时核对其与保存视图一致。验证语义一致性只作检查，不将旧报告改算为新结果。
- 两者都拒绝损坏 JSON、错误必需结构、非法 token/比例/时间、正文认证字段及不支持格式版本。错误说明版本或字段位置，不能显示未经验证的新报告数值。合法部分覆盖、仅计数、仅工具报告及不可统计报告都属于可读取报告。

兼容方向为新工具读取 v1/v2。旧工具仍只支持 v1，不能要求其读取新 v2；不提供默默删去新增信息的降版本导出。旧报告原样展示或重新导出不凭空升级；按旧范围重算才使用当前来源生成新 v2，并保留原范围。`show` 仍不能借参数改变范围或增加明细，`recompute --update` 仍是显式更新入口，退出码 `0/2/3/4` 的既有含义保持不变。

### 4.6 网页交付、加载与图表交互

交付一个可由浏览器直接打开的静态 HTML 查看器，脚本、样式、图表与必要解析资源全部随包提供，可离线使用。采用原生页面控件和 SVG 条形图，不依赖前端框架、CDN、账号或后端进程。现有安装复制流程可以携带这些资源，保留已有目标不同内容拒绝覆盖的行为；本次设计编写不执行安装。

页面从空态开始，只提供用户选择单个已保存 JSON 的入口。文件在浏览器内存中解析和验证；成功后整体替换当前报告，失败时清空本次展示并显示明确原因，避免上一报告被误认为加载成功的新报告。关闭或重新打开页面后回到空态，不自动保存报告、最近文件或筛选状态。

页面包含报告身份与范围、原报告六列分组和合计、分布图表、三个独立明细视图，以及覆盖/来源/未归属/内部证据/独立工具报告说明。来源路径按文字展示，不自动打开；文件名和报告标签均按文本渲染。页面不调用 Python、不请求本地日志或任意网络资源，也不建设浏览器存储或上传流程。

为满足 JSON 的精确整数合同，网页使用随包提供的小型无损 JSON 解析器及整数表示，不先把超过 JavaScript 安全范围的整数解析为浮点数再转换。优先复用现成解析模块，不另写通用 JSON 解析器。数值文本保留精确整数，图形长度允许显示精度舍入；表值不能随图形舍入。浏览器支持需求为本地文件选择、SVG 和精确整数处理能力，缺少必要能力时明确说明运行环境不可用，不错误加载报告。

| 交互 | 数值来源与行为 |
| --- | --- |
| 默认分布 | 按互斥分组展示已保存总 token 小计，旁边显示同报告精确表值；没有可用总量时标明图表不可用，其他有效指标和证据仍可读 |
| 指标切换 | 可选择输入、输出、缓存读取或总量，各图只显示所选指标，不叠加包含关系不同的指标 |
| 明细切换 | 模型、代理、轮次仅使用该报告已保存的独立视图；不存在的维度显示不可用及原因 |
| 行筛选与展开 | 按当前视图的已有标签/身份选择显示行，或展开该行指标与来源；条件、隐藏行提示及清除入口可见。筛选不生成新任务范围，也不产生重新聚合的“筛选总量” |
| 合计与占比 | 原报告范围和合计固定；图表占比分母直接取该指标保存的 `summary` 已记录小计，筛选后保持原分母，并标明未显示行及覆盖范围。图形缩放和占比是显示运算，不重新计量调用 |
| 未知、零及部分量 | 未知没有数值条，不用长度零代表；已知零显示零；部分小计有明确标记。分母零则占比不适用，缺字段则说明可量化子集，不将剩余未知补为零 |

模型、代理、轮次视图都不与默认分组再次相加。未纳入所选任务的会话辅助/未归属量、源之间重叠未知的备选量和工具报告放独立说明区，不加入任务图表分母；完整会话范围已纳入的会话辅助仍在内部辅助组中贡献一次。视图筛选只改变可见内容，不能在二期网页中暗中触发新范围统计或来源重读。本次批准范围为各独立视图内的行筛选；模型与代理等维度联动并生成新的子集合计不在当前方案内，后续如提出该交互，应明确差异并重新确认，不得擅自实施或后移既有要求。

## 5. 测试决策与直接验收

### 5.1 测试 seam

用户已经确认两个外部测试 seam 及不可替代的真实两端验收：

1. 沿用现有“明确来源与统计请求 → CLI → 最终表格/JSON、退出状态及文件副作用”。现有 subprocess 与工作区外临时输入是 prior art；适配、归属、统计和输出一并受测，不逐函数复制测试，也不新建形式化大模型评测平台。
2. 新增“用户选择已保存报告 → 浏览器可见表格、图表、明细和筛选”。从实际页面操作检查加载错误、精确值、状态及无来源/网络读取；不能只断言页面元素或截图文件存在。

Codex、ZCode 的自然语言选择、桌面授权路径、追加请求、后台工作、恢复和分叉仍按需求进行真实交互验收。构造日志用于确定性边界回归，不能替代一期收尾与内部来源核查。原始来源复算的预期值由独立 SQL/原记录核对产生，不调用被测归一化器生成答案。

## 7. 补充说明与 Karpathy 精简与自检

### 7.1 基线、假设与差异

基线证据见第 1.2 节：保留一期范围、命令、去重、互斥分组、主代理语义、未知、导出、保存结果与重算；现有单维明细、源映射及内部分类限制直接影响方案。本设计不改动实现、Skill、一期规格、产品版本或执行计划。

假设是当前两端仍能提供至少既有已验证的实际 usage；新增身份来源及内部关系必须按具体版本核查，不能以字段名证明含义。第 1.3、4.2、4.3 节列出了未验证事实及对应降级，未假定所有环境自动定位、所有内部类别有 token、DB/rollout 可直接相加或真实分叉已完成验收。核心前提若被证据否定，须修订设计并明确受影响行为，再由用户决定，不能以全未知输出降低完成标准。

已批准技术选择为离线查看器、报告 v2 和预计算独立视图；新读取器兼容旧报告，旧工具读取新 v2 会明确不支持。网页行筛选保持原合计和分母，是报告视图操作；任务范围与统计结果不改变。这些选择均有二期需求依据，本轮仅授权继续编写执行计划，不存在已经执行的未经批准行为变化。设计审批与此前测试 seam 确认分开记录，均不替代执行计划批准或实施授权。

### 7.2 满足同一要求的可行方案比较

| 选择 | 可行方案比较 | 采用理由及最小限制 |
| --- | --- | --- |
| 网页交付 | 离线静态查看器；只接收报告、不接触日志的本地 Python 网页进程 | 两者均可展示已保存 JSON。静态方案不需要端口、进程退出和请求处理，原生文件选择满足加载；不为三期操作预建服务 |
| 多维展示 | 生成报告时保存共用内核的三个独立视图；本地查看进程用同一 Python 内核从已保存归一化记录计算视图 | 两者均避免浏览器另写统计。选择预计算使报告本身即可离线展示，旧报告不重算。仅添加实际需要的三个视图，不建立交叉组合立方体 |
| 报告演进 | v1 增加可选视图/证据并更新新读取器；明确 v2 并保留 v1 读取 | 两者均可兼容旧文件。v1 扩展改动更少，但旧读取器会静默丢弃不认识的证据；v2 能明确区分需验证的新结构及不支持状态。接受旧工具不能读新文件的可见限制，不新增迁移服务 |
| 定位组织 | 在现有操作中分别维护判断；两端产出共同证据结果，现有操作复用决定 | 前者也能满足行为，但同一冲突会在多个入口重复处理。采用一个内部结果，不新增公共命令/注册协议，源特有规则仍在各 Adapter |

无更简单且同时保证真实调用去重、任务归属、加权缓存率和已保存值一致的替代统计方案；这些职责已由一期内核承担，二期复用而非另行设计。无损整数解析只为已有精确整数合同，使用随包模块；图表使用原生 SVG，避免新增图表框架和网络依赖。
