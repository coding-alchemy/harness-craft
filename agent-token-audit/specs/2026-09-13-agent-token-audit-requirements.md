## 1. 核心目标与需求来源

用户能够查看大模型 Harness 在指定任务、会话中消耗的输入、输出、缓存命中等 token 用量，并区分有记录的数值与无法统计的部分。核心问题是“这项工作消耗多少，主要消耗在哪里”：默认提供任务汇总，并能展开模型、主代理和子代理明细。一期以表格交付，后续可复用统计结果输出网页或可视化插件。不把缺少任务难度、完成质量和模型控制的 Harness 横向排名作为核心结论。

用户明确指定：一期支持 Codex、ZCode；二期支持 OpenCode、Claude Code。

参考材料为用户提供的 `agent-token-audit-skill-design-spec.md`（2026-09-11）。其中的 ZCode 优先顺序、估算算法、固定 Skill 目录和“拿到即可开工”等指令均不自动构成当前要求。字段、版本和保留策略必须重新验证。

## 3. 用户可观察行为

### 3.1 查找与选择统计范围

工具能列出可统计的会话及其 Harness、标识、已知时间范围和数据可用性，并列出会话中的轮次候选。标题仅在源记录有值时提供，不能依赖模型生成标题完成统计。

日常支持“统计当前会话”“统计从开始讨论需求到现在的用量”等自然语言请求。范围明确时直接执行，存在多个合理边界时才要求选择；不要求用户日常查找会话 ID 或填写日志路径。脚本依据明确范围计算，不能由模型心算用量。

支持整个会话、一轮、同会话多个明确轮次及会话内时间区间。任务与轮次分开，不能默认把一轮称为完整任务；一期保留显式不连续轮次集合。Agent 根据用户目标及可用上下文定位范围，输出明确轮次集合或时间范围后交给脚本；有多个合理解释时先请用户选择，缺少文本与轮次关联证据时列出可辨识的候选，不擅自按相似度拼接。时间区间采用左闭右开，接受带时区时间并在报告中显示实际边界。不能把整个会话冒充某个任务。

轮次按 Harness 可识别的执行周期定义；执行中追加消息未启动新周期时仍归当前轮次，不强制按用户消息拆分或估算消息前后用量。选择轮次使用实际身份，来源显示编号仅作展示线索。消息关联或用量缺失时分别说明，不能因能枚举轮次就宣称该轮用量完整。

“当前会话”或“截至现在”在收到统计请求时固定截止点，不随着报告生成推进；本次统计调用不进入默认范围。自然语言入口使用当前统计请求的起点，而非脚本稍后启动时间；无法可靠取得起点时明确给出可用截止点并要求选择，不能声称已排除本次统计开销。独立 CLI 无 Agent 统计轮次时以命令开始时刻为默认截止点，允许显式指定时间。

会话恢复后保持同一逻辑身份和原有累计；压缩不自动创建新任务。分叉会话独立统计分叉后实际发生的调用，继承历史仅作来源说明；重新向模型发送继承上下文产生的输入正常计入。原会话 100 万、分叉后新增 20 万时，分叉会话显示 20 万，而非 120 万。无法识别继承记录时标明不确定性，不能直接累加复制历史。子代理跨越下一轮启动时间时，按明确父子关系归属，不能仅按时间邻近归属。

再次统计同一任务默认复用已确定的范围，不自动增加轮次或推进截止点。只有“更新到现在”或明确指定新增工作时，才重新确定需纳入的范围；歧义仍需确认。当前对话可提供已确定范围，按需导出的 JSON 保存其会话标识、轮次集合或时间区间及截止点，以便后续加载。未保存且当前对话中找不到可靠范围时重新定位，不能仅凭任务名称恢复。

“重新展示已保存报告”读取保存的结果，不扫描日志；“按原范围重新统计”使用保存的范围读取当前日志，源已丢失时如实报告，不能用旧值充当新计算。两种操作须明确区分，不建设独立任务管理数据库。

### 3.2 统计字段与含义

| 字段 | 要求 |
| --- | --- |
| 总输入 | 归一化为包含缓存读取和供应商单独计量缓存创建部分的完整输入；各源字段关系须有依据 |
| 缓存读取 | 输入中命中缓存的 token，不能再次加到总输入上 |
| 缓存写入 | 单独展示来源明确报告的写入量；不默认再加到总输入上 |
| 非缓存读取输入 | 仅在输入和缓存读取口径已确认且均有值时，计算总输入减缓存读取；不称为“普通输入计费量” |
| 输出 | 源明确报告的输出 token |
| 推理输出 | 源支持时作为明细；是否包含于输出由适配器确定，不能重复累计 |
| 总 token | 口径确认后为总输入加输出；缓存及已包含的推理 token 不再次相加 |
| 缓存命中率 | 同一组输入与缓存读取均已知的事件，缓存读取之和除以输入之和；显示覆盖范围，不平均逐请求百分比 |
| 调用数 | 已识别、去重的实际模型调用数；仅有累计 token 时不能从 usage 事件数量推断调用数 |

缺失、脱敏、不支持均显示为未知或不支持，并附原因。源报告的 0 与未知分别保存；若 0 的业务语义未验证，展示“源报告 0，语义未确认”，不得宣称没有缓存写入。

### 3.3 汇总与归属

表格以所选任务或会话为主体，支持按 Harness、模型、主代理/子代理查看明细。跨模型合计仅代表 token 数之和，不代表成本或相同工作量。

任务按调用归属计量。排除无关轮次，只排除该轮产生的模型调用；所选后续调用若仍携带该轮历史文本，其实际输入与缓存用量照常计入。不按提示词片段拆分 token，不推算“假如未发生被排除轮次”的用量，也不重新执行任务来获得反事实值。

同一真实调用的多个日志副本、流式消息和累计快照只能贡献一次用量；真实重试调用若分别产生 usage，应分别计入。调用失败不意味着没有 token 消耗；源没有报告失败用量时必须暴露这一缺口。

任务统计默认包含能明确归属的后代子代理和压缩、真实重试等内部模型工作，保留主代理、子代理、内部辅助调用明细。后台子代理持续归发起任务，即使其执行跨越下一轮；截止点之后才发生的用量留给更新范围后的报告。本口径不等于允许把用户在另一个会话开展的独立业务任务拼入一期任务。会话标题生成等可归属会话但无法归属任务的工作，列入“会话辅助/未归属”，不摊给最近的任务。模型身份未知时放入“模型未知”，不丢弃记录。

### 3.4 来源、完整性与表格输出

每份报告显示所选边界、固定截止点、实际读取时间、来源文件定位、已记录用量、仅有调用计数的部分、工具报告的独立数值和缺口说明。活跃任务显示“截至当前记录，未结束”；墙钟跨度与各模型调用耗时之和分开，不能相互替代。固定截止点避免统计操作自我追赶，但源日志后补可能改变同范围的新报告；不能据此承诺重跑数值必然相同。

某字段只覆盖部分调用时，数值标为“已记录小计”，不能以 0 补齐后标为完整总数。覆盖率只有在同一范围内存在可信调用总数且匹配成功时才计算；否则完整性为未知，不能因没有发现缺口就报 100%。

缓存命中率分母为 0 时显示不适用；部分缺失时只给已知子集比例，并显示该子集的调用数或输入覆盖量。工具报告的子代理累计量与直接 usage 分栏展示，不相加，不能按比例臆拆输入与输出。

默认在对话中展示简洁 Markdown 表格，详细来源和缺口放表后；直接运行 CLI 时显示终端表格。只有用户要求保存或导出时才写文件，支持 Markdown、CSV 和 JSON，不制作样式化 XLSX 工作簿。各格式使用同一份统计结果。JSON 保留整数、未知值、字段来源及范围身份；CSV 同时保留数值、完整性状态和缺失原因，不能只导出一个有歧义的数字。

默认表格列为分组、输入、输出、缓存读取、缓存命中率和总量；分组为主代理常规调用、子代理常规调用、内部辅助调用及合计。内部辅助单列后从主/子常规行移出，保证每次调用只进入一行；无法确认类型的记录单列“未分类”，不丢弃用量。按模型、具体子代理或轮次展开时使用独立视图，不将多个视图再次相加。缓存写入、推理输出、调用数、非缓存读取输入及耗时在详细信息中提供，缺失字段明确显示未知。

表前显示任务名称、会话、所选轮次或时间范围和截止点；表后说明输入包含缓存读取、数据覆盖及来源。任何指标不完整时，其数值标为部分覆盖，合计称“已记录小计”；缓存命中率注明是否只针对已知子集。耗时在不连续任务中仍表示已说明的首尾墙钟跨度，而非扣除插入任务后的净执行时间。

数值计算只读取用量和关联所需元数据；自然语言定位范围时可按需使用所选会话中必要的对话内容，不把对话正文复制进数值事件或导出报告。报告不包含认证信息或响应 headers。日志只读，生成报告的目标路径由调用方指定；临时验证产物遵守仓库的工作区外存放约束。

## 4. 直接验收标准

下列是一期完整验收目标；增量执行计划已按用户要求删除，当前实现与未闭合验收状态见[模块说明](../README.md)。

| 编号 | 用户可观察结果与直接证据 |
| --- | --- |
| A1 | Codex、ZCode 各选一个已知任务，人工从原始记录按调用复算输入、输出和缓存，与任务表格逐项一致；保留可回源定位 |
| A2 | 同一会话含两个任务和子代理时，单任务表格互不混入；完整分组的任务、会话辅助和未归属记录构成会话总量，重叠选集不能直接相加 |
| A3 | 同一调用在请求记录及累计事件同时出现、重复读取相同日志或复制分叉历史时，用量不增加；独立重试有 usage 时确实增加 |
| A4 | 两次调用分别为输入 100/300、缓存读取 90/0 时，合计输入 400、缓存 90、非缓存读取输入 310、命中率 22.5%；其中一个缓存字段缺失时不得仍宣称整体 22.5% |
| A5 | 截断、只有脱敏日志、未知格式、缺少累计基线或计数器重置时，报告明确指出哪些量不可知；已知部分不丢失，未知部分不填 0、不估算 |
| A6 | 选择连续时间区间时，边界事件不重复；选中多轮、跨日、压缩和异步子代理的已知样例，归属与明确选择一致 |
| A7 | 同一统计结果的终端、Markdown、CSV、JSON 数值和状态一致；JSON 可被独立脚本读出并重现表格，无需重新读取 Harness 日志 |
| A8 | 输出中不出现原始提示词、回复或认证数据；执行前后源日志内容不被工具修改 |
| A9 | 只有工具累计数或没有任何遥测时，能区分“仅工具报告”“不可统计”和“确认零用量”，不生成虚假完整总数 |
| A10 | 在当前会话用自然语言发起统计，范围明确时无需用户寻找日志路径或 ID；两种合理任务边界导致不同结果时先展示可辨识的候选供选择，选择后表格严格对应所选范围 |
| A11 | 已知样例主代理 10 万、两个子代理分别 20 万和 30 万、压缩调用 5 万时，完整任务合计 65 万且各明细可解释；只看主代理为 10 万，不能将其标成完整任务总量 |
| A12 | 统计请求开始后继续发生模型调用，默认报告仍截止于该请求开始时刻并排除本次统计操作；后台子代理保持原任务归属，仅计入截止点之前可计量部分，无法切分的跨界调用明确说明 |
| A13 | 同会话第 1、3 轮属于任务，第 2 轮无关：显式选择第 1、3 轮时仅计入它们及其已关联子代理，重复选择同一轮不增加用量；累计回退路径不得先过滤再差分而混入第 2 轮 |
| A14 | 同一执行周期接收两条用户消息时仍作为一个轮次列出并正确求和；第 3 轮请求携带第 2 轮历史时，选择第 1、3 轮得到它们的原始 usage 之和，不额外扣减历史文本 token |
| A15 | 普通统计只展示表格，不新建报告文件或启动采集；显式导出 CSV、Markdown 或 JSON 时仅生成指定格式和路径，数值及缺口与展示结果一致 |
| A16 | 保存任务第 1、3、5 轮及原截止点后，默认重算保持该范围；明确要求更新后才纳入新增范围。删除原日志后，仍可展示 JSON 中的旧报告；重算必须说明当前来源缺失，不能拿旧值伪装新结果 |
| A17 | 原会话 100 万、分叉新增 20 万的固定样例中，分叉默认显示 20 万；恢复原会话后新增调用继续累计；继承身份不明确时不能报无条件完整总量 |
| A18 | 主代理常规、子代理常规、内部辅助三行分别为 110,000、220,000、55,000 时，默认总量为 385,000；输入合计 350,000、缓存读取 270,000 时命中率为 77.14%。模型视图不额外加入总量，缺失字段和未分类记录仍可见 |
