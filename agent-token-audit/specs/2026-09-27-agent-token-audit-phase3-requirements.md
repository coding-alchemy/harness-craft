## 1. 目标与阶段依赖

在二期的 Codex、ZCode 定位、内部消耗和只读报告网页基础上，使网页成为完整的统计操作入口。定位和内部消耗的基础改进在二期验收；本期复用其结果，不再次设立同一补齐任务。

三期仍只面向现有两端，四期将本期网页能力对齐到 OpenCode、Claude Code。任务限单一用户会话，沿用一期及二期指标语义、未知状态和报告合同。长期可选需求判断不因网页增强自动纳入。

## 2. 更完善的网页功能

### 2.1 目标行为

网页从二期只读报告查看器演进为可操作的统计入口，功能方向及初步用户行为如下。

| 功能方向 | 用户行为 |
| --- | --- |
| 浏览会话与轮次 | 查看 Codex、ZCode 可用会话、轮次、能力说明和缺口，明确选择统计对象 |
| 范围选择与统计 | 选择会话内轮次集合或时间区间、代理范围和截止点，明确发起统计，结果呈现实际采用范围 |
| 报告复用 | 分清展示旧报告、按原范围重算、明确更新范围；显示实际截止点及新增范围 |
| 诊断与明细 | 查看模型、代理、轮次、内部调用和来源缺口；失败时说明原因及可采取的操作 |

范围选择沿用一期：支持整个会话、单轮、同会话连续或不连续轮次集合，以及带时区的左闭右开时间区间；使用稳定轮次 ID，不以显示序号代替身份，也不因追加消息另造轮次。代理范围沿用默认纳入有证据归属的后代及内部调用、只看主代理常规调用的既有含义。

展示旧报告仍不得扫描来源。用户浏览会话或轮次时，可读取对应来源用于列举，但不因此自动发起统计、重算或推进范围；统计或重算须由用户明确触发。来源不可用时，已保存报告仍可展示，重算须说明缺失，不能拿旧值充当新结果。

### 2.2 当前上下文和统计一致性

独立网页通常没有 Harness 的当前会话/请求上下文。只有能取得可信关联时才能提供“当前”操作，否则要求选择会话，不得以最新记录猜测。网页新发起“截至现在”统计或明确更新到现在时，在请求入口固定并显示截止点及来源；显式历史范围按所选边界执行。从 Harness 上下文发起的统计沿用可信请求起点，不重置为较晚的处理时间。

网页与 CLI 复用相同统计逻辑。对相同来源快照、范围和截止点，结果的数值、状态及缺口一致。后补记录可能改变重读结果，应如实说明。

网页筛选已有报告只影响视图，与重新读取来源统计须可区分。按原范围重算保持保存的会话、轮次集合或时间区间、代理范围及截止点；明确更新才重新确定范围，并显示新增范围及实际截止点，歧义仍需用户选择。不得无提示更改保存报告或推进范围，二期只读能力继续支持。

网页运行形态（本地服务、桌面集成或其他方式）、服务生命周期及安全边界须按目标行为选择最小设计。当前未批准公共托管、多用户账号或远程来源访问。

## 3. 网页复用所需接口

1. **定位与归属：** 复用二期身份、候选、证据、冲突和内部调用归属结果，网页不重新猜测或解析来源。
2. **统计操作：** 将列举、明确范围统计、展示旧报告、原范围重算、明确更新与 CLI 参数解析分离，供网页复用；保留 CLI 既有合同。
3. **结果及兼容：** 明确网页操作结果、参数/读取错误、来源能力不足和版本兼容表达；有效部分及其缺口仍可见，不能被笼统错误吞掉。合法旧报告仍可读，不支持版本或损坏报告明确提示，不能静默展示错误数值；维护两端来源样例及共同行为验证。

只整理本期网页实际需要的边界，不提前完成五期完整输入端规范，不建设动态注册或插件市场。

## 4. 直接验收与设计前提

| 编号 | 直接验收标准 |
| --- | --- |
| P3-A1 | Codex、ZCode 分别演示会话/稳定轮次浏览、整个会话、单轮、连续和不连续轮次集合及带时区的左闭右开时间区间选择、代理筛选、明确发起统计和诊断明细；结果显示实际采用范围、截止点及来源缺口 |
| P3-A2 | 展示旧报告、原范围重算和明确更新可区分；原范围重算保留会话、轮次或时间区间、代理范围及截止点，明确更新显示新增范围；筛选不推进范围或无提示更改保存报告；展示报告不访问来源，源删除后仍可展示，重算明确来源缺失且不复用旧值冒充新结果 |
| P3-A3 | 相同固定来源快照、范围和截止点下，网页与 CLI 数值、状态及缺口一致，错误不隐藏有效部分 |
| P3-A4 | 无可信上下文的网页要求选择会话；可信上下文才提供当前操作；新发起“截至现在”统计及更新到现在均在请求入口固定截止点，显式历史范围按所选边界执行；Harness 发起的统计沿用可信请求起点，追加输入不误用轮次起点，统计期间新消耗不追入固定报告 |
| P3-A5 | 二期合法报告及只读查看能力继续支持；不支持版本和损坏报告明确失败；接口调整不改变 CLI 既有合同、用户范围或指标语义，源记录保持只读，普通查询不自动保存或采集，报告不包含正文或认证信息 |
| P3-A6 | 按获批设计验证网页运行和退出生命周期、安全边界；交付范围与获批形态一致，不擅自引入公共托管、多用户账号或远程来源访问 |

进入三期设计前应确认网页功能组合、交互和错误处理；设计还需明确运行形态、生命周期、安全边界及请求起点规则。不能静默删减已确认方向或扩张范围。

## 5. 非目标

本期不接入新 Harness，不重新承担二期定位和内部消耗的补齐验收，不实施五期整组适配器规范或长期可选能力。

## 6. Karpathy 精简与自检

基线：二期两端定位、内部消耗、报告合同和只读网页；一期稳定轮次、范围及代理策略、固定截止点、旧报告复用和 CLI 合同继续有效。

假设与差异：独立网页通常无当前上下文，证据不足必须选择会话；运行形态待设计，不预设服务或账号系统。列举读取仅明确原浏览功能的必要行为，不新增自动扫描、统计或更新范围。

最小方案：复用已有统计行为及二期定位与归属，只整理网页实际需要的操作边界。暂无更简单且同时满足主动统计、CLI 一致性及参数解析分离要求的可行替代；单纯筛选报告无法主动统计，另建统计内核不满足同一逻辑复用，均不作为等价方案。

删除审计：原定位和内部消耗章节移至二期，四端对齐移至四期；本期只保留网页行为、实际需要的接口及其验收。合并重复的设计前确认与未批准运行边界表述，保留确认时序和限制，不删功能方向。

直接验收：P3-A1 至 P3-A6 验证两端完整网页操作、范围及来源副作用、CLI 一致性、上下文与截止点、报告兼容和获批运行边界，不以接口存在代替结果。
