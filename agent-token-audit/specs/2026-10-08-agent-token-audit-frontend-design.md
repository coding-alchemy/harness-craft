## 1. 问题陈述

用户认为当前前端“奇丑无比”，希望参照已指定的三个外部工具。当前来源配置、时间字段、候选与保存报告堆在长页面上；查询后先看到大量元数据和表格，每日横条随日期数增加页面高度。页面缺少指标、趋势、排行和证据之间的主次关系，常用操作难找。

目标是让用户用已有查询获得清晰的用量仪表盘，先回答“已记录多少、主要消耗在哪、何时发生”，再下钻到会话、轮次和来源证据。界面重排必须保留完整操作能力及原有计量合同。

## 2. 解决方案

以 Kimi 的仪表盘布局和紫蓝视觉为骨架，结合 DSH 用量工具的紧凑筛选栏与轻量表格、上下文工具的概览和详情分层。页面采用“整体用量 / 会话分析 / 已保存报告”三个页面内标签；查询后的整体视图依次呈现范围带、四张指标卡、日趋势、模型/会话排行与可展开证据。

固定仓库地址长期维护在[基线第 1.1 节](2026-10-07-agent-token-audit-implementation.md#11-用户指定的外部参考)。下列参考均已在前轮核对 README 和公开截图，未运行外部软件或审计全部源码：

## 3. 用户故事

以下覆盖本次呈现变化及重排必须保留的行为，新增卡片和控件限于第 4 节，不能从故事自行扩展产品范围。

1. **U01** 作为网页用户，我希望整体用量、会话分析和已保存报告有清楚的入口，以便直接找到当前操作。
2. **U02** 作为首次使用者，我希望看到明确空态和查询按钮，以便主动发起统计，不把未查询误认为零用量。
3. **U03** 作为查询者，我希望紧凑地选择 Harness、代理范围并查看来源，以便确认统计对象。
4. **U04** 作为查询者，我希望展开编辑完整时间边界和显示时区，以便保留秒、微秒、日界与左闭右开区间。
5. **U05** 作为结果阅读者，我希望待提交配置与结果实际范围分开，以便知道这份报告采用的范围和固定截止点。
6. **U06** 作为结果阅读者，我希望先看到已记录总量、输入、输出和缓存命中率，以便迅速了解主要指标。
7. **U07** 作为结果阅读者，我希望部分、未知、确认零、仅计数、仅工具及失败状态可辨，以便不把缺口当成完整结果。
8. **U08** 作为缓存分析者，我希望命中率注明配对子集和覆盖，以便避免把总输入误当分母或重复加缓存读取。
9. **U09** 作为趋势阅读者，我希望在高度稳定的日柱图中切换输入、输出、缓存和总量，以便比较不同日期，长序列仍可查看。
10. **U10** 作为趋势阅读者，我希望未知日期和无法归桶量有说明，以便理解日桶与已记录小计的对账关系。
11. **U11** 作为整体查询的下钻用户，我希望点击日期查看该份报告中的当日分布，以便分析一天的消耗而不重新读取来源。
12. **U12** 作为整体查询的下钻用户，我希望明确进入会话当日统计并逐级返回，以便沿保存的日交集和固定上界查询，保留原整体结果。
13. **U13** 作为排行阅读者，我希望并排比较模型与会话并切换排行指标，以便找到主要消耗，同时辨认会话自身小计与含后代统计的口径区别。
14. **U14** 作为会话选择者，我希望沿用候选搜索、排序、分页与勾选，以便明确选择集合，不把可见行误当查询范围。
15. **U15** 作为任务分析者，我希望选择整个会话、单轮、连续或不连续轮次，并保留 Shift 选择和空选语义，以便统计实际任务范围。
16. **U16** 作为从 Harness 转交的用户，我希望可信启动关联会话和请求起点仍可选择，以便按明确身份查询，不误认最新会话为当前会话。
17. **U17** 作为明细核对者，我希望图表与分组、模型、代理、轮次及内部记录准确联动，以便查看同一身份的证据，并区分返回全部明细和清除行筛选。
18. **U18** 作为证据核对者，我希望按需展开时间线、内部关系、会话索引和来源位置，以便检查分类、归属、生命周期与耗时限制，缺口摘要始终可见。
19. **U19** 作为已保存报告使用者，我希望加载旧报告只展示保存值，以便来源隔离或丢失后仍可查看，坏文件不会残留旧成功结果。
20. **U20** 作为已保存报告使用者，我希望原范围重算和明确更新分开，以便重算保留范围/来源/截止点，更新前核对完整集合及增删差异。
21. **U21** 作为结果比较者，我希望基准与新结果各自标明身份、范围和状态，以便避免串报表或用旧值冒充来源缺失后的新结果。
22. **U22** 作为报告使用者，我希望明确导出 JSON、CSV、Markdown 并重新加载，以便保留当前结果的数值、状态与范围，原文件不改写。
23. **U23** 作为离线使用者，我希望同样清楚地阅读合法 v1/v2/v3 报告，以便不依赖服务、网络或原始来源，旧报告缺少的能力有说明。
24. **U24** 作为窄屏或键盘用户，我希望卡片自适应、宽表格在卡片内滚动且焦点可见，以便访问查询、图表、导航、折叠与定位动作。
25. **U25** 作为核对精确值的用户，我希望完整大整数和未知原因可查，以便不因 K/M 舍入、浮点损失或省略状态而误判用量。
26. **U26** 作为本地工具用户，我希望切标签、展开、筛选和加载报告不自动统计或保存，以便保持显式查询、来源只读和原有服务停止规则。

## 4. 实现决策

### 4.1 页面组织与职责

保留共同操作层、报告校验与共享呈现层。网页交互层组织现有表单和结果，服务页与离线页共用结果样式；后端操作、HTTP 契约、报告版本和安装方式不变。切页面内标签只切换可见区，保留有效结果与选择；切 Harness/会话仍按原规则清除待提交候选并丢弃失效响应，不另建查询状态、路由或持久偏好。

| 区域 | 呈现与行为 |
| --- | --- |
| 顶栏 | 产品名、Codex/ZCode 选择、现有请求/错误状态；展开来源详情，不为状态增加轮询 |
| 查询栏 | 时间范围和显示时区摘要、代理范围、明确查询；初始展开，成功渲染后折叠为单行入口，失败时展开；展开可修改条件并重新查询，不改变默认范围、空值或提交合同 |
| 结果范围带 | 实际身份、会话集合摘要、范围、固定截止点、时区、代理策略及状态；完整范围可展开核对，与表单分开 |
| 指标卡 | 直接呈现报告 summary 的已记录总量、输入、输出、缓存命中率；保留字段状态和配对子集覆盖 |
| 日趋势 | 以保存日桶按时间排列纵柱；保留四种指标及日期下钻，长序列在卡片内滚动；保留每个保存日桶，不按周/月再聚合，不插入虚假零桶 |
| 排行 | 模型与会话桌面并排、窄屏纵排；保留现有指标和排序默认、精确数值、定位与完整身份 |
| 证据区 | 分组表、记录、时间线、内部关系、会话索引及来源详情按块展开；缺口摘要和无法归桶量常显 |

首屏预算优先用于实际范围、指标卡与日趋势。继续压缩间距或缩小图表会损害必要说明与日期、柱高的可辨性，因此查询成功后复用原生 `details` 折叠配置，保留完整表单入口；失败展开只恢复配置可见性，连接或请求失败不清已有报告，busy/stale 响应不改变折叠状态，fatal 沿用既有凭据失效处理。

会话分析继续提供浏览会话、轮次和请求候选、轮次选集、时间与代理范围、明确统计。可信启动关联会话及转交请求操作可见；来源缺标题时用稳定身份，不生成标题或展示对话正文。

整体查询结果中的日期选择只消费保存分布；“进入该会话当日统计”明确读取来源，生成独立单会话报告，保留保存日交集和固定上界。面包屑返回不修改原整体报告。会话排行仅自身小计，与默认包含可靠后代的单会话结果差异持续提示。

已保存报告区分加载、原范围重算及完整范围更新，更新前展示增删与边界差异；基准和新结果分区标识并各自绑定操作。隔离来源后旧值仍可读，新计算失败或缺失不得回填。离线入口只提供原有只读展示；共享样式不为保存报告或离线页新增查询、日期下钻能力。

### 4.2 视觉与语义

沿用前版提案的系统深浅配色：深色使用中性背景与紫蓝强调色，浅色提供对应层级，不另建主题设置。桌面内容宽度约 1280px，卡片间距 16–24px、圆角 10–12px；统一按钮、输入、分段控件和焦点样式。标题、主数值、说明有清楚字号层级，表格用行分隔、等宽数字和悬停高亮。

完整整数在卡片或精确值表中可见，不用 K/M 替代；图形比例沿用精确整数缩放，提示提供原值。部分用琥珀色加文字、未知给原因、确认零显示明确零；零分母标不适用，冲突不伪装已知。颜色不是唯一状态依据。

输入包含缓存读取，互斥分组以外的模型/代理/轮次视图不相加。时间线仍区分调用、逻辑请求、累计区间和未知粒度；不补造调用跨度、耗时、标题或上下文成分。图表定位自动展开目标证据区，并沿用完整身份及保存键；折叠不能使已有定位和键盘操作失效。

### 4.3 复用、替代与清理

| 部分 | 决策 |
| --- | --- |
| 复用 | 共同操作、报告验证、无损 JSON/BigInt、保存日交集、排序/筛选、记录联动、输出与安装资源 |
| 替代 | 将日横条替换为纵柱，重排页面区块，统一控件和共享样式；不并存第二套日趋势实现 |
| 新增 | 页面内标签的可见性切换、指标卡及必要折叠呈现，职责限于页面组织 |
| 清理 | 合并重复技术说明到对应帮助区；删除“点选日期下钻在后续版本提供”的过期提示及本次替换产生的废弃样式 |
| 保留 | 实际范围、固定截止点、精度提示、覆盖和缺口、全部既有操作及独立输入校验；不清理无关逻辑 |

呈现沿用原生 DOM/SVG 与随包资源，无构建步骤或 CDN。

## 5. 测试决策

### 5.1 已确认边界与先例

用户已确认采用现有浏览器服务页和离线查看器作为最高交互边界；通过实际查询、下钻、定位、下载与重新加载验收，不新增测试接口。CLI 的同值核对和原始记录独立复算是必要证据，不复制浏览器计量规则。

测试覆盖共享呈现层、网页交互层及受影响安装资源，观察值、范围、状态、动作效果、请求与文件副作用，不以 DOM 顺序、CSS 类名、内部函数或像素相等代替行为验收。

现有先例包括：OverviewCLI 的日交集/无法归桶量、大整数、配对子集、微秒导出重开与保存范围测试；Actions 的整体查询、更新集合、显式清空与小数秒保留；Guard 的来源边界；CLI 的旧报告、导出/重算和安装副本保护。它们支持构造回归，不能替代真实浏览器、真实两端来源或安装副本运行。基线中的历史浏览器与安装验收是先例，不能作为改版后已通过的证据。

## 6. 不在范围内

- 新增 Kimi/DSH 来源、跨会话业务任务识别、后端接口、报告版本或第二套计量内核。
- 参考工具的自动刷新、SSE、增量缓存、费用定价、账号额度、关页退出、Harness 内嵌插件。
- 来源未提供可靠合同的项目排行、小时桶、系统/工具/消息上下文分解；时间快捷预设与年度热力图需另行明确边界和缺失日语义，未加入本次提案。
- 独立短启动命令、Skill 网页启动路由及其他入口实现；此前三种使用方式的需求保留，不因本提案被关闭或替代。
- 无关代码重构、版本发布或追认基线中的未闭合产品验收。

## 7. 补充说明

### 7.1 基线、假设与批准范围

本轮核对了权威实现合同、领域术语、前版设计及网页表单、共享样式、报告渲染、查询/下钻、结果状态和相关测试。现有报告呈现接口 renderReport / renderOverviewReport 已共享服务和离线入口，runOverviewQuery 已接共同操作层；响应失效与各结果区绑定机制必须保留。适用决定由权威实现文档承接，模块未发现独立 ADR。

批准范围包含系统深浅配色、三个参考组合、三标签、配置/证据折叠、指标卡、日纵柱和样式统一；初始整体空态及现有排行/范围默认保留，不要求像素级复制。审批与实施授权记录见第 7.3 节。

### 7.2 Karpathy 精简与自检

1. **基线：** 第 7.1 节列出本轮源码/接口核对，权威合同覆盖精度、范围、计量、联动、安全、保存复用与兼容；第 4 节逐项说明复用、替代、新增和清理。
2. **假设与差异：** 第 7.1 节记录已批准范围；最终查询折叠及失败展开行为由第 4.1 节承接。本次收尾不改变计量、请求或保存合同。
3. **最小方案：** 同一功能可采用单页锚点加折叠，机制更少，但三类操作仍共处一个长文档，需更多滚动和辨认；采用前版三个页面内标签，让来源查询和保存报告操作边界更清楚，新增仅可见性切换。框架/图表库也可实现，但增加构建、分发与组件适配成本；原生 DOM/SVG 可覆盖现有柱图、卡片与定位，无需新增依赖。
4. **删除审计：** 第 1 节对应用户外观与操作问题，第 2 节对应三个固定参考，第 3 节用 U01–U26 覆盖呈现和既有行为，第 4 节承接布局及复用/替代决策，第 5 节逐项对应直接验收，第 6 节保留既有范围边界，第 7 节记录假设与审批。已合并前版散落的合同说明，删除方案末尾、清理列表后及发布段落中的重复声明；保留时间精度、缺口、独立验收和未闭合项。只明确导航失效及日期下钻的原有适用面，不增减已讨论功能。
5. **直接验收：** A01 直接检查用户能看见、找到和操作核心界面；A02–A07 检查重排后的精确值、选择/联动、请求、复用、离线与安装。实施与复评结论、直接验收证据及产品未闭合项统一见实现文档第 10.1 节。
