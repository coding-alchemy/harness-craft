## 1. 分类目标、范围与顺序

让统计分析支持更多 Harness，并让后续来源能够按照统一输入规范接入现有统计和展示能力。当前实际支持 Codex、ZCode；接入目标与已支持范围分别记录。

| 需求组 | 用户结果 | 当前状态与依赖 | 直接验收 |
| --- | --- | --- | --- |
| 新增 Harness 与四端能力对齐（第 2 节） | 接入 OpenCode、Claude Code，并保持 Codex、ZCode 行为 | 原四期：需求已批准，未实现；承接现行一期至三期基线，前序未闭合验收继续保留 | P4-A1–P4-A9 |
| 统一适配与接入规范（第 3 节） | 四端全部通过统一输入边界，其他 Harness 开发者可按规范实现最小接入示例 | 原五期：需求已批准，未实现；先完成四端能力对齐，再做完整统一改造 | P5-A1–P5-A4 |

第 2、3 节及验收表保留“四期”“五期”和 P4/P5 编号作为历史追踪标识；各节的“本期”仅指对应需求组。分类不改变原先后顺序，不用统一适配规范反过来阻塞新端接入。

四端对齐要求覆盖一期统计及二期定位、内部消耗和完整网页能力。整体分析、消耗解释、费用与性能是否扩展到 OpenCode、Claude Code 仍须另行确认；已有两端的已验收行为须保持。Kimi Code 目前是用户指定参考工具的来源，不因参考该工具自动成为本轮必须接入的第五种 Harness。

浏览器插件是[功能优化和完善中的长期产品形态目标](./2026-10-17-agent-token-audit-functional-improvement-requirements.md#5-浏览器插件长期产品形态)，多 Harness 来源能力由本文承接。浏览器扩展与动态适配器插件装载是不同范围；浏览器形态目标不自动增加插件市场、账号或远程注册平台。

## 2. 新增 Harness 与四端能力对齐

### 2.1 核心目标与阶段依赖

接入 OpenCode、Claude Code，并回归 Codex、ZCode，使四种 Harness 对齐一期统计基础及二期定位、内部消耗和网页的完整能力。前序未闭合的验收项不能从对齐范围中排除。

二期先完善已有两端；本期独立验证新来源，不把已有两端的字段、问题或支持状态当作新端事实。完整输入端统一改造、规范、接入示例及验收属于五期；后续能力的需求判断长期保留。

分期顺序上本期承接[二期整体分析和消耗解释](./2026-10-07-agent-token-audit-implementation.md)及[三期费用与性能](./2026-10-17-agent-token-audit-functional-improvement-requirements.md#3-费用与性能分析)。本次归类保持一期统计基础及二期定位、内部消耗和网页能力的四端对齐范围；二期整体分析、消耗解释及三期费用与性能是否扩展到 OpenCode、Claude Code 另行确认，不因文档归类自动扩大。Codex、ZCode 已验收行为不得因接入新端回退。

### 2.2 四端能力对齐

#### 2.2.1 用户能力

OpenCode、Claude Code 接入后应支持 Codex、ZCode 在一期基础能力及二期定位、内部消耗和网页能力要求的完整用户行为，并回归 Codex、ZCode：

- 自然语言入口与独立 CLI；列出会话、稳定轮次和可用于截止点的用户请求。
- 支持会话、单轮、同会话连续或不连续轮次集合、带时区的左闭右开时间范围；任务与轮次分开。
- 按统一口径统计输入、输出、缓存读取/写入、缓存命中率、可用推理明细及调用数；显示来源和未知、部分覆盖。
- 归属可信的后代代理和内部调用，支持互斥分组、模型/代理/轮次明细及只看主代理。
- 保持调用去重、真实重试计入、恢复累计、可验证分叉去重、异步后代归属和固定截止点。
- 支持表格、Markdown/CSV/JSON、按需导出、展示旧报告、按原范围重算及明确更新范围。

自然语言范围明确时直接统计；多个合理任务边界会产生不同结果时，呈现可辨识候选并按用户选择执行。重复查询保留原会话、轮次集合或时间区间、代理范围和截止点，明确更新才扩展；不能用整个会话代替指定任务。

“能力对齐”指相同用户行为、报告合同与计量规则，不要求源格式或字段相同。每端须说明支持版本、已验证能力、部分支持和未知原因。来源缺字段时如实降级；不能把所有字段都列为未知就宣称接入完成。若来源证据无法满足核心能力，应提出明确差异供用户决定。

定位与内部消耗按第 2.2.2 节、报告合同按第 2.2.3 节、网页能力按第 2.3 节对齐；仅达到一期 CLI 基线不算完成。

#### 2.2.2 定位与内部消耗

四端均遵守现行实现文档第 4 节的定位规则：分别确认会话与本次请求身份，证据充分时自动定位；缺失或冲突时说明原因、提供可辨识候选并保留选择，不凭最新记录或相同工作目录猜测。自然语言使用可信请求起点，独立 CLI 使用命令开始时间；不能误用追加请求所在轮次的更早起点。合成及明确非用户输入不得作为截止请求；等价副本合并证据，冲突不能静默择一。

OpenCode、Claude Code 按现行实现文档第 3 节及第 10.3 节“定位、内部与离线”的要求逐项独立调查重试与失败、压缩与摘要、标题与会话辅助、子代理后代、后台及其他内部工作，读取和关联所有有可靠证据的现有 usage。恢复、分叉和后台子代理定位不得误指其他范围。逐端记录可信定位改善及剩余人工步骤，不用一个端的结果代表其他端。

每类保留可回源证据，区分可计量、仅计数、仅工具报告、关联不明和来源未提供。不能恢复未记录数据、估算缺失量或按时间邻近分摊；需新增埋点、改造 Harness 或持续采集时，列明差异另行决定，不自动实施。Codex、ZCode 对已验收行为做回归。

#### 2.2.3 共同计量和报告合同

四端完整继承现行实现文档第 5 节的指标口径与计量约束：输入/缓存/推理不双计、成对已知记录加权命中率、未知不补零、真实调用去重而独立 attempt 分别计入、后补记录如实说明。任务限单一用户会话，源只读、普通查询不自动保存或采集、报告不含正文及认证信息。

保持报告格式、指标状态和来源缺口一致；合法旧报告继续可读，不支持版本和损坏报告明确失败。新增来源不能要求网页直接读取私有字段计算。

### 2.3 网页对齐与必要接口

四端报告均可在只读网页中准确展示范围、数值、状态、来源、缺口和图表；源删除后仍可展示报告，加载报告不触发来源扫描或重算。

二期网页操作在四端均可使用，包括浏览会话/轮次、范围及代理选择、明确统计、诊断明细、旧报告展示、原范围重算和明确更新。相同固定快照、范围及截止点下，网页和 CLI 数值、状态、缺口一致；没有可信当前上下文时要求选择，不猜会话。

浏览会话/轮次可读取对应来源作列举；统计或重算仅在用户明确触发后读取来源计算。

复用现有来源读取、归一化、共用统计与展示边界。来源特有的读取、字段解释和身份关系留在适配器；通用计算消费归一化输入，展示消费统一结果，不直接解析私有字段或散落来源特例。只整理新来源接入实际需要的入口、能力说明及重复逻辑，维护各端来源样例和共同行为验证；完整输入端统一改造和对外规范仍留在五期。

### 2.4 直接验收

保留验收编号 P4-A1–P4-A9，验收场景、强度和完成条件保留；旧阶段引用按对应能力更新。

| 编号 | 直接验收标准 |
| --- | --- |
| P4-A1 | 四端各选择已知真实任务，从原始记录独立复算输入、输出及缓存，与报告一致；版本、来源和缺口可回查，不能以全未知报告宣称接入 |
| P4-A2 | 四端用真实多任务会话验证明确范围直接统计、歧义候选选择及范围复用；不连续轮次不混入无关轮次，重复查询保留原会话、轮次或时间区间、代理范围及截止点，明确更新才扩展；重复记录不增量、独立 attempt 有 usage 时增量；恢复、分叉和异步后代归属有真实或可验证证据及明确限制 |
| P4-A3 | 新两端分别验证二期定位全部场景，包括追加请求、等价副本、时间/身份冲突、合成消息、恢复/分叉、后台子代理和多活跃会话；证据充分免手查 ID，否则说明原因及候选；逐端说明支持场景、改善项及剩余人工步骤；固定报告不追入统计操作消耗 |
| P4-A4 | 新两端逐内部类别独立调查并复算，可补齐量正确归属，未知归属可见；缺 usage、关联或调用总数时保留已知量及源证据，不填零、不估算；无法证明完整调用总数时不报 100% 用量覆盖率 |
| P4-A5 | 四端报告在只读网页重现精确数值及图表，未知/零/部分覆盖可辨，占比注明分母与覆盖范围，缺少维度明确不可用；筛选条件可见，视图不重复计量；隔离来源后仍展示且不访问日志 |
| P4-A6 | 四端分别演示二期完整网页操作及 CLI 一致性：会话/轮次浏览、范围及代理选择、明确统计、诊断明细、旧报告展示、原范围重算、明确更新及缺来源处理；当前上下文和请求截止点规则一致，错误不隐藏有效部分 |
| P4-A7 | 四端可导出、展示和重算；合法旧报告可读，不支持版本和损坏报告明确失败；Codex、ZCode 一期基础能力及二期定位、内部消耗和网页能力无回归 |
| P4-A8 | 四端源记录只读，普通查询不自动保存或采集，网页及导出不含正文或认证信息；核心能力差异须经用户决定后才能调整完成标准 |
| P4-A9 | 四端依据各自已验证的字段语义，独立核验输入 100/300、缓存读取 90/0 得到输入 400、缓存 90、非缓存读取输入 310、命中率 22.5%；缺字段时仅报带覆盖说明的已知子集，零分母显示不适用；缓存、缓存创建及已包含推理量不重复加总，源报告零与未知保留区别 |

### 2.5 非目标与设计前提

本期不以五期适配器规范完成作为接入前置条件，不建设动态插件平台，也不实施长期可选能力。

设计需确定 OpenCode、Claude Code 首批版本、运行环境、来源、字段语义及身份关系，逐端列明无法满足项。网页与报告沿用现行二期定位、内部消耗及网页能力合同；来源差异不自动授权缩小能力或宣称完整。

### 2.6 Karpathy 精简与自检

基线：现行实现文档第 10.3 节基础行为 B01–B18，以及二期定位、内部消耗、报告与网页能力合同。当前代码仅支持 Codex、ZCode，通过共用统计生成单会话 v2、整体 v3 报告，保留合法 v1 可读性；本期四端对齐范围仍按第 2.1 节界定，不把新端需求当作已实现事实。

假设与差异：新来源可得证据待验证，能力对齐不等于字段相同；不把旧两端的限制或自动定位结果外推到新端。

最小方案：扩展来源入口，复用共用统计、报告和网页。新来源解释、可信身份及独立核验是完整对齐所必需；目前没有已验证的更简单方案可同时满足这些要求。完整统一改造留在五期，不为接入另建统计内核或插件平台。

删除审计：适配器整组工作归本文第 3 节、需求判断归功能优化和完善类长期保留；本期承接一期统计基础及二期定位、内部消耗和网页能力的四端完整对齐及验收。合并重复能力列表和旧报告禁扫描述，保留逐端真实复算、缓存样例及全部范围、未知、归属和副作用约束。

直接验收：P4-A1 至 P4-A9 逐端验证真实数值、范围、可信身份、内部补齐、报告和网页兼容，不能以接口调用成功代替。

## 3. 统一适配与接入规范

### 3.1 核心目标与必选范围

统一 token 获取相关输入能力，通过适配器模式改造 Codex、ZCode、OpenCode、Claude Code，并输出供其他 Harness 接入的接口规范。本期交付包括四端统一改造、对外规范、最小接入示例及验收，不能只交付规范文档。

一期基础能力、二期定位/内部消耗/网页能力及四期规定的完整用户行为，以及前序形成的报告、定位、内部归属、统计和网页接口是本期基线。统一改造不改变用户范围、指标语义或已验收行为，不重建独立统计系统。长期可选需求判断不作为五期完成条件。

本次归类保持四端统一改造、八类输入能力、对外规范和最小示例范围。二期整体分析、消耗解释及三期费用与性能中已经验收的 Codex、ZCode 行为也须在统一改造中保持；这些分析能力是否扩展到新两端沿用四期的独立范围决定。

### 3.2 输入端抽象与四端改造

#### 3.2.1 所有输入能力

“获取 token 相关的全部能力”不仅是解析 usage 字段，也包括正确统计所需的来源和身份信息：

| 能力 | 统一边界需要表达的内容 |
| --- | --- |
| 来源探测与读取 | 来源类型、路径、版本、可用性、只读与一致性边界、缺失或损坏原因 |
| 能力声明与语义 | 可支持的指标、字段包含关系、记录粒度、定位和归属能力，以及部分/未知原因 |
| 会话、轮次、请求身份 | 稳定身份、生命周期证据、请求时间、可靠别名、合成消息分类、候选和冲突 |
| 用量及时间 | 原始 usage 对应的归一化数值、字段状态与零值语义、时间来源、逐调用与累计区间的区别 |
| 调用与去重 | 调用/attempt 身份、等价副本、多源冲突及不能可靠合并的表达 |
| 关系和归属 | 子代理后代、发起轮次、后台延续、内部调用性质、会话辅助和未归属量 |
| 恢复和分叉 | 逻辑会话延续、继承调用身份、祖先基线及不能判断的部分 |
| 来源证据与覆盖 | 回源定位、后补记录、覆盖依据、只有计数/工具报告/无 usage 的区别 |

适配器负责 Harness 特有的发现、读取、解释及身份关系；通用范围选择和聚合消费明确输入，展示层消费统一结果。通用计算及网页不直接解析 Harness 私有字段。适配器不得更改用户选定范围或为缺失值估算 token。

#### 3.2.2 四端统一改造

Codex、ZCode、OpenCode、Claude Code 均通过统一输入边界工作，不能只规范新来源而保留旧来源旁路。改造保留一期基础能力、二期定位/内部消耗/网页能力及四期验收行为和合法旧报告可读性。

接口表达真实能力差异，不要求所有来源伪造相同字段。某来源不支持时，提供能力状态与原因；核心用户行为未满足时明确提出差异，不能以接口调用成功或空报告代替适配验收。

抽象形式、类型和模块组织留给设计确定。

### 3.3 对外接口规范和接入示例

#### 3.3.1 规范至少包含

- 必选/可选能力、数据字段、值状态、错误与能力不足的表达。
- 身份、归属、请求起点与固定截止点、时间边界、去重、指标包含关系和证据责任。
- 来源及报告接口版本、兼容范围与不兼容变更规则。
- 新来源到统一输入的映射，以及累计值、未知字段、缺请求身份和来源冲突的处理。
- 最小接入示例、代表性样例及能证明新接入可用的验收步骤。

规范不能承诺所有 Harness 都提供完整用量，也不以现有四种来源的偶然同名字段限制未来来源。

#### 3.3.2 接入者结果

开发者按规范实现最小示例适配器后，既有统计和网页能正确展示已知用量、身份与缺口，不需在通用计算和展示中加入该来源的特殊分支。选择适配器所需的明确配置可以保留。

示例只验证接口合同，不自动承诺接入第五种真实 Harness。若示例证明合同无法表达必要信息，应修订规范并回归四端，不允许靠私有旁路绕开。

### 3.6 非目标与设计前提

### 3.7 Karpathy 精简与自检

最小方案：整理现有适配器模块的共同边界，或迁入专门适配框架，均可表达统一合同。优先复用前序读取、归属、共用统计和报告边界；新增框架是否必要须依据四端差异在设计中说明，本需求不预设。四端统一改造、规范、示例和共同验证均是交付要求，不以仅写文档或新增平台替代。
