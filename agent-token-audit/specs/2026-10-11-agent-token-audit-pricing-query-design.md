## 1. 问题陈述

用户目前须自行准备价格配置，省略配置时没有费用估算；项目没有可重复调用的官网价格更新功能。整体结果与日期下钻容易铺开长会话列表或把视野带到证据区末端。整体查询还承担大量读源、重复校验和隐藏表格生成工作，缩小时间范围并不能消除这些成本。精确时间输入虽灵活，日常查询却需要反复填写。

本设计让用户在现有三入口使用有依据的默认价格，明确更新价格，在紧凑仪表盘上按需看会话和证据，并直接选择常用时间范围。费用仍为已记录用量的估算，不能推导实际账单；提速不能降低精度、来源核验或报告校验。

## 2. 解决方案与基线

### 2.1 用户操作

- 新查询默认采用随 Skill 交付的最新已启用官网价格快照；用户可改用自定义价格，或明确选择仅看 token/性能。普通查询不联网。
- Harness 对话明确调用 Skill“更新默认模型价格”，读取固定官网、记录成功读取时间、校验候选并更新默认引用。保留此前读取快照；失败保留原默认值及其时间。
- 整体页初始选择最近7天，不自动查询；今天、本周、本月、最近1/3/7天、最近1个月（30天）、全部时间和自定义可选。切换只改待提交条件。
- 会话排行与日期会话分布默认呈现数量、摘要和展开入口，明细分页。点日期在图表附近展示摘要，明确进入会话才切标签并查询。
- 用键索引、一次分组、按需绘制及有界解析复用减少工作；每份报告仍从本次确认的来源快照、固定范围和价格生成。

### 2.2 继承与批准差异

继承源只读、缺失不补零、精确整数/金额、逐指标独立性能样本、固定截止点、明确查询、三入口同值、保存范围与价格快照、三格式导出、离线零网络，以及键盘与390px可读性。前序未验项继续按实现文档第10节单列。

本轮批准的变化是：新查询省略价格时使用默认官网估值；历史记录可用当前快照估值；增加明确更新默认价格的动作；调整会话呈现与滚动；整体页初始待提交范围改为最近7天；增加进程内解析复用。自定义历史规则、旧报告加载、保存价格重算及无价父报告下钻保持原合同。本版字段与接口已随V0.3获批，不能把设计批准当成实施授权。

### 2.3 实测根因与重审

现有操作层已统一三入口的范围、价格与保存复用；分析模块无 I/O。价格配置 schema v1 强制历史生效时间，不含官网读取时间、当前价估值模式或长度档，单加一份价格 JSON 不足以满足新要求。

前端候选表已有20条分页，会话索引原本默认折叠；实际问题是整体会话排行全量展开、非本页缺口逐条追加、日期面板在证据区后自动滚动，以及折叠证据仍预生成全部正文。

固定截止点 `2026-10-11T06:47:15.485133+00:00`、时区 +08:00、真实全量来源、无价格的诊断如下：

| 指标 | Codex | ZCode |
| --- | ---: | ---: |
| CLI 耗时（未加 profiler） | 10.361秒 | 32.356秒 |
| 会话/计量记录 | 621 / 4,512 | 1,141 / 29,584 |
| CLI 美化 JSON 大小 | 35.2 MB | 217.5 MB |
| Chrome 无损解析 | 0.685秒 | 6.453秒 |
| Chrome 完整校验 | 0.212秒 | 56.819秒 |
| Chrome 生成结果 DOM | 0.212秒 | 2.231秒 |
| 初次生成节点数 | 72,012 | 591,715 |

浏览器数据来自实际 `file://` 文件选择后的共用链，并非网页查询端到端计时；不能与 CLI 耗时相加。HTTP 紧凑响应须另测。profiler、文件系统冷热与源变化影响耗时，应在相同环境下对照。

源码与 profiler 确认：Codex 每次重新读/解析全部日志；ZCode 先取得约1.36 GB数据库快照，再读取配套日志并聚合。时间过滤在读源后，Codex 只选今天仍耗6.947秒。浏览器工具投影校验逐成员扫描全部样本并用数组查成员，形成二次增长；临时键索引替代实验将同一报告 Node 校验从67.237秒降至3.086秒，三类篡改仍拒绝。实验只支持根因和局部替代可行性，不能当作产品回归。

本轮增加解析缓存、扩展持久价格合同，因此在此先做机制重审：正常大报告应减少重复工作，坏报告仍先完整拒绝；来源改变或缺失后不能复用旧值。继续堆压缩样式、放宽校验、仅以mtime判缓存命中均不满足这些场景。选择收敛扫描与绘制、验证内容后复用解析；保留一致DB快照，不声称消除了数据库复制成本。具体复用边界见4.5节。

## 3. 用户故事

1. 作为查询用户，我希望没有自定义价格时也能得到有依据的费用小计，以便直接使用工具。
2. 作为查询用户，我希望看到当前官网标准API价估值、币种与读取时间，以便判断金额的口径和新旧。
3. 作为历史查询用户，我希望明确用哪次当前价格估算历史用量，以便避免误认为当年的账单。
4. 作为自定义价格用户，我希望我的完整配置优先，以便沿用约定的历史价格规则。
5. 作为仅查用量的用户，我希望明确关闭费用计算，以便保持原来的 token/性能查询方式。
6. 作为查询用户，我希望身份、档位或计价字段不足时保留已定价分项并说明缺口，以便避免把未知当免费。
7. 作为维护者，我希望通过 Skill 明确更新固定官网价格，以便以后重复更新而不重新组织抓取流程。
8. 作为维护者，我希望每次成功读取都有时间记录，即使价格相同，以便核对报价的新鲜程度。
9. 作为维护者，我希望部分来源失败、价格条件不全或写入失败时原默认值仍可用，以便避免发布半份配置。
10. 作为安装用户，我希望完整安装副本自带价格资源且不依赖开发仓库路径，以便独立运行。
11. 作为整体查询用户，我希望默认最近7天并能选择自然日或滚动范围，以便快速完成常见查询。
12. 作为精确范围用户，我希望仍能选择全部时间和自定义边界，以便保留已有控制能力。
13. 作为查询用户，我希望切快捷项不统计、不修改已有报告，以便先调整条件再明确提交。
14. 作为跨时区用户，我希望自然日、周一与月起点按所选时区解析，以便避免DST和月份边界错误。
15. 作为仪表盘用户，我希望整体查询后先看到范围、指标与日趋势，以便快速理解结果。
16. 作为仪表盘用户，我希望会话排行和日期会话分布按需展开并分页，以便不被长表淹没。
17. 作为下钻用户，我希望点日期只在图表附近显示摘要，以便保持视野和原报告。
18. 作为下钻用户，我希望明确进入会话才执行查询，并沿父报告截止点与价格，以便比较同口径结果。
19. 作为证据核对用户，我希望明确定位时自动展开并进入目标页，以便折叠和分页不阻断核对。
20. 作为性能敏感用户，我希望同一服务重复查询减少解析工作，源改变时又准确重读，以便兼顾速度和正确性。
21. 作为保存报告用户，我希望加载与原范围重算保留当次完整价格和绝对时间边界，以便官网更新不改变旧结果。
22. 作为换价用户，我希望明确选择默认或自定义新规则才重新定价，以便新旧估算可辨且原文件不改写。
23. 作为离线用户，我希望断开服务后仍能查看完整保存数据和价格依据，以便独立核查。
24. 作为其他工具的调用方，我希望 CLI、网页与 Skill 在同来源、范围、截止点、时区和规则下同值，以便稳定复用。

## 4. 实现决定

### 4.1 职责与复用

| 模块/边界 | 修改与保留 |
| --- | --- |
| Skill | 增加明确的官网价格更新动作、默认价与仅token说明；保留身份、请求起点、歧义候选及明确查询规则 |
| CLI / HTTP | 将价格选择和快捷范围转成共同 Query；HTTP继续只收配置文本/保存报告文本，不接受价格URL、服务器路径或写入动作 |
| 共同操作层 | 统一解析价格选择、捕获本次快照和截止点；保存、父报告价格及范围继续先校验后读源 |
| 价格资源管理 | 一处小型 I/O 边界，负责随包默认引用、历史读取快照、候选校验后的受保护原子启用；分析模块继续无 I/O |
| 适配器 / 关系 / 内核 | 保留来源守卫和一致快照；适配器只补有依据的判档计数口径。复用本次索引并重建关系、选集、投影与缺口 |
| 分析 / 两侧报告校验 | 扩展报价模式与条件；复用精确分项计价，键索引替代重复扫描；继续独立校验完整保存结果 |
| 页面交互 / 共享呈现 | 复用标签、details、20条分页和现有失效版本；服务页与离线页共用按需绘制，不在浏览器计量 |
| 输出 / 安装 | 三格式保留新价格依据；完整资源安装继续幂等/拒冲突，已有安装器若已能递归复制则不改 |

只新增价格资源管理这一必要职责：默认值的读取和受保护更新不能放进无 I/O 分析或离线呈现。解析缓存由现有服务持有并传给读取路径，不建第二个服务、统计内核或事件系统。

### 4.2 默认官网价格与配置版本

#### 4.2.1 固定来源与首批覆盖

固定读取 [OpenAI API价格](https://developers.openai.com/api/docs/pricing)、相关[模型说明](https://developers.openai.com/api/docs/models/gpt-6.1-sol)与[缓存计费说明](https://developers.openai.com/api/docs/guides/prompt-caching)，以及 [BigModel API价格](https://docs.bigmodel.cn/cn/guide/start/pricing)和其[官方Markdown](https://docs.bigmodel.cn/cn/guide/start/pricing.md)。模型页用于身份/条件交叉核对，数值以对应官方价格表为依据。

首批覆盖本轮真实记录中八款可核价模型：gpt-6.1-sol、gpt-5.6-terra、gpt-5.6-sol、gpt-6-astra、gpt-6-sol、GLM-5.3、GLM-5.3-Flash、GLM-5.2。更新这份目录，不能仅更新当前主模型；当前未出现的全厂商模型目录不在范围内。

默认定义为“当前官网标准API价等价值估算”：OpenAI采用Standard，BigModel采用标准按量API价。Fast/Batch/Flex、地区附加费、套餐额度与折扣不混入该口径。记录中套餐来源明确按API价估值，不声称实际服务档、扣费或套餐剩余额度已经得到验证。

默认映射使用经核查的完整源provider/model组合：OpenAI记录的 `openai` / `openai_http`，及BigModel记录的 `builtin:bigmodel-coding-plan`、`account:bigmodel-individual-coding-plan`、`builtin:bigmodel-start-plan`、`account:bigmodel-start-plan` 对应具体模型。每条映射保留依据和“按官网API价估值”的产品口径；不能因此把任意同名自定义端点认定为官方直连。无验证路径、未知模型、`codex-auto-review` 底层身份未公开可核价等情况保持未定价，不通配provider、不裁模型后缀、不套主模型价。

#### 4.2.2 最小配置合同

保留价格配置 schema v1 的全部历史匹配行为；增加 schema v2，专门表达 `price_basis=current_official_estimate`，不把读取时间伪造为历史生效时间。

| 信息 | v2合同 |
| --- | --- |
| 快照身份 | schema版本、唯一revision/快照身份、估值模式；一次读取生成新身份，同价重读也保留 |
| 来源 | 每个实际读取来源的官方URL、带时区 `fetched_at`、所读内容摘要；摘要不是官网版本，不复制整页正文进项目 |
| 规则与映射 | 稳定ID、官方完整供应商/模型、源身份的一次精确映射与依据、来源引用；保留原身份证据链 |
| 金额 | 明确币种、每百万token单位、非负有限十进制字符串单价与互斥分区；沿用Decimal/BigInt精确复算 |
| 条件 | `service_tier=standard`、完整单请求输入量的上下界与原官网依据；上下界明确是否含等值点，缺上界表示无上界。当前OpenAI分界为官网标注的272K输入token，短档含边界、长档不含；写入整数阈值前须核对官网单位定义，不将未核实条件发布为可用规则 |
| 官网时间 | `official_effective_from/to` 仅在官网明确公布时保存，并附依据；未知省略。它不替代 `fetched_at`，也不把当前估值改成历史匹配 |
| 未覆盖项 | 无相应token计价量纲、缺价或官方身份不可核查的原因；不补成零单价 |

v1继续按记录计价时间匹配历史生效区间，规则冲突不静默选价；v2按本次选定的当前快照估值，不要求记录落在官网读取日期之后。v2的同一身份/服务档区间必须互斥，发布校验拒绝重叠；记录无匹配或条件不足保持未定价，不能按文件顺序或最高/最低价选择。两种模式不在一份配置中混用；用户显式选v1时也不从默认配置补齐其缺规则。

单请求长度只来自能证明完整单请求输入量的证据。累计区间、含多次调用或重试且无法确定单请求量的记录，不能拿输入和猜档位；身份、分区或档位不足时说明未定价，保留不依赖缺失条件的可定价分项。适配器只保存非正文的证据与口径，不为判档创造新用量。

OpenAI缓存写入是普通输入/缓存读取/缓存写入的互斥分区，不在总输入费用上叠加。写量未知保持未知；BigModel token·小时缓存存储价不当作每百万缓存写入价。输出已含推理时不重复计价。不同币种分别给已定价小计与覆盖，不合并为总账单。

#### 4.2.3 报告兼容与价格选择

外层报告 `format_version` 继续为v2/v3；新报告 `analysis.schema_version` 提升为2，容纳v1/v2价格配置、新条件及逐记录命中依据，性能口径不改。两侧继续接受合法analysis v1及无扩展旧报告；原报告加载/导出不改其版本，重算才生成新扩展。不支持版本、条件坏引用、篡改分项/映射仍拒绝。

| 操作 | 省略价格选择 | 明确选择 |
| --- | --- | --- |
| 新 report / overview | 随包当前默认快照 | 自定义配置优先；仅token/性能不加载默认价 |
| 原范围重算 / 更新范围 | 保存规则；原无价仍无价 | 选默认或合法自定义新配置并发起计算才换价；只换价不设置范围update |
| 父报告下钻 | 父报告完整快照；无价仍无价 | 此操作不接受另一个待提交价格，改价应明确新建查询 |
| show / 本地加载 / export | 保存值 | 不接受新价格选择，不读默认价或官网 |

CLI保留 `--pricing`，增加明确 `--default-pricing` 与 `--no-pricing`；显式选择互斥，default/custom用于report/overview/recompute，no-pricing仅用于独立新report/overview，不增加保存报告清除价格的行为。HTTP在现有action中增加可选 `pricing_mode=default|custom|none`，none同样仅用于独立新查询：省略模式且有 `pricing_text` 是既有custom调用；省略两者依上表解析。custom必须带合法非空文本，default/none不得夹带文本；父报告通道与任何新选择互斥。

共同Query保留价格对象，增加明确选择语义，不能把None同时用作“自动默认”和“父报告明确无价”。默认价在操作入口读取并捕获完整快照，进行中更新不能串入已发请求；新请求才能使用新默认。非法自定义配置仍在读源前拒绝，不退回默认价。随包默认缺失/损坏时给明确配置错误，用户可明确改选仅token继续；不把坏默认静默当无价成功。

网页新查询表单默认“官网默认价格”，可切自定义/仅token；不预联网读取价格。保存区默认“沿保存规则”，独立提供默认/自定义换价；替换基准清选择并废弃旧FileReader结果。价格模式切换同样使此前未完成的文件读取失效，不能由旧回调恢复custom；复用现有读取版本与提交期间禁用规则。表单编辑不影响旧结果，结果显示实际快照、各来源读取时间、估价口径、条件及缺口，不用当前待提交配置解释旧报告。

JSON封存完整配置、命中身份/规则/条件、精确分项与缺口。CSV/Markdown从同一保存结果投影新价格依据、读取时间、档位与精确值；维持既有行类别和明细字段，不新增逐记录展开或反向重建要求。离线只消费保存值；价格局部缺口不改变token退出码。

### 4.3 固定更新与安装

沿现有Skill维护明确更新流程：读取固定官网及条件→形成候选和各来源真实读取时间→调用确定性校验/写入→保留历史快照并原子切换默认引用→报告旧/新身份、时间、变化和未覆盖项。普通查询、启动网页、加载报告均不触发它。

CLI增加 `pricing-update` 动作，以 `--candidate` 接受已读取形成的候选；它校验结构、来源白名单、映射、精度、档位及固定目录覆盖并执行写入，不心算、不静默补条件，不自带任意URL抓取。目录覆盖指每个目标模型都有本轮可核查规则或已核查的未公开价格原因，不要求撤价模型永远有价，也不能把读取失败伪装成官网无价。结构合法不能替代真实读取证据，Skill必须实际取得官方原文。

每次成功读取到的价格和时间都保留为小型历史快照；同价重读也记录。部分来源成功但全目录未完成时，成功读取记录可保留为未启用候选，原默认保持；不混入上一轮来源并谎称本轮全量更新成功。完整候选校验通过并成功切换默认引用才报告“更新成功”；失败保留旧引用与原时间，清理临时写入。

历史快照先安全写入，再同目录原子替换默认引用；引用只接受资源根内的快照身份，不接受任意路径，写入拒绝覆盖来源日志/报告及其链接别名。当前已启用文件与历史只保存价格及非敏感依据，不保存官网整页、对话正文或认证。

更新作用于实际加载的Skill资源副本：项目级Skill更新项目配置，独立安装副本更新自身配置；开始时标明目标，不偷偷反向修改另一份仓库或安装。完整安装复制默认引用及其可用快照资源，保持现有幂等与拒冲突，安装/查询都不自动联网取价。

本轮OpenAI官方Docs可读取，但直接HTTP `.md`曾返回403，未核实稳定价格JSON API；BigModel官方Markdown可直接获取。初版固定的是能使用官方文档/网页能力的Skill工作流，不承诺无大模型爬虫在所有Harness稳定取价。某Harness缺读取能力时明确更新未完成，不用第三方价填补，不影响已有默认快照的离线使用。

### 4.4 会话呈现与视野

整体会话排行、日期会话分布、完整会话集合/索引默认只呈现数量、状态/缺口摘要与入口；展开才生成正文，长表复用20条分页。会话分析的候选保留搜索、排序、勾选、跨页选集与明确浏览；不因为整体查询、标签切换或已有关联身份自动获取并铺开所有候选。

模型概览、指标卡与日趋势继续可读；费用会话排行同样按需展开。分页只改变视图，不改总量、费用、覆盖、集合、图表数据或导出，完整排行和证据仍可访问。

日期摘要与面包屑放在日趋势邻近。点柱只使用保存分布、不发统计请求、不跳到证据区；明确“查看会话”才展开该日分页表，明确“进入该会话当日统计”才切会话标签并查询。沿父报告日交集、截止点和价格，返回保留整体结果及待提交条件。

复用原生details，首次展开才生成折叠正文；长样本/记录/时间线明细分页，关闭再开保留该报告的视图状态。报告替换后清旧节点与绑定，沿用既有失效版本，不另建持久偏好或新状态机。缺口计数、原因摘要、未知与无法归桶量常显；非本页会话缺口改为摘要加按需详情。

明确定位必须通过已有保存键找到目标，展开其祖先、生成正文、选择含目标的页后滚动/聚焦；不可仅因目标尚未生成就报告“找不到”。表格、图表及导航保持键盘可达和390px无页面横向溢出。离线共享这些展示能力，仍不增加回源查询或服务页日期下钻。

### 4.5 性能收敛与缓存边界

按根因先后收敛四处工作，保持同一数据和完整校验：

1. 浏览器校验一次建立样本键索引及组成员/精确和，替代逐成员全扫描和includes。仍校验唯一键、排序、完整成员集合、数值、跨度包络和隐私边界，不只校验当前页。
2. 共享呈现按需生成折叠正文和分页行；排行切指标只更新已展开表，不提前绘制全体样本/会话。图表依完整保存投影，不用分页子集代替合计。
3. 后端在本次归属与selected确定后建立会话、轮次、维度及日桶索引，替换重复过滤。复用原聚合语义、排序与缺口，不新增长期统计结果副本。
4. 服务持有有界进程内解析缓存。CLI单次进程不承诺暖缓存收益；服务退出清理，无后台扫描、持久索引或跨服务复用。

缓存复用单元为一次来源适配器输入的完整有限快照及配套文件集合；不引入逐行追加/累计差分。每请求重新发现并经SourceGuard确认路径，然后读取当前有限内容。键包含Harness、真实路径/有序成员、解析语义与内容摘要；新增、消失、损坏、替换或内容改变都重新处理，不能只以mtime/大小判定命中。DB仍先取得现有一致只读快照，再对实际读取的表结构/行与配套日志生成内容签名；不能用DB/WAL stat替代一致性证据。

缓存只保留适配器归一化的非正文白名单证据；原始字节仅用于本次读/摘要，不进入缓存。关系绑定、跨源去重、父子闭包、选集、价格、统计及read_at每次重建。缓存对象须与请求工作副本隔离，不能被bind、核心解释或分析接线的原地操作污染。采用有限条目和字节上限，超限/淘汰/未命中走原读解析路径，不截断来源；内部上限按目标大报告的内存实测确定，不暴露成用户配置平台。

数据库复制和当前内容读取仍有成本，缓存只减少重复解析/归一化，不声称零读源或“实时索引”。复制、摘要、隔离的成本须计入冷/暖总耗时；真实大报告无收益时应收敛实现和记录原因，不能用小样本命中宣称完成。

HTTP使用现有紧凑JSON，保留全部数据和无损整数；CLI/下载格式不改。压缩只有传输实测证明有收益时再评审，不预先加入Worker、压缩协议或永久DB。任何省字段、少校验、缓存截至现在的整报告均不在本方案内。

### 4.6 快捷时间与固定范围

| 选项 | 解析出的范围 |
| --- | --- |
| 今天 | 所选时区本日00:00至本次截止点 |
| 本周 | 所选时区本周一00:00至本次截止点 |
| 本月 | 所选时区本月1日00:00至本次截止点 |
| 最近1/3/7天 | 同一截止点向前24/72/168小时 |
| 最近1个月（30天） | 同一截止点向前720小时 |
| 全部时间 | 无下界，截止点仍为本次固定入口时间 |
| 自定义 | 现有完整带时区文本边界与精度，显式上界继续合法 |

整体页初始最近7天，不产生请求。切选项只改待提交条件；自然范围随所选显示时区计算，IANA按真实日界/DST，不以固定24小时算自然日。滚动范围为实际经过小时，与自然日可辨。快捷态显示选项/时区摘要，自定义边界不参与提交；切回自定义恢复待提交的精确边界。实际绝对边界以本次查询结果为准，不把页面预览时间当截止点。

HTTP的overview请求增加可选 `time_preset=today|week|month|last_1d|last_3d|last_7d|last_30d|all`；与自定义from/to、父报告或保存重算范围互斥，custom继续使用现有from/to且省略time_preset。服务在现有处理入口先固定一次started，操作层结合有效tz解析绝对 `[from,to)`；非法时区或组合在读源前拒绝，不默改为本机时区。CLI与Skill可以通过同一Query表达预设；增加整体查询 `--time-preset`，仍保留原from/to与可信Harness截止点方式，不能为快捷项改变请求身份合同。

CLI显式to/可信request_start/request_id与快捷项组合时，以其唯一合法截止点为锚，不与from同时提交；HTTP整体页预设只锚定本次服务入口，不接收另一个待提交to。request_id须先由源证据确认截止点，再解析快捷范围；非法结构/时区仍先拒绝。解析逻辑只在共同操作层维护，浏览器不独立生成另一套边界。

报告只保存已解析的绝对from/to、时区与原截止点依据；表单可提示快捷名，但加载、离线和原范围重算不重新解释“今天/最近7天”。快捷仅作用于新整体查询，不替代已有保存更新的完整边界差异确认。成功折叠查询表单、失败展开，以及busy/stale/fatal的既有处理保持。
