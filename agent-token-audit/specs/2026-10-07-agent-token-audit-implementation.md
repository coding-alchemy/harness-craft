## 1. 定位、范围与阶段

工具回答“指定任务、会话或整体范围消耗多少，主要消耗在哪里”。Agent 用自然语言确定范围，Python 脚本确定性计量，浏览器展示同一份结构化结果。跨模型 token 相加只表示数量，不表示费用、同等工作量或质量排名。

| 阶段 | 范围 | 当前结论 |
| --- | --- | --- |
| 一期：初步构建基础能力 | 两端只读适配、会话/轮次/请求候选、任务范围、去重与后代归属、表格、按需导出、报告复用与安装 | 基础能力已形成；基础收尾与接受差异见第 10 节 |
| 二期：功能整体完善 | 可信定位与内部消耗、离线图表、本地网页操作、整体用量分析、记录解释与时间线联动 | 功能代码已形成；定位/网页按接受边界闭合，整体分析和解释仍有独立待补验项，不能称整期验收通过 |
| 三期：费用与性能分析 | 明确本地价格、费用分组与下钻、独立 TTFT/来源观测区间吞吐/工具耗时、保存规则重算及三入口交付 | 六票实施、直接验收及最终复评完成；用户于 2026-10-11 明确要求清理已完成计划并提交，前序未验不追认 |

当前只接入 Codex、ZCode。任务限同一用户会话及有明确关系的后代；跨会话整体分析不识别或拼接跨会话业务任务。普通查询不保存、不持续采集；只承诺可用记录的小计及缺口，不估算已删除或未报告用量。本文不定义未实现能力或后续路线图。

## 2. 系统结构与数据流

`audit.py → cli.main → operations.run(Query)` 与 `web.py → webapp.serve → Handler._run_action → operations.run(Query)` 共用操作层；自然语言 Skill 也是上述脚本的调用方。操作层负责来源选择、身份/截止点、保存范围复用和操作分派，不承担 argparse、HTTP 或终端渲染。

读取路径是 `codex.read` 或 `zcode.read/read_database → relations.bind → core.report/overview → operations 分析接线 → analysis → formats`。适配器只读真实证据，归一化、去重后绑定继承/后代关系；内核对一份记录集合筛选、聚合并生成解释。浏览器 `shared.js` 校验和渲染保存值，`web.js` 管查询与交互状态，不另建统计内核。无 I/O 的 `analysis` 模块为每份新报告按来源证据生成独立性能；价格为随包官网快照（schema v2，新查询默认）、历史显式配置（v1）或显式换价，读源前完成价格配置校验、规则匹配与 Decimal 分项计价，入口只解析/提交配置并展示结果。

运行需要 Python 3.9+，Python 产品代码仅用标准库；浏览器使用随包无损 JSON、原生 SVG 和控件，无构建步骤、CDN 或账号。报告、来源读取和输出三者分离；保存结果展示提前返回，来源路径只作证据，不能触发展示时扫描。

## 3. 来源、字段、去重与归属

### 3.1 Codex

默认读取 `CODEX_HOME/sessions`（缺省 `~/.codex/sessions`）或显式 JSONL。身份来自 payload，不从文件名、目录、模型角色或时间邻近猜会话。优先逐调用 `token_usage_record.payload.usage`，以会话及 `response_id` 去重；同源累计通知是校验视图，不再次加总。

旧记录仅在 assistant 回复唯一、核心字段有效且与累计差值相符时采用 `last_token_usage`。否则在完整源序列上先求累计差分，再筛选轮次集合。首个累计快照无零基线不当增量；重置/回退不截负为零。跨未选轮次或跨边界的区间不能按比例拆分，不能仅凭时间包络把整段计入。新旧覆盖重叠择一计量，字段冲突不吞掉其他可靠量。会话 `model_provider`（如 `openai_http` 保持原值不改写）与轮次模型上下文保留进记录作为价格身份；无明确身份绑定的记录不猜价。

`compacted.compaction_response_id` 明确对应调用时，将该调用移至内部辅助，不新增用量。无对应 usage 时说明可能已计或缺失。逐调用记录只有 usage 时刻而无开始时间，只画点，不补造调用跨度。`item_completed` 的 `CommandExecution`/`McpToolCall` 有结构化身份、状态与原生 duration（secs/nanos 精确换算不截整数毫秒），部分版本另有起止毫秒时间；只这两类纳入工具耗时证据，其他 item 类型与文本输出不据此宣称支持，命令参数与输出正文不复制。同会话跨文件的工具身份副本合并一次，冲突保留。

### 3.2 ZCode

默认优先现有 `~/.zcode/cli/db/db.sqlite` 的 `model_usage.raw_usage_json`；没有数据库时读 rollout/log。`--database` 和 `--source` 表示不同计量入口，不混合相加。DB logical_request_id 与 rollout requestId 无调用级桥接，不能凭 trace、相近时间或相同数值认定同调用。数据库入口核对同级 rollout，可读值以补充来源独立列示，明确跨源重叠未知、未并入小计、未按报告范围筛选。

rollout 以会话/request/attempt 识别调用，流式、非流式完成和失败的同 attempt 副本只计一次；独立 attempt 有 usage 分别计入。顶层与 response usage 冲突明确降级。DB 行是逻辑请求结果，不能冒充完整独立重试次数；`retry_count` 非零时说明调用总数与失败用量可能缺失。数值列默认零不能替代缺失 raw usage。计数日志与 rollout 只有在会话、调用、attempt 和类型可匹配时才形成可信缺口数；不能用日志总行数减 rollout 行数。

轮次候选合并 `turn_usage`、`model_usage.turn_id` 及明确事件的稳定 ID。只有 usage 也可选、可统计，但生命周期未知；后补事件只补同一候选。`session_input.kind=sendText` 是真实输入证据；只用 `promoted_message_id` 关联提升后 message，截止点取入队接收时间。合成 message、明确非用户输入及可靠别名拒绝作为用户请求；旧记录分类或关联字段缺失保持未知，不凭正文、时间或 ID 前缀合并。

字段核查覆盖 Codex 0.153–0.159、ZCode 0.16.3–0.16.9 的代表性记录，不承诺所有版本/操作系统/入口。已验证 BigModel Coding Plan/Start Plan 及 account 变体的同一写入器字段语义；其他供应商保留原值及未知，算术相等不证明包含关系。`cacheWriteTokens=0` 语义未确认，`reasoningTokens` 未报告；不能宣称确认零或外推全供应商。记录保留 `provider_id` 与完整 `model_id` 作为价格身份，供应商语义未验证的记录不猜价。DB `model_usage` 另保留 `started_at/first_token_at/time_to_first_token_ms/completed_at` 与 `tool_call_count/retry_count` 作为模型性能时间事件证据（同一逻辑请求粒度）；旧结构缺列时该入口按已核查的来源未提供处理，不凭数值列补造首 token。DB `tool_usage` 保留会话/轮次、tool_call_id、状态、原生 duration 与调度至完成时间：原生执行耗时与调度跨度不是同义字段，分列保存不判冲突；写入器可把缺失 duration 转为 0，单凭 DB 零值保持未知，有明确执行完成日志等独立证据才确认零。JSONL `tool.call.started/completed/failed` 有稳定工具身份与 duration，按完整会话/tool_call_id 合并起止与完成副本只计一次；无会话身份的工具/MCP 日志不按 trace 或时间猜归属。DB 工具与相邻日志仅在完整会话/tool_call_id 唯一一致时合并（补足真实执行起点或核实零值），关联不明的补充项单列不重复计入。

### 3.3 去重与关系

同一真实调用合并全部来源定位；冲突只降级受影响字段，不平均、不多计。时间、粒度、状态、耗时的证据缺失可由可靠副本补齐，相反事实保留冲突；布尔值不当数字，等价时区字符串按同一时刻比较。来源文件有限快照只读完整行，损坏/未完成行标位置和影响，不复制原文到诊断。

明确父子/spawn/root turn 关系递归把后代归发起任务；后台跨下一轮仍归原任务。`workflow_child` 按 task_type 归后台后代，不能当分叉或额外一份内部量。关系缺失/冲突的已知量保留未归属，不按时间补链。压缩不新建任务，恢复沿同一会话累计；分叉只计新增调用，明确祖先关系和调用身份才剔除继承副本。重新发送继承上下文的新调用照常计入；缺祖先或累计基线保留不确定性。

逐端核查重试/失败、压缩/摘要、标题/会话辅助、子代理/后代、后台/其他五类来源。`internal_support` 的尚未核查、已核查可用、源未提供、存在缺口是能力状态，不是互斥用量组。可计量、仅计数、仅工具、关联不明分别说明；未读取不能写为源不存在。

## 4. 身份、范围与固定截止点

会话与请求分别确认。可信 Harness 上下文/环境身份须与源唯一匹配；无身份、多候选或冲突时显示稳定身份、已知时间、能力及原因并等待选择，不自动用最新会话。标题仅源有值时显示。范围明确直接统计；真实歧义导致不同结果才询问。已确定范围优先从当前对话或显式保存报告复用，不能仅凭任务名称恢复或扩展；重叠选集明确提示且不能直接相加。自然语言定位可按需读所选会话必要正文，数值事件和报告不保存正文，不建任务数据库或自动相似度分类器。

整个会话、单轮、连续/不连续轮次均支持；连续区段转为明确稳定 ID 集合，重复 ID 不增量。轮次是执行周期，消息不是轮次，追加输入未启动周期就不另造轮次。任务只排除未选轮次的调用，所选调用携带的历史上下文仍按实际 usage 计入，不扣提示词片段或反事实用量。轮次与时间约束可组合。

时间为带时区 `[from,to)`，要求 from < to。完整调用用结束/usage 时刻过滤；跨截止点不按比例切 token，累计区间跨下界或未选轮次不能拆，缺可信时间不静默计入。默认包含可靠后代及内部；`--main-only` 只主代理常规，另列内部辅助也排除（65 万任务样例中为 10 万）。

| 场景 | 截止点合同 |
| --- | --- |
| 自然语言本次/追加请求 | 使用本次请求自身可信创建/入队起点，不能用共享轮次或首请求起点；缺可信起点列可用边界待选择，不声称排除统计开销 |
| 独立 CLI | 参数解析/读源前的命令开始；显式历史上界覆盖默认，request-start 字符串本身不证明身份 |
| 网页截至现在 | HTTP 处理入口第一步固定 UTC `web_request_start`，不冒充浏览器点击瞬间或完成时间 |
| 保存范围重算 | 沿旧会话/集合、轮次、区间、代理策略、来源及 cutoff_source，不随当前环境或读取时间推进 |
| 明确更新 | 展示完整新范围、增删与边界差异后提交；截止点未指定才用新入口时间；切 Harness/单会话对象需新查询 |

范围固定不等于源快照冻结，后补记录可改变同范围重算。统计期间新消耗不能追入原固定报告；无法切分的调用列缺口。环境只给会话不证明请求；非用户/合成请求不因显式给 ID 而合法。

## 5. 指标、视图与完整性

指标保留 value、state、reason、源字段：源报告、推导、未知、冲突。完整输入包含源计量的缓存读/写；缓存读取不再加输入，缓存写入独立展示不默认再加，已包含于输出的推理量不再加。语义已验证且字段已知才得到非缓存读取输入=input-cache_read、total=input+output；源总量不符标冲突。

缓存率只取输入和缓存读取成对已知记录，计算两者总和之比，不平均逐调用比例；附 paired_records、输入及缓存覆盖。输入100/300、缓存90/0得到400/90/22.5%；缺一个字段不能宣称整体22.5%，零分母不适用，合法100%缓存率允许。调用覆盖率是另一指标，无可信分母不能报100%。

默认表列分组、输入、输出、缓存读取、命中率、总量。主代理常规、子代理常规、内部辅助、未分类互斥；内部性质优先，再按代理身份分组。模型/代理/轮次是同一记录集的独立视图，不相加；`--detail` 从保存视图投影。跨多轮累计区间单列无法拆分，不复制进每轮。缓存写入、推理、调用数、非缓存输入、耗时在详细信息提供。

直接 usage、可信调用计数、工具累计是独立通道；工具不拆输入输出、不加直接小计。会话辅助可进完整会话/整体，无法归任务的量不摊最近任务；继承副本、补充来源和排除诊断单列。未知模型不丢记录。

| 结果状态 | 含义 |
| --- | --- |
| partial | 有可靠已记录小计，仍未证明完整调用覆盖；字段缺失不补0 |
| count_only / tool_only | 分别保留计数或独立工具报告，不能因无usage吞掉结果 |
| unstatisticable | 无可用计量证据，未知不画零 |
| confirmed_zero | 范围内全部会话有完整零调用账本、截止前结束且无相反记录/缺口/工具；空列表不足以证明零 |

展示命中率四舍五入到两位小数，计算仍使用原始整数。表前给身份、范围、固定截止点，表后给 read_at、来源、缺口与覆盖。部分合计称已记录小计；视图隐藏行不改变合计、分母或范围。

## 6. 整体分析、日趋势、排行与下钻

`overview` 在单一 Harness 内默认纳入本次解析的全部会话，也可显式选稳定 ID 集合；保存实际集合，重算冻结，更新才改。父子闭包在一份已去重记录上选择一次，不能把逐会话报告相加；主代理策略只所选根的常规调用。新显式未知 ID 报错，保存集合缺失保留范围并说明缺口，不用旧值。

整体 v3 保存总览、`days`、模型/会话 `rankings`、`session_index`、独立通道及缺口。整体轮次视图不可用，不能跨会话把同名轮次混成一行。会话排行是该会话自身小计；进入单会话统计默认含可靠后代，两者口径不同需提示。

时区支持 IANA 名或 ±HH:MM，CLI 缺省系统本地偏移并声明，网页预填浏览器时区可改；无时区文本不当UTC。按可信usage/结束时刻归本地日；日范围保存为原范围与该日的交集，保留原边界精度/拼写，微秒和 DST 日界使用内核同一规则。已在整体范围的跨日累计区间不硬分日，存 `unbucketed` 独立对账；缺时间记录不进任何合计。

日桶缓存率仍成对加权，排行未知不归零，输入/输出/缓存/总量与覆盖对应。点日期只用保存的日模型/会话分布，不读源；带价格的整体报告另在费用投影区给各币种的模型/会话排行、日期分布与无法归日项（同一计价结果的独立视图，不相加）。点“进入该会话当日统计”明确发起独立v2，使用保存日交集和固定上界，并携带父报告保存的价格规则快照（HTTP 下钻以父报告文本传递该语义，不从页面当前待提交配置取价；父报告未配置价格则当日统计不含费用）。整体→日期→会话逐级返回保留原查询及整体结果，不在v3嵌套或修改它。

候选列表文本筛选/列排序/固定页长分页只帮助下一次选择，结果行筛选只隐藏展示，重新计量必须明确点击。查询前编辑不改已有报告，图表与列表不生成筛选子集合计。

## 7. 记录解释、生命周期、耗时与联动

新v2/v3在同次统计结果上保存可选解释，不另计量。粒度分 `model_call`、`reply_usage`、`logical_request`、`cumulative_interval`、`unknown`；call_count=1或键前缀不能证明逐调用。计量行 `record_keys` 只引用本报告 records，独立通道只在自己通道定位，排除项不得加入计量行。

显式选中的轮次全部保留，含无 usage 或缺起止者；其他查询只纳入贡献记录涉及的轮次及有可信生命周期且与范围相交的轮次。无法证明落入范围、又未被显式选择或记录引用的候选只说明限制；生命周期跨出计量范围时保原始边界并标范围外上下文，不能截短后称完整轮次。

时间线按真实会话＋轮次身份组织，原始轮次与任务归属轮次分别保留；后代只按明确链归属。同名轮次在不同会话不串行，追加消息不新造轮次。可信时间稳定排序，缺时间放未知区；显示排序不改变累计差分。来源所读状态与截止前状态分别表达：结束事件在截止后就不能宣称当时已结束，只见起点称截至边界未确认结束，不能推断当前进程仍运行。

墙钟只取主会话所选轮次最早可信开始至最晚可信结束，不连续选集保留中间间隔；后代各列跨度，整体不造跨会话全局墙钟。缺端点、逆序、冲突、未在截止前结束或覆盖不全给未知原因。原生轮次duration是独立证据，不能填模型调用耗时。

条目耗时来自自身直接字段或可信起止，精度可比却矛盾列冲突，仅精度不同分别标注；拒负数、布尔、非有限数，明确0可显示。已有 activity.call_duration_ms 仅在所有纳入记录都有有效同粒度耗时才给完整和，否则为未知；已知子集、有效/缺失/冲突计数分别保存。逻辑请求耗时不混模型调用/累计区间；并行重叠不扣，墙钟≠耗时和，不因果分摊。串行两次10秒墙钟/和20秒；0–10与5–15并行墙钟15、和20秒。

费用与独立性能由第 11 节维护；性能候选与解释中的 token 记录及轮次墙钟不是同一集合或口径，不能互相替代。

图表行身份由维度类型及完整身份确定，轮次用结构化会话/轮次；截断标签、显示序号或拼接分隔符不能充当身份。图表、表格、键盘定位同一身份，一次选一个维度行/记录替换此前定位。指标切换保留、维度切换清除；“返回全部明细”与“清除行筛选”作用不同。定位只按保存键高亮/滚动/展开，空匹配给原因；行筛选不改定位集合、范围、合计、缓存子集或分母。每结果区闭包绑定自身报告，失效或坏文件清旧联动和导出绑定。

明细展开给完整身份、原始/归属轮次、粒度、时间语义、指标与耗时状态、分类/关系依据、文件完整路径及行号或DB表/行ID；不自动打开来源，不含正文/异常正文/headers/认证或模型生成的解释。内部分类只凭明确证据，五类来源的支持状态不能画成额外堆叠用量。

费用与性能共用 v2/v3 可选 `analysis` 扩展；其内部 schema version 区分两档：无价格/v1 显式配置生成 1，v2 官网快照计价生成 2（含逐记录命中身份/规则/档位证据），v1 报告明确拒绝扩展。报告保存的价格配置快照可为历史 v1（显式配置，按生效区间）或 v2（官网读取快照，按档位条件且规则/映射引用须属于本快照实际读取的来源）；无价/v1 报告不因缺 v2 证据升级版本。新 v2/v3 必存性能部分，有价格配置（默认快照或显式提交）才另存费用部分；旧报告缺扩展仍合法，不补造工具区、不自动升级原文件。

| 扩展部分 | 保存内容 |
| --- | --- |
| 价格配置 | 本次完整规范配置快照、修订和来源依据，包含未命中规则，以支持固定范围后补记录；不只保存可变文件路径 |
| 逐记录计价 | 引用本报告 token 记录稳定键，保存完整价格身份/状态、命中规则、计价分项、精确 token/单价/金额及未定价原因 |
| 费用投影 | 按币种的摘要、完整身份模型/会话/日期成员和无法归日项；成员来自同一已定价分项，不把投影视图相加 |
| 性能样本 | 独立稳定样本键、会话/轮次/归属、事件时间、粒度、状态、精度、依据和源位置；有对应 token 记录才附引用，没有 usage 不伪造引用 |
| 性能投影 | 按指标/同口径分组的有效成员、计算分子/分母、保存结果、日分布与缺口；工具调度跨度不混进执行耗时集合 |

v2 不携带费用投影，v3 费用部分必须携带模型/会话/日期及无法归日投影。价格配置快照含未命中规则和明确别名依据，不保存可变配置路径；成员引用本报告稳定记录键，金额来自同一计价分项，各投影不相加。性能样本键使用完整会话＋源调用/item 身份，有对应 token 记录才附 record_key；工具样本恒不引用 token 记录。

Python 与浏览器分别核验扩展版本、必需字段、白名单、枚举、非负精确整数、规范十进制字符串、键唯一、引用、价格分区、聚合及工具跨度包络。逐分项 token 必须与所引计量记录相符，再核对金额与摘要；已命中记录必须沿“计量身份→可选别名来源/目标→命中规则”一致，别名按 ID＋来源身份定位，保留合法同 ID 不同来源配置。两侧只核验文件内证据，不回源、重新匹配或重新计价；坏扩展不静默剥离后显示成功。

性能日桶由内核相同日界与各指标入样事件生成，不由浏览器聚合。v2 首次生成使用本机本地时区并在 performance.tz 声明，保存展示及原范围重算沿用该声明；v3 用保存 scope.tz。金额与比值的精确值、事件定义、状态、覆盖和缺口完整保留，旧工具可能丢新扩展，不能承诺其保留三期结果。

选择在生成分组时保存行级引用，避免浏览器再维护累计跨轮、后代和日桶成员规则；v2/v3 可选扩展复用既有范围分支，代价是旧工具可能丢扩展。时间线复用 SVG/表格，不另引图表框架。

旧报告无解释合法，按已存字段有限定位，缺关系标旧报告未保存完整定位，不能猜补。当前show/JSON再次导出保原版本及扩展；旧工具可能忽略/丢解释，需支持解释的版本才保完整，旧工具不读v3明确报不支持，不降版本导出。重算才生成新的v2/v3，原文件不修改。

`show --saved` 只加载展示，零读源；`recompute --saved` 保旧范围/来源/截止，源缺仍可展示旧报告但新报告明确缺失，不能回填旧指标或解释。`--update` 唯一改范围，轮次/会话提交完整集合。HTTP缺字段保留、显式null转CLEAR清空、值替换；CLI不构造CLEAR。兼容差异保留：新 `report --from ""` 的 scope.from 为 `""`；保存更新空from与省略均沿旧下界。更新表单下界为完整带时区文本，不截秒/微秒，重开不改日期/时区组合。

默认表格/Markdown；`--format` 只改标准输出，显式 `--export --output` 才写。JSON、CSV、Markdown使用同一结果，CSV附范围、状态/原因、来源、解释粒度/单位/覆盖，不把独立通道再加合计；Markdown显示部分覆盖及来源。CSV 同时从同一保存的 `analysis` 扩展投影费用与性能行：价格配置快照（含未命中规则，即价格依据）、逐币种精确金额与两位小数显示值、计价覆盖与未定价原因、v3 费用投影成员，以及各性能指标的精确分子/分母、单位、事件定义、候选/有效/排除计数与原因、工具跨度包络和分组/日成员；无扩展或缺费用/性能部分的报告只给说明行，不补零。JSON 是完整重载入口，CSV/Markdown 不承诺反向重建。文件写入先拒来源/已加载报告及符号/硬链接别名，使用同目录临时文件＋原子替换，清临时文件。

### 8.1 价格快照与保存结果复用

共同 Query 接受可选 pricing 对象；新查询省略价格时默认使用随包官网快照（`pricing/`，schema v2），可显式自定义或仅 token（CLI `--default-pricing`/`--no-pricing`，HTTP `pricing_mode` default/custom/none 互斥）；CLI --pricing 读取本地 JSON，HTTP pricing_text 接收 FileReader 文本，不接收任意配置路径、URL 或命令。只在 report/overview/recompute 传新价格；候选、show 和 export 不接受。null、空文本、非法版本/结构/时间/单价在读源前拒绝，不把坏配置当省略，已加载价格文件加入导出落点保护。`pricing-update --candidate` 校验真实读取形成的 v2 候选（固定来源白名单、规则/映射引用须属于本快照读取来源、固定目录全覆盖才启用），快照先存后原子切换默认引用；价格资源的读取（默认引用、快照文件）与写入（快照目录、默认指针替换）均以真实路径包含性核验锁定在随包资源根内，越界直接拒绝并保留原默认引用与既有快照。

| 场景 | 配置与操作 |
| --- | --- |
| 新查询 | 省略价格采用官网默认快照（`--default-pricing`/`pricing_mode=default` 同为其显式拼写）；显式仅 token（`--no-pricing`/`pricing_mode=none`，限独立新查询）才不配置费用；性能按来源能力计算。用户加载自定义配置只改变待提交条件，明确查询才产生新报告 |
| 原范围重算 | 省略新配置沿用报告所存规则；明确提交合法新配置才换价。使用旧来源、集合、时间、代理策略与 cutoff，不因改价设置 update |
| 明确更新范围 | 沿现有 update 合同核对完整新集合及边界；未选择新价格仍沿保存配置，新增记录无规则则未定价 |
| 展示与导出 | `show`、本地 JSON 加载及 export 均只校验保存对象；不读取当前价格文件或原始来源，不重新计算 |
| 旧报告 | 无新扩展时显示未保存费用/性能；明确重算可生成新分析，未提交价格则仍未配置，不追溯猜价 |

加载旧报告只消费保存值和保存能力；原范围重算默认采用完整保存价格快照，源后补的新模型缺规则仍未定价。明确选合法新价格并发起计算才换价，不改变范围/cutoff，不写原文件；范围更新沿已有完整集合/三态合同。网页保存区使用独立 FileReader 换价通道，替换基准时清空待提交换价并废弃旧异步结果；读取期间禁用重选，结果说明捕获本次提交价格快照，等待期间后选价格不能串入已发请求。价格或性能局部缺口不改 token 退出码及有效部分结果合同。

## 9. 入口、安装、网页运行与安全

CLI操作为 `sessions/turns/requests/report/show/recompute/overview`。退出0=列举/展示成功或确认零，2=有效部分/计数/工具，3=不可统计，4=参数/读取错误；2仍须展示。`--pricing` 仅用于 report/overview/recompute 的明确费用查询，非法配置按参数错误退出；费用局部缺口在分析状态中表达，不把整份 token 报告判失败。性能按来源能力随每次 report/overview/recompute 计算（无需价格配置），指标不可用或局部缺口同样在分析状态中表达，不阻断原 token 查询。请求起点、source/database和范围互斥按现有参数验证，失败不静默改参数。完整调用示例见[README](../README.md)。

自然语言Skill只负责范围、候选等待、可靠请求起点和调用脚本；明确请求直接执行，有歧义展示可辨候选等待，不代答。默认不保存，图表操作不统计。安装器复制完整Skill/scripts/viewer资源到目标，已有相同内容幂等，不同内容拒覆盖；安装不自动刷新Harness或发布。

独立离线 `viewer/index.html` 只读用户选JSON，无服务探测或日志扫描，来源隔离后仍展示。损坏文件清本次结果、不残留成功外观。缺文件选择/SVG/精确整数等浏览器能力给明确限制；真实缺失环境验收仍未取得。

本地服务由用户显式启动，只 `127.0.0.1`，系统空闲端口、每次随机凭据，fragment转页面专用请求头，不进报告/查询/日志。验证Host、Origin和凭据，无Origin也需Host＋凭据；静态资源白名单、无跨域/外部脚本连接。回环本身不足以阻止其他网页访问；不宣称防已控制账户的本地进程。服务启动/页面加载不读源，点击才每请求独立读取（守卫发现＋当前内容捕获；服务端另持有有界进程内解析复用，命中时来源列表中的 WAL/SHM 等易变伴随文件按本次请求重建，不回填上次来源），无监听/后台队列，页面单飞，默认120秒超时。

启动限定来源真实根/文件及DB精确wal/shm、相邻关系log/rollout。发现和读文件前SourceGuard校验解析路径，拒越界符号链接；网页不能提交任意路径/命令/SQL/URL/服务器导出落点。保存input只是复算描述，明确重算也须属本次允许来源，不合则拒并提示按该源重启，不能偷偷换默认源。CLI原选择合同保留。

活跃WAL且有SHM时SQLite `mode=ro` 事务backup到工作区外快照；无SHM等情况复制稳定DB/WAL、核对前后stat，持续变化有限重试后失败。临时快照用后清，源不打开可写。诊断仅白名单元数据，错误给类型/位置而非原始正文，HTTP不记录请求日志。

## 11. 费用与独立性能的实现决定

### 11.1 职责与来源证据

分析集中在 analysis.py 一个无 I/O 模块，消费已确定候选与规则；不发现/绑定会话、不另建价格平台或浏览器计算内核。适配器保留供应商、完整模型、时间和工具证据；relations/core 复用归属、继承排除、选集及日界，operations 负责配置、快照复用和接线，formats/shared.js 分别保护各自不可信保存输入。

以下支持边界来自已核对的真实来源字段和 ZCode 写入器；字段出现不证明全部版本/供应商支持。实现接线与直接验收结论分别见架构说明及第 10.1 节。

| 来源 | 有依据的字段与映射 | 支持边界 |
| --- | --- | --- |
| Codex 价格身份 | 会话 `model_provider`、明确的 `thread_settings_applied.thread_settings.model_provider_id/model`，以及轮次模型上下文 | 保留源供应商标识，不把 `openai_http` 自动改成 `openai`。只把同线程已生效设置绑定到其作用域内记录；上下文冲突、累计区间跨身份变化或无明确绑定时未定价 |
| Codex TTFT/吞吐 | 所核 JSONL 未提供可与逐调用 usage 唯一配对的请求起点、首 token、生成终点三元组 | 当前不可计算，明确原因。`task_complete.time_to_first_token_ms` 是执行轮次口径，轮次可含多次调用，不代替请求/调用 TTFT；消息时间也不补造首 token |
| Codex 工具耗时 | `item_completed` 的 `CommandExecution`/`McpToolCall` 有结构化身份、状态、原生 duration；部分同时有起止毫秒时间 | 只纳入可证明实际执行的这两类，duration 的 secs/nanos 精确换算；起止跨度与原生耗时分别保存。其他 item 类型及通用文本输出不据此宣称支持 |
| ZCode DB 价格身份 | `model_usage.provider_id/model_id/raw_usage_json` 与记录起止；行定位保留 | 使用原始身份和已验证 usage 语义；默认数值列不替代 raw usage，套餐名不构成单价或账单证据 |
| ZCode DB TTFT | `started_at/first_token_at/time_to_first_token_ms` 属同一逻辑请求；写入器取首个非空 text/reasoning delta | 标注“首个可观察文本/推理 token”。纯文本/推理流可核对；含工具参数输出却无法证明最早 token 的记录不入样。原生延迟与时间差互相核对，不提升为独立 attempt 粒度 |
| ZCode DB 吞吐 | 同一逻辑请求的已知 output、首 token 与 `completed_at`；完成时间在结果返回后写入 | 按用户接受的来源观测区间计算并标注尾部处理开销；重试使首 token 与最终输出对应区间不明、输出口径未验证或非文本首 token 不明时排除，不冒充服务端纯速率 |
| ZCode DB 工具 | `tool_usage` 的会话/轮次、tool_call_id、状态、duration 及调度至完成时间 | 原生执行耗时与调度跨度不是同义字段，不因不同而判冲突。写入器可把缺失 duration 转为 0，单凭 DB 零值不能确认零执行耗时 |
| ZCode JSONL | rollout/完成日志有 provider/model 和 usage；`tool.call.started/completed/failed` 有稳定工具身份与 duration | 所核模型 JSONL 无首 token 事件，TTFT/吞吐不可用；工具按明确会话/tool_call_id 合并起止与完成副本。无会话身份的 MCP 日志不凭 trace 或时间猜归属 |

DB 入口继续以 DB 计量模型，JSONL 模型补充来源不合入小计。工具是独立通道：DB 工具与相邻日志只有在完整会话/tool_call_id 唯一一致时才合并，补足真实执行起点或核实零值；关联不明的补充项单列，不重复计入工具耗时。JSONL 入口只消费其本次声明来源，不自动切 DB。所有读取仍经过现有来源守卫与快照边界。

同一证据的副本只计一次，反事实保留冲突；不同语义的原生执行耗时和调度跨度并列展示。DB duration 大于零可按已核写入器解释为原生耗时；零值需有明确执行完成日志等独立证据，否则保持未知。不能把合成零耗时 item 或调度时间当执行证据。

### 11.2 本地价格配置与匹配

价格配置默认为随包官网快照（`pricing/`，schema v2，经 `pricing-update` 真实读取更新），可显式提交自定义 v1 JSON（CLI `--pricing` 文件／网页文件选择加载文本）或显式仅 token；查询时不发网络请求、无账号发现。Skill 将用户指定配置转交 CLI。显式仅 token 的独立新查询费用状态为“未配置价格”，不影响原 token 结果；省略价格不是未配置，按默认快照计价。

| 配置内容 | 最小合同 |
| --- | --- |
| 版本与来源 | 配置 schema version、用户规则修订标识；每条规则有稳定 ID、来源引用及来源版本。引用只作说明，不发网络请求 |
| 匹配身份 | 源供应商标识与完整模型身份精确匹配；不去掉供应商、截断后缀、使用模型名模糊匹配或隐式默认模型 |
| 时间与币种 | 带时区生效区间 `[effective_from,effective_to)`，上界可省略；显式币种。按源记录的可信计价时间匹配，不按打开或计算时钟 |
| 单位与单价 | 配置统一采用每百万 token 的单价，以非负有限十进制字符串表达；外部其他单位的价格由配置者明确换算并保留原来源说明，界面显示单位 |
| 输入分区 | 选择总输入统一价、非缓存读取输入＋缓存读取分价、或已证实互斥的其他输入＋缓存读取＋缓存写入分价；缓存写入若有源证据证明独立于已收费输入，可独立计价，不能仅凭字段名认定独立 |
| 输出分区 | 选择完整输出统一价，或在推理包含关系已证实后选择其他输出＋推理分价；不能在完整输出价上再加包含的推理 |
| 别名 | 可选显式身份映射，保留源/目标完整身份与映射依据；只做一次精确映射，不做链式、循环或通配符推断。依据不足时不启用 |

结构、类型、版本、规则 ID、时间或单价格式错误作为配置错误，在读源前拒绝本次请求；缺某一配置分项的价格保持未定价，不能默认零。相同身份与时间命中多条规则为该记录的规则冲突，不用文件顺序、最新版本或币种优先级静默选价，其他身份的可计价结果仍保留。

新调用按原计量时间匹配历史价格；累计区间没有完整身份和统一适用规则时不强行计价。区间跨价格生效边界，不按 token 比例切分，也不拿末端价格覆盖整段。供应商字段语义尚未验证、别名冲突或价格语义与来源包含关系不匹配，分别给未定价原因。

### 11.3 分项计价、精度与覆盖

分项基于已验证的包含关系生成互斥计价 token：非缓存读取输入复用输入减缓存读取；缓存写入若包含于输入，拆价前必须证明可扣除分区及已知数值，若源证明它独立于已收费输入才允许单列计价；输出拆推理价同理。总输入统一价不另外收已包含的缓存读/写价，不自行推断套餐、折扣、汇率或附加费用。

每个可计价分项的费用为精确 token 数乘单价除以一百万。使用 Python 标准库 Decimal，以十进制字符串建立单价，按整数位数、单价精度和求和规模设置足够的计算精度；不通过浮点中转，也不逐行舍入后相加。保存金额为规范十进制字符串；默认显示两位小数、四舍五入，详情/导出保留未舍入值并说明显示精度。

缺价或缺一个 token 分项时保留其余已定价分项，记录状态为部分计价，不伪装整条或全范围金额。按币种求和，模型/会话/日期都是同一分项集合的投影；费用模型身份包含供应商，不能复用只含模型名称的标签作唯一键。跨日累计已计价金额进入“无法归日”，不分摊，不与日期视图再次相加。

覆盖分别给出参与记录数、完整/部分/未定价记录数及各计价分项的已知 token；比例只对可证明的同口径分母计算。价格已知的记录比例不是完整调用覆盖，跨分项也不拼成一个“费用覆盖率”。未定价金额未知，不用已定价金额占比表示缺口。无记录不自动费用零；零单价、确认零用量和缺价分别表达。

### 11.4 模型性能选集、计算与时间合同

性能候选可没有 usage，复用相同会话、轮次/后代、代理策略与来源边界；候选不追加为 token 计量记录，不修补已有 token 合计。三类指标独立判断，缺输出量不影响有证据的 TTFT，无模型 usage 不影响真实工具耗时。

工具的副本和分叉继承只在完整真实工具身份及明确祖先关系一致时排除，新身份的重新执行照常计入；不按命令文本或时间认定重复。只看主代理时仅纳入可靠主代理常规工具，分类/关系未知的样本说明排除原因，不补造内部分类。

| 指标 | 计算及入样时间 | 状态与聚合 |
| --- | --- | --- |
| TTFT | 可信首 token 时间减同一请求起点；以首 token 事件判断是否落入 `[from,to)`，要求起点不晚于首 token | 缺结束但首 token 已在截止前出现，可保留 TTFT 并注明执行未完成。确认零延迟可保留；负值或同语义证据冲突排除。展示样本值、同口径有效样本均值和覆盖，不混轮次/调用/逻辑请求 |
| 吞吐 | 已知 output 除以首 token 至可信区间终点的正时长；以区间终点判断范围，要求完成在截止前被证实 | 未完成、零/负区间、重试导致配对不明或输出口径不明时排除；已知零 output 且正区间可得零吞吐。聚合为同一有效集合的输出和除以区间时长和，不平均逐行速率 |
| 工具执行耗时 | 可信原生执行 duration，或有明确实际执行起止时求差；以可信完成事件判断范围 | 已完成失败调用仍可展示真实耗时并保留状态；执行未结束只给状态。原生与推导值须同语义才互校；调度跨度独立展示，不加入执行耗时和 |

三项入样事件可能不同，性能有效集合不必等于 token 选集；这一区别在摘要、日图与保存证据中明示。事件恰在 cutoff 不纳入，已确认起点但截止前没有所需终点的样本说明边界；跨下界的完整样本按其入样事件纳入，不比例裁时或 token。工具/调用的关系不明时保留未归属证据，不摊入邻近轮次。

时间按源单位精确归一化：毫秒时间保留原精度，Codex secs/nanos duration 不截成整数毫秒。保存原事件定义、粒度、源精度、原生/推导依据、值/状态/原因；真假布尔、非有限和负数不进入有效数值。每项独立统计有效、缺失、冲突及排除原因，只有可证明候选分母才给比例。

按相同 Harness、粒度与事件定义分别聚合，特别保留 ZCode 逻辑请求和 Codex 工具类别差异；不输出跨 Harness 效率排名。TTFT 均值、吞吐比值与工具耗时和使用各自保存成员，日桶复用内核时区/日界，以对应入样事件分日，不由浏览器重算。工具并行耗时和不是墙钟，原轮次墙钟合同保持。

比值保存精确分子、分母及其单位，显示值保留两位小数并标明舍入；不把循环小数的有限显示当精确值。日期/分组的平均延迟或吞吐重新由该组成员的分子/分母生成，不从已舍入的上一层值推导。

### 11.5 工具耗时与调度跨度

工具执行耗时是 `analysis` 扩展性能区的独立指标与独立通道：工具候选不要求模型 usage，复用相同会话、轮次/后代、代理策略与来源边界，不追加为 token 计量记录、不改变 token 合计；仅工具累计 token 的 `tool_reports` 不构成执行次数/时间证据。稳定身份＝完整会话＋真实 item/tool_call_id（不用命令文本、时间邻近、显示行号或截断标签）；分叉继承副本只在完整真实工具身份与明确祖先关系一致时排除，新身份的同命令重执行照常计入。耗时取可信原生执行 duration（Codex secs/nanos 精确换算为整数纳秒，不截整数毫秒；ZCode duration_ms 精确换算），或无原生值时有明确实际执行起止求差；原生与推导须同语义才互校（所核真实数据 DB duration_ms 与日志 durationMs 完全一致；日志 durationMs 与事件时间戳跨度系统性有别，语义不同分列不判冲突），调度至完成的跨度独立保存展示，不加入执行耗时和，也不修改原轮次墙钟。已完成失败执行保留真实耗时与失败状态；执行未结束只给状态。以可信完成事件纳入 `[from,to)`，恰在截止点排除，跨下界完整样本不比例裁时。负值、布尔、非整数、同语义证据冲突分别排除；确认零（有独立证据）可显示，未知零保持未知。代理/后代归属沿原范围策略；仅主代理策略只纳入可靠主代理常规工具，分类/关系未知的样本说明排除原因，不补造内部分类，未知不摊到邻近轮次。

聚合按 Harness/工具类别/事件语义分别进行：耗时和保存精确分子（各样本精确 ns 之和）与样本集合；调度/执行跨度包络（各样本调度或实际执行起止的最早起点至最晚终点，并行不扣重叠、不等于耗时和、不由耗时反推端点）分列；串行两次 10 秒为包络 20 秒、耗时和 20 秒，区间 [0,10] 与 [5,15] 并行为包络 15 秒、耗时和 20 秒；日桶用完成事件与保存时区；有效/缺失/冲突及排除原因逐指标显示，无可靠候选分母不给比例。

样本生成时，执行与调度区间分别要求起止成对：任一侧缺失即将该组两侧保存为 null，完整端点保持原值，不跨组拼接或从原生耗时反推。可信 native duration、完成事件、精度与来源仍可独立保留；derived 仍要求完整真实执行起止，未有完整可靠区间时包络未知。Python/浏览器校验继续严格拒绝保存文件中的单边端点。

工具样本在扩展内保存独立稳定键、会话/轮次/归属、类别、状态、事件时间、精度、原生/推导依据、执行与调度端点、源位置，区别于仅报 token 累计的 `tool_reports`；record_key 恒为 null 不伪造引用；`analysis` 扩展校验要求键唯一、无 token 记录引用、坏样本冲突/聚合与包络重算一致、非有限/负数不入有效值、隐私白名单（不含命令参数、输出正文或认证）；仅含 TTFT/吞吐两项的旧保存报告仍合法展示，不补造工具区。
