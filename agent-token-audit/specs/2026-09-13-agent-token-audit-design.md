## 1. 基线、已知限制与证据等级

用户的当前要求和一期/二期划分是需求依据。已读取仓库根 `AGENTS.md`、`README.md`、规格工作流及既有规格格式；仓库检索未发现可复用的 token audit 实现。本次新建模块级规格，不改动其他模块。用户附件是参考设计，既不是执行授权，也不是经当前环境验证的接口规范。

用户面对的问题是无法稳定按任务或会话查看模型消耗及其来源，直接累加不同日志还可能重复或漏记。方案是自然语言确定统计范围，脚本读取本地遥测、按调用归属归一化和求和，再展示可追溯且说明缺口的表格。本文以已批准需求 V0.5 为唯一行为基线，不改变其一期范围、统计口径或 A1–A18 验收要求。

2026-09-13 只读抽查本机最近 Codex 会话、ZCode rollout 和当日日志，检查字段及数值，不把正文复制进规格。以下仅为样本观察，不能外推到所有版本或所有调用：

| 本次证据 | 对设计的影响 |
| --- | --- |
| Codex 的 `~/.codex/sessions/2026/09/13/rollout-*.jsonl` 同时含 `token_usage_record` 和 `event_msg/token_count` | 两类记录不可直接相加，优先验证逐调用记录，累计值用于对账或回退 |
| `token_usage_record.payload` 含 `thread_id`、`turn_id`、`session_id`、`root_turn_id`、`response_id`、`usage`、`turn_token_usage`、`thread_token_usage` | 存在直接关联线索，但字段名称本身不能证明父子关系及累计范围 |
| Codex usage 样本含输入、缓存读取、缓存写入、输出、推理输出及总量；样本总量等于输入加输出 | 保留完整字段；推理与缓存包含关系仍需针对适配版本验证 |
| ZCode 的 `~/.zcode/cli/rollout/model-io-sess_subagent_agent_*.jsonl` 样本中 usage 位于 `response.usage` | 不能只实现附件中的顶层 `usage`；有多个候选位置时须检查冲突 |
| ZCode rollout 顶层含 `requestId`、`attempt`、`sessionId`、`turnId`、`querySource`、`startedAt`、`completedAt` | 可用于调用身份与边界，不能只靠文件名或时间邻近归属 |
| ZCode 子代理记录的 `querySource=subagent`，但 `model.role=main` | 不能单凭 `model.role` 判断主代理/子代理 |
| ZCode 当日日志出现 `model.sdk.stream.completed` 和 `model.sdk.generate.completed`；后者样本为 `session_title`，两类 usage 样本都脱敏 | 请求计数需识别调用类型，不能将流式完成事件视为所有模型调用的唯一来源 |
| ZCode 日志有 `subagent.spawned` 及 `agentId`、`parentToolCallId` | 可用于建立关系；异步子代理、续接和缺失链路仍需样例验证 |

本次未验证所有版本兼容性、数据保留策略、完整任务计数、分叉继承行为及账单一致性。附件中的具体 golden 数值没有配套固定输入，不能直接拿来作为本工具的验收证据。

针对 Q5，补充只读核查同会话不连续轮次的可行性，以下仍为代表样本证据：

| 补充证据 | 对范围选择的影响 |
| --- | --- |
| Codex 主线程的用户消息 metadata 与 usage 中的轮次 ID 能匹配启动记录；一个轮次可关联多条用户消息 | 存在明确集合筛选的基础；不能把消息序号直接当轮次序号 |
| ZCode 主会话 12 个不同 `turnId` 仅对应 8 个不同 `turnNumber`，失败后存在显示编号重用 | 使用会话与稳定轮次 ID 联合识别，工具展示序号仅供选择 |

连续与不连续范围都可表示为已选轮次 ID 集合。不连续选择只增加集合输入、同会话校验、重复去除及缺失 ID 提示；子代理关联、缺失数据和累计计数问题两者共有。因此按 Q5 的条件授权保留一期不连续选择，不以未经验证的工作量猜测收窄范围。以上是可行性判断，不是已实现验收。

## 2. 最小方案与职责

采用一个本地命令行入口，内部按顺序完成数据探测、解析归一化、范围选择、聚合及输出。内核采用 Python 处理文本日志和 CSV/JSON；薄 Skill 负责自然语言交互，命令行可独立使用。按需读取，不引入常驻采集、定时保存、历史数据库、任务注册表或网络服务。具体包名和文件拆分在执行计划中安排，不增加公共插件注册或动态适配框架。

适配器负责 Harness 特有的记录解析、身份关联、字段语义和重复识别；通用聚合只消费已归一化的调用或区间用量。展示层只消费统计结果，后续网页无需重复实现计数逻辑。

自然语言入口结合当前环境定位 Harness 和会话，按需读取所选会话的相关内容理解用户指定范围，再调用同一命令行入口。范围明确时直接执行；有多个合理边界时呈现用户能辨认的候选后等待选择。数值内核只接收明确范围和用量元数据，不接收大模型估算数字；用于定位的正文不进入统计导出。复用当前对话中已确定的范围，或按需加载报告 JSON；不建立独立任务管理数据库。当前实施状态见[模块说明](../README.md)。

定位“当前会话”时使用可验证的 Harness 当前会话标识或本次请求关联信息，再与候选记录匹配；不能仅因工作目录相同、文件最近修改或源字段名为 session 就选定会话。会话列表至少返回逻辑身份、Harness、已知时间范围、源有则提供的标题以及能力状态；轮次列表提供稳定身份、展示顺序、已知时间与来源关联状态。需要选择时显示用户可辨识的候选，已有可证明对应关系时不再要求手填 ID。候选内容缺失就说明缺失，不能用模型编造标题或轮次描述填补证据。

同一入口提供四类操作：列出会话及数据能力、列出会话轮次、按明确范围生成报告、加载已有 JSON。加载明确区分仅展示保存结果和按保存范围重算；重算才读取 Harness 日志。CLI 的参数拼写可在执行计划中定稿，操作含义和输入输出行为以本文为准，不机械继承附件的三个独立脚本。

### 2.1 用户故事与需求覆盖

以下用户故事均取自已批准需求，不新增产品能力；括号中的验收编号指向需求第 4 节。

1. 作为 Harness 用户，我希望在 Codex、ZCode 查看可回源复算的任务输入、输出和缓存用量，以了解真实记录的消耗。（A1）
2. 作为会话使用者，我希望不同任务及其子代理准确归属，以免其他任务被算入。（A2）
3. 作为报告使用者，我希望重复日志不增加用量、真实重试会增加用量，以免得到失真的总量。（A3）
4. 作为缓存分析者，我希望缓存计量和加权命中率采用一致口径，以判断已知输入的缓存表现。（A4）
5. 作为历史任务查询者，我希望截断、脱敏及计数器异常明确显示缺口，以免把未知当成零。（A5）
6. 作为范围选择者，我希望跨日、跨轮及异步工作的边界正确，以得到所选范围的用量。（A6）
7. 作为报告复用者，我希望各输出格式保留一致数值和状态，以供独立展示或继续分析。（A7）
8. 作为本地数据所有者，我希望源日志保持只读、报告不带对话正文或认证信息，以安全复用报告。（A8）
9. 作为数据不足时的查询者，我希望区分仅工具报告、不可统计和确认零用量，以理解证据实际支持什么。（A9）
10. 作为日常使用者，我希望用自然语言选范围，明确时直接执行、歧义时才选择，以免手查日志 ID。（A10）
11. 作为任务负责人，我希望看到包含子代理和内部调用的任务总量，也能只看主代理常规调用，以了解消耗分布。（A11）
12. 作为统计发起者，我希望截止点固定在本次请求开始，以免报告持续纳入自身开销。（A12）
13. 作为穿插处理多项工作的用户，我希望选择同会话不连续轮次，以排除中途无关调用。（A13）
14. 作为执行中追加说明的用户，我希望消息与轮次区分、历史上下文按实际 usage 计入，以保持统计可复算。（A14）
15. 作为临时查询者，我希望默认只看表格、需要时才导出，以免每次查询留下文件或启动采集。（A15）
16. 作为任务复查者，我希望区分展示旧报告和按原范围重算，以便复用范围且看清当前数据是否缺失。（A16）
17. 作为恢复或分叉会话的用户，我希望恢复继续累计、分叉只计新增调用，以免继承历史重复计量。（A17）
18. 作为汇总阅读者，我希望默认分组互斥、明细视图不重复加入总量、未知记录仍可见，以准确解释表格。（A18）

### 2.2 非目标

沿用需求既定边界：一期不支持用户跨会话业务任务，不接入 OpenCode、Claude Code，不建设网页、插件平台、历史采集或任务数据库，不估算缺口、进行计费对账、按上下文内容作反事实归因或制作样式化 XLSX。后续展示复用仅依赖现有结构化结果，不为未来能力预建额外接口。

## 3. 统计所需的最小数据

### 3.1 范围与用量记录

每条可聚合记录保存以下信息；不要求源提供全部字段，缺失值明确标记：

- 身份：Harness、来源会话、逻辑会话/轮次、调用或 response 标识、attempt，以及有证据的父子代理关系。
- 时间：源时间戳、明确存在时的开始与结束时间、源内序号；不按完成时间重排后盲目求累计差分。
- 维度：模型及供应商、主代理/子代理/辅助调用类型；未知值保留为未知。
- 用量：总输入、缓存读取、缓存写入、输出、推理输出；每个字段保留数值状态、原字段名及采用的语义规则。
- 来源：文件路径、行号或源记录标识；不复制请求正文。
- 粒度：单次调用或累计差分区间。区间用量保留两端快照与跨度，不能伪装成单次调用。

数值状态至少区分“源报告值”“从已知值推导”“未知/不支持”“语义冲突”。工具报告值独立保留其覆盖范围，不并入直接 usage。调用计数与 token 字段证据分开，不用一个 provenance 标签掩盖某些字段缺失。

指标沿用需求第 3.2 节的归一化合同：总输入已包含该源计量的缓存读及单独缓存创建部分，输出只计一次；推理输出若已经包含于输出，不能另加。非缓存读取输入和总 token 在字段语义已确认时分别由输入减缓存读取、输入加输出得到。字段缺失或源报告 0 但语义未知时保留其状态，不用数值关系检查替代语义依据。命中率只在输入与缓存读取成对已知的同一批调用或已确认区间上求两者之和的比值；分母为零显示不适用，子集比例附覆盖说明，不取逐调用百分比平均值。

### 3.2 报告结果

一份结构化结果包含所选范围与子代理策略、固定截止点及其来源、实际读取时间、分组行、各指标已知小计及状态、可证实的覆盖信息、未归属记录和来源定位。JSON 带格式版本，日期采用带时区格式，未知数值为 `null`；展示层将状态翻译为中文。

范围保存逻辑会话身份及来源 Harness、明确轮次 ID 集合或时间区间、截止点、子代理策略和用户可读标签，不以显示序号代替 ID。JSON 同时保存结果，足以不读取日志就重新展示原报告。加载时校验格式版本和必需结构；重算使用保存范围重新探测当前源，不能把旧指标作为缺失日志的替代值。默认不扩展集合或截止点，显式更新才由自然语言入口重新确定范围后提交内核。

自然语言入口默认展示 Markdown 表格，CLI 默认打印终端表格，两者均不自动写报告文件。显式导出时才将同一统计结果交给指定的 Markdown、CSV 或 JSON 输出器；不制作样式化 XLSX。CSV 展开分组行及字段状态，保留范围标识和来源定位；Markdown 与终端表格在数值旁显示部分覆盖提示，详细来源可放表后。格式化不重新聚合，不持久化中间事件仓库。

默认展示采用[需求第 3.4 节](./2026-09-13-agent-token-audit-requirements.md#34-来源完整性与表格输出)的六列及互斥分组。内部辅助性质优先决定默认分组，其余按主/子代理身份归类；无法可靠分类的调用进入未分类行。调用记录仍分别保留代理身份和调用性质，按模型、子代理或轮次生成独立视图，不能把内部调用在两个维度上的出现当成两次消耗。整数字段保留精确值，展示命中率四舍五入到两位小数，计算使用原始整数；缺口提示不因格式化或汇总消失。

“只看主代理”按需求 A11 选择主代理常规调用组，并明确显示该筛选；不是仅按代理身份把另列的内部辅助调用又加回。A11 样例因此为完整任务 65 万、主代理筛选 10 万。源模型角色字段不替代主/子代理身份，无法可靠分类的记录继续在完整报告中显示未分类状态。

报告保留活跃/结束状态及其证据；无法确定结束时显示未知，不能把最后一条 usage 时间直接当作任务结束。首尾墙钟跨度和单次模型调用耗时之和分别显示及说明，不连续任务不扣除中途插入工作的时间，也不使用子代理并行耗时之和充当墙钟时长。

所有数据源只读。导出目标解析后的实际位置若与本次输入日志或其解析源冲突，拒绝写入；报告内容由字段白名单投影，源请求/回复正文及认证 headers 不进入导出。该约束落实需求 A8，不能仅靠默认导出目录规避。

## 4. Harness 适配

### 4.1 Codex

先探测实际结构和可关联字段，不按文件日期或产品名称假设 schema。

优先验证 `token_usage_record.payload.usage` 是否是逐调用增量，并核对 `response_id` 作用域、累计字段和模型上下文。能够确认时按调用身份去重，同源 `token_count` 仅用于校验，不再加总。

仅有 `token_count` 时，在同一已验证计数器作用域和连续段内，对完整可用序列的累计字段按源顺序求相邻差分，再按已确认归属过滤所选轮次；不能先过滤成不连续序列再差分，否则会将被排除轮次的用量带入。读取所选范围之前必要的基线；首条快照只有在确认从零开始时才能视为增量。重复累计快照贡献为零；重置、回退、分叉或重连继承须识别新段，不能把负差分截成零后继续报告完整。

若相邻快照跨越统计边界或多个轮次，差值不能按时间比例切分。只有能证明其计数器覆盖的全部用量均属于所选会话、轮次集合和时间范围，才能作为区间小计；所选轮次的首尾时间包住该区间并不足以证明集合包含。若累计区间跨第 1、2、3 轮而只选择第 1、3 轮，在没有第 2 轮可独立排除用量或更细记录时，必须标为无法精确归属，不能把整段计入。`last_token_usage` 只有能确认对应唯一调用时才可独立使用，不用它填补区间中所有缺失调用。

新旧格式混合时，对重叠覆盖范围交叉核对并择一；冲突保留诊断，不能回退后再次累加。逐字段检查，某字段异常不必丢弃其他仍有可靠来源的字段。

### 4.2 ZCode

识别 rollout 的 `response.usage`，并探测是否存在历史顶层 `usage` 结构；两个位置同时存在且不一致时标记冲突。按已确认作用域内的请求标识和 attempt 识别真实调用，多个日志源的同一调用只记一次。独立 attempt 有真实用量时分别统计。

解析结构化日志的流式完成、非流式完成、失败和子代理关系。流式与非流式完成事件只有在身份匹配与实际语义确认后用于调用计数；不统计所有 `model.request.completed` 行作为请求数。脱敏 usage 仅用于状态识别。

计数日志与 rollout 按会话、调用、attempt 和类型匹配后，才能形成可信的缺口数；无法匹配时报告各源覆盖情况，不直接以日志总行数减 rollout 行数计算缺口。

GLM 等适配只对已验证字段语义启用归一化。`cacheRead <= inputTotal` 与 `total = input + output` 是一致性检查，不能单独证明字段含义；缓存命中率高低和输入增幅不作为格式有效性的硬条件。缓存写入为 0 保留原值及语义状态，不照抄附件中“恒不报告”的全局断言。

### 4.3 后续适配边界

二期按用户指定增加 OpenCode、Claude Code。只约定适配器向通用聚合提供上述记录和能力信息，不预建动态插件注册、SQL 通用层或所有供应商映射表。不能按附件“Claude Code 每行直接求和”的建议跳过去重验证。

## 5. 范围归属、聚合与失败处理

1. 将会话选择、明确轮次集合或时间区间转为唯一范围定义。连续轮次范围与显式不连续选择均转为源轮次 ID 集合，校验同会话归属、未知 ID 和重复 ID；工具展示序号不替代稳定 ID。轮次按 Harness 执行周期识别，追加消息未启动新周期时不另造轮次。优先复用当前对话或显式加载 JSON 中的明确范围，缺失时重新定位；不能仅凭任务名称恢复或扩展。轮次分组不得把同一源调用重复分配，重叠的用户任务选集显示重叠提示。只筛选调用，不解析提示词片段来扣除历史上下文用量。
2. 通过确定的父子关系纳入全部后代子代理，以及可归属的压缩、真实重试等内部模型调用。后台子代理持续归发起任务，关系不完整的记录列为未归属，不按时间或模型名称猜测。一期不拼接用户跨会话开展的独立业务任务，但包含自动派生子代理；这两类范围不能混为一谈。
3. 按实际调用身份去重。恢复时沿用同一逻辑会话，分叉后独立统计新增调用：以可验证继承标识、原始调用身份和分叉关系剔除继承副本，不凭时间或正文相同猜测。重新发送继承上下文产生的新调用正常计入。累计计数含祖先用量时需已验证的分叉基线，不能将首个累计值全记给分叉。缺少身份或基线时暴露不确定性，不能声明完整总量。
4. 新发起“截至现在”统计的截止点取统计请求起点，由自然语言入口从可验证的请求消息时间或对应轮次边界取得后传入脚本；请求是执行中追加消息时不能误取共享轮次更早的启动时间。CLI 直接调用时取命令起点；复用原范围保持旧截止点，历史范围使用显式上界。时间过滤采用结束/usage 记录时间落入 `[from,to)` 的口径并明示；这不是按真实生成时间切分单次调用的 token。按轮次确定归属后仍应用截止点，不能为纳入完整子代理而越界。跨界调用不按比例拆分，缺少时间的记录不能静默通过过滤；可证明仍在执行或跨界时报告覆盖限制。源后补用量可能使同截止点重算值变化，固定截止点不等于源快照冻结。
5. 逐指标求已知小计并传播缺失状态；缓存率只在成对已知字段上计算。累计区间内模型不明或发生切换时，归入模型未知区间，不强行按模型分摊。
6. 输出主代理、子代理、辅助/未归属明细与适当总量。缺少范围完整性证据时总量标为已记录小计；工具报告放独立部分。

损坏行、不完整末行、未知版本或字段冲突应报告位置和影响范围。活跃日志只统计截至读取快照的完整记录，末行写入中不能当作零用量。直接 usage、调用计数和工具报告是三个独立证据通道：有哪一种就展示哪一种，不能在缺少前两者时提前丢弃工具报告。仅有子代理工具累计数时，结果明确为“仅工具报告”，保持原粒度、不拆输入输出、不并入已记录小计；三者均不存在时才为不可统计。只有源完整覆盖且明确没有调用时才能确认零用量，存在相冲突的非零报告时不能判零。

错误提示与退出状态区分完整结果、部分结果、不可统计及参数/读取错误；具体退出码在接口定稿时定义。部分结果是有效可审阅产物，不应被笼统异常吞掉。

## 6. 直接验收与未验证事项

按[需求第 4 节](./2026-09-13-agent-token-audit-requirements.md#4-直接验收标准)逐项验收。Codex、ZCode 各用一个固定范围的真实样例人工复算；测试构造覆盖重复、真实重试、累计重置、跨边界差分、缺失字段和异步子代理。真实样例提取最少必要元数据，临时输入、评估输出和报告均放工作区外。

独立核验以原始来源及选定边界计算预期值，不用同一归一化函数生成预期答案。特别检查输入/缓存不会双计、推理输出不会双计、父任务不会因子代理镜像记录双计；计数断言不能代替这些行为验收。

### 6.1 外部行为测试边界

沿用已批准 A1–A18 的范围，主测试边界是“指定 Harness 日志输入及明确统计请求 → 调用命令行入口 → 检查最终表格/JSON、结果状态与实际文件副作用”。适配、聚合和格式化通过这一入口一起受测，不为每个内部函数建立一套镜像测试。测试输入在工作区外构造，预期数值由原始用例独立给出，不能先调用被测归一化器再生成预期值。

自然语言入口另做最少量的完整交互试跑：Codex、ZCode 各验证已知当前会话直接统计，以及存在真实歧义时的候选选择；确认最终传给同一内核的范围与用户选择一致。这是 A10 及 A12 的既定外部验收，CLI 数值测试不能代替它，不引入新的大模型形式化评测平台。

仓库没有现成 token audit 测试边界可复用；沿用模块就近规格和工作区外样例/结果约束。测试只固定外部行为，不断言内部文件数量、函数划分、私有调用顺序或某个 Python 数据结构。

在既有验收中落实以下针对性场景，不增加验收范围：同目录两个活跃会话不得自动选最新文件（A10）；仅工具累计数必须保留（A9）；主代理常规与压缩独立分组（A11、A18）；累计区间跨被排除轮次时不得按时间包络放行（A5、A13）；缓存字段缺失及零分母（A4、A5）；导出目标指向源日志时保护源数据（A8）；没有可靠结束事件时不冒充已结束（A6）。

### 6.2 尚需实测的事实

以下为设计阶段确定的技术验收事项。真实 usage 复算及外部 CLI 回归已经开展，整体交互验收仍未闭合；当前进展以实施路线图为准：

| 技术未知项 | 对应核验及不通过时的行为 |
| --- | --- |
| Codex 新旧 usage 增量、累计作用域和缓存/推理包含关系 | 逐调用复算及重叠对账（A1、A3、A4）；只使用已确认字段，冲突与缺失如实显示 |
| ZCode 历史文本到轮次的映射及截断程度 | 真实任务边界选择（A5、A10、A13）；只能定位候选时供用户选择，不能承诺自动识别完整历史 |
| 主子代理、恢复与分叉继承身份 | 跨轮子代理和分叉复算（A2、A11、A17）；不确定关联单列，不硬合并 |
| 追加统计消息的时间与跨界调用 | 固定截止点检查（A12、A14）；取不到可信边界时说明并请求明确选择 |
| 互斥分组、范围复用和导出一致性 | 成品报告对照（A7、A15、A16、A18）；不能拿结构或文件检查代替数值与交互验收 |

实施验证记录实际 Harness 版本和样本覆盖的格式；发现未知版本时探测能力并按已确认口径降级，不承诺所有历史版本。Codex、ZCode 各有真实任务准确复算仍是一期验收的必要条件，不能以全部降级为未知宣称两个适配器已经支持完成。

## 7. Karpathy 精简与自检

### 7.1 假设与取舍

Q1–Q15 的产品口径集中在需求第 2 节，需求 V0.5 保持不变。Q5 的可行性抽查支持一期保留显式不连续集合；Q13–Q15 确定原范围复用、分叉新增用量及默认互斥分组。本次补足其实现合同：当前会话证据匹配、主代理常规筛选、区间全集归属、三个证据通道与外部入口验收。Python、参数拼写和内部文件拆分属于实现选择，最小形态仍为一个入口、两个适配器及通用聚合/输出。

已接受的取舍是部分历史报告可能没有完整总量、默认不持续留存、任务不跨用户会话且不作上下文内容级归因。未知项是第 6.2 节的字段语义、关联及数据覆盖，需要固定真实样例验证。“只看主代理”遵循已批准 A11 的 10 万结果，不擅自改成含另列压缩用量的 15 万。V0.6 已于 2026-09-13 获用户批准；批准设计不等于批准执行计划或授权实施。

### 7.2 最小方案比较

更简单的“分别写两个脚本直接求和并打印”无法可靠解决 Codex 累计/逐调用重叠、跨轮任务和子代理归属，也会迫使后续网页再实现统计。采用一个入口、两个适配器、通用聚合和结构化报告即可覆盖核心目标。

更简单的“只输出终端文本”能满足即时查看，但不能稳定保留未知状态、来源和范围供后续展示复用，因此提供按需 JSON 导出。默认只展示、显式请求才生成文件，不需要先建设 HTTP API、数据库、前端框架或 XLSX 样式系统。

复用原范围只需当前对话中的明确选择或已导出 JSON，无需新增任务注册表。比“每次重新理解同名任务”多保存确定范围，能避免无意扩展；比独立数据库更小，同时满足 Q13 的展示旧报告和原范围重算。

对 Q5，更简单的“只支持连续时间段”不能排除任务中途插入的无关轮次，也不能解决异步子代理归属；连续轮次本就能转换为 ID 集合，额外允许不连续集合不会引入新的聚合模型。因此保留这一最小能力，不建设自动任务分类器。

### 7.3 删除审计

相对附件，取消一期仅 ZCode 的范围、固定估算系数和误差等级、盲区全文硬抄、三个固定脚本拆分、未经本机验证的跨平台字段承诺和没有固定输入的 golden 数值。将数据源探测与语义检查合并到适配器能力报告；把“缺口”和“来源”按实际记录生成。

将用户故事逐项对应 A1–A18，避免为套模板增加未请求的能力。把重复降级描述收敛为三个证据通道，移除“无 usage 和计数即不可统计”的过早结论；明确区间集合包含、主代理筛选和当前会话定位，减少让实现者自行补语义的空间。验证集中在外部入口及必要自然语言交互，不按内部模块堆叠测试。保留全部原有去重、截止点、缺口、复用、分叉及输出约束，不增加主动留存、任务数据库或新的测试框架。

逐节映射：第 1 节为基线，第 2 节为工具形态，第 3 节为报告及复用，第 4 节为适配，第 5 节为归属与失败处理，第 6 节为验收，第 7 节为取舍；每节均对应用户目标、必要设计决策或验证。A1–A18 直接覆盖原始记录复算、选择与不连续轮次、去重、子代理、截止点、缺口、按需输出、旧报告复用、分叉和默认表格；文件存在、链接与格式检查仅证明文档交付质量。

### 7.4 当前交付状态

需求 V0.5 与设计 V0.6 的行为基线保持已批准状态；计划批准不构成实施授权，实施范围以用户独立明确的执行指令为准。当前已有 Codex/ZCode 适配器、独立 CLI、薄 Skill、导出与安装入口；自然语言交互及真实分叉覆盖仍有待验收项，尚不声明一期全部完成。用户已要求删除七票增量计划，剩余项见[模块说明](../README.md)。本次仅同步授权及执行状态，不改变一期行为或 A1–A18。
