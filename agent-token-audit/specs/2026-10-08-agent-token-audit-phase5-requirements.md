## 1. 核心目标与必选范围

统一 token 获取相关输入能力，通过适配器模式改造 Codex、ZCode、OpenCode、Claude Code，并输出供其他 Harness 接入的接口规范。本期交付包括四端统一改造、对外规范、最小接入示例及验收，不能只交付规范文档。

一期基础能力、二期定位/内部消耗/网页能力及四期规定的完整用户行为，以及前序形成的报告、定位、内部归属、统计和网页接口是本期基线。统一改造不改变用户范围、指标语义或已验收行为，不重建独立统计系统。长期可选需求判断不作为五期完成条件。

本次编号调整保持四端统一改造、八类输入能力、对外规范和最小示例范围。二期整体分析、消耗解释及三期费用与性能中已经验收的 Codex、ZCode 行为也须在统一改造中保持；这些分析能力是否扩展到新两端沿用四期的独立范围决定。

## 2. 输入端抽象与四端改造

### 2.1 所有输入能力

“获取 token 相关的全部能力”不仅是解析 usage 字段，也包括正确统计所需的来源和身份信息：

| 能力 | 统一边界需要表达的内容 |
| --- | --- |
| 来源探测与读取 | 来源类型、路径、版本、可用性、只读与一致性边界、缺失或损坏原因 |
| 能力声明与语义 | 可支持的指标、字段包含关系、记录粒度、定位和归属能力，以及部分/未知原因 |
| 会话、轮次、请求身份 | 稳定身份、生命周期证据、请求时间、可靠别名、合成消息分类、候选和冲突 |
| 用量及时间 | 原始 usage 对应的归一化数值、字段状态与零值语义、时间来源、逐调用与累计区间的区别 |
| 调用与去重 | 调用/attempt 身份、等价副本、多源冲突及不能可靠合并的表达 |
| 关系和归属 | 子代理后代、发起轮次、后台延续、内部调用性质、会话辅助和未归属量 |
| 恢复和分叉 | 逻辑会话延续、继承调用身份、祖先基线及不能判断的部分 |
| 来源证据与覆盖 | 回源定位、后补记录、覆盖依据、只有计数/工具报告/无 usage 的区别 |

适配器负责 Harness 特有的发现、读取、解释及身份关系；通用范围选择和聚合消费明确输入，展示层消费统一结果。通用计算及网页不直接解析 Harness 私有字段。适配器不得更改用户选定范围或为缺失值估算 token。

### 2.2 四端统一改造

Codex、ZCode、OpenCode、Claude Code 均通过统一输入边界工作，不能只规范新来源而保留旧来源旁路。改造保留一期基础能力、二期定位/内部消耗/网页能力及四期验收行为和合法旧报告可读性。

接口表达真实能力差异，不要求所有来源伪造相同字段。某来源不支持时，提供能力状态与原因；核心用户行为未满足时明确提出差异，不能以接口调用成功或空报告代替适配验收。

抽象形式、类型和模块组织留给设计确定。

## 3. 对外接口规范和接入示例

### 3.1 规范至少包含

- 必选/可选能力、数据字段、值状态、错误与能力不足的表达。
- 身份、归属、请求起点与固定截止点、时间边界、去重、指标包含关系和证据责任。
- 来源及报告接口版本、兼容范围与不兼容变更规则。
- 新来源到统一输入的映射，以及累计值、未知字段、缺请求身份和来源冲突的处理。
- 最小接入示例、代表性样例及能证明新接入可用的验收步骤。

规范不能承诺所有 Harness 都提供完整用量，也不以现有四种来源的偶然同名字段限制未来来源。

### 3.2 接入者结果

开发者按规范实现最小示例适配器后，既有统计和网页能正确展示已知用量、身份与缺口，不需在通用计算和展示中加入该来源的特殊分支。选择适配器所需的明确配置可以保留。

示例只验证接口合同，不自动承诺接入第五种真实 Harness。若示例证明合同无法表达必要信息，应修订规范并回归四端，不允许靠私有旁路绕开。

## 4. 阶段承接

| 前序阶段 | 已形成或应形成的边界 | 五期新增工作 |
| --- | --- | --- |
| 二期定位、内部消耗及离线网页 | 两端定位证据、内部归属、报告合同及只读网页 | 复用已验收边界，不无故重做 |
| 二期本地网页操作 | 共用统计操作、网页/CLI 一致性及错误表达 | 纳入输入与报告兼容合同 |
| 二期整体分析、消耗解释及三期费用与性能 | 已验收的 Codex、ZCode 整体分析、消耗解释及费用/性能能力 | 保持已验收行为，纳入对应来源能力与时间语义；不自动扩展新两端分析范围 |
| 四期 | 四端完整能力对齐及独立来源证据 | 核对真实差异，使四端全部经过统一输入边界 |

开始本期改造前须核对四期完整能力对齐的验收基线。前序尚未闭合的要求不得从本期兼容和回归范围中排除，也不能以统一接口已完成替代前序验收。

## 5. 直接验收

本轮将验收编号调整为 P5-A1–P5-A4，保留四端全部改造及完整回归强度；二期整体分析、消耗解释及三期费用与性能对已有两端的已验收行为另作保持检查。

| 编号 | 直接验收标准 |
| --- | --- |
| P5-A1 | 四端各用真实来源样例从原始记录独立复算，统一输入后的结果与复算一致；范围、数值、归属、状态及来源证据保持一期基础能力、二期定位/内部消耗/网页能力及四期规定的行为；确定缺陷另行明确处理 |
| P5-A2 | 四端 CLI、自然语言、只读报告和网页操作按一期基础能力、二期定位/内部消耗/网页能力及四期完整验收范围回归；合法旧报告仍可显示，不支持版本和损坏报告明确失败；重算和更新语义分明，展示旧报告不读来源；旧来源不保留绕过统一输入的旁路 |
| P5-A3 | 最小示例适配器按规范产生正确统计与网页结果；可选能力缺失清楚降级，不给通用计算和展示添加来源特例 |
| P5-A4 | 规范及共同验证能揭示重复调用、attempt、累计差分、缺失身份、合成请求、分叉继承及未知指标错误；版本、能力不足和来源冲突的处理可操作 |

五期完成条件是四端统一改造、规范、接入示例和上述验收全部满足。长期可选能力是否实施另行决定，不阻塞本期且不随本期自动启动。

## 6. 非目标与设计前提

本期不承诺接入第五种真实 Harness，不建设动态插件装载、远程市场、注册服务或开发者账号，不实施长期可选能力。

设计须以四端真实来源差异和前序完整行为要求决定输入合同、模块组织、兼容与迁移方式，不凭同名字段预设统一能力。

## 7. Karpathy 精简与自检

基线：四期第 2、3 节及 P4-A1 至 P4-A4，一期基础能力、二期定位/内部消耗/网页能力及四期完整行为和验收。当前源码仅支持 Codex、ZCode，由来源读取、关系归属和共用统计生成单会话 v2、整体 v3 报告并保留合法 v1 可读性；四端真实差异与成熟行为须经四期验证，不把未来接口当作已实现事实。

假设与差异：最小示例验证合同，不承诺第五种真实来源或所有来源完整 usage；不能虚构字段满足接口。技术组织和兼容迁移待后续设计，分期迁移不改变原适配器工作范围；暂无未经批准的行为差异。

最小方案：整理现有适配器模块的共同边界，或迁入专门适配框架，均可表达统一合同。优先复用前序读取、归属、共用统计和报告边界；新增框架是否必要须依据四端差异在设计中说明，本需求不预设。四端统一改造、规范、示例和共同验证均是交付要求，不以仅写文档或新增平台替代。

删除审计：完整保留八类输入能力、规范五项内容、四端无旁路、接入结果及必要独立复算。合并重复非目标和合同修订要求，删除阶段承接表中重复本期目标的行；长期判断单独保留，本期不重复前序统计或网页实现。

直接验收：P5-A1 至 P5-A4 验证原始记录复算、四端完整回归、报告兼容和示例接入后的实际统计与网页结果，不以规范文件或接口存在代替。本文修订不代表这些产品行为已经验收。
