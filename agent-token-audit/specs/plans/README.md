## 1. 目录与状态规则

按主题保存路线图和依赖顺序编号的 tickets。每票是可独立演示、验收的完整用户行为路径，包含交付结果、Blocked by、文档状态、Agent triage 状态、直接验收和非目标；路线图维护整体目标、覆盖关系及执行顺序。

需求与设计获批后才能编写计划。用户确认拆分粒度和依赖不自动等于批准完整计划；计划批准也不替代每次实施的独立明确授权。“执行完飞书通知我”等通知请求只授权通知。计划批准后才能按仓库规则调整 triage，依赖未完成的票仍不能执行。

## 2. 测试与交付门禁

- 每票通过实际命令行入口，以原始样例和明确范围检查最终表格、结构化结果、状态及文件副作用；自然语言行为另经真实完整交互验证。网页票用 CLI 报告作基准并执行实际浏览器加载/图表/筛选，不以页面结构或截图存在代替行为证据。
- 数值预期独立于被测归一化代码；格式、文件存在和测试退出成功不能代替报告内容及用户行为验收。
- 测试输入、源副本、运行日志、报告和临时结果存放工作区外；产品测试代码不包含真实对话或认证信息。
- 各阶段维护同一“未发布”产品条目，不因票完成新增产品版本或发版；提交前检查文档链接及 git diff --check。
- 用户明确结束某主题的增量计划时，同一变更删除其路线图和 tickets，并移除索引行；现行规格、实现和变更日志保留最终行为。
