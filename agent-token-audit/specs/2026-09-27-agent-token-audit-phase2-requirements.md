## 1. 核心目标与阶段边界

用户在已接入的 Codex、ZCode 中更可靠地定位当前会话和本次请求，统计更多有证据的内部模型消耗，并通过只读网页理解报告的分布、范围和数据缺口。二期保留一期全部未闭合事项的收尾，不等待新增 Harness。

三期在现有两端上增强网页操作；四期接入 OpenCode、Claude Code，并使四端对齐一期至三期的完整成熟能力；五期完成输入端统一改造、对外规范、接入示例及验收。跨会话汇总、趋势、费用、持续采集和长期保存等需求判断见长期迭代需求，不绑定任何一期的完成条件。

## 3. 更可靠的当前会话与当前请求定位

### 3.1 Codex、ZCode 定位完善

分别对 Codex、ZCode 验证支持的运行环境与身份来源，包括 Harness 上下文、环境身份、明确记录关联和候选选择。来源必须有可验证依据；不得仅凭最新文件、相邻消息时间、相同工作目录或 ID 前缀判断身份。

证据充分时自动定位，减少用户查询 ID 的步骤；证据缺失、冲突或多个候选无法区分时，说明原因、提供可辨识候选并保留用户选择。不能为减少提问而降低身份可信度。

分别确认会话身份与请求身份。本次请求采用自身可信起点；追加输入不能误用更早的轮次起点。合成或明确非用户输入及其可靠关联别名不能作为截止请求。等价请求副本应合并其来源证据；时间或身份冲突不能静默择一。

自然语言入口无法取得本次请求的可信起点时，说明可用截止点并让用户选择，不能声称已经排除统计操作消耗。独立 CLI 继续以命令开始时间作为默认截止点，允许显式指定时间。

恢复、分叉、后台子代理以及同时存在多个会话时，定位不能把当前工作误指向其他范围。

### 3.2 改善验证

以本期改进前的一期定位行为、已支持场景及人工步骤为基线，逐端说明哪些步骤通过可信证据消除，哪些场景仍需人工处理及其原因。不设无证据的自动成功率目标；一个 Harness 的结果不能代表其他端。源未提供可信身份时，如实说明人工流程及限制。

## 4. 更完整的内部模型消耗

### 4.1 逐端调查和补齐

对 Codex、ZCode 以下来源类别逐项核对原始记录、身份、usage、时间、归属及覆盖：

| 类别 | 核查要点 |
| --- | --- |
| 重试与失败调用 | 不同 attempt 是否有独立 usage；失败是否消耗 token；只留最终结果时缺失什么 |
| 压缩与摘要 | 是否对应真实模型调用；usage 是否已包含于累计值；如何归属任务 |
| 标题与会话辅助 | 是否能识别真实调用；只能归属会话时如何单列 |
| 子代理和后代 | 启动、续接、异步执行、多级后代能否关联发起任务 |
| 后台及其他内部工作 | 是否有 token 记录、调用性质和归属证据；未知记录如何保留 |

源提供可靠记录但现有适配未读取或关联时，应补齐。相同调用去重，独立调用有 usage 时分别计入。工具累计报告与直接 usage 独立显示，不简单相加。

调查须覆盖已知入口，包括 ZCode 数据库与 rollout 的身份映射和重试缺口、Codex 压缩记录关联；OpenCode、Claude Code 的独立调查与同等能力验收属于四期。

### 4.2 证据及不可恢复的数据

每类内部调用记录可回源证据和支持状态：有用量且可计量、仅调用计数、仅工具报告、记录存在但关联不明、来源未提供。不能证明完整调用总数时不报 100% 调用覆盖率；无缺口发现不等于证明完整。

不得估算源未记录或已删除的用量。会话辅助不能按时间邻近分摊给任务；不能归类的已知用量要保留。若补齐依赖新增 Harness 埋点、改造 Harness 或持续采集，应提出范围差异与影响供另行决定；这不自动授权实施，也不能作为忽略现有可读取数据的理由。

## 5. 继承行为与共用接口

### 5.1 既有能力与本期整理

一期范围选择、稳定轮次、调用去重、恢复和可验证分叉、后代归属、互斥分组、模型/代理/轮次明细、只看主代理、表格及 Markdown/CSV/JSON 按需导出、旧报告展示、原范围重算和明确更新均继续有效。

本期整理定位结果中的确定身份、候选、证据、冲突和不可用原因，供 CLI、自然语言入口及后续网页复用；内部调用与归属只提取现有两端证据支持的共同概念，源特有判断留在适配器。来源读取、指标归一化、共用统计与展示保持分离，不建设第二套统计内核。

### 5.2 共同计量约束

1. 先验证来源字段语义和包含关系。缓存读取、缓存创建及已包含于输出的推理量不能重复相加。
2. 缓存命中率是同一批成对已知记录的缓存读取总和除以输入总和。只覆盖已知子集时标出覆盖范围。
3. 缺失不能补零；源报告零与确认零分开。调用计数、工具累计报告与直接 usage 分开展示。
4. 同一真实调用只计一次；真实的不同 attempt 有 usage 时分别计入。不能证明身份相同则不强行合并来源。
5. 后补记录可能改变同范围的重算结果。来源丢失时不能用旧值冒充新统计。
6. 任务仍限同一用户会话；有明确关系的后代归入任务，不等于跨会话业务任务拼接。
7. 源日志只读，普通查询不自动保存或采集；报告不含原始提示词、回复或认证信息。

## 6. 只读网页与可视化

### 6.1 报告展示

用户选择已保存的 JSON 报告后，网页展示任务名称、Harness、会话、轮次或时间范围、截止点、读取时间、状态、统计结果、来源和缺口。读取报告不得扫描 Harness 日志、触发统计、改变范围或重算来源。

网页呈现与表格一致的分组和合计，可在现有报告数据内筛选及展开模型、代理、轮次明细，并以图表展示消耗分布。图表与精确数值来自同一报告。未知不画成零，部分覆盖不冒充完整总量；占比注明分母与覆盖范围。报告缺少维度时标明不可用，不推造分类。视图筛选条件清楚可见，维度明细不得重复计入总量。

原始日志即使已删除，网页仍可展示报告；来源路径作为证据呈现，不自动读取。二期网页不提供会话扫描、范围重选并触发统计、重算、采集或跨报告汇总。网页运行和交付方式由对应设计确定，不预设技术框架、账号或云端上传。

### 6.2 报告合同与兼容

明确网页依赖的报告字段、版本、未知值、范围、截止点、分组、指标状态、来源和缺口表达。兼容现有合法 `format_version=1` 报告；不支持版本或损坏报告明确提示，不静默显示错误数值。报告新增内容仍使用同一统计结果，不改变一期口径。

维护现有两端来源样例和共同行为验证。本期只整理定位、内部归属和报告实际需要的接口边界，不制定完整第三方适配器规范或建设动态插件注册系统；后续分期按第 1 节执行。

## 8. 非目标与设计前提

本期不接入 OpenCode、Claude Code，不提供网页主动统计、重算或范围更新，不实施完整适配器规范和长期可选能力。统计入口的定位及内部消耗改进不改变网页只读边界。

设计需明确两端支持环境及身份证据、内部类别可得数据与不可补齐项、报告兼容方式、网页加载和交付方式及图表交互。若现有来源无法满足核心行为，须列明差异供用户决定；不能以全未知报告或仅写限制说明替代可补齐能力。

## 9. Karpathy 精简与自检

基线：对照原二期报告可视化、原三期定位和内部消耗、一期已批准需求/设计，以及现有两端读取、共用统计、`show`/`recompute` 和 `format_version=1` 报告。源码仍有 ZCode 多来源身份映射及重试、Codex 压缩关联限制；一期 A1–A18 不变。

假设与差异：用户已确认两端定位、内部消耗和只读网页；来源身份、usage 与覆盖上限仍需逐端验证，不承诺所有环境自动定位或恢复未记录用量。分期调整不改变既有统计行为；用户于 2026-10-01 审批通过并授权编写计划，技术组织以对应设计为准，未增加新 Harness、采集或未经批准的完成标准差异。

最小方案：复用现有读取、共用统计和 JSON 结果，只补可信定位、已有 usage 的读取/关联及只读报告展示。独立报告查看器和整合既有入口均可满足用户行为，交付形态见对应设计；本需求不为此预设服务或另一套统计内核。文档继承一期合同并迁入本期改进，避免全量复述一期。

删除审计：第 1 节保留统一排期，第 6.2 节合并重复排期但保留必要接口、样例和验证边界；第 2 节保留全部收尾，第 3、4 节保留定位场景和内部类别，第 5 节继承计量，第 6、7 节保留网页与验收，第 8 节保留设计前提。新 Harness、网页操作、适配器整组工作及长期判断分别完整移至所属阶段，没有删除或推迟本期要求。

## 10. 验收边界与已批准差异

用户于 2026-10-01 明确接受以下四项裁定；这些裁定适用于已验收基线，继续有效。本节记录已批准差异，不改写第 2、7 节的原始验收要求。用户于 2026-10-02 要求撤回新增规则并完成验收闭合；SKILL 已恢复已验收基线，二期按以下边界闭合。

1. **stat4 处置**：保留未遵循既有候选等待规则的失败记录；接受同一普通请求的干净样例作为候选流程验收证据，用户已确认其选择由本人在原界面完成。新增规则已按最新指令撤回，沿用已验收 SKILL；不宣称历史失败已修复，也不取消实际歧义时先呈现候选并等待选择的既有规则。
