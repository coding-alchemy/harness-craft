## 1. 核心目标与阶段依赖

接入 OpenCode、Claude Code，并回归 Codex、ZCode，使四种 Harness 对齐一期统计基础及二期定位、内部消耗和网页的完整能力。前序未闭合的验收项不能从对齐范围中排除。

二期先完善已有两端；本期独立验证新来源，不把已有两端的字段、问题或支持状态当作新端事实。完整输入端统一改造、规范、接入示例及验收属于五期；后续能力的需求判断长期保留。

分期顺序上本期承接[二期整体分析和消耗解释](./2026-10-07-agent-token-audit-implementation.md)及[三期费用与性能](./2026-10-08-agent-token-audit-phase3-requirements.md)。本次编号调整保持一期统计基础及二期定位、内部消耗和网页能力的四端对齐范围；二期整体分析、消耗解释及三期费用与性能是否扩展到 OpenCode、Claude Code 另行确认，不因期号变化自动扩大。Codex、ZCode 已验收行为不得因接入新端回退。

## 2. 四端能力对齐

### 2.1 用户能力

OpenCode、Claude Code 接入后应支持 Codex、ZCode 在一期基础能力及二期定位、内部消耗和网页能力要求的完整用户行为，并回归 Codex、ZCode：

- 自然语言入口与独立 CLI；列出会话、稳定轮次和可用于截止点的用户请求。
- 支持会话、单轮、同会话连续或不连续轮次集合、带时区的左闭右开时间范围；任务与轮次分开。
- 按统一口径统计输入、输出、缓存读取/写入、缓存命中率、可用推理明细及调用数；显示来源和未知、部分覆盖。
- 归属可信的后代代理和内部调用，支持互斥分组、模型/代理/轮次明细及只看主代理。
- 保持调用去重、真实重试计入、恢复累计、可验证分叉去重、异步后代归属和固定截止点。
- 支持表格、Markdown/CSV/JSON、按需导出、展示旧报告、按原范围重算及明确更新范围。

自然语言范围明确时直接统计；多个合理任务边界会产生不同结果时，呈现可辨识候选并按用户选择执行。重复查询保留原会话、轮次集合或时间区间、代理范围和截止点，明确更新才扩展；不能用整个会话代替指定任务。

“能力对齐”指相同用户行为、报告合同与计量规则，不要求源格式或字段相同。每端须说明支持版本、已验证能力、部分支持和未知原因。来源缺字段时如实降级；不能把所有字段都列为未知就宣称接入完成。若来源证据无法满足核心能力，应提出明确差异供用户决定。

定位与内部消耗按第 2.2 节、报告合同按第 2.3 节、网页能力按第 3 节对齐；仅达到一期 CLI 基线不算完成。

### 2.2 定位与内部消耗

四端均遵守现行实现文档第 4 节的定位规则：分别确认会话与本次请求身份，证据充分时自动定位；缺失或冲突时说明原因、提供可辨识候选并保留选择，不凭最新记录或相同工作目录猜测。自然语言使用可信请求起点，独立 CLI 使用命令开始时间；不能误用追加请求所在轮次的更早起点。合成及明确非用户输入不得作为截止请求；等价副本合并证据，冲突不能静默择一。

OpenCode、Claude Code 按现行实现文档第 3 节及第 10.3 节“定位、内部与离线”的要求逐项独立调查重试与失败、压缩与摘要、标题与会话辅助、子代理后代、后台及其他内部工作，读取和关联所有有可靠证据的现有 usage。恢复、分叉和后台子代理定位不得误指其他范围。逐端记录可信定位改善及剩余人工步骤，不用一个端的结果代表其他端。

每类保留可回源证据，区分可计量、仅计数、仅工具报告、关联不明和来源未提供。不能恢复未记录数据、估算缺失量或按时间邻近分摊；需新增埋点、改造 Harness 或持续采集时，列明差异另行决定，不自动实施。Codex、ZCode 对已验收行为做回归。

### 2.3 共同计量和报告合同

四端完整继承现行实现文档第 5 节的指标口径与计量约束：输入/缓存/推理不双计、成对已知记录加权命中率、未知不补零、真实调用去重而独立 attempt 分别计入、后补记录如实说明。任务限单一用户会话，源只读、普通查询不自动保存或采集、报告不含正文及认证信息。

保持报告格式、指标状态和来源缺口一致；合法旧报告继续可读，不支持版本和损坏报告明确失败。新增来源不能要求网页直接读取私有字段计算。

## 3. 网页对齐与必要接口

四端报告均可在只读网页中准确展示范围、数值、状态、来源、缺口和图表；源删除后仍可展示报告，加载报告不触发来源扫描或重算。

二期网页操作在四端均可使用，包括浏览会话/轮次、范围及代理选择、明确统计、诊断明细、旧报告展示、原范围重算和明确更新。相同固定快照、范围及截止点下，网页和 CLI 数值、状态、缺口一致；没有可信当前上下文时要求选择，不猜会话。

浏览会话/轮次可读取对应来源作列举；统计或重算仅在用户明确触发后读取来源计算。

复用现有来源读取、归一化、共用统计与展示边界。来源特有的读取、字段解释和身份关系留在适配器；通用计算消费归一化输入，展示消费统一结果，不直接解析私有字段或散落来源特例。只整理新来源接入实际需要的入口、能力说明及重复逻辑，维护各端来源样例和共同行为验证；完整输入端统一改造和对外规范仍留在五期。

## 5. 非目标与设计前提

本期不以五期适配器规范完成作为接入前置条件，不建设动态插件平台，也不实施长期可选能力。

设计需确定 OpenCode、Claude Code 首批版本、运行环境、来源、字段语义及身份关系，逐端列明无法满足项。网页与报告沿用现行二期定位、内部消耗及网页能力合同；来源差异不自动授权缩小能力或宣称完整。

## 6. Karpathy 精简与自检

基线：现行实现文档第 10.3 节基础行为 B01–B18，以及二期定位、内部消耗、报告与网页能力合同。当前代码仅支持 Codex、ZCode，通过共用统计生成单会话 v2、整体 v3 报告，保留合法 v1 可读性；本期四端对齐范围仍按第 1 节界定，不把新端需求当作已实现事实。

假设与差异：新来源可得证据待验证，能力对齐不等于字段相同；不把旧两端的限制或自动定位结果外推到新端。

最小方案：扩展来源入口，复用共用统计、报告和网页。新来源解释、可信身份及独立核验是完整对齐所必需；目前没有已验证的更简单方案可同时满足这些要求。完整统一改造留在五期，不为接入另建统计内核或插件平台。

删除审计：原适配器整组工作移至五期、需求判断长期保留；本期承接一期统计基础及二期定位、内部消耗和网页能力的四端完整对齐及验收。合并重复能力列表和旧报告禁扫描述，保留逐端真实复算、缓存样例及全部范围、未知、归属和副作用约束。

直接验收：P4-A1 至 P4-A9 逐端验证真实数值、范围、可信身份、内部补齐、报告和网页兼容，不能以接口调用成功代替。
