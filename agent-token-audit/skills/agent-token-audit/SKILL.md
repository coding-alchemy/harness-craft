# Harness Token 用量统计

日常用自然语言确定范围，由本目录的 `scripts/audit.py` 确定性计算。使用 Python 3；命令的当前参数以 `python3 scripts/audit.py --help` 为准，脚本路径相对于本 Skill 安装目录解析。

## 1. 确定会话、任务和截止点

一期支持 Codex、ZCode。任务可包含同一用户会话中的连续或不连续轮次，默认包括能可靠关联的后代子代理与内部模型调用。一条追加消息可能仍属于原轮次；所选调用携带的历史上下文正常计入。

先复用当前对话中已明确的范围或用户指定的已保存 JSON。再次统计同一任务保持原轮次集合、时间边界及子代理策略；只有明确要求“更新到现在”或新增范围才扩展。没有可靠旧范围时重新定位，任务名称本身不是范围标识。

新查询优先用 Harness 提供的当前会话身份。`--current` 仅匹配当前进程中的 `CODEX_THREAD_ID` 或 `ZCODE_SESSION_ID` 与记录，不按工作目录或最新文件选会话。若运行环境直接提供可信会话 ID，可将其传给 `--session`；无法证明对应关系时运行 `sessions --harness codex|zcode`，给用户展示可辨识候选，等待选择。已有明确身份时不要求日常手填 ID 或日志路径。

用 `turns --harness … --current` 或 `--session …` 取得稳定轮次 ID。根据用户目标和当前对话选择明确集合，逐个传入 `--turn ID`。需要历史文本定位时，只按候选来源读取相关片段辅助选择，正文不进入数值记录或报告。有两种合理边界且结果不同时，先展示候选及影响并等待用户选择；不要把整个会话当作含糊任务的替代范围。

新发起“当前会话”“截至现在”统计时，将截止点固定为本次统计请求的起点。可运行 `requests --harness … --current` 取得请求 ID、源时间和定位，再将能确认对应本次请求的 ID 传给 `--request-id ID`。已有可信请求时间时可传 `--request-start ISO_TIME`；执行中追加消息使用它自身的时间，不使用共享轮次更早的启动时间。无法确认请求对应关系时，说明可用截止点并请用户选择，不能用稍后启动脚本的时间冒充已排除统计开销。

历史范围使用显式 `--from`、`--to`，带时区，口径为完成/usage 时间落在左闭右开区间。范围固定不等于日志快照永久冻结，后补记录可能改变同范围重算值。

## 2. 计算与展示

例如，身份和本次消息均已确定时：

```bash
python3 <本Skill目录>/scripts/audit.py report --harness codex --session <会话ID> --request-id <本次统计消息ID>
```

任务查询再传入选定的 `--turn` 集合。默认原样保留脚本的六列表格、实际范围、截止点、已记录小计、覆盖限制和来源。需要结构化结果时使用 `--format json`；数值及缓存率由脚本给出，不自行心算、估算缺失用量或把未知改成零。

`--main-only` 只看主代理常规调用，排除已另列的压缩等内部辅助，不能将它称作完整任务总量。`--detail model|agent|turn` 生成独立明细视图，不能再次加入合计。工具累计报告保持独立，不与直接 usage 相加。无法归属的记录单列，不按时间邻近或模型名称摊给任务。

脚本退出码 `2` 表示有效的部分结果或仅计数/工具报告，继续展示数值及限制；`3` 为不可统计，说明具体缺口；`4` 为参数或读取错误，修正明确问题或请用户补足选择。不要因为退出码非零而隐藏已经产生的有效报告。

Harness 拒绝执行统计命令时，说明所需命令及权限缺口，等待其正常授权流程；同一拒绝不换写法反复重试，也不委派其他代理代为执行。

## 3. 保存与复用

普通查询只展示，不生成文件。用户明确要求保存时，添加 `--export markdown|csv|json --output <指定文件>`；后续可复算范围须保存 JSON。各格式来自同一结果，不导出提示词、回复正文或认证信息。

- 展示旧报告：`show --saved <报告.json>`。不读取当前日志。
- 按原范围重算：`recompute --saved <报告.json>`。重新读取当前来源，来源缺失时不能拿旧数值补齐。
- 明确更新：`recompute --saved <报告.json> --update` 默认将截止点更新到命令开始；自然语言“更新到现在”应同时传入本次请求的 `--request-id` 或 `--request-start`。若用户还要求新轮次，先确认完整的新集合，再提供 `--turn`。

恢复保持同一会话累计，分叉按可验证的原始调用身份排除继承副本，新请求携带继承上下文产生的用量照常计入。身份或累计基线不明时保留限制；不把尚未验证的来源版本声称为完整支持。
