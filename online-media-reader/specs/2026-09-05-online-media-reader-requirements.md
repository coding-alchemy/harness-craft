## 1. 核心目标与基线

用户打开视频报告后，先用一句话理解内容，再阅读详细完整的整理稿；需要查看原话或回到视频核对时，依次提供经过排版与标点优化的完整字幕、原始字幕和分时间字幕。

现有报告在标题、来源信息和处理说明后直接输出“完整连续字幕”，随后按字幕轨输出带时间戳的文字。“完整连续字幕”由当前第一条主字幕轨的非空 cue 按顺序拼接，不进行语义整理；ASR 经有证据的画面校对后，连续全文和分时间字幕同步更新。校对前的 ASR 保留在复核输入中。

本次改变报告的阅读层次，继续保留来源、画面校对和按时间核对能力。本需求与同日期的新设计共同界定本次优化和验收；旧设计保留原文，本次差异及其与基线的关系由新设计说明。

## 2. 报告内容与固定顺序

| 顺序 | 内容 | 用户可观察的要求 |
| --- | --- | --- |
| 1 | 标题、来源信息及处理说明 | 保留平台、链接、作者等现有信息，以及适用的来源限制和复核状态说明 |
| 2 | 一句话概括 | 正文以一个完整句子说明视频的核心主题和主要结论或价值，便于快速理解 |
| 3 | 完整版内容 | 根据原始字幕分析、提取和总结，形成详细完整、适合连续阅读的整理稿 |
| 4 | 完整字幕 | 在原始字幕基础上补充必要的标点、断句和段落排版，保留原话和叙述顺序 |
| 5 | 原始字幕 | 原“完整连续字幕”改名后的内容，沿用主字幕轨的连续全文，不因阅读整理而改写 |
| 6 | 分时间字幕 | 保留当前主轨与附加轨的时间范围、文本和来源标签，继续支持回看核对 |

有平台摘要时继续放在字幕之后，并标为“补充信息，非正文”。平台摘要不能充当新的一句话概括或完整版内容的文字依据。

## 3. 各层内容的行为边界

### 3.1 原始字幕与分时间字幕

“原始字幕”按用户要求直接承接原“完整连续字幕”的含义：来自最终选定的主字幕轨，可能是可靠平台字幕、原始 ASR 或有证据校对后的 ASR；它不特指校对前的识别结果。保留现有的空白规范化和 cue 拼接规则。

两种字幕继续由同一主轨渲染。新增的整理操作不回写 cue、不修改时间戳，也不替代 ASR 画面复核。校对前的 ASR 仍可从原有复核材料回查。

### 3.2 完整字幕

以原始字幕全文为基础，按语义补充必要的标点，合并被 cue 切开的句子，并按自然语义分段。无时间戳，便于连续阅读和复制。

保留全部字词、原有顺序、重复和口语表达，只调整标点、空白与排版；标点处理不得改变原意，数字中的小数点、正负号、缩写和 URL 内的符号也须保留。不能借排版之名删减内容、概括段落、改写专有名词或纠正没有证据的识别错误。

### 3.3 完整版内容

读取原始字幕全文后，梳理主题、论述关系与结论，使用恰当的小标题、段落或列表组织成完整文章。允许把口语改为书面语、调整叙述组织，并合并不增加信息的重复表达。

整理稿必须覆盖全部实质信息：原文出现的观点、解释和论据、例子、名称、数字及单位、步骤及其依赖顺序、条件、限制、例外和结论。没有出现的内容不补造；结构随原文确定，不强制套用固定文章模板或压缩比例。不能只写几个要点，也不能把原始字幕直接复制后当作分析整理结果。

保留作者的立场和不确定程度，分清事实陈述、作者判断和举例；原文存在冲突或无法确认的识别内容时，如实保留疑点，不凭常识补齐。整理产生的衔接和归纳应能由原始字幕支持，不引入外部知识、事实核查或翻译。

### 3.4 一句话概括

根据原始字幕的整体内容提炼一句完整的话；可以参考已经核对的完整版内容，但最终依据仍是原始字幕。只覆盖最核心的主题和结论或价值，不拼成信息堆叠的长句，不把原标题直接当作概括，也不放大作者原有的确定程度。

放在来源信息及处理说明之后、完整版内容之前，作为报告正文的第一项。

## 4. 适用范围与待批准解释

1. 本次优化默认用于通过 Skill 交付的、有可用主字幕全文的视频报告，不要求用户每次追加“总结”指令。小红书图文 OCR 和 `--probe-only` 沿用现有行为。
2. “来源报告的后面”按现有输出理解为标题、来源元数据与处理说明之后；不新增另一份来源报告。
3. “原始字幕”采用第 3.1 节的既有主轨含义；若用户希望特指未经画面校对的 ASR，会改变当前同源渲染行为，需要调整本草案。
4. 拟由当前 Agent 完成三项语义整理，脚本继续负责字幕取得与基础报告。单独运行提取脚本不自行调用大模型；Skill 最终交付时必须完成三项整理并写回 `result_path` 指向的唯一 Markdown。
5. ASR 先完成既有复核流程，再基于最新原始字幕整理。复核不可用时保留相应说明，新增文字不意味着字幕已经校对。没有可用主轨全文时不生成貌似完整的内容；整理未完成时保留已有字幕并说明缺口，不宣称整份报告已完成。

以上解释和实现分工随本文一起提交用户审阅，尚未批准或实施。除本节列出的待确认解释，本次没有拟缩小、替代或推迟的用户要求。

## 5. 直接验收标准

1. 打开同一份最终报告，能够按第 2 节的顺序从概括、完整文章逐层读到原话和时间证据；来源信息保持可用。
2. 选择缺少标点、句子跨 cue、包含多段论述的字幕：完整字幕有合理断句和分段，逐句对照原始字幕，全部字词和顺序保留且含义一致。
3. 选择包含多个主题、具体名称、数字、例子、步骤、条件与例外的视频：逐段对照原始字幕，完整版内容保留每项实质信息，文字经过分析组织而能独立连续阅读；不是要点摘要或直接复制。
4. 对包含条件性结论的视频，一句话概括准确表达核心内容且不将条件性判断改成无条件事实；位置是来源信息之后的正文开头。
5. 整理前后逐项比较来源信息、原始字幕、分时间字幕、附加轨及冲突提示，除既有章节改名外，这些内容不被整理操作改变；有证据的 ASR 纠正在各阅读层保持一致，校对前的原文仍能回查。
6. 实际执行一次可靠平台字幕和一次 ASR Skill 流程，均在原 `result_path` 交付上述完整报告；显式 `--output` 不出现第二份正文。整理中断或写入失败时已有字幕可继续读取，并明确未完成的部分。
7. 图文 OCR 仍按图输出，字幕为空时不编造阅读稿，只探测模式不进入整理步骤。

语义质量采用逐段来源对照与最少量行为试跑判断，不以标题匹配、文件存在、字数、测试通过或格式检查替代。验证产物放在 Git 工作区外。

## 6. 人工评审门禁

本文及对应的新设计获得用户明确批准后，才编写执行计划；执行计划另行批准后，才修改 Skill、脚本和测试。
