## 1. Problem Statement（问题陈述）

用户需要从抖音、B站和小红书的公开链接取得可核对的文字。视频可能有完整字幕、不完整字幕或没有字幕；小红书还包含图文笔记。处理流程需要同时保证文字质量、可核对性和合理的访问成本。

核心目标是根据内容质量和用户目的自适应选择文字来源：可靠字幕直接采用；字幕不足时下载媒体并转写；ASR 结果以视频画面作为可用的纠错证据；用户需要本地源或原音核验时允许下载；小红书图片逐图 OCR。最终视频文字同时提供连续全文和带时间戳版本。一次运行的中间材料和最终结果统一收敛到命令启动目录下的 `.media`，并以结果文件和运行清单明确交付位置、处理路径、复核状态及失败阶段。

V0.5 已能稳定取得原始 ASR，但实际样本把画面中的“TOOM舆情”识别成“痛与情”，后续模型又凭领域知识误改成“识微商情”。仅依赖 ASR 提示词或模型自由润色，无法让能力较弱的模型稳定得到可核对结果；复核过程需要脚本化地提供画面证据，并约束纠正只能基于证据发生。

## 2. Solution（解决方案）

Skill 接收一个受支持 URL，通过统一入口完成以下流程：

1. 识别平台和内容类型，取得标题、作者、发布时间、时长及规范 URL。
2. 视频以 ASR 作为稳定默认路径，同时在 30 秒总预算内机会性探测平台字幕。优先级为中文人工字幕、中文自动字幕、平台默认人工字幕、平台默认自动字幕，只下载并验证最高优先级的一轨。
3. 字幕已实际取得、文本非空、时间戳递增且不存在明显覆盖缺口时，作为主要文字源。
4. 字幕缺失、不可访问、损坏、明显不完整、探测超时、与页面信息冲突，或用户要求原音核验时，立即下载媒体并执行语音转写。
5. ASR 成为主文字源时，脚本为每个 cue 生成有界的视频画面复核证据并保存原始 cue；Agent 检查全部 cue 后只提交有画面依据的纠正项，脚本据此重渲染最终结果。无画面依据的内容保留原始 ASR，并明确未核实，不以领域推断替换。
6. 视频输出从同一主字幕轨生成一段不含时间戳的连续全文，并保留带时间戳版本；两者不得由 Agent 分别手工维护。
7. 用户只要求保留媒体且字幕可靠时，下载媒体但不重复转写。
8. 小红书图片按页面顺序下载到临时目录并逐图 OCR，不生成画面描述。
9. 生成 Markdown 后删除成功运行的普通中间材料；ASR 原始 cue 和复核依据随结果保留，失败运行保留非 Cookie 材料，用户明确要求保留的媒体进入固定产物目录。匿名 Cookie 在所有路径删除。

平台 AI 摘要只能作为补充信息，不能替代字幕或语音转写。

## 3. User Stories（用户故事）

1. 作为用户，我希望提交抖音、B站或小红书视频链接后获得字幕或转写，从而直接阅读视频内容。
2. 作为用户，我希望可靠的平台字幕优先于语音识别，从而保留更准确的文字。
3. 作为用户，我希望字幕不足时自动下载并转写，从而获得完整内容。
4. 作为用户，我希望转写带时间戳并标明来源，从而可以回到原视频核对。
5. 作为用户，我希望小红书图文按图片顺序输出 OCR，从而保留原始阅读顺序。
6. 作为用户，我希望可以要求保留媒体，从而支持后续人工复核。
7. 作为用户，我希望输出包含来源链接和可取得的元数据，并统一使用 Markdown。
8. 作为用户，我希望登录限制、验证码、依赖缺失或提取失败被明确报告，而不是产生貌似完整的结果。
9. 作为用户，我希望无需指定输出路径也能在当前目录的 `.media` 中稳定找到结果，并能从结构化输出和运行清单定位处理阶段及产物。
10. 作为用户，我希望 ASR 中的产品名、数字和同音词能依据视频画面复核，并保留原始转写，从而区分证据校正与推断改写。
11. 作为用户，我希望视频输出额外包含一段没有时间戳的连续全文，从而可以直接阅读和复制。

## 4. Implementation Decisions（实现决策）

### 4.1 基线与边界

- 仓库以顶层模块承载可复用 Skill；本能力作为独立模块，不修改现有模块。
- Skill 使用简短入口调用内部脚本；内部命令不承诺公共 Python API。
- 主读取入口接收单个 URL，以及可选的输出覆盖、媒体保留和 Whisper 模型参数；复核入口只接收主读取入口生成的运行目录和结构化纠正项，不接受任意来源的 Markdown。

复核入口固定为：

```bash
python3 scripts/review.py <run_dir> --corrections <corrections.json>
```

主读取入口在 ASR 为主文字源时通过 stdout 返回 `review_required: true`；Agent 完成全部 cue 检查并调用复核入口后才能交付“校对版”。可靠在线字幕和图文 OCR 不进入该复核分支。

### 4.2 组件

实现只包含以下组件：

- 一个统一入口，负责路由、运行目录、处理决策和结构化结果；
- 抖音、B站、小红书三个独立适配器；
- 字幕规范化、媒体转写、图片 OCR 三个公共处理器；
- 一个有界的 ASR 画面复核处理器，负责提取证据帧、保存原始 cue、校验纠正项并重渲染；
- 一个小型运行目录边界，负责固定路径、运行清单、原子交付和清理。

配套架构图提供[可编辑 PPTD](../architecture/online-media-reader-architecture.pptd)、[SVG 预览](../architecture/online-media-reader-architecture.svg)和[PNG 预览](../architecture/online-media-reader-architecture.png)；本设计是架构与行为的单一文档事实源。

适配器返回统一内容清单：平台、原始 URL、规范 URL、内容类型、标题、作者、发布时间、时长、字幕轨、媒体项、图片项和补充摘要。该清单只作为内部边界，不发布稳定 JSON API。首版不建立适配器注册中心、抽象基类或插件系统。

### 4.3 平台规则

- **抖音**：支持视频详情链接和含 `modal_id` 的个人页弹窗链接；需要会话时使用独立临时浏览器上下文取得匿名 Cookie。AI 章节要点单列为摘要。
- **B站**：支持官方长短链接，只处理 URL 指向的当前视频或分 P。
- **小红书**：区分视频与图文笔记；视频使用通用字幕/转写流程，图片按页面顺序 OCR。

只处理无需账号授权的公开、单条内容。登录、验证码、私密内容或地区限制出现时停止，不自动登录或绕过限制。

### 4.4 字幕与转写

字幕探测由统一入口调用平台适配器确定性完成，不调用大模型分析，也不在平台正常取数路径之外追加浏览器或第三方解析服务。普通运行与只探测模式使用相同的平台取数策略；例如抖音公开页为空壳时，两者都会使用独立匿名浏览器会话读取 SSR。30 秒是在线字幕验证路径和一次瞬时故障重试共享的墙钟总预算，不是单次请求超时；抖音取得字幕元数据所必需的公开页、匿名会话、SSR 和字幕正文请求也共享该预算。有结果立即返回。只对最高优先级的一轨下载正文并检查文本数量、时间范围和异常间隔，不把“接口列出字幕”直接视为可用。

探测结果分为 `usable`、`absent`、`inaccessible` 和 `invalid`。只有 `usable` 采用在线字幕，其余状态以及预算耗尽都直接进入 ASR。统一入口提供只执行该判断、不下载媒体或运行 ASR 的探测模式，输出机器可读的状态、决策、原因和耗时。

需要媒体时，适配器使用 `yt-dlp` 或经页面验证的媒体地址下载：

- 仅用于转写时选择足以清晰识别语音的媒体；
- 用户要求保留时选择平台可得的最佳常规音视频格式；
- 需要转写时用 `ffmpeg` 提取音频，再以 `faster-whisper small` 生成时间戳文本；用户可以显式指定其他 Whisper 模型。

中文内容转写时向 faster-whisper 明确传入 `language="zh"`，并把标题、作者等已取得的短上下文作为 `initial_prompt`，以改善专业词识别。上下文只辅助识别，不进入正文。未判断为中文时保留自动语言识别。

完整人工字幕优先于 ASR。不完整字幕以完整 ASR 为主要正文，并把原字幕单列；两者实质冲突时并列输出并提示人工核对，不自动拼接或改写。

ASR 是主文字源时，主入口生成 `review/input.json` 和复核帧。每个 cue 至少取中点帧；超过 4 秒的 cue 另取四分之一点和四分之三点，单个 cue 最多三帧。复核优先复用已经取得的含视频媒体；只有音频流时取得可读文字所需的低清视频流，不把复核下载当作 `--keep-media` 产物。复核帧按 cue 编号和相对位置命名，`input.json` 记录 cue 编号、时间范围、原始 ASR 和对应帧，避免 Agent 自行推算时间或拼接命令。

Agent 必须检查 `input.json` 中全部 cue 的对应画面。产品名、专有名词、数字和画面逐字字幕可以按可见文字纠正；普通画面文案不能补写成语音内容。每条纠正项必须包含 cue 编号、替换后的完整 cue 文字和至少一个存在于该 cue 的证据帧。画面没有文字、文字不可读或与语音可能不同的 cue 保留原始 ASR；Agent 可以标记待听校，但不得凭领域知识改写，也不得声称已回听音频。

复核入口校验 cue 与证据帧的对应关系，只接受主入口生成的结构化复核输入。它保留 `review/input.json` 中的原始 ASR，应用有效纠正项后通过现有渲染器原子替换 `content.md`，并把处理路径标为“语音转写（ASR）+ 画面字幕校对”。没有有效纠正项时同样记录“画面无可用校对文字”并保留原始 ASR。脚本不根据 OCR 相似度或语言模型猜测自动替换文字。

### 4.5 图片 OCR

小红书图文使用 PaddleOCR 简体中文模型识别中文和英文。每张图片形成独立小节；空结果写明“未识别到文字”。不描述画面。视频复核只提取供 Agent 查看和引用的证据帧，不调用图片 OCR，也不把画面内容自动写入字幕。

### 4.6 输出与运行目录

最终 Markdown 包含：标题、平台、内容类型、原始及规范 URL、作者、发布时间、处理路径、视频连续全文、视频带时间戳字幕/转写或逐图 OCR。字幕、ASR、画面校对、OCR 和平台摘要必须明确区分。标题只去除两个至少四字符、直接相邻或仅由空白分隔的完全相同半段，不做语义改写。

视频连续全文固定使用主字幕轨，即带时间戳部分的第一轨；可靠在线字幕优先，在线字幕不可靠时使用 ASR 或画面校对后的 ASR。渲染器把非空 cue 按顺序规范为单个段落：去除 cue 首尾空白并折叠内部换行；相邻边界只有在两侧均为 ASCII 字母或数字时插入一个空格，其余情况直接连接。连续全文和时间戳版本必须由同一轨 cue 一次渲染，复核后也从更新后的 cue 重渲染，避免两份正文漂移。图文 OCR 不生成“连续字幕”章节。

命令启动时的当前工作目录是“执行目录”。普通运行不要求 `--output`，固定使用以下结构；目录名不使用标题：

```text
<执行目录>/.media/
├── tools/
│   ├── faster-whisper/        # Whisper 模型
│   └── paddleocr/             # PaddleOCR / PaddleX 模型缓存
└── <platform>-<content-id>-<YYYYMMDDTHHMMSS+0800>/
    ├── content.md
    ├── manifest.json
    ├── review/                 # 仅 ASR 主路径
    │   ├── input.json          # 原始 cue 与证据映射
    │   ├── corrections.json    # Agent 提交的证据化纠正项
    │   └── frames/             # 每个 cue 最多三张复核帧
    ├── artifacts/
    │   └── source.<ext>       # 仅 --keep-media
    └── work/
        ├── source.<ext>
        ├── audio.wav
        ├── subtitle.vtt
        ├── images/001.<ext>
        ├── ocr/               # 图片格式转换
        └── cookies.txt
```

短链接在取得规范 URL 前可以使用不含标题的临时运行目录，取得内容 ID 后立即规范化目录名；解析失败时保留可诊断的 `unknown` 标识。`--output` 继续作为显式兼容覆盖，此时该路径是唯一最终结果，运行清单仍位于 `.media` 并指向它。

`manifest.json` 至少记录输入 URL、规范 URL、平台、内容 ID、状态、阶段、处理路径、复核状态、结果路径和产物路径。最终内容先写同一文件系统中的 `.part` 文件，再原子替换为最终文件；显式输出的外部 `.part` 在失败或中断时删除。`--keep-media` 同样先在 `work/` 完整取得并验证媒体，再原子发布到 `artifacts/source.<ext>`，失败不得留下正式半文件或把它列为产物。首版的媒体验证指下载或合流命令成功且文件非空；不额外引入 `ffprobe` 或完整解码依赖。只有替换成功才把运行状态标记为成功。成功后删除 `work/`，但保留 ASR 复核所需的 `review/`；失败保留非 Cookie 中间材料。Cookie 仅当前用户可读，并在正常、异常和用户中断出口删除。

普通运行成功时 stdout 输出单个 JSON，至少包含 `status`、`stage`、`result_path`、`processing_path`、`review_required`、可用时的 `review_path` 和 `run_dir`；失败时 stderr 输出单个 JSON，至少包含 `status`、`stage`、`error` 和 `run_dir`。ASR 主路径在复核入口完成前不得被 Agent 表述为“已校对”。`content.md` 或显式覆盖文件是正文唯一事实源，JSON、复核输入和清单只负责定位、证据追溯及诊断。

依赖按实际分支检查：媒体下载需要浏览器能力或 `yt-dlp`，转写和视频抽帧另需 `ffmpeg` 与 `faster-whisper`，图片 OCR 需要 PaddleOCR。脚本不安装依赖；缺失时只报告能力和失败阶段。运行时模型由现有依赖按需取得，但 Whisper 的 `download_root` 与 PaddleX 的 `PADDLE_PDX_CACHE_HOME` 固定指向执行目录 `.media/tools/`，不写用户全局模型缓存。用户另行授权安装时也优先使用当前项目本地位置，不默认写入 `/usr/local/bin`。不实现无限重试。

## 5. Testing Decisions（测试决策）

### 5.1 测试接缝

用户可观察的处理结果只通过统一入口验收。第三方响应、短音频和图片使用固定样本，输出写入工作区外临时目录；字幕解析、共享预算和平台字段映射可以在模块级注入 HTTP 与时钟边界进行确定性单元测试，但这些内部函数不构成公共兼容合同。

自动测试至少覆盖：

1. 三个平台的受支持链接能规范化到正确内容；
2. 可靠字幕成为主要文字源，且没有媒体需求时不下载；
3. 字幕缺失或明显不完整时下载并输出带时间戳 ASR；
4. 可靠字幕加 `--keep-media` 时下载媒体但不运行 ASR；
5. 在线字幕与 ASR 冲突时分别输出并提示核对；
6. 小红书图片按顺序输出 OCR，包括空结果；
7. 不支持的 URL、依赖缺失、登录墙和工具失败返回明确错误，并清理 Cookie 与临时文件。
8. 字幕探测只读取最高优先级的一轨，全部字幕请求共享 30 秒预算；无字幕、不可访问、无效或超时不会阻断 ASR。
9. 只探测模式不下载媒体、不执行 ASR，并输出可供脚本判断的结果。
10. 默认运行在命令启动目录的 `.media` 下生成规范运行目录、`content.md` 和完整 `manifest.json`，stdout 可直接定位结果。
11. 成功清理 `work/`，失败保留非 Cookie 中间材料并在 stderr 与清单中记录失败阶段；所有退出路径都删除 Cookie。
12. `--keep-media` 只在 `artifacts/source.<ext>` 保留媒体；显式 `--output` 仍可用且不会产生第二份正文事实源。
13. 中文 ASR 收到 `language="zh"` 和标题/作者短提示；直连媒体转写不错误依赖 `yt-dlp`；重复标题只做完全半段去重。
14. Ctrl-C 返回结构化错误和退出码 130；显式输出与保留媒体在写入、下载或合流失败时不留下 `.part` 或正式半文件。
15. OCR 格式转换、PaddleOCR 模型和 Whisper 模型均位于本次执行目录的 `.media`，不使用系统临时目录或用户全局模型缓存。
16. 从项目根目录和模块目录都能收集并运行同一组测试。
17. 视频存在主字幕轨时输出不含时间戳的连续全文；连续全文和带时间戳版本由同一组 cue 生成，复核后同步变化。
18. ASR 主路径为每个 cue 生成一至三张有明确映射的证据帧并保留原始 cue；可靠在线字幕路径不生成复核材料或额外下载视频。
19. 复核入口拒绝未知 cue、跨 cue 证据、缺失证据和空白替换；有效纠正项原子重渲染正文，原始 ASR 保持可回查。
20. 复核项为空时保留原始 ASR 并记录未取得可用画面文字；脚本不执行 OCR 猜词或无证据替换。

### 5.2 直接验收

使用公开真实链接直接证明：

1. 抖音、B站和小红书均能通过对应适配器生成 Markdown；
2. 可靠字幕、下载转写和小红书图片 OCR 三条路径各有一个结果与网页或原音一致的样本；
3. 输出正确区分人工字幕、自动字幕、ASR、OCR 和平台摘要；
4. `--keep-media` 能在对应运行目录的 `artifacts/source.<ext>` 保存媒体且不保留 Cookie；默认运行不在 `.media` 之外散落媒体、日志和结果。
5. 对无平台字幕或字幕接口不可访问的视频，入口在字幕探测预算结束后自动开始 ASR，而不是以字幕错误终止；只探测模式在 30 秒内返回相同决策。
6. 从任意执行目录运行而不传 `--output` 后，stdout 返回的 `result_path` 可直接打开完整正文，`manifest.json` 与真实路径、阶段和产物一致；人为制造处理失败时 stderr 能定位保留的运行目录且其中没有 Cookie。
7. 中文专业主题样本的转写调用实际收到中文语言和页面上下文；重复标题样本只删除完全重复半段，非完全重复标题保持不变。
8. 在处理和交付阶段分别触发用户中断、外部输出替换失败、媒体下载失败与合流失败后，stderr、退出码、Cookie、`.part`、正式媒体和 `manifest.json` 与上述失败合同一致。
9. 首次执行 ASR/OCR 时，实际模型下载与图片格式转换路径都位于该执行目录的 `.media`；系统临时目录与用户全局模型缓存不出现本次新增内容。
10. 使用“TOOM舆情”真实样本运行 ASR 后，复核输入保留错误原文，证据帧能直接读到“TOOM舆情”；提交该证据化纠正后，最终连续全文和对应时间戳 cue 均为“TOOM舆情”，并且不会误改列表中的“识微商情”。
11. 对可靠平台字幕样本，最终 Markdown 同时包含无时间戳连续全文和原有时间戳字幕，且没有 ASR 复核目录；对图文样本不出现连续字幕章节。

文件存在、测试通过、Skill 校验器和 `git diff --check` 只能作为辅助证据。

## 6. Out of Scope（非目标）

- 其他平台、批量 URL、播放列表、主页或收藏夹；
- 需要账号授权的内容、自动登录或风控绕过；
- 翻译、摘要生成、事实核查、图片描述、视频画面自动 OCR 和语言模型自动纠错；
- 云端 ASR/OCR、长期媒体归档、缓存、数据库、服务或 Web UI；
- 公共 SDK、稳定 JSON API 和适配器插件框架。

## 7. Further Notes（假设与默认值）

- Skill 与模块名为 `online-media-reader`，默认允许模型自动选择，也支持显式调用。
- 默认优先中文字幕，不自动翻译其他语言。
- 每次处理一个公开 URL；B站只处理当前分 P。
- 语音转写默认使用 `faster-whisper small`，图片 OCR 使用 PaddleOCR 简体中文模型。
- 第三方页面变化可能导致适配器失效；字幕访问失败必须与确认无字幕区分，但两者都回退 ASR。
- 字幕探测预算覆盖字幕专用请求；当平台必须先通过页面会话取得字幕元数据时，该必要取数也计入同一预算。普通元数据和后续媒体地址访问不因字幕探测获得额外重试。瞬时网络错误最多重试一次，且不能突破剩余预算。
- 执行目录是进程启动时的 `cwd`；`.media/` 是本地运行产物目录并由项目根 `.gitignore` 忽略。
- 运行目录同秒重名时允许增加数字后缀以避免覆盖；该后缀不改变内容 ID 和时间字段含义。
- 连续全文只来自第一条主字幕轨；附加核验轨和不完整原字幕继续保留时间戳形式，不重复生成连续全文。
- ASR 画面复核默认发生，不新增开关；只有音频流时允许额外取得低清视频，因此 ASR 路径可能增加下载时间和流量。`--keep-media` 的含义不变，复核视频在取帧后删除。
- 画面复核依赖 Agent 能查看本地图片。环境没有视觉能力时，复核入口使用空纠正项完成并把结果标为未取得画面校正，不把原始 ASR 表述为已校对。

V0.5 默认值继续有效；V0.6 新增的连续全文与画面复核行为已批准。
