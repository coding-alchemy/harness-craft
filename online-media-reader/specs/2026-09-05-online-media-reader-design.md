## 1. 本次目标与文档边界

本次实现需求中的三项优化：将“完整连续字幕”改名为“原始字幕”并增加有排版和标点的“完整字幕”；根据原始字幕形成详细完整、适合阅读的“完整版内容”；提炼“一句话概括”，按用户指定顺序组织报告。

本文与同日期需求成对保存，仅定义本次变化和验收。旧设计保持原文，作为既有能力的基线；平台访问、字幕探测、媒体下载、ASR 画面复核、图片 OCR 和运行目录继续由旧设计约束。

本文获批后，仅以下差异在适用范围内以本文为准：旧设计第 4.6 节的连续全文标题和报告顺序改用本次结构；旧设计第 6 节排除的“摘要生成”对本次基于字幕的一句话概括和完整版内容开放。平台摘要仍是补充，无证据字幕纠错仍不在范围内。本文不替换旧设计的其他要求，也不把旧设计的批准状态继承为本次批准。

## 2. 基线对照

修订前已读取对应需求、旧设计与现有 Skill、读取和复核入口、渲染器、字幕模型、处理流程、运行目录实现及渲染测试，确认以下接口与行为决定本次方案：

| 既有事实 | 对本次设计的约束 |
| --- | --- |
| `scripts/omr/render.py` 从 `subtitle_tracks[0]` 拼接连续全文，再渲染全部字幕轨 | 原始字幕承接当前主轨，附加核验轨和不完整在线字幕保持单列 |
| 连续全文规范化 cue 空白并按既有中英文边界规则拼接，与时间戳版本同源 | 本次改名保留这些规则；阅读整理不回写 cue 或修改时间戳 |
| `scripts/omr/review.py` 根据原始快照应用有证据的纠正，再重渲染正文 | ASR 阅读整理在复核终态之后进行，使用最新原始字幕；校对前 ASR 仍从原有材料回查 |
| `scripts/read.py` 返回的 `result_path` 是唯一正文位置，可能由 `--output` 覆盖 | 新增三项内容写回同一路径，不另建第二份报告 |
| `RunWorkspace.deliver` 通过临时文件原子替换；成功清理 `work/` | 阅读整理只依赖已落盘全文，沿用原子交付要求，不依赖已清理媒体 |
| 脚本没有大模型调用；`manifest.json` 的成功状态记录脚本阶段 | 语义整理由当前 Agent 完成，Skill 交付另行核对阅读稿是否完整 |
| 现有报告头部为来源元数据及处理说明，图文 OCR 和只探测模式不生成视频全文 | “来源报告”按现有来源区理解，本次新增阅读层默认只适用于有可用主轨全文的视频 |

## 3. 设计决策

### 3.1 报告层次

最终展示顺序固定为：

来源信息及处理说明 → 一句话概括 → 完整版内容 → 完整字幕 → 原始字幕 → 分时间字幕。

标题保留在来源区之前；平台摘要如有则继续在字幕之后标为补充。各层的完整定义以[需求第 2—3 节](./2026-09-05-online-media-reader-requirements.md)为准：完整字幕只调整标点和排版；完整版内容分析、组织并保留全部实质信息；一句话概括准确表达核心主题与主要结论或价值。

“原始字幕”是原连续全文的改名，可能来自可靠平台字幕、ASR 或有证据校对后的 ASR。渲染器继续一次生成原始字幕与分时间字幕，Agent 保留这两部分原文。

### 3.2 生成与核对

1. 通过既有入口取得基础报告。有待复核 ASR 时，先完成现有画面复核并取得 `reviewed` 或 `unavailable` 终态；可靠字幕或复核已不可用时直接进入整理。
2. 读取最新原始字幕全文，补充必要标点、断句和段落，生成完整字幕；核对全部字词和顺序保留，标点不改变语义或数字、URL 等内容。
3. 以原始字幕为依据分析主题、论述关系与结论，形成完整版内容。逐段对照观点、论据、例子、名称、数字、步骤、条件、限制和例外，确保全部实质信息有去向，口语与无新增信息的重复可按需求整理。
4. 基于原始字幕整体内容提炼一句话概括，可参考已核对的完整版内容；核对核心含义与确定程度一致。
5. 按第 3.1 节的展示顺序组装报告。生成顺序不改变最终展示顺序。

长内容按原始顺序读完并逐段处理，合并时核对衔接；不根据缩略预览或局部字幕生成全文结论。整理保留来源中的疑点和作者立场，不以外部知识扩写，不把平台摘要作为新内容的依据。

### 3.3 同一报告的交付

Agent 保留脚本输出中的既有来源字段、原始字幕及其后的字幕轨、提示和补充信息，只插入三项派生内容。来源区缺少适用的复核说明时，根据最新 stdout 或运行清单补充说明；整理结果不意味着原始字幕已经校对。

将组装完成的整份报告写入 `result_path` 同目录的临时文件，复读核对原文部分未变、三项内容及顺序正确后，原子替换同一 `result_path` 并清理临时文件。替换失败时保留先前完整文件。上游字幕变化需要重新整理时，重新读取最新全文并整体替换三项派生内容，避免重复章节。

没有可用主轨全文时，不生成貌似完整的阅读稿。整理未完成或中断时保留已有字幕并说明缺口，不能仅凭脚本返回成功就宣称整份报告完成。

### 3.4 实现范围与最小方案

本次调整限定于 `scripts/omr/render.py` 中的章节标题、`SKILL.md` 的整理和交付指令、对应 `README.md` 使用说明及必要验证。原始字幕和时间戳的同源关系继续由脚本保证，三项语义内容由当前 Agent 生成；不新增命令、模型服务、配置项或运行状态协议。

更简单的方案是只改标题并要求“总结一下”，但这不能明确区分完整字幕与完整版内容，也不能保障完整信息覆盖和固定阅读顺序。因此选择章节改名加三项明确的 Agent 整理要求。另建模型接口或独立报告命令不属于核心目标所需能力。

本次优化面向 Skill 最终交付；单独运行提取脚本仍取得基础报告。该分工以及原始字幕含义、视频适用范围，属于[需求第 4 节](./2026-09-05-online-media-reader-requirements.md)中待用户批准的解释。

## 4. 本次直接验收

以下场景对应[需求第 5 节](./2026-09-05-online-media-reader-requirements.md)，只验收本次优化及其影响的既有行为；旧设计的其他验收标准继续有效。

| 对应需求验收项 | 场景 | 直接证据 |
| --- | --- | --- |
| 1、4 | 内容包含条件性结论的视频报告 | 用户打开报告，来源区之后首先读到准确的一句话，随后依次阅读完整版内容、完整字幕、原始字幕和分时间字幕，概括没有放大结论 |
| 2 | 缺少标点、句子跨 cue、包含多段论述的字幕 | 完整字幕有合理断句与分段，逐句核对全部字词、顺序和原意保留 |
| 3 | 含多个主题、具体名称、数字、例子、步骤、条件与例外的视频 | 逐段核对原始字幕，全部实质信息在整理稿中有对应内容，且组织成适合连续阅读的完整文章 |
| 5 | 可靠字幕、ASR 有证据纠正，以及存在附加轨的结果 | 整理没有改动原始字幕、时间戳或附加轨；有证据纠正在各阅读层一致，校对前 ASR 可回查，来源限制仍可见 |
| 6 | 各运行一次可靠平台字幕与 ASR Skill 流程，并检查显式输出 | 原 `result_path` 中交付完整报告，显式 `--output` 没有生成第二份正文；不是只在聊天中补充整理稿 |
| 6 | 整理中断或最终写入失败 | 原路径已有字幕完整可读、临时文件被清理，交付说明指出未完成部分 |
| 7 | 图文 OCR、主轨无可用全文和 `--probe-only` | 保持各自行为，不生成虚假的视频阅读稿或触发额外整理 |

语义质量使用逐段来源对照与最少量实际行为试跑；自动检查辅助验证字幕同源和未被改写。所有验证产物放在 Git 工作区外。标题匹配、字数、文件存在、测试通过或格式检查不替代以上阅读结果。

## 5. Karpathy 精简与自检

- **基线与假设：** 第 2 节列出影响方案的源码行为；原始字幕沿用主轨、“来源报告”指现有来源区、仅视频默认生成三项阅读内容、当前 Agent 承担语义整理，仍随需求待批准。
- **最小方案与取舍：** 采用章节改名加 Skill 整理与交付指令，原因见第 3.4 节；不增加模型服务，代价是独立脚本只生成基础报告，内容覆盖由 Agent 逐段核对。
- **删除审计：** 从本次设计中移除旧平台访问、下载、OCR、缓存、目录树及历史问题的重复说明，以基线链接承接；各阅读层定义集中在需求中，设计仅保留生成、交付与验收决策。旧设计原文恢复，三项优化及所有验收要求未删减。
- **直接成功证据：** 第 4 节把本次验收映射回需求，分别证明快速理解、完整阅读、原话保留与回源核对；本轮只调整文档组织，产品行为尚未实施或验收。
- **行为差异：** 本轮按用户要求把设计改为独立文档，未改变上一版报告方案；待批准解释保持显式记录，没有已实施的未经批准行为差异。
