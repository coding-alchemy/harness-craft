## 1. 目标与规格优先级

实现三项已批准方向：证据随默认结果持久保存，修复 PaddleOCR 首次下载日志污染，支持抖音图文逐图 OCR。本文只设计这些变化，不重构平台架构或视频阅读整理。

本文已获批准，在本次范围内覆盖基础设计第 4.3、4.5 节中抖音仅视频、小红书独有图文的限制，以及第 4.6 节中成功后删除 OCR 原图的处理；旧规格中统一要求验证产物写入工作区外临时目录的条款，对本次持久证据改为需求第 2 节的默认输出路径。其他平台、字幕、复核、媒体保留及安全要求仍由基线约束。旧文档不改写；冲突范围在此明确，不让后续实现继续把证据位置或抖音支持当作未决事项。

## 2. 基线对照

起草前已核对三份旧规格、对应新需求和以下源码。基线为评审后的当前实现；`f0f7940` 及后续 `b749ed6` 是验收记录变化，未修复本次两处产品问题。

| 既有接口、行为或限制 | 对设计的影响 |
| --- | --- |
| `RunWorkspace.create(cwd, ..., output)` 以启动目录创建 `.media`；`result_path` 支持显式覆盖 | 不新增输出根配置；复用每次运行目录，保持唯一正文 |
| `complete()` 清理 `work/`；`review/` 保留；清单记录结果路径但不保存一般内容快照 | 新证据不能留在 `work/`；仅补必要的证据入口与来源快照 |
| `review/input.json` 保存原始内容和 cue，帧引用相对运行目录；清单及部分快照字段含路径 | 复用既有复核包，迁移不能只复制正文，须修正实际路径字段且不改 cue |
| `ocr_image` 对整个 worker stdout 做单个 JSON 解析；worker 导入、初始化和推理未隔离输出 | 修复在独立 worker 内，保留调用方严格协议和现有替代命令接缝 |
| `douyin.normalize_url` 仅解析 `/video/`、`modal_id`；`fetch` 固定返回 `video` | 增加图文 URL、条目类型和有序图片映射；工作区内容 ID 解析也需支持 `/note/` |
| `ContentManifest` 已有 `image_gallery` 和 `ImageItem(index, url, ocr_text)` | 不新建图文领域模型或平台专用 OCR 管线 |
| `pipeline.process` 已逐图下载、OCR 后返回；渲染器按图片编号输出空结果 | 抖音复用此分支；补证据发布而非复制整个分支 |
| `read.py --probe-only` 已按非视频类型返回 `use_ocr`；公共图片下载尚无请求上下文参数 | 保持探测不下载；仅在真实 CDN 取图证据要求时向共享下载边界传递必要请求上下文，不绕过访问限制 |

上一轮使用真实 worker 配合受控第三方替身复现了“退出码 0、stdout 带进度文字、调用方解析失败”；去掉进度或改写 stderr 后返回正常。原生文件描述符输出可绕过 Python `redirect_stdout`。这证明协议缺陷，不等于真实冷模型下载验收。合成图文条目也复现了固定视频分流；真实抖音页面字段仍需在实施时从用户样本核对，不凭合成样本宣布支持。

## 3. 设计决策

### 3.1 持久证据边界

继续使用现有运行目录，新增 `evidence/`，不把证据放入 `.media/tools/` 或另建仓库。沿用 `review/` 保存 ASR 原文与纠正帧，不在新目录再复制一份相同复核包。

- `evidence/index.json` 记录本次证据入口：实际正文位置、材料类型、相对运行目录的本地路径及适用的图片编号或文字来源。`manifest.json` 增加可选的 `evidence_path` 指向该索引；旧运行无此字段仍可加载。
- 非复核路径的原始文字用一个必要字段白名单快照保留轨来源、cue 或逐图 OCR；不得直接持久化携带 Cookie、认证头或全量响应的对象。已有复核包可满足的原文回查直接引用该包。
- OCR 原图按稳定编号放入 `evidence/images/`，与 OCR 原始结果一一对应；格式转换产物仍属于 `work/ocr`。原图保留不依赖 `--keep-media`，不改变视频保留开关。
- Agent 的逐段来源核对、章节替换检查、失败演练和样本缺口记录写入本次 `evidence/verification.md`，只引用实际材料，区分未验、失败、通过和经批准暂缓。需保存的前后对照属于明确标识的核对快照，不作为另一份正式正文。

正文来源区增加证据入口，显式输出时按正文与证据的实际位置建立可用链接；其他阅读顺序不变。重新整理替换本次派生章节和对应核对记录，旧证据仍有效的保留，依赖旧内容的结论重新核对。迁移或改写索引不得改变原始 OCR、cue 或纠正内容。

只探测入口继续只输出 JSON，不因此产生正文或证据包；验收中需留存的探测输出由执行任务放入所验收运行的证据目录，不改探测协议。

### 3.2 发布、失败与存量迁移

脚本取得原文和图片后，在成功清理之前将必要材料通过同文件系统暂存与原子替换发布到 `evidence/`，材料齐备后发布索引。正文交付前确认其引用的脚本证据已经完整。沿用现有阶段与结构化失败出口；证据不完整时不标成功，Cookie 无论结果均清理。普通中间材料仍可删除，不以“持久证据”为由保留全部 `work/`。

Agent 阅读整理在脚本交付之后发生，不能把脚本成功当作语义验收成功。整理前后沿用既有唯一正文原子替换；验收记录绑定它实际检查的内容，若正文替换或核对记录更新中断，交付说明必须指出哪一步未完成。这里只保证单文件原子发布与准确完成判断，不引入多文件事务系统。

存量迁移属于后续执行任务，而非新增长期迁移命令：

1. 只读盘点明确的旧运行目录及其显式正文，列出必要材料、缺失项和敏感字段；持久根采用本任务启动目录的 `.media`。
2. 在持久根选择不冲突的目标，先复制完整可用材料，保留旧原件；不复制模型缓存、Cookie 或无关会话日志。
3. 按字段修正清单的 `result_path`、复核路径、产物路径和快照内确实指向旧目录的本地路径，保留相对帧引用；不对所有文本进行全局路径替换。显式正文保持单独唯一位置，默认运行不伪装成显式运行。
4. 对照源与目标核查正文、原始 cue、图片和纠正记录；路径或敏感字段的必要调整单独说明。核查新引用在不访问旧路径时仍有效后才将新位置作为正式交付。
5. 缺失项进入新位置的核对记录，需要补证的真实场景重跑，不覆盖原运行来伪装历史恢复。旧原件清理由用户另行授权，不包含在本次迁移中。

在普通运行创建目录之前，解析输出根的真实路径，检查其是否位于 `/tmp`、`/private/tmp` 或当前平台的系统临时根之下，包含通过符号链接间接指向这些位置的情况；命中时明确要求从持久目录运行，不创建持久结果或偷偷改换输出位置。显式正文参与本次持久交付时同样检查。只探测仍不产生持久证据，保留其既有暂存清理合同。实施验证的可丢弃暂存使用持久输出根内明确的工作子目录，不新增输出根配置或临时目录白名单开关。这是落实禁止临时存证所需的入口限制，已随本文获批。

### 3.3 OCR 机器结果与日志隔离

在 `ocr_runner.py` 的第三方导入之前，保留原 stdout 的独立结果通道，将文件描述符 1 和 Python 层标准输出导向 stderr；导入、模型构造、实际消耗推理迭代器和退出期间的第三方日志均不能进入结果通道。最后仅向保存的结果通道写入一次 JSON 并刷新。该隔离仅作用于独立 OCR worker，不修改主进程全局 stdout。

优先使用标准库文件描述符操作实现，不增加日志框架或结果临时文件协议。实现必须覆盖 Python 输出和原生直接写入、缓冲刷新及异常退出；不能只在模型构造外包一层 `redirect_stdout`。调用方继续严格解析整个 stdout；非零退出码仍报告 stderr 中的有效错误，不转为空识别。

保留 `OMR_OCR_BIN`、worker 参数、模型选择、缓存位置及格式转换行为。确定性回归从真实 worker 进程边界注入会在导入、构造或推理阶段输出进度的替身，证明最终机器结果始终可解析；真实冷缓存验收另行执行，不以替身测试替代。

### 3.4 抖音图文分流与复用

扩展 URL 规范化支持 `/note/<id>`，保留官方域名和内容 ID 校验，短链接展开后识别实际路径，不一律改写为 `/video/`。现有 `/video/` 或 `modal_id` 取到图文时仍依据条目正确分流；`workspace.content_id_from_url` 同步解析图文 ID，避免正常图文目录变为 `unknown-*`。

适配器取得请求 ID 对应的条目后，先检查真实类型及图片集合，再进行视频字幕或媒体提取。页面含 `video` 字段并不足以判定视频，图文可带配乐。字段映射以用户真实样本为依据，只支持观察到且有回归覆盖的页面结构，不预置猜测性的多套协议。

已知图文的每个原始图片项生成一个 `ImageItem`，保持页面顺序；同一图的多个地址是候选，不是多张图。条目没有有效图片、某张缺地址或类型数据冲突到无法可靠判断时明确失败，不过滤掉坏项后声称完整，也不调用 `_probe_inaccessible` 将已知图文伪装为视频。元数据不足且无法判断类型的图文入口明确报告无法取得图文数据；既有视频字幕不可访问回退 ASR 的行为不变。

图文不填视频主轨或合成媒体来源，进入现有公共 OCR 分支。下载和识别错误补充对应图片编号；如真实 CDN 要求 Referer 等请求上下文，只对共享图片下载边界补最小必要参数，并保留小红书行为。发布原图与识别证据后仍由现有渲染器逐图交付；不新增图文总结或背景音乐转写。

### 3.5 最小方案与改动范围

只涉及抖音适配器、必要的共享图片下载参数、OCR worker、公共处理流程的证据发布、运行目录及其 ID 解析、证据链接渲染、Skill/README 和对应测试。既有正文整理由 Agent 负责，原文和证据的可靠发布由脚本负责；不把自然语言语义检查伪装成脚本能力。

更简单的方案是仅手工迁移现有报告、让用户暖缓存后重跑、把 404 改为“不支持图文”。它不能保证下一次运行仍保留证据，不能修复首跑，也不满足抖音图文支持，故不采用。再建独立图文管线、证据数据库或新模型服务则无必要，故复用现有边界。

## 4. 验证与直接证据

执行计划按可独立验收的能力组织，不把下面的测试分类当作阶段票。实现前先为两个已复现故障及新证据生命周期建立能失败的回归，再验证实际结果。

| 对应需求 | 验证接缝与场景 | 直接交付证据 |
| --- | --- | --- |
| A1、A2 | 读取入口、复核入口及 Agent 整理；默认/显式输出、临时路径及符号链接，清理、中断与重整理 | 在持久位置逐项打开来源、原图、cue 和报告；临时目标被明确拒绝，依赖旧路径的访问被排除；正文唯一且失败不被误报为完整交付 |
| A3 | 有复核包、显式输出及缺失工件的迁移 | 新位置的逐项迁移记录和源/目标对照；实际可读的帧与图片，不把台账代替材料 |
| A4、A5 | 真 worker 子进程日志替身；公开图文独立冷缓存首跑、暖缓存复用，下载失败及无文字图 | 冷启动首次成功的实际逐图结果、必要且脱敏的模型下载记录；失败及空结果可区分 |
| A6、A7 | 从真实页面提取的最小脱敏固定样本；图文详情/短链接、坏图、类型冲突、只探测及真实用户图文 | 图片数量、顺序和逐图文字对照；确认无视频下载、ASR 或视频阅读层；小红书图文与普通抖音视频回归 |

冷缓存验证使用持久输出根内独立的验证执行目录，让其 `.media/tools/paddleocr` 自然为空；不删除或移动用户既有模型缓存。所有持久验收材料遵守需求第 2 节。真实 OCR 文字质量须与原图对照，不能将“有输出”或“有四个标题”表述为“全部识别准确”。

## 5. Karpathy 精简与自检

- **基线对照：** 第 2 节覆盖输出、清理、复核快照、OCR 协议、抖音类型和共享 OCR 七类约束；新增证据不改变正文唯一性或原文同源。
- **假设与取舍：** “默认路径”沿用命令启动目录 `.media`，不是安装目录；普通图文默认保存必要原图，显式正文与证据可分处；“持久”指本地随结果保留，不承诺备份。独立结果通道优于宽松解析。真实抖音字段、CDN 请求条件及存量缺失清单需实施时核实，不能据猜测关闭验收。
- **最小方案：** 第 3.5 节比较更简单方案，并说明它无法满足三项核心结果；不新增模型、通用迁移命令、证据数据库或图文专用框架。
- **删除审计：** 访问限制、字幕预算、ASR 纠正、阅读层定义与原子正文交付均引用基线，只描述受影响处；目录职责和失败边界分别集中在第 3.1、3.2 节，不复制旧平台全流程。保留全部新要求及旧的安全、原文和唯一正文约束。
- **直接验收：** 第 4 节对应需求 A1—A7，分别验证持久回查、冷启动成功及真实抖音逐图阅读，自动测试和格式检查只作辅助。
- **行为差异与门禁：** 三项方向及本文明确的原图默认保留、证据索引与临时输出路径拒绝等细节均已于 2026-09-06 获批；尚未实施，不存在已执行的未经批准行为差异。未修改旧文档、未调整历史暂缓项或代替用户批准执行计划。
