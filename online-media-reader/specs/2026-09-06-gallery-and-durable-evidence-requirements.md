## 1. 核心目标与范围

用户打开默认输出目录中的报告后，能够持续回查支撑报告和验收结论的原始材料；在依赖已安装、模型尚未缓存的环境中，第一次图片 OCR 就能正确交付；提交公开抖音图文链接后能按原图顺序读取文字，而不是收到视频下载错误。

本次是独立新增需求，不改写旧需求、旧设计或其历史批准记录。新增三项能力以本文及配套新设计界定；视频报告的阅读层次、原始字幕与时间戳同源、ASR 证据纠正和唯一正文继续遵守既有规格。

## 2. 持久证据与交付位置

### 2.1 默认位置与生命周期

1. 默认输出位置继续指命令启动目录下的 `.media/<平台>-<内容ID>-<时间>/`。正文、运行清单和持久证据归属同一次运行，不另设全局证据仓库。
2. 持久证据禁止写入或依赖 `/tmp`、其真实路径 `/private/tmp` 或其他会被自动清理的系统临时目录。验收任务不得通过在系统临时目录启动命令而把 `.media` 间接放入其中；默认目录不可用时明确失败，不偷偷回退临时目录。
3. ASR 继续保留已有 `review/`。图片 OCR 保留按图对应的原图与原始识别结果；其他来源保留核对本次报告所需的原始文字。验收记录与其引用的材料也随所属运行保存。只保留必要材料，不默认归档整段视频或全量浏览器会话。
4. 成功清理 `work/` 不删除持久证据。证据写入或发布失败时不能声称可回查交付完成；保留已完整发布的正文与证据，并说明失败阶段。中断不得留下被当作正式证据使用的半文件。
5. 显式 `--output` 仍指向唯一正文，不额外生成 `content.md`；证据保留在默认运行目录，运行清单和正文提供可用的定位关系。新验收中的显式输出也不得位于系统临时目录。

### 2.2 可核对性与存量材料

证据必须能从报告或运行清单定位，并对应本次实际来源。原始识别文字与后续整理结果分开，图片顺序、cue 编号及纠正依据可核对。证据不等于第二份正文；重新整理整体更新当前验收结论，不累加重复章节或把旧结论当作新结果。

对既有 `/tmp/omr-verify` 材料先逐项盘点，再将仍存在的必要材料复制到本次选定的持久默认输出根下，核对内容及引用后切换正式位置。先前显式输出样本也迁移到该持久根内的明确位置，不保留两个正式正文。未经单独批准不删除旧原件或覆盖既有目标。

缺失的报告、原图或复核材料明确标记缺失；需要以其证明验收的部分必须补跑或补齐，不凭历史勾选重建证据。用户已明确暂缓的验收项仍按原裁定处理，不标成实测通过，也不因迁移自动恢复或扩大验收要求。

持久材料不得保存 Cookie、认证头、登录状态或可复用的认证凭据；用于公开分享的访问参数须与账号认证信息区分，不因机械删参破坏原有来源回查。记录、复制和链接前检查敏感信息，不把完整 HTTP 会话当作证据留存。

## 3. 图片 OCR 首跑可靠性

1. 保留 PaddleOCR 和现有模型缓存位置；已安装依赖且网络、模型服务可用时，首次下载模型不能因日志污染而导致识别结果无法解析。
2. OCR 子进程 stdout 只承载一个完整机器结果；第三方导入、初始化、下载及推理日志与结果隔离，包括直接写标准输出文件描述符的输出。
3. 缓存后运行继续正常；空识别结果继续表达“未识别到文字”。真正的模型下载、初始化或识别失败必须明确报错，不伪装成空结果或成功。
4. 保留严格结果解析，不以搜索 JSON 片段、截取最后一行或自动重跑掩盖首跑失败。不安装新 OCR 服务、不更换模型，也不把本次修复扩展成无证据的 OCR 自动纠错。

## 4. 抖音图文实际支持

1. 支持公开单条抖音图文，包括 `/note/<id>` 详情地址、官方短链接展开后的图文地址，以及现有入口取得的真实图文条目。既有视频及 `modal_id` 入口保持可用，内容类型以实际条目为依据。
2. 按原始图片顺序逐图下载与 OCR，每张图独立输出“第 N 张”；有图片但无文字时保留该图位置并写明未识别到文字。
3. 已识别为图文的内容不进入视频下载、音频提取、ASR 或视频复核，不因条目含有配乐或类似视频字段而误分流。不生成一句话概括、完整版内容、完整字幕、原始字幕及分时间字幕等视频阅读层。
4. 图片条目缺地址、图片无法取得或 OCR 失败时，指出图文处理环节及可定位的图片编号；不得静默跳图、把不完整图集声明为完整结果，或回退到视频路径报无关的媒体 404。
5. 复用既有小红书逐图 OCR 行为，不建立平行处理器。`--probe-only` 对可识别图文返回 OCR 决策，但不下载图片、不执行 OCR/ASR 或生成阅读稿。
6. 保留官方域名校验、请求内容 ID 核对、匿名访问和访问限制处理。登录墙、验证码与私密内容仍停止，不绕过限制。

## 5. 直接验收标准

| 编号 | 场景 | 用户可观察的通过条件 |
| --- | --- | --- |
| A1 | 默认输出的真实视频和真实图文 | 只使用持久运行目录即可阅读报告、回查原文字段、原图及适用的 cue 纠正证据；清理成功运行的 `work/` 后仍可核对，不依赖系统临时目录 |
| A2 | 显式输出、中断、证据写入失败与已有报告重整理 | 正文只有一份；路径引用可用；失败不破坏已发布完整材料且明确缺口；重新整理不残留旧派生章节或冒用旧验收结论 |
| A3 | 存量证据迁移 | 逐项区分已迁移、缺失、待补验；已迁移材料实际可打开且正文、cue、图片映射未变化；旧临时位置不可访问时仍能独立复核；缺失证据未伪记为恢复 |
| A4 | 真实图文的全新独立模型缓存首跑及暖缓存重跑 | 首次实际下载后直接取得逐图文字，不需失败后手动重跑；第二次复用缓存仍成功；日志不混入机器结果；不清除用户原有模型缓存来制造冷启动 |
| A5 | OCR 失败和无文字图片 | 真实失败不被当作成功或空文字；无文字图保留原编号且明确为空；针对已知 stdout 污染的回归测试能先失败再通过 |
| A6 | 用户抖音图文真实样本，以及详情和短链接入口 | 图片数量、顺序与原页面一致，逐图对照文字和来源，无静默跳图；不执行视频下载/ASR，无视频阅读层。不能只靠合成数据或友好报错关闭此项 |
| A7 | 图文错误分支及既有能力回归 | 缺图片、下载失败、访问限制明确失败；`--probe-only` 不处理媒体；普通抖音视频和小红书图文仍能交付各自报告，既有字幕、复核与唯一正文行为不变 |

自动测试辅助验证分流、协议和清理；直接语义与交付验收不可由文件存在、标题匹配、测试数量或 `git diff --check` 替代。所有作为持久验收依据的材料遵守第 2 节，不进入 Git 跟踪。

## 6. 非目标与批准边界

不新增平台、批量任务、账号登录、云端服务、图片描述、图文总结、OCR 智能纠错、长期全量媒体归档或公共 SDK。不把可靠平台字幕真实流程和复核 `unavailable` 的历史暂缓等同于通过，也不借本次规格调整其批准状态。

用户于 2026-09-06 明确批准本文 V0.1 与配套设计 V0.1，允许据此编写独立执行计划；执行计划另行批准后才修改实现、Skill 或迁移存量材料。本次规格批准不等于执行计划获批。
