## 1. 用户可观察的交付结果

源 Skill 能指导 Codex 按 V0.5 判断何时测试、何时等待、何时复用确认、何时仅通知已有状态，并使用 Auto-review 与现有审批可见命令。其他 Harness 继续当前发送与审批行为。此阶段交付可审阅的源指令和离线证据，不宣称已实现离席真实送达。

## 2. 实施步骤与文件范围

1. 核对执行授权和上游批准版本；读取 `skill-creator`、`writing-for-agents`，检查当前源 Skill、测试及设计要求仍适用。只在当前非主分支实施，保留已有设计改动。
2. 修改[源 SKILL.md](../../../skills/feishu-notify/SKILL.md)：将 Codex 首次准备置于原发送路由前，按设计第 5 节处理请求分流、已有调用证据、Auto-review 模式、固定测试及收件确认。记录限于当前对话，包含分叉、恢复、上下文保留与用户主动变更接收人的处理。
3. 收敛冲突措辞：既有“无需再次确认”指业务外发授权，不跳过 Codex 首次收件确认；正文变化须重新准备、接受当次平台决定，但不承诺一定出现人工提示。保留单次脱敏重写、未知投递不补发及结果优先。非 Codex 分支继续现有 argv/stdin 合同，不继承新增测试门禁。
4. 维护[合同测试](../../../tests/test_skill.py)，只补充必要指令分支与边界；复用现有 CLI、客户端、配置与安装测试，不复制其实现断言，不增加新运行器。静态字符串断言只证明必要约束存在，不能代替指令语义或真实收件。
5. 同步 [README](../../../README.md)、[USAGE](../../../docs/USAGE.md)、[应用设置指南](../../../docs/FEISHU_APP_SETUP.md)、[现行合同](../../feishu-connector.md) 与 [CHANGELOG](../../../CHANGELOG.md)：新能力置于“未发布”，说明源实现与真实链路验收状态；保留已发布 V1.4 及更早记录。设计中的历史基线继续保留，不改写为已实测。

## 3. 验证与直接验收

运行[路线图](README.md)规定的模块回归，确认旧 argv/stdin、卡片、配置、重试及六文件安装测试未回归。按下列场景逐项语义走查，必要时选最少行为试跑，材料置于工作区外：

| 场景 | 应作出的决定 |
| --- | --- |
| 首次明确通知意图，原任务已获执行授权 | 在开始或继续前测试；Auto-review 已知可用时不再问模式，不申请持久前缀 |
| 测试成功但未收件确认；再次要求通知 | 继续等待，不重发测试，不开始原任务后续执行 |
| 已确认、进入新对话/分叉、恢复原对话、用户说明接收人变更 | 分别复用、重测、按本对话记录复用、清除确认并重测；不把继承记录当本对话确认 |
| 无执行中任务且仅要求完成后通知；仅仓库规则自动通知 | 前者只发前一任务状态，后者维持 `task --auto`；不插入测试、不启动或恢复任务 |
| 原任务待批准，用户只确认收到测试 | 仍待批准，不把收件确认为设计、计划批准或执行指令 |
| Auto-review 缺信息、人工模式可切换、功能不可用、模式切回人工 | 分别只核实缺项、等待用户切换、报告不可用、重新核实离席条件；不反复投递测试 |
| 隐私拒绝、无更安全替代、已重写、review 超时、未知投递或 `skipped` | 按设计第 6 节与现行合同处理；不绕过、不跨进程补发、不假报送达 |
| 其他 Harness 的纯文本、富文本、显式任务与仓库自动通知 | 沿用既有接口与授权，不出现 Codex 首次测试或配置要求 |

完成标准：所有设计分支均能据源指令得到一致决策；测试与公开说明不扩大任务执行或消息授权；模块回归与相对链接、`git diff --check` 通过。按仓库第 5–7 节执行适用的标准、规格和 Prompt 检查；若触发机制重审条件，先补齐证据，不继续叠加修补。

## 4. Karpathy 精简与自检

单独对照 V0.5 审核实现和全部修正建议：只保留必要的 Codex 分支，正文、脱敏及失败决策保持单一来源；撤回无实际场景支持的新增要求，优先删除或复用。报告保留的既有合同、删除的冲突措辞、仍有的重复以及未验证范围。确认无未经批准的行为差异后，才能将本阶段标为完成并进入 02。

## 5. 非目标

不修改 CLI、配置、客户端、卡片、HTTP、重试或安装机制；不配置 reviewer policy、规则、网络 allowlist，不创建激活文件。此阶段不安装用户 Skill、不发送真实飞书、不发布版本或操作远端 Git。真实收件和离席可用性由 [02](2026-10-18-02-delivery-acceptance.md) 验收。
