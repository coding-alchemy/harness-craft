## 1. 用户可观察的交付结果

用户在真实 Codex 会话收到首次测试卡片并确认固定目标；同对话再次通知不增加测试，离席时成功、失败及待确认任务能按各自授权收到有效结果卡片，无新的人工审批等待。安装内容、实际限制和公开说明一致，其他 Harness 无新增首次测试门禁。

## 2. 前提与安装

1. 确认 01 的实现、语义检查、适用评审与离线回归全部满足，执行授权仍有效。阶段转换时核对最新差异；如后续修正影响已验收行为，重验受影响部分。
2. 操作者已配置测试应用与固定测试接收人，能确认真实收件；保留当前沙箱与组织限制，使用实际支持 Auto-review 的 Codex 会话。测试消息仅含固定测试内容或简单测试任务的非敏感结果，不读取或打印真实秘密来补足接收人证明。
3. 复用安装器 `python3 -B feishu-connector/install_skill.py`；受管文件冲突且确需更新时使用现有 `--force`。只更新 manifest 现有六文件，逐一核对内容和权限，确认已安装入口独立可用；不手工复制受管文件，不改安装器或用户权限配置。
4. 使用安装副本验证新指令已加载；需要新会话、分叉或其他人工界面操作时由操作者配合。新对话不能只通过沿用本工作对话的确认来替代。

## 3. 行为与真实链路验收

按设计第 8 节执行，合并可复用的准备，避免为每个断言重复测试。各案例的任务和通知须明确获授权；一次完成后通知不能被扩展为任意后续任务通知。

| 验收组 | 直接观察与证据 |
| --- | --- |
| 首次与等待 | 新对话中使用简单、已授权的只读任务并要求通知；任务开始前收到一张固定测试卡片。未确认期间保持等待，再次提出通知不重发；用户确认收到并认可目标后才继续 |
| 执行中追加通知与授权边界 | 首次追加时暂停后续执行，确认后继续；仅“完成后通知”且无执行中任务时只发前一任务状态。任务待批准时，收件确认不能启动或恢复实现；仓库自动通知不插入额外测试 |
| 同对话复用与三种终态 | 同一确认后的对话分别使用获授权的成功、失败和待确认测试任务；保留非敏感任务与结果信息，每个节点收到一张对应卡片，无额外测试卡片和人工审批等待。失败用无破坏性的预期失败场景，待确认不代替用户作决定 |
| 新对话、分叉与恢复 | 新对话和分叉首次使用均重新测试，恢复同一对话可复用其明确记录；压缩后的记录仍保留所属对话及用户确认，不因记录丢失静默认定已准备完成 |
| 模式与配置边界 | 人工模式等待切换、不可用时报告限制；同对话模式变化不重复收件测试。用户明确要求接收人变更后的重测只面向其指定测试目标，不推断或扩大范围 |
| 失败隔离与单次重写 | 核对拒绝、超时、状态不明、`skipped` 和隐私重写正反例；只有现行条件全部满足才重写一次，结果语义保留。无更安全替代、再次拒绝或未知投递时停止，原任务结果不受影响 |
| 其他 Harness | 用现有非 Codex 环境或明确 Harness 身份的最少行为试跑，结合 01 的 argv/stdin 回归，确认纯文本、富文本、显式任务及仓库自动通知没有新增测试、确认或 Codex 配置要求 |

真实首次收件和三种离席终态必须实测，记录当次平台决定、未等待人工审批及操作者真实回执；`Feishu message sent` 不能单独代替回执，退出码 `0` 不能把 `skipped` 变成发送。首次收件确认后的离席测试期间，操作者无需处理新的审批提示，之后核对收件。

纯指令分支可使用最少的无网络行为试跑与模拟工具结果；拒绝/超时等场景不得通过危险外发、扩大权限或修改生产配置制造。证据明确标记真实与模拟；模拟结果不替代前述实际送达要求，也不作为平台总会放行的证明。无法核对的项列为未完成，不静默删去验收范围。

## 4. 验证、状态与收尾

1. 证据放在工作区外临时目录，只保留脱敏的调用与回执信息；计划内更新验收状态及缺口，不复制运行报告。缺少用户确认、运行能力或环境信息时按路线图维护 triage 状态，保持本 ticket 未完成。
2. 真实验收发现问题时，在已批准范围内修正并重验受影响行为；涉及新增机制、持久合同或扩大职责时先按 AGENTS.md 重审，行为差异须批准，不借验收放宽设计。
3. 根据最终证据同步 README、USAGE、应用设置指南及现行合同，准确区分已实现、已实测和仍有限制的内容。用户已另行授权将本次日志转为 V1.5 正式记录；此后保留该发布历史，不因补充验收改写历史或再次新增产品版本。规格与标准检查后单独执行 Karpathy 终审，核对修正建议没有引入重复机制或无依据要求。
4. 最终按 `verification-before-completion` 复核本阶段及路线图的用户结果。阶段 01 后没有实现改动时沿用其仍适用的回归证据；有改动时重跑受影响检查，不以纯收尾为由重复所有实测。运行 `git diff --check`、相对链接和最终差异范围检查。
5. 全部直接验收满足且无待确认缺口后，在同一变更删除本主题路线图与两张 ticket，更新[计划索引](../README.md)，并清理设计和公开说明中指向已删除计划的链接。交付最终行为、真实证据与限制；本地提交、安装成功或测试通过都不能单独触发计划删除。

## 5. 非目标

不要求用户持久允许命令前缀，不修改 Codex policy 或组织策略，不放宽网络权限，不添加补发、后台服务、接收人绑定或新 CLI。无需覆盖所有 Harness 产品或制造破坏性错误；保留既有公共合同，并对新增 Codex 分支提供必要独立核验。发版、推送、强制推送和创建额外 worktree 均不属于本阶段。
