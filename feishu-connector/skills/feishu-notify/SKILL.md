# 飞书通知

仅在用户明确要求发送消息，或仓库指令启用自动任务通知时使用本 Skill。入口相对当前 `SKILL.md`：`scripts/feishu_notify.py`。

## Codex 对话级准备

仅 Codex 执行本节，置于下文发送路由之前；其他 Harness 保持现有 argv/stdin、显式发送与仓库自动通知行为，不新增首次测试、收件确认或 Codex 设置要求。通知授权、原任务执行授权、平台审批与真实收件分别判断，不能互相替代。

### 请求分流与已有证据

按以下顺序决定是否准备首次测试：

| 当前请求与证据 | 行为 |
| --- | --- |
| 仅要求“完成后通知我”，没有正在执行的任务，也没有新的任务执行授权 | 只发送一次前一任务当前状态；不额外测试，不启动、恢复或继续任务，不记录离席准备完成 |
| 仅仓库规则授权结果或待确认节点的自动通知 | 沿用 `task --auto`；规则本身不授权前置测试卡片 |
| 本对话已有用户明确确认的测试记录 | 跳过测试，核对本次通知授权后进入下文发送路由 |
| 已授权具体任务执行并要求结果通知，本对话未确认 | 在任务开始或继续前测试；执行中追加通知时先暂停后续执行，待收件确认后才继续 |
| 直接要求发送指定消息，本对话未确认 | 先测试并确认，再按原有 `send`、`rich` 或 `task` 发送原消息 |

需要测试时先核对本对话调用证据：已发送但待确认则继续等待，不重发；已有失败或状态不明则遵循下文失败合同，不自动再次发起；尚未发起才准备测试。再次要求通知不构成重复测试或重试授权。收件确认不批准需求、设计或执行计划，也不授权开始或恢复原任务；原任务待批准时仍保持待批准。

### Auto-review 与首次真实收件

以当前会话权限信息核实 Auto-review。桌面端对应 **Approve for me**，CLI 对应 `approvals_reviewer = "auto_review"` 并保留能产生审批请求的交互式策略（如 `approval_policy = "on-request"`）。已知可用时直接继续；信息不足只询问缺项；当前为人工模式且客户端支持切换时，请用户选择 Auto-review，选择前不发送测试。功能不可用或组织不允许时报告当前环境不可用，不反复要求切换。

这些是环境前提，Skill 不自动修改配置、policy、命令规则或网络 allowlist；不以 Full Access、关闭审批或宽泛持久前缀替代。用户已有规则由平台处理，不承诺每次必然出现 reviewer 项。

1. 在可见对话说明：向已配置固定接收人发送非敏感测试卡片，只确认本对话链路，不附加工作区数据。
2. 按下文 Codex 审批可见调用，离线 `prepare-shell` 准备显式 `task`，不加 `--auto`，固定字段为：

   ```json
   {"flow":"task","status":"success","project":"Codex","conversation":"飞书通知测试","content":"这是当前 Codex 对话的飞书通知测试。请回到本对话确认已收到，并认可当前配置的固定接收人用于本次请求的通知。"}
   ```

3. 仅移除准备输出最后一个换行，原样提交完整命令，设置 `sandbox_permissions=require_escalated`；支持目标限制时仅允许 `open.feishu.cn:443`。理由说明测试用途与固定目标，不建议新的持久 `prefix_rule`，不改用审批后 stdin。
4. stdout 出现 `Feishu message sent` 后，等待用户明确确认真实收件并认可该固定目标。命令成功、reviewer 批准和 Agent 自述均不能代替确认；等待期间不继续原任务后续执行，不发送测试催收。
5. 用户确认后公开记录“本对话飞书测试已确认，用户认可当前固定接收人”；只记录于当前对话，不含完整 Open ID、凭据或配置值。再核对原任务执行授权，满足时才继续。

测试卡片不代替原消息或任务终态通知；固定测试正文也不批准未来所有正文。

### 确认复用与离席边界

同一对话确认后不重复测试，也不再要求收件确认；每次业务通知仍需对应授权，一次完成后通知只覆盖该任务一次结果。新对话（包括分叉）重新测试，不沿用父对话确认；恢复同一对话可复用其明确记录。上下文压缩应保留确认所属对话与用户确认，归属不明时不能推定已确认。

用户明确修改固定接收人或要求重新测试时，清除本对话确认并重走首次流程；无此信号时不增加每次配置探测，不新增接收人指纹或持久状态。会话切回人工审批或权限条件变化时，重新核实离席条件，不为此重复收件测试；不能自动继续时报告需要用户处理。

每个终态使用真实 `success`、`failure` 或 `confirm` 及有信息量的任务结果，沿用下文授权、脱敏、准备和结果合同。首次收件不能代替终态真实收件证据。休眠、断网、进程退出、任务取消或平台中断不保证通知，不增加补发队列或后台服务。review 超时、中止或工具错误不等同于安全拒绝；按执行证据区分未执行与状态不明，本流程不自动再次发起。拒绝时报告被拒动作和原因，只有下文全部条件满足才可单次重写；目标归属证据不足不能靠删空结果补足，不重复申请。

## 调用合同

使用支持 argv 的执行器时，直接调用入口；每个动态值必须是独立 argv，不得拼接 Shell 字符串、插值或交给 Shell 解析。

### 外发授权

用户明确要求“发送飞书消息”“完成后发飞书”或表达同等含义，即构成本次联网与外发授权：向连接器已配置的固定接收人执行一次显式发送，无需再次向用户确认外发授权；Codex 仍须先遵循本对话首次收件流程。用户指定正文时保留其原意和具体信息；命中下列敏感类别时只替换具体值，保留其余结果语义。

未指定正文时，生成简短且自包含的任务结果通知，并使用显式 `task`：`project` 和 `conversation` 标识任务上下文，`status` 表达结果，`content` 承载正文。正文至少包含：成功的任务标识、核心结果及相关时的验证或产物位置；失败的任务标识、未完成的具体原因及安全下一步；待确认的任务标识、需要用户决定的事项及选项或影响。项目、模块、分支、提交号、测试数量、仓库相对路径和不含秘密值的失败原因属于普通任务信息，不因动态或来自工作区而删除。完整日志、完整 Diff 和内部推理不默认附加。

首次发送前脱敏：密码、API key、访问 Token、Cookie、私钥、验证码、App Secret、连接串中的凭据、配置文件或环境变量中的秘密值，以及身份证件号、电话号码、私人邮箱、家庭地址和用户明确标记为保密的具体内容不得进入飞书 payload。以如 `[已脱敏：Token]` 或 `[已脱敏：个人信息]` 的短标记替换具体值；任务、状态、非敏感原因和结果必须保留。

平台拒绝后的单次隐私脱敏重写仅在下列条件同时满足时允许：工具明确发送进程尚未创建；拒绝原因指向正文隐私、秘密或目的地信任；工具明确允许提交更安全的替代内容；本通知尚未执行过重写。重写只删除或替换敏感值，继续保留任务标识、状态和安全结论，然后重新离线准备并申请一次审批，最多重写一次。审批再次拒绝、执行器不支持升级、配置错误或远程错误时立即停止并报告失败；投递状态不明时明确报告状态不明；不重试、不更换渠道，且不得跨进程重试。

本次授权不允许更换、推断或扩大接收人，不得附加完整日志、Diff、凭据、Token、配置值、内部推理或其他未要求上下文，也不自动延续到后续消息。平台安全审批与网络限制仍然有效，不能绕过；投递状态不明时仍不得跨进程重试。

### 执行权限

`send`、`rich` 和实际发送的 `task` 都需要访问飞书网络。用户明确要求发送时，在首个真实发送子命令（`send`、`rich` 或实际发送的 `task`）调用上直接请求执行器提供的沙箱外联网权限；不得以发送子命令先在网络隔离沙箱中试发或探测飞书连通性。`config` 等明确不联网的诊断不计入真实发送调用，可以在沙箱内执行。

使用 Codex 执行器时，在上述首个真实发送子命令调用上设置 `sandbox_permissions=require_escalated`，并说明权限仅用于固定连接器向已配置接收人发送本次消息；执行器支持限制网络目标时，仅允许 `open.feishu.cn:443`。用户的明确发送请求已经构成外发授权，无需再次通过对话确认外发授权；Codex 首次收件确认仍适用，但仍须正常发起并接受平台的工具级权限审批，不得绕过审批。

联网权限或审批拒绝时，遵循「外发授权」的单次隐私脱敏重写条件；条件不满足时停止调用并明确报告消息未发送，不得退回网络隔离沙箱试发或改用其他渠道绕过审批。

路由按下表选择；argv 与网络权限独立：使用独立 argv 或 stdin 只是安全传参方式，绝不授予网络能力。只有连接器在配置允许且实际调用飞书时才联网，stdin 不提供网络能力。

| 场景 | 调用 |
| --- | --- |
| “完成后通知我”等提醒请求且未指定正文 | 显式 `task`，生成已脱敏的任务、状态和执行结果，不添加 `--auto` |
| 用户明确要求任务通知且指定正文或卡片字段 | 显式 `task`，不得添加 `--auto` |
| 仓库规则要求任务结果或待确认自动通知 | `task --auto` |
| 标题、分段、列表、链接或代码等格式信息 | 格式信息优先 `rich` |
| 简单短句 | `send` |

显式 `send` 发送用户指定的纯文本：`python3 scripts/feishu_notify.py send --message "原文"`。不得添加完整日志、Diff、内部推理或其他上下文。

显式 `rich` 发送通用 Markdown 卡片：`python3 scripts/feishu_notify.py rich --title "标题" --content "**正文**"`。它固定为蓝色标题和一个 `lark_md` 正文，不使用任务状态标题。

`task` 发送固定、自包含的 interactive Markdown 消息卡片，只接受 `--status success|failure|confirm`、非空 `--project`、非空 `--conversation`、非空 `--content` 及可选 `--auto`：

```bash
python3 scripts/feishu_notify.py task --auto --status confirm --project "HETU" --conversation "个股-二期-架构师" --content "请选择 A 或 B"
```

项目名和对话框名必须是非空、单行、有效 Unicode，拒绝换行和 NUL；正文必须非空且为有效 Unicode，可包含 Markdown 换行，并且原样传递，不解析、重组、截断或拆分，即使超过飞书限制。不得传入任意消息类型、卡片 JSON 或后台模板。

状态标题严格为 `<项目名>-<对话框名>-<状态中文>`：`success` 为“任务完成”（green），`failure` 为“任务失败”（red），`confirm` 为“待确认”（orange）。消息卡片固定只含 `config.wide_screen_mode`、`header.template`、`header.title`（`plain_text`）及一个正文 `div`（`lark_md`）。

```json
{"config":{"wide_screen_mode":true},"header":{"template":"orange","title":{"tag":"plain_text","content":"HETU-个股-二期-架构师-待确认"}},"elements":[{"tag":"div","text":{"tag":"lark_md","content":"请选择 A 或 B"}}]}
```

自动通知仅用于仓库指令明确启用的任务结果或待确认节点；手动取消不调用连接器，每个节点最多执行一次。失败正文只能提供用户可见原因，不能包含内部推理、完整日志或敏感上下文；通知失败不得改变原任务结果。stdout 出现 `Feishu message sent` 才表示 `sent`（已发送）；`Feishu notification skipped: autoNotify=false` 表示 `skipped`（未发送）。

## Shell 执行器调用

### Codex 审批可见调用

Codex 使用 POSIX Shell 执行器时，先在任务工作区、网络隔离沙箱内调用 `python3 scripts/feishu_notify.py prepare-shell`；若需要覆盖项目根，在子命令前传入 `--project-root /absolute/project/path`。通过独立 stdin 写入与下文相同的四种白名单 JSON。`prepare-shell` 不读飞书配置、不构造客户端、不联网，也不发送消息。

准备成功后，只移除 stdout 最后的一个换行，将其余命令原样作为新的执行调用，不得重建、补充或重新引用。真实命令设置 `sandbox_permissions=require_escalated`，审批理由只说明连接器向已配置固定接收人发送本次可见正文。正文或其他动态字段变化时必须重新准备并接受当次平台决定，不承诺一定出现人工提示。

命令无法提交、审批拒绝或联网权限被拒绝时，除「外发授权」中满足全部条件的单次隐私脱敏重写外，立即报告未发送，不重试、不重建命令，也不回退 stdin、文件或环境变量传参。审批通过后沿用现有发送、自动 no-op、进程内重试和结果判断；只有 stdout 出现 `Feishu message sent` 才报告已发送。

完整正文会出现在 Codex 工具调用、审批记录和可能的会话记录中。继续禁止附加凭据、Token、配置值、完整日志、Diff、内部推理或其他未要求上下文。

### 非 Codex stdin 兼容入口

在不存在审批前 payload 可见性要求的非 Codex 环境中，执行工具有独立 `stdin` 通道时可继续调用 `python3 scripts/feishu_notify.py stdin`。该入口保持 `send`、`rich`、`task`、`task-auto` 四种白名单和现有行为，但不得用于 Codex 的真实发送。

```json
{"flow": "send", "message": "用户指定的原文"}
```

```json
{"flow": "rich", "title": "标题", "content": "**正文**"}
```

```json
{"flow": "task", "status": "success", "project": "HETU", "conversation": "个股-二期-架构师", "content": "已完成"}
```

```json
{"flow": "task-auto", "status": "confirm", "project": "HETU", "conversation": "个股-二期-架构师", "content": "请选择 A 或 B"}
```

## 联网结果与重复风险

网络错误仅以脱敏类别报告：`network.dns`、`network.timeout`、`network.tls`、`network.connection`、`network.unreachable`。它们、限流和服务端错误耗尽进程内重试时返回退出码 `5`；投递状态可能不明，调用方不得跨进程重试，以免重复发送。连接器只在单次逻辑发送内复用 UUID 并最多额外重试两次。
