# 变更日志

按产品版本记录主要功能、兼容性变化与已知限制。

## 未发布

- 论文 PDF 核验：片段被数学字形或页缝分成两段、各段逐字齐全且有序时登记待复核，不再报缺字；译注剩余文字按公式切段核对，对象内找不到时，段落宿主只在剩余文字确实跨页时按两页页文本核对，表格单元格宿主按页文本有序核对。
- PDF 外链核验：原文写 `https://fmt.dev` 这类裸域名、PDF 里存成 `https://fmt.dev/` 时算同一地址；协议、主机、其余路径、查询或片段不同仍报 `external-link-missing`。
- 链接目标锚点：LaTeXML 正式解析稿按宿主写入锚点（段落、文献、单元格在行内，公式在式号行，图与节独占一行），未写入的目标在解析时列出；源对账把空锚点按零宽处理；参考家族核验按序比较锚点的 id、写法，以及是否与前一个锚点同块；PDF 核验判定锚点目的地时不计宿主自身字形。
- LaTeXML 无序列表：默认标记（•、–、∗、·）不进入正文，自定义标签保留；重新解析前写出的旧解析稿，源对账按保留默认标记的读法整篇比对。
- `export_pdf.py` 新增 `--katex-macros`（宏表只改交给渲染器的 TeX，写入导出报告）与 `--check-math`（只渲染公式，一次列出全部失败；带 `--source-adaptation` 时公式类型与正式导出一致）。
- `export_pdf.py --image-adaptations <json>`：项目级声明在导出时裁剪 SVG 的 viewBox、覆盖显示宽度，图片文件、快照与注册表不改；声明摘要进入导出报告与交付身份，导出后改动声明核验报 `image-adaptations-mismatch`。
- SVG 插图：绑定显示宽度的 SVG 派生位图至少是显示宽度的 2 倍像素，不足时宽高同乘整数倍，显示尺寸与版面不变；倍数写入导出报告，核验按报告重建。含这类 SVG 的 PDF 随之变大（HSTU 约大 10%，ULTRA-HSTU 约大 6%）。
- PDF 版面：标题与紧随的长代码块一起移页时记放宽项交视觉复核，没有标题粘连的整块移页仍判 `code-page-gap`；链接文字按词边界断行，表格编号链接不断开，带链接的图片与图注同页。
- 图片与图题居中：单独成段的图片（含带链接的图片）在版心内水平居中，指向图片的独立锚点按版心左缘核对目的地；紧跟图片、以加粗“图 N”“Figure N”“Fig. N”或子图标号开头的图题一行放得下时随图居中，多行时铺满版心、两端对齐。
- 交付校验：对账时输出表格只解析一次，取检查事实时不做全站准入，同一次计算内共用导航事实，CUDA PG 13.5 单次从约 1 小时 49 分缩短到约 12 分钟、结果不变；身份计算与取检查事实输出 `identity`、`check-facts` 进度阶段，阶段运行超过 60 秒时每 60 秒输出一行 running 进度。
- 交付文书与重导出：新增 `render_delivery_notes.py`（visual、link、delivery、files），从记录与证据渲染统计段，需人判断处写 `〔待补：…〕`，复核备注或登记的用户说明留有 `〔待补` 时交付校验不通过；记录登记了 verify_pdf 检查时，重导出参数（`--require-display-map`、`--toc-sections` 等）与之不一致即在渲染前停止。
- 程序化目检：`--visual-aid` 另给页脚页码核对与关键页清单；会话与子代理都不能读图时，以“【程序化目检】”开头的视觉复核须绑定带 `--visual-aid` 的核验，并写明用户抽查结论后才能通过交付校验。
- 数字复核：差异 ID 改为“角色、原值、数字前后各 6 字（去掉 HTML 标签、空白归一后）、同前后文序号”，不含行号，只改格式时 ID 不变；`--prepare-reviews` 列出与上次闭合复核相同和新增的项。
- 工作包合并：同一源文件经符号链接或物理路径给出都算同源（按真实路径比对），内容相同的另一个文件仍报“异源包”。
- 检查器变化后的恢复：身份变化报错列出变化的身份键和文件；`references/workflow_helpers.md` 写明四步恢复顺序与检查点。
- 清理：`references/cleanup.md` 写明记录绑定的快照在清理后验收完成前保留；新增只读的 `verify_delivery.py --after-cleanup [--published-root …]`，单独给 `--published-root` 报参数错误。
- 诊断：核验缺导出证据时只报根因，`--source-adaptation` 漏写路径直接报错，导出 work-dir 接受相对路径；对账差异第一屏归类计数，全部写入 `reconcile_diffs.txt`；参考译文核验超过 10 条告警时默认归类（`--verbose` 逐条），逐项数字提示汇总为一行，只有一条的告警类别只打印一行。
- 文档：翻译约定写明双语题注回显里 `*`、`^`、`_` 的转义；`references/latexml_source.md` 增论文链路最小命令。
- 兼容性：
  - LaTeXML 论文用新版重新解析后，`source.md` 多出锚点行，没有这些锚点的旧译文核验不通过。
  - 按旧 ID 闭合的数字复核与工作包证据失效；样式表、导出器与核验器有改动，带 `--visual-aid` 的 verify_pdf 检查身份也变了，PDF 项目已闭合的视觉与链接复核失效；新导出的图片位置与 SVG 像素和旧 PDF 不同，显式视觉复用不能沿用旧的视觉复核。
  - 导出报告新增 `katex_macros`、`image_adaptations`、`svg_raster_scale` 键，没有 `svg_raster_scale` 的旧报告按 1 倍核验；核验报告的 `visual_aid` 新增 `footer_ok`、`footer_anomalies`、`key_pages`。
- 已知限制：
  - 核验盲区：锚点挪到相邻、原本没有锚点的块时，参考家族核验查不出；表格单元格译注按页核对时，同页别处的相同文字可能掩盖单元格内的删改（整行删改仍报 `text-missing`）；清理后核对不比对只登记在 `files`、不在输入里的目录文件。
  - 复核与目检：数字前后 6 字内的文字改动（含中文拆段在断点处多出的空格）会让该项作为新增项重审；工具只能确认“用户抽查”一行已写入，确认不了用户看过；译注剩余文字改按页文本核对的位置不登记放宽项，不会列入关键页。
  - 导出：文字版 PDF 来源的确认数学不经 `--check-math`；严格参数比对只保护重导出（首次导出时记录里还没有 verify_pdf 检查）。
  - 图题：图片与图题写在同一段（图片行下一行紧接图题、中间没有空行）时整段居中，多行图题也逐行居中；不加粗或段首带残留源文记号（如 `[FIGCAPTION] `）的图题不会被判定为图题，不居中。

## V1.7 — 2026-11-16

- 源侧对账的脚注引用只取编号，带方括号与裸数字两种写法结果一致；定义首行跳过空白文本，正文里跟冒号的 `[^N]` 仍算引用。链接目标认出包住图片的外层链接，链接文字不跨空行。
- 只有表头行的表（Sphinx 选项卡里的单格代码表）认领其后的格内代码。带 id 的引用块成为来源对象：解析稿在引用块前写锚点，合章后指向它的链接跳到引用块。
- figure 开头的别名 id 与自身 id 一样登记为其中的图片：解析稿在图片前写出别名锚点，合章后指向别名的链接跳到对应图片。脚注被多次引用时，解析稿里的回链写成纯文字 `(1, 2, 3)`，与单次引用一致。
- 翻译约定写明 `[BLOCKQUOTE]`、`[DEF-LIST]`、`[FOOTNOTE-LIST]`、`[DETAILS]` 的可读写法；锚点绑定按两侧共用的段落枚举计数，按约定改写后绑定不变；译文提示框标签接受“中文（原标签）”的任意原标签。API 解析稿片段的片段核验检查链接顺序，翻译约定与工作包任务同步写明。
- 来源记录的快照条目可选 `source_broken_links`：原站快照里本来没有的链接目标，未登记时合章阻断并报出页、译文行号和原目标，回源登记后合章去掉链接、保留文字，API 核验按同一登记重建预期。合章一次报出所有页的锚点、链接和表格问题，错绑写明期望与实际紧随的对象及行号，失败时不写出成品。
- 安装脚本写 `.install-manifest.json`；安装副本被改时，解析、合章和核验在 stderr 开头列出被改的文件，结果照常产出。`SKILL.md` 写明不改已安装的 Skill 目录，以及升级重译时可用的旧合章导航恢复和限制。
- 兼容性：带 id 引用块的页，解析稿多出锚点行（PG 13.5 只有 unified-memory），译文要在引用块前补锚点并按约定写引用；原样保留 `[BLOCKQUOTE]` 等提示的旧译文照常通过。async-copies 的解析稿多出 3 行别名锚点，compute-fabric-transport、compute-capabilities 的脚注回链变成纯文字，这几页的旧解析稿和译文要用新版重新解析并按约定准备。存量恢复时，同一节的引用块按位置对应：含带 id 引用块的那一节，旧译文的 `>` 引用块须与原文一一对应。片段核验新查链接顺序后，cuBLAS 现有 33 个译文包里 wp_001、wp_023 会报链接顺序。仓库级安装测试合同多一个默认为空的 `generated_files` 字段。
- 验收：BPG 13.5 单页 21 节、PG 13.5 全部 54 页及 13.4 async-barriers 解析对账通过；PG 副本第 1–6 章不加项目补丁合章与 API 核验通过，unified-memory 与 extended-gpu-memory 合成的临时章合章与核验通过，各项损伤样本被拒绝；unified-memory（13.4 与 13.5 快照）按约定写成 `>` 引用块后，存量恢复把两段引文各自对到对应的引用块，写成列表时被拒；全量回归的失败集合与改动前相同（本机 7 个 PDF 用例在改动前同样失败）。

## V1.5 — 2026-11-09（正式版）

- 论文翻译与 PDF 交付使用同一记录。导出前完成翻译就绪检查，替换成品前复查身份。正式核验保留独立源对账与成品检查，同一调用中复用已执行且身份一致的翻译核验。视觉复用的历史证据仅绑定完整交付身份。受验证的目录进入正常记录流程，正文仍须逐项覆盖。复核候选预填当前绑定和逐项待办，数字提示按类呈现，仍按实际回源结果闭合。
- LaTeXML 保留图片对象、题名出版注及跨行公式。有序列表保留条目顺序和嵌套，保留列表内图片、图题及其图与子图归属。来源准备输出锚点、资源及表格候选，裁决后由正式解析独立对账。文字版 PDF 按确认的原页字形、块、题名和出现身份物化。数学装配逐字保留源顺序，支持已确认的同源材料复用。
- PDF 每次打印前重新量测实际版心。确认的公式与式号保留对应，表格数值、目录目标、图题和正文独立核对。复杂中文题名使用 v2 视图声明，v1 的纯文本题名继续可读。必要的 SVG 派生保留原件及依赖，并按成品像素和显示宽度核验。
- 独立核验继承报告记录的有效来源依据，校验各项实际摘要。译注剩余文字按 PDF 文本对象核对并定位输入、行、页及对象。确认 PDF 的脚注内表格与代码共用既有脚注块视图，覆盖翻译、工作包及合并。
- 当前导出报告从首次 PDF 复核绑定开始使用持久路径。显式视觉复用核对旧实际复核、报告、绑定及同条件的全部页面像素。链接、语义和源对账仍分别闭合。缺原渲染条件或发现差异时实际目检。旧校验器会拒绝 v2 题名声明或 `visual=reused`。
- LaTeXML 列表内图片与文字同处一个超链接标签时，正式解析会在写出前拒绝该输入。
- 按 V0.2 验收了 HyFormer v2 §3.1、§5 与 TokenMixer-Large v2 第 8 页 §5 的两条真实完整链，以及五篇论文的独立场景。固定基线同范围的正式家族核验从 4 次降至 2 次、从 2 次降至 1 次，独立源对账和 PDF 核验次数保持。V1.5 发布回归通过七组 shell 测试、1312 项 Python 测试及 233 个子测试。历史归档及费用有缺口，保留在实际试点说明。见[需求](specs/2026-11-07-paper-workflow-optimization-requirements.md)与[设计](specs/2026-11-07-paper-workflow-optimization-design.md)。

## V1.4 — 2026-10-24（正式版更新）

- CUDA/Sphinx 数学解析保护公式内部空格与标点，只转换一对最外层定界；独立源对账保留内部定界并排除行内代码。
- 单页 API 可使用完整家族核验；有序 / 无序列表按真实 Markdown 读取信息计数，标题工作清单复用现有导出入口。
- API 保留链接图片及原目标、富引用 / 分组脚注 / 图例 / details 和两类 Sphinx 标签页的块顺序与父属；标签及其面板进入独立有序对账，未知富容器明确定位。PDF保留列表内原始围栏代码及父项归属，首标题为H2时印刷目录不重复同一目标。
- 简单表格按实际格位及格内硬不变量核验，拒绝缺行、伪行和格代码错绑；v2表头依据原DOM、映射及实际来源范围贯通翻译和精确转换，不从Markdown加粗推断角色，v1人工表示及td强调保持兼容；正式v2交付必须实际消费匹配当前来源、快照、映射及范围的项目/导航上下文，缺失或错配明确拒绝。中间包显式使用 `--table-code-stage intermediate`；经当前复核的合并以 `--finalize-table-code` 转为可读格位说明，最终 Markdown/PDF 拒绝实际解析标记。旧包须按当前检查身份重核。
- API 可显式展开可解释的 rowspan / colspan，生成 GFM 与绑定快照的 v2 表映射，保留头分组、空覆盖及格代码原点；配套文件只发布新位置。单快照映射接入现有全源准入及局部资格，无关表事实不因新映射文件路径变化而失效，v1 人工转换语义保持。
- 多快照来源按自身表映射及声明区间独立对账，局部表号不累加；旧声明须唯一归属，两级冲突及跨快照重复消费拒绝，局部资格保留其他快照有效包。
- API 保留可定位的源对象锚点，合章可用现有来源记录证明页到章归属并转换稳定命名空间；最终核验重建链接对象关系。PDF 裸片段仅查本章，旧跨章回退须据源改为明确文件目标。
- 规则 / 术语变化沿用实际选区、任务差异及逐包当前资格；历史任务声明的只读引用受同一输出保护。CUDA 同构样例区分词义语境、保留空格位，技术疑误与排版注分开处理。
- 工作包合并使用最终目录暂存、flush/fsync、独立重读核验和单文件原子替换；候选、写入或替换失败保持旧成品，首次失败不留下最终文件。
- PDF 译注剩余文字核验使用原 Markdown 独立删除区间及整章脚注上下文，兼容命名 / 数字 / 重复引用，保留同行正文与代码字面记法；真实正文或脚注缺损仍拒绝。
- PDF 导出在内联 / 打印前检查候选核验依赖和实际 Chromium 能力，位图 / 脚注 / 视觉辅助按实际模式检查并报告解释器与隔离安装入口；缺库不再伪装为图片尺寸未知，失败保持旧成品。
