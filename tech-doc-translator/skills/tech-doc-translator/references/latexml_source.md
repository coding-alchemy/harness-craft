# LaTeXML 来源翻译闭环

适用：原始快照由 LaTeXML 生成（如 arXiv HTML），无论是否含 MathML。
入口 `parse_reference_html.py --source-adaptation <依据.json> --adaptation-output <候选依据.json>`；
完整工作流、合同与真实论文注意点如下。

## 1. 身份与依据文件

- 主 Agent 先独立确认论文身份（预期/实际题名、论文 ID、版本、最终 URL、
  取得时间、确认依据），写入输入依据的 `paper_identity`；历史 manifest 的
  取得时间只作历史引用，快照摘要按实际文件重算，身份差异如实记录。
- 依据文件为 `version: 1 / format: latexml`：身份、快照摘要、裁决、
  `correspondences`、`unresolved`、可选 `groups`/`table_conversions`/
  `resource_substitutions`。输入中的旧 correspondences 不代替本次重建；
  消费者重读原始快照重算摘要，不把生成器自报摘要当独立证明。
- 未解决项（无 TeX 等）非空即阻断分派与完整交付：主 Agent 回源补齐或裁决
  后重跑解析；不猜写、不丢弃、不留内部占位符。

## 2. 适配与独立对账

- 适配器在原节点上直接转换：MathML `alttext` 逐字取 TeX（实体解码一次；
  含边界空白与换行，不裁剪），行内/展示类型保持；无 `alttext`/类型冲突
  逐节点进 `unresolved` 并保留序列化原文。
- 无 MathML 的字面数学快照（数学为字面 `$…$`/`$$…$$`）：文字按共享扫描器
  口径进入宿主对应；适配器把未被已确认记录消费的扫描跨度逐字登记为
  `math[k]` 对应（类型 + 逐字表达式 + 候选字符区间，node 接续 MathML 公式
  序号；定界与换行包装按实际写出形式登记），候选依据本次重建即可驱动拆包。
  全部公式对应（MathML 与字面）在序列化时以来源出现身份携带临时标记，
  展开后的实际写出区间即该出现的精确对应区间（相同表达式跨宿主不串位：
  不做全局文本首次命中，身份交换/篡改区间/共同遗漏均由独立对账按原快照
  拒绝；清单逐行、参考文献与列表逐条发射，行间/条目间相同表达式不串位），
  并按候选字符
  区间即实际源序组织，导出/核验按同一源序消费。对账端只承认出现身份传递的
  精确区间逐字对应（类型与定界包装一致）；宿主范围不再授予覆盖资格，
  切片不符、math 间真交叠、数量或顺序不符均拒绝。**边界**：跨行字面公式
  不在默认扫描结果中（D2 限定扫描边界），不登记对应，须由主 Agent 复核
  裁决。
- 逐字 TeX 覆盖全部宿主：段落、标题、图题与算法题注、列表项、代码清单、
  参考文献条目与表格格的行内公式统一走同一逐字行内序列化（哨兵分段 +
  `math_wrap` 逐字，含边界空白与换行），不再经归一化文本提取；独立端对账
  镜像同一事实口径。
- 独立对账 `reconcile_latexml_to_markdown` 用全新 DOM 遍历重建有序正文流，
  逐节点核对依据并比较两侧 token 流；容器直属文字按文档序进入正文流
  （不登记节点事实），段落内图片与文字按文档交错次序比较；清单/列表/
  参考文献条内无 MathML 的字面公式按共享扫描器口径分段进入公式事实
  （与候选侧同一口径，不归一为普通文字）。删正文、漏
  公式、等数替换、改类型、错归属、范围交叠、额外输出、无解释重复按目标
  原因失败。
- 输出保护：全部产物（Markdown、候选依据、有图时的尺寸映射
  `<stem>.images_display.json`）路径在适配前一并计算，对原 HTML、只读
  依据输入及彼此两两冲突检查（冲突直接拒绝且不写任何文件）；全部产物
  同组原子发布（同目录暂存 + 替换阶段失败回滚），任一失败整组保旧：
  已替换的旧目标按序从备份恢复，本轮新创建的成员撤销，并如实诊断区分
  恢复/撤销/未动三类结局。
- 图浮动体按 DOM 宿主记录父浮动体与子图序（中间 flex 单元等包装不影响
  文档序计数）；段落宿主内的图片以 `[IMG: images/<名>]` 块行按文档交错
  次序保留（图片在源位置成独立块行，前后文字保持原顺序），不静默丢弃。
  算法清单、命名脚注（定义内公式两端均从原 MathML 逐字重建）、等式组与
  式号、复杂表逐格裁决
  （`table_conversions`）与缺失资源同版本 PDF 替换（`resource_substitutions`，
  须实际裁剪并目检）走既有合同。

## 3. 消费链与 check_policy

- 依据记录本次解析的确认选区（顶层 `selection`，无选区为 `null`）与本快
  照 Markdown 的范围事实（顶层 `markdown.sha256/lines`，切片形式：去掉
  一个结尾换行的行数与摘要，多快照按序拼接时结尾换行是片间接缝）。旧格
  式依据无此二键：单依据整文行为完全不变；多依据场景任一缺键即拒绝。
  准入（拆包/恢复/合并共用）按依据 `selection` 对账（F2：按 `selected`
  选区解析后的同源拆包不再被要求补齐选区外节点）；交付预检核对记录声
  明的 `section_id` 与依据 `selection` 一致（未声明回落依据选区）。
- 拆包/恢复/合并/片段核验接受重复 `--source-adaptation`（单用行为不变）；
  多快照（F7）按给定顺序把当前源切片：每片行数须等于对应依据记录的
  `markdown.lines` 且 sha256 一致（证明无缝拼接且未漂移；覆盖不完整/
  漂移/顺序错误如实拒绝，不以"未闭合数学定界"等错误原因失败），逐片
  validate+完整对账（各用自己的 `selection`）后把公式对应/宿主区间按累
  计偏移合并为整文视图供后续逻辑消费；包 frontmatter 以
  `source_adaptations` JSON 列表登记全部依据引用。
- `split_work_packages.py` / `verify_translation.py --fragment` /
  `recover_work_packages.py` / `merge_work_packages.py` 均显式
  `--source-adaptation`；绑定失败即拒绝，不降级为普通来源。包 frontmatter
  记录依据路径与源字符区间/摘要。拆包、恢复与合并准入先重读原始快照执行
  完整原 DOM 对账（含适配有效性核验），对账失败即拒绝，不只核对公式绑定。
  片段核验按包范围装载依据视图并走包口径公式绑定（与恢复链路同一实现）；
  `[TABLE]` 块行内公式与其他位置同一确认集合口径（表内公式的对应登记即
  已登记格位事实），不设独立豁免。
  完整文档模式的整源核对保持不变。
- `check_policy`（D4）只投影本包字符范围实际涉及的节点对应、裁决、适配器
  身份与数字口径（不含全篇快照摘要，整篇核对由准入级全源对账承担）；
  无关事实变化不使本包证据失效。投影内的公式/图片等引用在全源准入通过
  后归一为已核验的包内局部出现名（角色前缀 + 包内 Markdown 序，如
  `math#1`、`figure#1`），组成员、图/组与裁决 node/into 引用随同一映射
  归一；保留局部顺序、类型、父属、原内容及相关组/脚注/裁决依赖，真实引
  用标签、官方编号与资源身份不作别名归一——别包新增 MathML 导致的全篇
  诊断编号变化不再误撤本包资格，相关事实变化仍失效。复核证据（
  `review_evidence.json`）逐包登记源/译文/两侧资源摘要、check_policy 投影、
  复核结论与数字处置（见 [numeric_review.md](numeric_review.md)）。
- 当前交付 `verify_delivery.py`：源链声明 `source_adaptation`（含
  `table_conversions` 与逐快照 `per_stem_map`），先独立原 HTML→解析
  Markdown 全量对账，再复跑核验；复核记录须绑定当前译文与源资源身份。
  单快照在条目级声明 `source_adaptation`（行为不变）；多快照（同一论文
  多份原始快照合并为一份解析 Markdown，各快照按声明的连续 `range` 无缝
  覆盖）改由每个快照字典各自声明 `source_adaptation`，路径解析与其他
  路径字段同规则（相对交付根），条目级字段与多快照并存按二义拒绝。
  每份依据只对应自己的原始快照：预检逐快照独立核对快照摘要、论文身份
  与逐节点对应（缺一份、顺序调换或身份错配即拒绝，指名快照序号）；全量
  对账按各自 `range` 逐段比较（第二段被改等损伤定位到对应快照）；图片
  资源替换（`resource_substitutions`）与资源基点各随快照自己的依据与
  快照目录，不用首个页面替全部来源。导出/核验消费翻译就绪投影的
  `source_adaptations` 列表（单快照沿用唯一 `source_adaptation`，行为不
  变）：扫描上下文取并集、已确认公式按序拼接成整文序列，多依据导出按章
  分配该序列（每章只绑定本章子序列，章内逐字对齐不符或分配后序列未耗尽
  即拒绝）；独立核验对空绑定章照常核对（渲染非空即失败），核对全部受来源
  约束的章节。含脚注定义的来源约束导出中，已确认序列的渲染消费（导出解析
  游标与独立核验期望序列同一入口）按脚注渲染投影：正文保持源序、被引用
  脚注定义内公式按首次引用序移到章末、同一脚注内保持源序；投影的公式
  掩蔽与跨度扫描、确认序列使用同一已确认来源上下文（已确认上下文才能
  识别的跨度不漏掩蔽，公式内部记法不被当作脚注引用）；确认条目逐字
  携带原 TeX（含边界空白），不回退裁剪分类；未引用定义残留仍由数量门禁
  拒绝。CLI 显式传入的 `--source-adaptation` 集合与投影声明不一致即
  拒绝。交付根一级文件全部登记角色；既有无关旧产物位于交付根时，以独立
  交付根承载当前交付，不动受保护旧文件。
