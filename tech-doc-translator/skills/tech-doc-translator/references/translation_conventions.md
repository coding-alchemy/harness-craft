# 技术文档翻译约定（Practice-first）

> 沉淀自真实 NVIDIA/Sphinx 类网页翻译实践。项目自身 `术语表.md` 与本约定冲突时，以项目术语表为准。

## 1. 源确认

- 动笔前 `curl -sIL <url>` 检查重定向链与版本号，记录落地 URL、版本和抓取日期。
- 抓取后的本地 HTML/PDF 为翻译唯一原文依据，不凭模型记忆补写。
- 章节范围以官方 TOC/导航为准；存在两种会改变交付内容的合理解释时先请用户裁决，不自行扩大或缩小范围。
- 每次换文档或复用解析器，分派前都要把原始源中的标题、图片、`<pre>`、块级公式和脚注等关键结构与解析产物做总量和顺序对账；未识别块级结构必须显式暴露，禁止静默丢弃。
- 行内 `<code>` 在解析产物中保持 Markdown 代码语义：按内容最长反引号串选定界符（``a`b`` 用双反引号包裹），链接标签内的代码同样保留；正文空白/标点整理不进入代码内容。对账时行内代码作为独立事实核对文字与位置，删定界符或换内容都会被拒绝。
- 表格与列表按归属对账：`[TABLE]` 行按 `' | '` 保留首尾空单元格（仅含代码的格位文字为空但列位仍在）；`[TABLE-CODE r=行 c=列#序]` 的格位坐标篡改（越界或换格）按归属检出；列表项核对层级、父列表内序号与项内"文字/代码"顺序，标签越过代码或跨父列表移动即拒绝。表格含未解释跨行/跨列（`rowspan/colspan` 非 1）时阻断分派。
- 获准的复杂表格重建使用逐表转换映射（`reconcile_html_to_markdown(..., table_conversions=<映射>)`）：`version: 1`，可选 `snapshot_sha256` 绑定快照字节；每张表以 `locate`（`table` 序号或 `table_id`，可选 `section_id`）定位，`cells` 逐源格登记 `row/col`（1 起、含表头行，与 TABLE-CODE 同口径）、实际 `rowspan/colspan`，以及 `targets`（输出表格位 `{"table": 序号, "row": r, "col": c}` 或移出说明 `{"note": [起始行, 结束行]}`；含格内代码的格只能声明表格位，代码不能随说明移出）。核验逐输出格进行：非空输出格文字按 `' / '` 分段（单一来源则整体相等）须与声明指向它的源格文字（行优先序、归一口径）一一相等——表头父子组合与共享值展开由此解释，数值篡改与附加文字确定性拒绝；格内代码按源格（行,列,序）映射到声明目标格位的 TABLE-CODE 键逐一相等，输出表孤儿代码必拒；一对多展开使格内行内代码/公式与脚注引用随格文字重复，次数由声明目标数推导。说明移出按声明行区间保留包含关系；表外内容照常全量检查。映射未覆盖的表保持原门禁；映射只描述已定位的转换事实，重建含义由绑定当前身份的回源复核确认。
- 译文使用真实 Markdown 表格，表格行内公式的 `|` 须转义为 `\|`（否则破坏列界）；公式对账在译文表格行内把 `\|` 归一为 `|` 比较（与解析侧 `[TABLE]` 行的未转义管道同一数学内容），表格外不归一。

## 2. 术语处理

1. **首现标注，后文可纯中文**：有通用中文定名的术语，如 线程块（thread block）、网格（grid）。
2. **保留英文不译**：社区惯用英文，如 kernel、warp、tile、cubin、fatbin、PTX、SM、bank、stream。
3. **一律不译**：代码、API/函数名、产品名（cuBLAS、NVCC、NVRTC）、版本号（sm_120）、数学公式。

项目内 `术语表.md` 为权威；没有时由主 Agent 创建最小 Markdown 表。

## 3. 固定转换规则

| 原文元素 | 译文处理 |
|---|---|
| 标题 | `# 1. English Title（中文标题）`；保留官方英文原题与编号 |
| 脚注 `[1]` | `[^1]`，注文全译 |
| Note / Warning / Important | `> **注（Note）**` 等引用块 |
| 图题 Figure N | `**图 N. 中文（English original）**` |
| 交叉引用 "see Section X" | 保留官方节号，不造链接 |
| 英文习语 | 中文意译 + 首现附英文，如 锁步（lock step）|
| 商标 ® / ™ | 原样保留 |

标题中的大小写、标点、弯引号和其他内容性字符也属于原题，必须逐字保留；纯 API/选项名标题可以不加中文后缀。

复杂表格允许根据官方页面重建列结构，但不得改变单元格含义。跨列表头需展平时保留分组关系；承载“不支持/不适用”等含义的空单元格统一写为 `—`，并保留原表说明或加必要译注。

## 4. 行文底线

- 复杂长句可拆分，但不改变逻辑关系。
- 代码围栏、标识符、命令、选项、路径逐字保留。源围栏已有的语言标签逐字保留；源裸围栏可补语言标签。
- 代码密集文档不得手工转写围栏内容；从源文程序化提取/回填，并在译后和合并后按顺序逐块比对。围栏数量相等不能替代内容一致。
- 源文段内硬换行先还原为完整句段再翻译，不逐行制造破碎短句。
- 疑似原文错误先回源确认；技术性误导照录，可加 `【译注：原文如此，疑为笔误】`。
- 官方重复内容保留，不替换成“参见第 X 章”。
- 只有在源文本程序化比对确认一致时，才可逐字沿用既有译文；存在差异的部分必须重新翻译并记录。

## 5. 交付形态

- 文件头部含 `> **原文** / **来源** / **译例说明**` 引用块；PDF 导出时“原文”“译例说明”由导出器按授权投影默认排除，“来源”等字段保留。
- 全书目录集中交付在交付目录的独立 `00_目录.md`：以官方 TOC/导航与已确认翻译范围为依据，按源顺序列出章、节层级及对应译文链接（相对路径 + 锚点），保留官方标题、编号与译文标题对应关系。单篇翻译同样生成该文件；用户明确不要目录时才省略。局部翻译只链接交付范围内内容并标明范围，不假装全书已翻译。
- 不再默认在每章文末重复附全书目录；原文固有的章内目录与官方重复正文保留。已有译文仅导出 PDF 时不修改、不搬迁其 Markdown，也不强制补建目录文件。
- 图片下载到 `images/`，不热链外站；按全书/全站建立图片顺序与身份映射，跨章复用同一资源，无官方图号的图片不得占用 `figure_NN` 名称。
- 暗/亮图片对只嵌入一个可读版本，并在译例说明中记录取舍；最终按 Markdown 所在目录检查相对路径，以文件魔数或 `file` 判断图片有效性，不依赖扩展名。
- 合并文件是新的交付产物。合并只做围栏感知的拼接和标题调整，禁止对全文执行不感知围栏的空白压缩或格式化。

## 6. 校验与裁决

- 硬不变量至少包括：标题数量与顺序、H1 约束、代码围栏配对及逐块内容、公式、图片顺序/存在性/有效性、脚注配对，以及项目指定的强 token。任一失败均不得交付。
- 表格、列表、段落和“语义块总数”会因合法重建发生漂移。漂移是必须逐小节定位和解释的告警，不能仅凭正负方向直接判丢失，也不能忽略后判通过。
- token 多重集适合定位标识符遗漏，字母多重集只适合作为解析损失兜底；二者都不证明顺序、结构或语义正确。
- 结构校验通过后仍须回到权威源复核数字与单位、否定与条件范围、指代与交叉引用、术语首现。翻译 Agent 的现象上报可作为线索，原文错误或解析器缺陷的技术定性由主 Agent 回源确认。
- 校验脚本也是待验证的软件：遇到 FAIL 先定位是产物问题还是口径问题；修改脚本后用已知正确产物回归，再按完整输入口径验证新产物。
- 任何内容、术语、合并或校验脚本修复都构成新的出错面；修复后重跑受影响检查，最终合并产物必须完整重验。

## 映射回补

- 存量译文恢复图片尺寸：`rebuild_images_display.py --manifest <清单> --output <交付映射>`（清单声明范围与同版本来源；只核对图片出现、尺寸与独立身份，不做全文对账，契约见 `<SKILL目录>/references/images_display.md`）。交付级映射固定写入 `export/images_display.json`（导出与核验两侧命令显式传入 `--images-display export/images_display.json`，回补 `--output` 指向同一位置）。
