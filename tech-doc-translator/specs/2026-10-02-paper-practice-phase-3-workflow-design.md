## 1. 问题陈述

主 Agent 已能拆包、复核、恢复、合并和完成交付，但每个项目仍需拼装任务书、手写逐包证据、维护目录并逐个执行交付检查。重复拼装容易遗漏真实强 token、适用转换口径、任务上下文或当前复核依据。用户需要减少这些操作，同时保留“机器通过、独立复核、工作包复用、最终交付”各自的资格边界。

现有包证据绑定源片段、译文、两侧图片资源、三个检查模块及强 token；恢复 / 合并接收的 `--approved-extra-math` 尚未进入证据比较，规则与术语的相关变化也没有对应字段。简单照搬旧生成器会沿用空 token 和全局 `done`，仅给生成器补字段又不会改变消费者的解释。目录同样必须消费实际标题目标规则，批量核对必须消费当前交付入口，才能避免多处维护不同结论。

## 2. 方案

保留主 Agent 编排和现有 CLI，增加各司其职的薄辅助入口：强 token 候选提取、工作包任务生成、逐包待复核证据生成与实际复核登记、目录生成、显式批次核对。共同事实继续从当前源、源包元数据、项目权威说明及真实 CLI 参数取得；不把这些入口包装成万能命令框架。

工作包任务和证据共用当前包映射；证据生成、恢复和合并共用逐包检查事实及资格比较。最终交付仍独立运行完整来源、检查与人工复核合同。目录生成和 PDF 导出共用标题目标构造，批量入口只逐项目调用现有交付核验。辅助输出不授予翻译、人工裁决或自动调度权限。

## 3. 用户故事

1. 作为主 Agent，我希望逐项、文件和适用的既有位置参数形成同一强 token 清单，以便换一种输入方式不会换一种核验结果。
2. 作为主 Agent，我希望重复配置去重、缺席项明确未检查，以便任务书和报告准确描述实际检查。
3. 作为主 Agent，我希望显式选用 PTX/ISA 预设后得到源位置明确的候选，以便先裁决适用口径再开展检查。
4. 作为译者，我希望普通小数、缩写和正文词缀不会自动成为强 token，以便预设不擅自改变翻译规则。
5. 作为维护者，我希望能回查候选到已确认实际清单的对应，以便了解哪些项进入本次检查及原因。
6. 作为主 Agent，我希望任务、证据、恢复、合并与交付使用同一实际清单，以便其中一个环节不能用空清单放行。
7. 作为翻译 Agent，我希望没有主会话上下文也能找到项目指令、规则、术语和适用样例，以便独立理解当前任务。
8. 作为翻译 Agent，我希望任务明确唯一只读源、唯一可写目标、源顺序及小节实例 / 片段 / 范围，以便不写入其他包或全局文件。
9. 作为翻译 Agent，我希望任务解释公式、代码、图片、表格与解析标记的输出合同，以便按正确表示交付而非保留被禁止的残留。
10. 作为翻译 Agent，我希望计数来自当前拆包脚本且差异可以上报，以便手工计数不支配真实内容。
11. 作为主 Agent，我希望四要素缺失、不可访问、源对账未成立或规则冲突时无法生成可分派任务，以便上下文缺口在分派前暴露。
12. 作为翻译 Agent，我希望任务提供当前可用解释器、Skill 位置与真实检查参数，以便安装位置变化后仍可执行。
13. 作为主 Agent，我希望源或规则变化定位前后内容并撤销受影响旧任务的完成认定，以便“已收到消息”不被当成内容已经同步。
14. 作为主 Agent，我希望证据依据当前源重建全部预期并核对唯一目标，以便缺包、错包或错目标不被译文数量掩盖。
15. 作为主 Agent，我希望硬检查通过只产生待复核记录，以便工具 PASS 与翻译 Agent 自检不能自动成为语义完成。
16. 作为复核者，我希望逐包登记实际回源复核、依据及未解决项，以便一个包的完成不能替其他包闭合。
17. 作为复核者，我希望数字差异、疑似原文问题与其他未解决项仍阻断相应语义完成，以便统计提示不会降低复核要求。
18. 作为主 Agent，我希望源、译文、图片依赖、检查器、真实 token 或适用口径变化使对应旧记录失效，以便不能只换摘要沿用历史结论。
19. 作为主 Agent，我希望无关有效包仍可按当前事实复验复用，以便局部补译或无关术语变化不迫使全部包重做。
20. 作为维护者，我希望生成或登记失败保留有效证据和成品，以便辅助工具不会破坏已有结果。
21. 作为验收者，我希望恢复与合并重新读当前文件、合并后再次全量核验，以便生成器和包记录不能代替最终路径检查。
22. 作为读者，我希望目录按独立确认的官方范围与顺序对应真实译文，以便单篇、多章和局部交付均能准确导航。
23. 作为读者，我希望同名章、重复标题、中文标点、连续连字符及围栏内伪标题被正确处理，以便链接不会跳到第一个同名对象或虚构标题。
24. 作为读者，我希望目录链接以目录实际位置解析，以便移动工作目录后阅读与 PDF 消费仍成立。
25. 作为导出执行者，我希望已有无目录 Markdown 仍能独立导出 PDF，以便新增生成器不会强加目录或修改正文。
26. 作为维护者，我希望批次只核对显式项目及各自实际交付模式，以便范围外项目、未请求的 PDF 或总结文件不被加入。
27. 作为验收者，我希望缺产物、未闭合复核、当前失败、证据过期及状态矛盾可定位，以便文件齐全或历史 PASS 不被算成完成。
28. 作为主 Agent，我希望无产物且无可信调度依据时报告状态不明，以便工具不会推断未分派或自动重派。
29. 作为维护者，我希望后续变更及重新验收记录留在现有说明和证据位置，以便历史与当前结论可分别回查。
30. 作为维护者，我希望批次核对不触发未完成项目清理，证据归位后引用仍有效，以便恢复资产与历史依据得到保护。

## 4. 实现决策

### 4.1 职责、输入与写权限

| 边界 | 输入与输出合同 | 复用 / 新增 / 删除 |
| --- | --- | --- |
| 强 token 输入与候选 | 既有参数、显式 UTF-8 清单；候选入口另接当前源与显式预设，输出位置及裁决对应 | 复用一期匹配 / 计数与真实参数解析；新增有限预设候选，不另写计数器 |
| 包事实与任务 | 当前源、策略、既有源包映射、显式项目上下文；输出每包任务书 | 复用拆包及四要素；新增文本生成与前置核对，不改源 / 译正文 |
| 包证据 | 同一包事实、当前译文及适用检查口径；输出待复核记录或登记某一包的实际复核 | 复用资源摘要、片段检查与恢复资格；收敛生成 / 恢复 / 合并中的事实构造 |
| 目录 | 独立确认的官方范围 / 顺序及最终译文对应；输出指定位置的独立目录 | 复用消费者标题目标构造，删除将被共享部分的重复构造，不写章节正文或资源 |
| 批次 | 显式项目清单、各项目现有交付记录和证据位置；输出本次逐项核对报告 | 逐项目复用当前交付入口；不增加状态库、调度器或完成判据 |

辅助 CLI 使用参数数组及已知入口，不执行项目 JSON 中的任意 shell 命令。源、译文、规则、术语及资源只读；只有指定任务书、候选报告、证据候选或目录可由相应入口写入。生成目标不得与只读输入、译文目标或旧有效证据重合；登记更新走 §4.3 的发布合同。主 Agent 仍集中写术语、全局映射和说明。

项目上下文以 `--project-context` 显式输入 JSON，仅列事实引用及当前适用口径，不解释任意条件或执行规则。`project_root` 给出路径基点，`skill_dir` / `python` 给出本次工具位置；源包路径使用拆包元数据中的实际路径。写入任务前核对可访问性；未声明解释器时使用生成器的实际解释器，环境不适用则报告，不自动建环境。

| 项目上下文字段 | 事实来源与消费方式 |
| --- | --- |
| `instructions`、`rules`、`output_contract` | 引用现有项目指令、适用翻译规则及模板；每项为文本引用与可选明确选区，选区可定位并保留内容摘要，无选区则整份文本适用 |
| `glossary` | 项目术语或已选择子集、语境及共享层顺序，复用当前读取 / 选择器与项目优先级；空配置明确本项目没有配置，不覆盖已有选择 |
| `source_record`、`source_scope` | 引用已有来源声明及确认范围，消费其家族、版本、快照 / 选区、解析源与转换对应；LaTeXML 使用二期原始来源合同，PDF 使用当前裁决合同，不复制成另一份来源清单 |
| `check_args`、`token_decisions` | 真实适用参数及主 Agent 对预设候选的裁决对应；实际 token、额外公式与转换从现有清单 / 已批准依据取得，不由辅助入口裁决 |
| `examples`、`return_contract` | 当前特殊规则及同构样例引用、返回要求；非同构样例明确不能仿照的部分 |
| `source_review` | 现有主 Agent 来源 / 范围裁决内容及当前绑定引用；调用来源预检 / 原始源独立对账核对实际输入，仅存历史 PASS 不构成依据 |

来源准备只复用现有预检 / 对账中不依赖成品的职责，不在分派前强加尚未存在的最终 PDF、交付成品或交付级映射。完整来源身份与最终布局仍由最终交付入口核验。来源事实没有资格或选区不明时不输出可分派任务。

LaTeXML 限定数学上下文直接复用二期同一个 `--source-adaptation` 来源入口及当前片段投影，贯穿拆包、片段核验、恢复和合并；`source_record` 仅引用这份权威来源记录，任务书据它生成真实参数，`check_policy.source_adaptation` 消费同一相关投影，不再声明另一份来源。手工参数调用可独立闭环，不依赖 `--project-context` 生成器。

### 4.2 R3：同一实际清单与有限预设

1. `--strong-token-file` 可重复提供；UTF-8 空白行忽略，每个非空行一个 token，去首尾空白，保留行内字符，`#` 不作为注释。文件缺失、不可读、参数缺值或逐项参数明确传入空 token 均失败；合法空文件明示“未配置”，不能覆盖其他已配置项。该文件只承担 token 输入，不充当一期独立官方标题基准。
2. 逐项、文件与该家族本来接受的 token 位置参数统一合并去重。标题、源路径等其他位置参数保留原职责；只修改真实参数解析入口及交付事实的消费，不在外层猜测参数。计数、边界、遗漏 / 增加和缺席项告警全部调用一期实现。
3. 显式 `--preset ptx` / `--preset isa` 只在候选入口生效。有限内置模式识别已支持的指令、点修饰符、百分号寄存器形态；输出声明支持语法及源位置。只在已明确的代码 / 指令语境取候选，不把正文缩写、小数或词缀作为同类。不能解释的语法报告未覆盖，不提供任意正则配置，不推断架构语义。
4. 候选保存 token、匹配形态、源位置 / 片段及当前源摘要；主 Agent 逐项采纳、拒绝或待定，已采纳项才写入实际清单。对应关系保存在现有项目口径或本次证据中，不创建审批台账。预设本身不能直接令核验使用候选，也不影响术语译法。
5. 去重保持首次出现的顺序及原字面字符 / 大小写；清单呈现使用该顺序，绑定比较使用同一实际 token 集合的确定性排序表示。输入文件、预设或裁决的变化只有改变实际检查事实时才撤销相关结论；文件布局、重复项、等价参数写法不单独制造新的检查语义。候选报告仍保存来源依据，以便回查。
6. 同一实际清单交给任务、包证据及恢复 / 合并；最终交付的真实参数解析取得同一清单并纳入现有身份投影。PDF 源从其现有裁决清单的 `conventions.strong_tokens` 消费，不另添一条不经裁决的 token 通道。

### 4.3 R6：逐包事实、证据与资格消费

当前包证据是以包名为键的对象；保持这种组织及已有字段，不增加中央状态或第二完成记录。生成器、恢复和合并在现有恢复模块内共用一个包事实构造，输入为“当前源 + 明确策略 + 旧源包映射 + 当前目标 + 真实检查口径”。源范围与顺序仍由拆包重建，不由生成器复制拆分算法或从实收到的译文推断。

| 逐包字段 | 内容与消费者 |
| --- | --- |
| `source_digest`、`target_digest` | 当前源片段与目标正文摘要；复用当前摘要边界，生成 / 恢复 / 合并重新读文件 |
| `resource_digests`、`source_resource_digests` | 按实际出现的两侧图片身份，包含 SVG/CSS 后续依赖；缺摘要不能以相等空值通过 |
| `checker` | 实际片段核验及事实构造的有限依赖身份；沿用显式依赖集合，包含本次新增且实际决定资格的公共模块，不扫描全仓库 |
| `strong_tokens` | 本次已裁决实际清单的规范化表示，保持现有字段职责 |
| `check_policy`（合同增量） | 本包实际适用的额外公式、转换、规则 / 术语及已启用辅助口径；生成 / 恢复 / 合并使用同一构造和比较 |
| `review.semantic`、`review.unresolved` | 保留 `pending` / `done` 及未解决项；硬检查仅写 `pending`，主 Agent 实际独立回源复核且未解决项为空才登记 `done` |
| `review.note`、`review.items`、复核日期 | 登记该包实际检查范围、来源与语义依据、已处置项及时间；未处置数字差异沿用 `unresolved`，不另设数字完成标志 |

`check_policy` 的字段按真实适用性构造，未选能力不填虚构项：

| 口径 | 绑定内容与变化范围 |
| --- | --- |
| `approved_extra_math` | 本包实际适用的原表达式及明确译注范围；消费者仍逐项比较，不扩大豁免 |
| `structural_conversions` | 本包已批准源位置 → 目标位置 / 表示的具体事实；沿用既有家族与逐表转换解释，无法适配时待处理，不设整类免检 |
| `source_adaptation` | LaTeXML 等实际启用来源适配的相关原始节点 / 转换事实及适配器身份；整份映射的无关部分不进入包级比较 |
| `rules`、`glossary` | 对本包实际适用的规则内容 / 明确选区、术语选择和语境；保持项目优先级，不把全项目无关章节变化混入每包 |
| `numeric_review`、`numeric_policy` | 二期显式启用时的真实参数与相关项目约定身份；约定不被解析成自动换算白名单 |

规则、转换或术语选区必须由权威文本及包的范围 / 选择依据验证，不由旧证据自报事实。无法明确影响范围时定位待复核，不声称已完成；没有证据只增加复核，不自动重译。完整源对账在当前准入时重验，整体快照摘要用于来源追溯及最终交付身份，不因一处无关内容变化机械撤销全部包；来源版本、公共规则或检查器等确实影响全部包的变化仍使相应复核失效。

**处理顺序：**

1. 只读重建当前全量预期，核对源包的键、范围、源片段正文 / 摘要、源顺序及权威唯一目标；重复、缺包、额外、异源、目标复用或错目标定位失败。局部范围必须显式声明，并从完整预期选取，不能反推。
2. 读取当前源与译文，复用片段硬检查及两侧资源身份；同时解析真实强 token 和适用检查参数。非空、计数相等或上下文字段齐全均不授予资格。
3. `prepare` 生成待复核证据候选，接收当前源 / 策略 / 源包及项目上下文，可显式读取现有 `--review-evidence`。硬失败、不可核验资源或依据缺口不生成完成项；候选包含本次检查及待复核项。现有条目经当次独立复验且所有适用事实一致时可原样带入，其余包进入 `pending`；不能为失效条目补新摘要并保留 `done`。旧有效证据保持原字节。
4. `register-review` 接收相同当前事实、候选证据、`--package` 的单一包身份及 `--review-record` 的主 Agent 当前实际独立回源复核记录，含复核范围、依据、已处置项及未解决项。入口复跑当前检查并比较记录当时的事实；有漂移、缺依据或未解决项时拒绝 `done`。无全局 `--semantic done`，不从子 Agent 回报推断完成；脚本验证绑定与记录内容，不能证明 Agent 没有误判。
5. 主 Agent 作为唯一记录写入者，更新证据前重读本次依赖和旧记录摘要，任一变化拒绝发布。采用新候选及同文件系统原子替换指定当前记录；失败不覆盖有效记录，历史副本按现有证据位置保留，不改写已发布证据索引或其引用文件。
6. 恢复自行重建并重验：缺译文 / 源变更 / 硬损伤与待复核分开报告，有效记录才列可复用。合并使用同一资格比较，但另核对独立全量范围、唯一目标、候选及实际成品；片段检查不能替代合并后全量检查，失败保旧。

包映射与正文事实只有一个当前构造，既有恢复 / 合并 CLI 保留。新增 `--project-context` 只给已声明项目口径提供当前依据；调用未声明该口径时不能消费携带该口径的旧 `done`。现有逐项参数继续可用，明确未配置的项目允许空清单，但已配置项目不得以空值代替。二期可人工产生相同记录并独立验收，不等待本期生成器。

最终交付继续使用其现有 `sources`、真实检查事实、`reviews` 和按目标实际覆盖投影的 `binding`。包证据不被转换成整套交付 `closed`；合并后源对账和语义复核、适用的 PDF / 视觉复核仍实际完成。二期数字项在最终交付中按其 semantic 待复核项和人工记录闭合，本期不增加第二标志。

### 4.4 R7：自足任务书及漂移处理

任务入口接收当前源、策略、源包目录及 `--project-context`，先按 §4.3 重建映射并验证拆包还原，再核对来源资格和上下文。输出以包为单位，不改写机械源包或已有译文；任务书引用源包元数据，不维护第二份可编辑包映射。

四要素按固定模板展开：必读指令 / 规则 / 已选术语及同构样例；唯一源和目标及真实范围；译文模板与当前特殊表示；脚本计数、自检入口及返回合同。公式、代码、表格、图片和脚注按当前内容选用既有规则引用，解析 `[TABLE]` 等结构须解释转为真实译文表示，不能与残留检查冲突。任务明确只写唯一目标，禁止写源、他包、术语表、目录、全局映射和交付说明。

检查命令按当前 Skill / 解释器位置和真实 CLI 参数生成，明确资源基点及 fragment 口径，不拼入无依据的固定路径。返回字段包括新术语及首现、原文 / 解析现象、已执行检查与不确定项；回报只用于主 Agent 定位，不能取得复核或合并资格。

生成及分派前核对四要素可读、计数来自当前脚本、规则无已确认冲突、来源对账成立；任何一项不满足只报告具体缺口，不输出可分派成功。无法可靠识别计数时明确不确定，以源文为准并上报，不手填新计数掩盖缺口。

源或规则变化后，主 Agent 先定位受影响包，任务辅助输出精确位置、前后内容及需重验事项，引用新的当前事实。旧源内容取只读旧源包正文；可选 `--previous-task` 引用历史任务保留的适用内容，规则旧文本未保留时引用主 Agent 现有变更说明中的明确前后依据。仅有旧摘要只能证明身份变化，不能重建旧文本；缺前后依据时报告缺口，不猜测变化内容。旧任务书和旧回报保留为历史，受影响完成认定暂停；翻译结果经当前恢复复验和重新实际复核决定复用，不自动迁移、覆盖或重派。无关包继续按当前资格复用；工具不负责发送消息、跟踪收件或调度并发。

### 4.5 R10：官方范围到实际目录目标

目录入口使用显式 `--manifest` 与 `--output`。清单的 `official_basis` / `scope` 引用当前独立官方 TOC / 导航或已确认的单篇标题范围；有序 `entries` 保留官方位置、原题、编号、层级及唯一译文 / 标题出现对应。沿用现有页面清单和标题基准，不从译文自身反推官方闭合；清单只是本次调用依据，不成为范围数据库。

1. 核对官方依据、明确交付范围与有序条目。部分范围写入可读说明且只生成已交付目标；官方未确认、条目漏关联或含范围外交付目标时不能报告完成，不按文件名排序。
2. 从最终译文取得实际标题、可见文字、层级、显式锚点及重复出现。将现有 PDF 章节解析中的“标题目标构造”收敛为一个有限公共函数供生成与导出共同消费，保留同一 Markdown 解析规则、原题 / 中文后缀语义、现有 slug 与同章 `-N` 编号；不维护近似 slug 副本、不折叠连续连字符。
3. 标题目标公共函数不启动浏览器、不打印 PDF、不做图片内联或 Pygments 代码高亮。使用已有 Markdown / HTML 解析依赖；提取时沿用实际消费者的行内解析和授权投影，所需可选解析扩展按使用能力加载。普通翻译无需安装浏览器；缺所需解析扩展明确报告，不回退成另一套标题算法。
4. 官方条目与译文以源范围 / 标题实例和清单中的对应消歧，并核对官方原题与实际标题。禁止借第一个同名标题替其他条目；长反引号 / 波浪围栏和代码内伪标题不进入目标。自动目录使用实际译文标题文字及官方编号，现有章 / 节层级保持。
5. 链接路径以输出目录文件的真实父目录为基点，按实际文件与片段做必要 URI 编码；不从 cwd 找目标、不写机器绝对链接。写入前逐条用同一目标表解析，写后从目录实际路径再次读取核对；生成不改变章节正文或资源，失败保留旧目录。
6. 默认生成独立目录，用户明确不要时跳过；不在各章末尾重复附全书目录，章内固有目录保留。已存在的用户目录有独有说明时保留或报告不能无损替换，不能整文件覆盖掉说明。

PDF 消费继续按现有显式目录角色、章级 / 一级节选择、分篇过滤、两遍打印与独立链接核验执行。独立仅导出任务没有目录输入时沿用无目录路径，不触发生成器。

### 4.6 R11：显式批次及现有留痕

批次入口接收 `--manifest`、实际解释器 / Skill 位置及指定报告位置。每项的 `project`、`record`、`evidence_dir`、`scope`、`mode` 只声明项目标识、现有交付记录 / 证据位置及实际范围 / 模式，`status_note` 可引用辅助状态说明；重复或歧义项目声明先报告，不扫描目录补项目。

逐项读取真实交付记录，核对清单声明与记录范围 / 模式相符，再以参数数组调用当前交付入口。`translation` 执行适用源对账及翻译 / 语义资格，`pdf` 不增加英文源或工作包要求，`translation+pdf` 执行两者；既有真实参数解析、完整身份、复核闭合和发布保旧为唯一通过依据。

报告逐项保留实际模式、范围、调用 / 退出结果、当前证据引用、失败诊断及状态矛盾。诊断分类用于定位缺产物、机器失败、复核缺口或身份过期，不另写一套资格算法或解析历史 PASS。一次本次验收失败即不完成；本次验收通过后引用新发布且当前身份一致的证据索引。报告发布前用现有身份计算核对其所引用的当前结果，期间漂移则标明已过期，不把旧通过写成当前完成。

状态表仅作提示。无产物且无可信调度依据时为“状态不明”；即使状态显示在途，也不推断未分派或自动重派。其他项目失败不取消独立完成项目的结果；批次返回有未完成 / 不明项，报告不掩盖部分结果。

后续源修复、口径变更或补译由主 Agent 在现有说明中登记日期、变化位置 / 前后内容、依据、受影响范围及新验收引用；历史内容与当前结论分开，当前完成引用最新有效证据。批次可报告需要更新的说明，不能自动改写旧复核或把项目修补脚本作为唯一记录。证据仍按既有持久目录与归位合同保留，报告和链接在清理后可访问，不新增变更台账。

批次核对自身不执行清理。正常翻译任务仍在其原交付验收后进入既有收尾；未完成、失败、暂停或独立仅导出项目不因批次运行进入清理，不删除历史证据、源包及恢复资产。

## 5. 测试决策

### 5.1 最高层入口与先例

主边界是用户已确认的实际工作包与交付链路。优先扩展已有拆包、恢复、合并、结构不变量、交付证据及 PDF 目录测试；只在确定性缺陷需要定位时补现有底层行为测试。预期来自独立固定样例、官方范围与主 Agent 实际回源记录，不由生成器反向生成预期。

测试观察目标内容、可复用 / 待复核资格、错误定位、当前证据及实际导航效果，不断言辅助函数布局、模板措辞或内部调用次数。只改纯规则时静态语义检查加最少试读；路径、真实 CLI、恢复、阅读器和 PDF 行为仍实际运行。临时样例、报告和候选均在仓库外。

## 6. 不纳入范围

不增加规则引擎、万能辅助命令框架、任务队列、调度器、状态数据库、依赖扫描平台、第二套身份 / 完成判据、自动语义评分或独立变更台账。预设不变成共享术语库，不从 URL / 厂商 / 文件名自动启用；不导入 LLM 项目词库。

不引入全局 `done`、自动补签、按行迁移译文、自动覆盖 / 重派、固定字数 / 重试 / 模型 / 并发、额外版本发布、扫描范围外项目或归档清空未完成资产。二期来源适配 / 数字审查、四期 PDF 候选及公式物化规则各自维护，本期只消费适用合同。

本期新增持久字段及辅助职责，满足 AGENTS 的机制重审触发条件。正常流程中，当前源与目标、资源及口径全部一致，人工逐包复核后可复用；失败场景是额外公式 / 转换 / 规则已变但旧字段仍相等，或新生成器忽略真实 token，消费者继续接收旧 `done`。根因在事实构造与消费范围不完整，不在缺一个包装脚本。

两种满足同一需求的可行方案：分别在生成器、恢复和合并补齐映射、片段检查及新字段比较；或将现有恢复中的当前包事实与比较收敛为一处，三个入口消费同一结果。前者改动集中但长期有三个同步点；后者复用已有资格边界且消除本次会新增的重复，选择后者。保留最终交付的独立全量核验，因为它检查合并产物及其他依赖，不能删除这项必要独立验证。

目录亦有两种可行方案：生成器调用整个导出章节管线但不打印；或提取该管线已有的有限标题目标职责供双方共用。选择后者，避免目录生成承担代码高亮、图片和渲染职责；保留实际行内解析和现有锚点语义，不用简化正则冒充消费一致性。批量入口直接调用当前交付 CLI 比新增批量判据更少机制；手工逐项目调用同样可行，但不能提供本需求的统一显式批次核对结果，故薄循环仅承担调用和报告。
