## 1. 问题陈述

原需求针对正文对齐、总标题、逐页页码及译者说明的 PDF 呈现。`torch.fx` 样本交付已完成，交付 Markdown 保持原样；通用目录出处自动排除在复审中仍会误删导航或误拒合法来源。本轮设计只处理该未验收的通用边界，不重做已验收的样本排版。

现有导出链已支持单篇/合订、印刷目录、来源门禁和独立核验，也已将章首出处排除并留在报告。当前问题集中在目录“译自……”段的自动判断：导出与核验采用同一错误投影规则，双 PASS 仍可能漏掉导航；格式失败时显式声明的加载顺序又让声明无法接管。第 8 节给出可判定的窄格式和失败处理。

## 2. 解决方案

导出前从原始 Markdown 和已确认的导出视图决定建立一份受输入身份约束的可见内容预期。来源仍从原始输入检查和留证；译者添加的出处、已标识说明及译注仅从 PDF 视图中排除。单篇显示中文文章总标题，合订显示独立的中文全书标题；章节标题、锚点与原始 Markdown 保持。打印层只改变普通正文段落对齐和页脚页码。独立核验从原始输入与导出视图决定重建预期，并从最终 PDF 实测可见内容、元数据、页码和现有保真条件。

## 3. 用户故事

1. 作为 PDF 读者，我希望普通正文段落两端对齐，以便连续阅读时版面整齐。
2. 作为 PDF 读者，我希望中英混排、行内代码和长链接仍清楚可读，以便对齐不损伤技术内容。
3. 作为 PDF 读者，我希望标题、代码、表格、图题和目录沿用各自布局，以便正文样式不误改其他区域。
4. 作为 PDF 读者，我希望每页看到实际页序和总页数，以便打印后定位页面。
5. 作为 PDF 读者，我希望目录页和正文页使用同一连续页序，以便页脚与印刷目录互相对应。
6. 作为 PDF 读者，我希望 PDF 不出现译者添加的前置出处和已标识的导览说明，以便从文章内容开始阅读。
7. 作为 PDF 读者，我希望参考文献链接、原文脚注和图题仍完整，以便可核对原文内容。
8. 作为译者，我希望原始 Markdown 中的来源和译注保留，以便保留翻译依据而只调整 PDF 呈现。
9. 作为译者，我希望出处虽然不显示，但来源不足仍在生成 PDF 前被定位并阻断，以便交付可回源。
10. 作为 PDF 读者，我希望总标题及文件属性标题一致且以中文呈现，以便文件列表和首页都能识别文档。
11. 作为合订读者，我希望看到全书中文总标题，同时各章的中英双语标题不变，以便区分文档与章节。
12. 作为导出执行者，我希望缺少中文题名时由 Skill 自动给出可追溯的译名，以便无需手工改写交付 Markdown。
13. 作为导出执行者，我希望无法识别说明边界或生成标题时得到可定位失败，以便不会误删内容或产出无依据标题。
14. 作为验收者，我希望知道每处 PDF 专属排除的原文位置及理由，以便确认合法投影以外的正文没有丢失。
15. 作为验收者，我希望用最终 PDF 检查页码、标题、链接和全部页面布局，以便打印成功或统计正常不会被误当成完成。

## 5. 实施决策

### 5.1 PDF 导出视图决定

沿用现有逐章解析与管理字段投影。先读取原始输入并固定有序输入及摘要，再加载声明并判断目录出处边界，随后以原始输入和获准片段完成来源门禁，打印前建立 PDF 可见内容。章首四类管理字段继续移出且来源留在报告；目录中符合第 8 节窄格式、仅承担前置出处作用的“译自……”段落自动从导出视图排除。格式无法判定时定位失败，或用受输入摘要绑定的声明只排除获准片段；两种路径都保留原 Markdown、导航和来源证据。

已标识的导览说明和译注按 Markdown 结构或显式的只读视图决定定位。已有明确语法的 `【译注：…】` 只在正文文本节点中移除该片段，不扫描代码或原文引用；无法仅由语法确定的既有说明（如 `torch.fx` 参考文献下的导览引用块）通过与输入摘要绑定的显式范围声明排除。声明至少给出输入身份、原始位置、排除类型和原文片段；整块和行内片段分开表达。位置越界、摘要漂移、跨越技术正文或范围重叠均失败。不能凭“出处”“译注”等词在全文搜索删除；边界无法确定时停在候选前并报告。

这些非输入可推导的决定合并为一份 PDF 视图声明，由 Skill 在导出前生成或沿用已确认的同版本声明，供导出与核验同时读取；不建立第二套术语表或通用配置继承。声明保存在可供最终交付复验的交付级证据位置，身份进入导出报告和完成绑定。没有显式说明要排除、且标题可从输入确定时，不强制生成空声明。原始 Markdown 和资源始终只读。

已实施的声明校验仍适用：`inline` fragment 在授权行区间内必须恰好出现一次；块排除不得跨越标题、代码或表格等技术正文。第 8 节对目录出处的 `kind` 和处理顺序作进一步约束，不放松这些校验。

### 5.2 总标题、章节结构与元数据

单篇从文章 H1 中识别已确认的中文译名；只有外文原题时，由执行 Skill 的 Agent 先翻译并在视图声明中记录原题、中文题名与依据。合订有独立书名时同理；缺书名时 Agent 根据已确定的有序输入范围与章题拟定中文合订标题并记录依据。导出脚本本身不引入在线翻译服务。无法得出可核对题名时拒绝生成，不回退为“目录”、第一章标题或外文原题。

单篇只替换 PDF 中文章总标题的可见文字，保留原始标题的层级、锚点和链接目标；章内其他标题不变。合订在最前可见区域加入非章节性的文档总标题，不额外创建封面页，也不将第一章 H1 改为书名。若标题含行内链接、公式等结构，投影应保留其目标与含义；不能保真时定位失败。PDF `Title` 元数据取同一中文总标题决定，不能再简单取首个输入标题。现有目录条目、章节大纲与锚点仍基于各章原有结构；核验须分别核对可见总标题和未改变的章节标题/目标。

单篇总标题取首章的**第一个 H1**，此前出现的 H2 不得冒充；无 H1 且无声明时定位失败。声明题名继续要求中文字段含 CJK、`original` 与 `basis` 非空，单篇能确定原题时 `original` 须与首个 H1 一致。

### 5.3 正文对齐与页脚

只给正文叙述段落增加两端对齐，末行保持自然对齐；继续使用既有长词折行与越界检查。标题、代码块、表格单元格、图题、印刷目录、脚注及其他专门区域不继承正文对齐。对照实际 PDF 检查中文字距和长链接，不为了修饰右边缘降低全书字号或改变代码文本。

在现有 Chromium 打印调用中生成底部居中的 `当前页 / 总页数` 页脚，页序与总页数取打印的最终分页事实，首页、目录页和章首页一律显示。页脚容纳于现有底部边距，页眉为空，不占正文版心。印刷目录原有探测/回填次数保持；每次打印使用同一页脚规则，最终以最终成品页数核对页脚与目录页码。具体打印模板需在目标浏览器环境验证，若不能在现有版心内稳定呈现，设计须重审，不以缩小正文或省略总页数降级。

### 5.4 独立核验与完成身份

独立核验从原始 Markdown、显式视图声明及既有来源映射重建允许的排除范围与中文题名预期，不信任导出报告给出的排除结论。报告记录输入与声明摘要、逐处排除位置/理由、题名来源与导出 PDF 摘要；核验核对其与实际参数一致。相同文字在正文合法位置重复出现时，不用全文关键词零命中作删除判定，而按章节、块及绘制位置核对允许的出现次数与顺序。

旧的“前置出处必须出现在 PDF 中”检查改为“输入来源门禁仍通过、被选择的前置出处不出现在输出位置”；目录来源段同样受该规则约束。标题核验区分原始 H1 与可见中文总标题，确认 PDF 元数据一致，同时继续检查章节标题、大纲、内部目标。逐页从最终 PDF 读取页序、总页数与文字坐标，核对页脚存在、正确、居中且与正文/脚注没有几何重叠；只接受处于页脚区域的页码作为页脚，不把正文中的相同数字误计为通过。最终交付身份绑定新增视图声明及样式政策；改变声明、输入、样式或成品均使旧 PDF 核验和视觉复核失效，沿用既有候选不覆盖成品的失败保护。

## 8. R2 目录出处自动排除重审（V0.6，已批准）

### 8.1 基线、失败场景与根因

已批准的 R2 要求所有 PDF 默认不显示译者添加的前置出处，同时保留目录导航、正文引用与其他原文内容；无法确认排除范围时须定位失败。章首管理字段已有确定边界，本节只重审 `00_目录.md` 中“译自……”出处。`torch.fx` 当前交付目录没有该段，样本 PDF 的验收不能证明通用目录规则正确。

现行链路沿用 CommonMark 块边界与来源门禁，但目录出处已连续出现四类失效：同引用块的列表、多行同段、同行导览、整行模板误判。第五轮直接复现：`译自 https://example.com/x；[Additional Guide](a.md)` 导出与独立核验均成功，PDF 却丢失导览；`译自 [原文](https://example.com/x)`、查询参数或下划线路径的单一合法来源则被拒绝。根因是把 Markdown 链接个数和字符白名单当成“唯一来源定位符”与“书目尾巴”：裸 URL 在文本 token 中不计数，英文导览被当尾巴，中文链接标签与 URL 字符被误当非法尾巴。两个入口按同一错误政策重建预期，所以双双通过不能证明其余内容完整。

另一个实测限制是 `Chapter` 构造时先运行自动目录判断，`--view-declaration` 随后才加载。模板拒绝的输入即使附有摘要匹配的合法声明，也在读声明前失败；“改用显式声明”的现行诊断因此没有可用退路。本轮设计须同时修正该顺序，仍复用现有声明 JSON 与来源门禁。

### 8.2 方案比较与决定

| 方案 | 对正常/失败场景的结果 | 决定 |
| --- | --- | --- |
| 给现行字符白名单、链接计数和行正则继续加例外 | 不能可靠区分裸 URL、链接标签与尾部内容；下一种语言或 URL 字符仍会改变判断。 | 拒绝；删除这些用于证明“仅为出处”的启发式。 |
| 目录出处全部改为显式声明 | 可以防止自动误删，但会回退已批准的 R2 默认自动排除；用户批准的是本设计的窄格式，没有批准此行为变化。 | 不纳入本设计，也不预先授权为下次自动退路；若未来提出，须单独说明差异并获批准。 |
| 保留 CommonMark 块边界，用**完整消费的一条来源语法**识别自动出处；其他候选在候选 PDF 前失败，允许受摘要绑定的显式片段声明 | 能覆盖现有 `译自 [Guide](URL)`、`译自 书名：URL` 等正例及中文标签、完整 URL；任何附加导航/说明留下未消费 token，直接拒绝。 | 已批准采用。比只接受单个链接多保留了既有“书名：URL”行为；比自由文本模板少一个无法判定的尾巴入口。 |

### 8.3 可自动排除的窄格式

结构条件先于行内条件：候选必须位于目录文件的**顶层独立单行段落**，或内容恰为**一个单行段落**的顶层单行引用块。段落或引用块含第二行、列表、第二段、嵌套块时定位失败；相邻的独立导航块保持原样。围栏代码中的“译自”是代码内容，照常保留；其他嵌套块内若出现带可定位来源的“译自”候选，应定位失败，不能当成已处理出处留在 PDF。一个目录至多自动采用一个出处块；出现多个候选时先拒绝并要求逐处明确范围。

去掉外层引用标记和首尾空白后，整行须完整匹配下表之一；`译自` 是明确的出处意图标记，允许紧随一个空格或 `：`/`:`。除了表中组成部分，不接受未消费的文字、第二定位符或第二链接。

| 形式 | 自动接受条件 | 例子 |
| --- | --- | --- |
| 单一来源 | `译自` + 一个 Markdown 链接、CommonMark 自动链接或裸定位符；Markdown 链接的显示标签可为中文或英文纯文本，目标单独按来源规则验证。 | `译自 [原文](https://example.com/paper?id=1)`；`译自 https://example.com/paper_v1.pdf` |
| 书名加来源 | `译自` + 非空纯文本书名 + `：`/`:` + 一个裸定位符；书名不得含另一个定位符、Markdown 链接、图片、代码或分隔冒号。 | `译自 NVIDIA CUDA Guide v13.4：https://example.com/book`；`译自 指南：https://example.com/book` |
| 可选书目尾注 | 前两种形式后只可再有**一对**全角括号，内容限 `YYYY-MM-DD`、`vN.N`、`vN.N.N` 或 `单个拉丁会议名 + 空格 + YYYY`；除此仅允许一个句末 `。`。 | `译自 [Guide](https://example.com/book)（2026-09-01）`；`译自 [Paper](https://example.com/p)（MLSys 2022）` |

这里的“纯文本”按词法限定：链接标签须由 CommonMark 解析为单个非空 text 子节点，不含强调、图片、代码或内嵌链接；书名只接受非空的汉字、ASCII 字母、数字、空格、点、连字符和下划线，首尾不能是空格或标点。尾注日期须是有效公历日期；版本号只接受 `v` 后接两段或三段由点分隔的十进制数字；会议尾注只接受**一个**由 ASCII 字母开头、后续为 ASCII 字母/数字/点/连字符的词，接一个空格和四位年份，例如 `MLSys 2022`。空白仅指普通空格，不接受制表符或换行；`译自` 与后续主表达式之间只允许一个空格或一个中英文冒号。超出这些形式须走第 8.4 节声明，不能扩写自动语法去猜它是否仍为出处。

定位符作为**整体 token**解析，再按既有“可定位具体原文”标准验证：Markdown 链接及自动链接采用 CommonMark 给出的目标；裸 URL/路径必须连续无空白，并在行末、唯一可选书目尾注 `（` 或句末 `。` 前结束。`?`、`=`、`&`、`#`、`_` 与路径斜线属于定位符内部，不能交给尾注字符检查；裸定位符中的未转义中英分号、全角分隔符、另一个链接起始符或剩余文本则使整行失败，确需分号的真实 URL 可写成 Markdown 链接或对分号编码。HTTP(S) URL 必须有主机内路径，本地路径须指向可定位文档。Markdown 链接目标及裸路径若解析为本次纳入的目录或章节文件，应视作导航歧义并拒绝自动排除。链接显示标签、书名和 URL 内部字符不套用书目尾注字符规则。书目尾注匹配完整值，不能以“都是拉丁字母”放行英文散文。来源真实性仍由原始 Markdown 的来源门禁和留痕核对；语法只证明这行没有额外的可见内容。

候选以“译自”开头却不完整匹配时，报告文件、行号及未匹配原因并在打印前失败，原件与旧 PDF 不动；绝不只删前缀或把整块当作出处。典型拒绝：裸 URL 后接 `[Additional Guide](a.md)`、单个链接后接 `See appendix`、第二链接、`（另见导览）`、图片/代码、缺少可定位来源、同段多行。未以“译自”开头的普通目录内容不受本自动政策影响。

### 8.4 显式声明路径与执行顺序

保留现有 `--view-declaration` version 1、输入有序路径与 sha256、`block`/`inline`、行区间及 fragment 校验，不增设第二份映射。复用现有 `kind` 字段约定 `toc-provenance`，使非规范但经确认的目录出处可被明确授权：独立纯出处块可用 `block`；出处与导航共享块时只能用**唯一匹配的 `inline` 出处片段**，剩余导航必须继续进入 PDF。声明片段须来自原始目录、以“译自”开头且含可定位来源；指向纳入章节的链接不能作为出处片段获准删除。其他 kind 不得绕过自动出处判定。

处理顺序调整为：读取原始输入和摘要 → 加载/校验声明 → 对未被 `toc-provenance` 声明覆盖的目录候选应用第 8.3 节自动语法 → 以原始来源和获准片段完成现有来源门禁 → 建立导出视图 → 打印与独立核验。声明覆盖与自动区间不能重复或重叠；解析错误、摘要漂移、越界或误含导航均在候选前失败。核验器从原始输入及同一声明**独立重建**出处位置、允许排除范围和应保留的导航，并在最终 PDF 检查，不以导出报告的结论自证正确。另从**未投影的目录原文**枚举所有指向纳入章节的链接：自动排除区间内出现这类链接须失败，其余链接文字/目标须在 PDF 中保留或按既有印刷目录折叠规则被明确计入；这项保护不从导出器报告的“已排除内容”反推。改变输入、声明或成品仍使旧验收绑定失效。

### 8.5 直接验收与边界

沿用真实 Markdown → `export_pdf.py` → `verify_pdf.py` → PDF 文本/链接/页面的接缝。正例至少覆盖第 8.3 节三种形式、中文/英文链接标签、URL 查询/片段/下划线、本地原文路径及现有 `译自 [Guide](URL)`、`译自 书名：URL` fixture；逐项确认只隐藏出处，目录链接、正文、页码和来源证据仍在。反例逐项覆盖第 8.3 节列出的混合内容、结构共享、多个候选和章节导航目标，检查非零退出、定位诊断、零候选、旧 PDF 不变。显式 `inline` 声明用“出处与导航同行”实测只去除已授权片段、保留导航，并让独立核验通过；篡改该导航或声明摘要须失败。`torch.fx` 成品内容未因本设计修改，不能用它单独代替通用反例验收。

本节定义下一次实现与验收的设计决定，不改交付 Markdown、翻译身份、标题/正文/页脚政策或现有用户默认要求。格式之外需要显式声明是已有“边界无法确定则定位报告”规则的具体化；若未来拟取消自动排除，必须另行取得用户对 R2 默认行为变化的批准。
