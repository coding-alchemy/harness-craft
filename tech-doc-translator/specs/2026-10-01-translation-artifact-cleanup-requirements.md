## 1. 目标与优先级

每次翻译任务完成交付验收后，清理已确认无用的产物，并对清理后的实际交付提供验收证据和交付说明。用户仍能直接阅读、直接重新导出，并恢复翻译工作区。

第一优先级是保证翻译输出效果：凡可能影响正文、排版、图片、公式、代码、链接或重新导出结果的文件，一律不允许删除。不能证明无影响时保留，不以缩减体积、目录整齐或删除数量替代交付质量。

清理不归档，恢复不得依赖已删除文件或归档。恢复所需的独有信息、项目口径与依赖必须保留；可重建的过程产物仅在确认能够由保留资产重建、且不违反输出保护要求后才可删除。

## 2. 范围与既有合同

- 覆盖 skill 已支持的 HTML 与文字版 PDF 源翻译，以及翻译任务附带的 PDF 导出；原文资产不限定名称为 `paper.pdf`，HTML 同版本快照和资源同样按用途保护。
- 保持既有源对账、语义复核、视觉复核、输入身份绑定及工作包恢复资格，不因清理而省略、降级或重新补签旧结论。
- 清理范围是当前翻译项目和本次任务拥有的过程产物，不因目录名相同扩大为全知识库扫描。用户提供的旧项目数量、路径、体积和脚本处置历史不作为通用规则或当前执行授权。
- 独立“仅导出已有 Markdown”不自动触发翻译工作区清理，也不因本需求新增英文源或工作包要求。用户另行请求存量项目清理时，沿用本需求的保护与验收要求，并明确实际范围。
- 不处理 Obsidian Sync、配额、历史版本保留期；体积记录仅作诊断，不能作为必须达到的指标。

## 3. 功能需求

### R1：按用途与依赖判断

文件名、扩展名和目录名只能筛选候选，不能单独决定删除。逐项核对内容、实际消费者、保留依赖、独有口径及未解决项。用途不明或证据不足者保留并说明原因。

必须保留最终译文、既有成品 PDF、原始图片、目录、术语表，以及直接阅读、直接重新导出、恢复翻译工作区与回查验收所需的资产。字节重复不自动允许删除仍被使用的路径；不按修改时间决定最终交付版本。

### R2：完整依赖保护

保护直接和间接依赖，包括 Markdown 图片与文档链接、嵌入内容、SVG/CSS 后续资源，以及导出命令、配置、映射、校验记录、项目脚本和恢复入口读取的文件。引用解析须使用实际消费者的路径基点；不能用 Markdown 直接链接扫描代替完整依赖检查。

允许 `source/`、`wps/`、`translated/`、`scripts/` 等因保留用途而存在；不要求目录清空。不可靠解析或无法排除引用时，不能将相关候选视为无用。有效消费者引用与仅供历史说明的文字提及分别判断，不机械改写历史记录。

### R3：验收证据与交付说明

验收证据、交付说明引用的证据归入翻译项目的 `evidence/`，不是本 skill 仓库的评估输出。导出的图片和阅读资源不放入 `evidence/`。

必须提供可读交付说明，保留单篇说明中的独有口径、未解决项与对应依据；不得因名称包含“总结”“交付”或“过程”直接删除。确需合并说明时，须逐项保全内容与可访问引用。

证据搬移须记录原路径、现路径和角色，检查内部相对路径、调用入口、交付说明链接与身份绑定。不得只搬文件后把历史 PASS 当成清理后验收，也不得覆盖仍需回查的历史证据。仍在使用的输入与历史报告须按实际角色区分，具体位置由设计给出。

### R4：不归档、直接清理

不生成 zip、tar 或其他供恢复使用的清理备份。完整操作清单应逐项列出路径、用途、大小、删除或保留理由，以及证据归位的来源与目标，不能仅展示分类汇总或 Top N。

删除仅限经核对的文件集合；执行前重查文件身份和用途未发生变化，变化项退出本轮删除。目录仅在确认为空且无保留用途时删除。新发现风险或验证缺口时停止相关删除，报告已执行与未执行项，不声称可从不存在的归档回滚。

正常翻译任务收尾自动清理已确认无用的文件，无须用户逐次批准删除清单，交付时提供完整清单和证据。该授权不扩展到用途不明、有潜在影响或范围外文件；这些文件保留，不为完成自动清理而猜测。D1 替代原文的逐次过目门禁。

### R5：保留恢复翻译工作区能力

清理后能够依靠保留资产与已有工具恢复项目的源输入、项目口径、工作包对应关系和复核状态，继续使用既有翻译、恢复、合并及核验流程；仅重新拿到一份可阅读成品不构成恢复。

对已有可复用工作包，清理不能使其因源包、译文、资源或证据缺失而退化为缺失或待复核；本来存在的待复核与未解决项如实保留。没有工作包的项目不为满足本需求新增工作包体系，但源解析、裁决、项目脚本及校验入口仍须可用。

可重建声明须有保留输入、具体工具及口径和实际重建验证，不能依赖重新翻译、重新作出已丢失的人工裁决或重新抓取可能变化的网络内容。阅读或直接导出必需的文件不因可重建而获准删除。

### R6：收尾顺序与直接验收

先完成原有翻译交付验收，再完成清理判定和必要证据归位，按 D1 执行删除，最后核验清理后的实际交付并提供说明。未完成、暂停或失败任务不进入本次“交付即清理”。

清理前核实依赖与可重建性；清理后核对保留交付物未意外改变、全部依赖仍可用，并实际验证阅读、重新导出与恢复能力。重新导出的 PDF 不要求字节一致，但在相同输入、工具环境和导出口径下，内容与呈现效果不得退化，既有机器和视觉完成合同不变。

验收证据须覆盖清理后状态，说明实际检查、环境、结果和缺口。计数不变、清理前 PASS、文件存在或单篇随机抽查不足以证明全项目无损。未知文件保留可作为安全清理结果，但已确认无用的内容尚未处理时不能宣称清理完成。

## 4. 直接验收场景

| 编号 | 场景 | 用户可观察的成功标准 |
| --- | --- | --- |
| A1 | 含最终译文、成品 PDF、目录和图片的真实项目 | 清理前后保留交付物内容一致；从实际路径阅读，图片、公式、代码及链接可用 |
| A2 | Markdown → SVG → CSS/图片的间接依赖，另有普通和引用式链接 | 间接资源及被引用文档保留；未知引用无法证明无影响时不删 |
| A3 | 清理后重新导出单篇或项目已有合订形式 | 不从归档或已删除文件取输入；正文、标题、目录、页码、图片尺寸、公式、代码与链接满足既有导出和视觉验收 |
| A4 | 已具有效复核证据的分包项目 | 恢复入口仍识别同一批可复用包，待复核和缺失状态不因清理被伪造或掩盖；能够沿用既有合并与核验流程 |
| A5 | 文字版 PDF 源项目 | PDF、裁决、golden、源 Markdown、映射及所需快照可用；原有源与译文核验可继续运行，不能靠重做人工裁决补缺 |
| A6 | 同名“候选”文件被使用、重复图片有独立引用、`source/` 有保留依赖 | 均按内容与用途保留；无“目录必须消失”或“同摘要即删除路径”的误删 |
| A7 | 证据搬移及包含独有口径、未解决项的单篇说明 | 说明内容不丢；证据可回查，引用和消费者读取正确，历史与当前结论不混淆；图片不进入 evidence/ |
| A8 | 已确认无用的缓存/废弃中间文件与未知文件并存 | 前者在门禁满足后直接删除且无归档；后者保留并说明；清单完整可查 |
| A9 | 删除前文件变化、验证失败、没有候选文件 | 变化或风险使相关删除停止；已有交付不被覆盖或伪称通过；无候选时如实记录无须删除 |

这些是待实现行为的验收标准，不代表本轮已执行真实清理或已通过验收。

## 5. 已确认决策与规格关系

- **D1：自动收尾清理。** 用户明确选择“自动清理已确认无用的文件，交付时提供清单和证据”。产品正常运行时不逐次询问；本仓库修改 skill 的需求、设计、计划与执行授权仍按仓库门禁分别处理。
- 本需求批准并实施时，同步[留痕需求](./2026-09-14-translation-traceability-requirements.md)中证据位置与已有目录原位条款、[PDF 源需求](./2026-09-26-pdf-source-translation-requirements.md)中源依据持久性条款，以及[翻译完整性需求](./2026-09-12-translation-integrity-requirements.md)的恢复合同引用。保持内容和资格要求，不将整理授权扩大为无条件删除。
- 外部输入文档保留原样；实施以获批执行计划为依据，存量知识库清理不因本需求批准而自动启动。
