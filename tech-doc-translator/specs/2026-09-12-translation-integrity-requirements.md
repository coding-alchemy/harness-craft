## 1. 核心目标

用户在现有四类 HTML 翻译流程中得到完整、可回源、可离线阅读的中文 Markdown：拆分不破坏源结构，恢复不误用过时或损坏译文，合并不漏掉任何应交付工作包，校验不把代码、公式或图片损伤报告成通过。

本期补齐既有承诺，不扩大到 PDF 输入、OCR、动态站点抓取、官方版本增量维护或未知术语自动发现。Markdown 的单篇/合订 PDF 导出已经实现，继续遵循已有规格。

## 3. 功能需求

### 3.1 R1：安全拆分工作包

- 保留按小节和按字符体量拆分两种用途。只在真实标题或完整语义块之间切分；代码中的标题样式、美元符号、表格符号均不参与外部结构识别。
- 代码围栏、行内/块级公式、表格、完整段落、列表及嵌套子项、定义/脚注与引用关系、图片与所属图题等紧密结构不能拆开。跨节依赖无法在单包内闭合时，合并相邻范围或保持较大包并报告原因，不能复制或移动正文来凑计数。
- 后续片段需要原小节信息时放在任务元数据中，不默认补写会进入最终正文的重复标题。
- 脚本生成标题、段落、列表项、表格和围栏等实际存在的结构计数，并记录源位置和顺序；没有可靠识别的结构显式报告，禁止把不确定计数写成零。
- 重新按顺序装配未翻译的工作包正文应还原输入 Markdown，包括代码内部空白；元数据与任务上下文不进入还原结果。
- 不完整或不能判定的结构必须定位，不能切坏后继续分派。字符阈值与完整结构的取舍见 D1。

### 3.2 R2：只复用经当前事实证明有效的译文

- 从当前权威源和明确的拆分策略重新计算预期包，核对原工作包对应的源内容。计数相等不能证明源未变化；不得先覆盖旧源包，再用新包为旧译文提供依据。
- 当前范围、源内容、译文内容及相关结构转换口径必须对应。源变化、代码/公式/图片损伤、可证明的正文截断均不得输出“可复用”。
- 恢复须重新运行适配包范围的硬检查；普通片段不必有 H1，不能套用整篇 H1 唯一约束。正文完整性和技术语义仍须主 Agent 回源复核，结构通过不能替代此判断。
- 对无法机械证明的段落/表格重建差异定位并保留为待复核；缺少旧记录的有效译文先复验，允许通过后复用，不因元数据缺失直接重译。
- 输出区分“可复用”“缺失/已失效需处理”“证据不足待复核”，列出包和原因。待复核项不计作完成，不进入可直接交付的合并；复核发现漏译时只补全或重做受影响部分。
- 既有有效文件不被恢复操作覆写；保留文件事实恢复，不建设中央状态数据库或逐段状态机。

### 3.3 R3：按独立全量范围合并

- 合并必须知道当前任务应有的全部工作包及其有序映射，不能用“实际收到几个文件”反推应有范围。源依据由当前源和拆分策略产生，不从译文目录倒推。
- 缺首包、缺中间包、缺尾包、缺小节末片、重复包、异源包、额外包、错误片段或错误目标映射均拒绝。没有全量依据时报告输入不足，不能报告完整合并成功。
- 输入实参顺序可以不同于源顺序；只有包身份和全量范围验证通过后才能按权威源顺序装配。局部交付须在任务范围中明确，不能借“局部”掩盖缺包。
- 只进行已批准的头部、分隔线、标题层级与资源路径装配；代码、公式及正文内容保持。重复官方内容仍保留。
- 合并候选在最终路径语境中执行全量复验，覆盖拼接处和全局资源。包内通过不能替代合并后通过；失败不得替换已有有效成品。

### 3.4 R4：四类源家族完整执行硬不变量

单页、分页、参考手册和多页面 API 保留各自入口与模板口径，同时对下列共同要求形成一致完成门禁；不以某条路线“较通用”为由降级。

| 对象 | 必须验证的行为 |
| --- | --- |
| 标题 | 英文原题、编号、内容性字符、数量、层级及顺序；包含无编号标题和现有深层标题；代码内注释不是标题。只允许项目已经批准且可逐项对照的标题/目录转换 |
| 代码 | 围栏正确配对；代码块数量、顺序、开启/关闭标记、语言信息与正文保持，逐块比较实际内容和空白；代码示例中的围栏不能误闭合外层 |
| 公式 | 行内和块级公式的类型、数量、顺序与原表达式保持；改符号、交换两个公式或少一项都失败；不靠美元符号计数，不做代数等价推断 |
| 图片 | 按 R5 验证来源身份、出现顺序、数量、最终引用和实际文件 |
| 脚注 | 引用/定义配对且相对源不缺失，不能把一组引用和定义同时删掉后仍通过；跨包引用按完整依赖范围核对 |
| 强 token | 项目指定 API、枚举、命令、标识符等不得遗漏或被替换；覆盖正文和代码，按项目既有口径报告多重集差异 |
| 未处理结构 | 解析占位符、不能解释的源到 Markdown 缺失或顺序变化继续阻断；HTML/PDF 到源 Markdown 的独立对账仍是分派前条件 |

表格、列表、段落等合法重建继续作为需要定位到小节的差异，由主 Agent 定性，不以计数减少直接认定语义丢失，也不以计数相等宣布语义完整。诊断至少包含源与译文文件、章节或可定位行/块序号、期望与实际差异。

已存在的历史数学包装异常若源译逐项一致，只能保留为回源告警；新增、扩大或改内容必须失败。获准译注和结构装配须有明确范围映射，不能成为整类代码、公式或标题免检开关。所有最终结论分别陈述硬不变量、源全量对账和语义复核状态。

### 3.5 R5：在最终目录验证离线图片

- 四类路线都以实际交付 Markdown 为基点解析图片引用；外链、绝对机器路径、只在启动 cwd 存在的文件不能满足离线验收。不得在校验时联网补图。
- 原始快照中的选定图片与译文中的每次出现一一对应。允许合法本地化、重命名、跨章复用，但不能只靠 basename 或总数确定身份；重复图片的每次出现仍计数。
- 核对文件内容身份并以魔数/`file` 或可靠解码判断实际类型；空文件、HTML 错误页伪装的 PNG 和不可读取资源均拒绝。至少保持当前 PNG、JPEG、GIF、WebP、SVG 的有效使用路径；未知类型不能默默通过。
- 跨章同资源保持单一副本；同名不同内容不能覆盖或串用，沿用现有冲突拒绝并由主 Agent 明确命名。暗/亮对只交付已选择的版本，保留选择依据；无官方编号的图片不占用 `figure_NN`。
- 图片身份与出现位置跟随拆分、合并和路径调整；已有 `images_display.json` 的宽度及来源合同不得丢失或被错误重绑。普通 Markdown 阅读的尺寸限制和旧译文无尺寸映射的 PDF 回退维持已批准行为。
- 有效的整个交付目录搬迁到另一位置并切换 cwd 后，图片仍可读取并通过检查；多个章节共享 `images/` 的合法目录组织仍可表达。

## 4. 直接验收

| 编号 | 场景 | 用户可观察的成功证据 |
| --- | --- | --- |
| A1 | 围栏内 H2、内嵌围栏、超阈值代码/公式/表格、跨行段落 | 包内结构完整，切点均为允许边界；源包按顺序还原与源一致，没有新增标题或丢字符 |
| A2 | 嵌套列表、定义与脚注、图与图题跨潜在切点 | 依赖内容留在可独立处理的范围内；超限有定位说明，未知结构没有被无声拆散 |
| A3 | 32→64 的源变化，或代码/公式变化但计数不变 | 恢复拒绝旧包作为当前有效结果，说明变化位置；无关有效包仍可复验复用 |
| A4 | 译文只留标题，或丢掉一个普通段落/表格单元格 | 不得报告可复用；明显损伤阻断，不能机械判断的部分进入回源复核，实际补齐后才接受 |
| A5 | 完整旧译文无验证记录；合法长句拆分/表格重建 | 通过硬检查与独立复核后可复用，没有仅因记录缺失或计数漂移重译全文 |
| A6 | 三包中的首/中/尾任一缺失，末片缺失、重复、额外、异源或映射错误 | 全部拒绝完整合并，诊断指出具体差异；已有成品内容不变 |
| A7 | 全量包逆序传入、显式局部范围、代码内 `---` 与图片语法示例 | 最终只按已确认源顺序完整出现一次；局部范围可核对，代码和图片示例不被分割或重写 |
| A8 | 各源家族改代码返回值/空白/语言标签、换公式符号/顺序 | 对每个匹配路线均阻断；未改动的正确译文通过，代码内美元符号等不产生误报 |
| A9 | 删无编号或深层标题、改层级/弯引号、整组删脚注、漏强 token | 各适用路线都发现差异；有明确映射的合法标题装配和一致历史公式包装保持可验 |
| A10 | 外链图、cwd 伪匹配、HTML 伪装图片、空文件、漏图、错序、同名换图 | 四类路线均拒绝；诊断定位到图的来源与交付位置，不依赖联网 |
| A11 | 图片重命名、暗亮取舍、跨章复用、同图不同宽度、搬迁交付目录 | 离线打开仍显示正确图片；来源身份/每次出现/尺寸映射对应，同名冲突未覆盖资源 |
| A12 | 逐包通过后在合并接缝引入重复/遗漏或改坏资源路径 | 最终复验检出，不能沿用逐包 PASS；修复后的交付按完整源范围再次验收 |
| A13 | 至少一份用户认可的真实技术文档范围，包含拆包、中断、恢复与合并 | 最终中文 Markdown 可读且逐节与原始源对账；代码、公式、图片完整；数字/条件/否定/术语回源复核完成，交付说明明确三层结论 |

四类路线分别要有代表样例，不把只覆盖 API 的测试作为所有路线的证明。真实样例身份、版本和可读路径在执行计划评审时固定；当前仓库 fixtures 用于反例和回归，不冒充 A13 已完成。

## 5. 假设、已批准取舍与非目标

- 继续以仓库 Skill 为唯一产品入口，脚本为内部工具，不承诺稳定公共 CLI；自然语言翻译与技术语义裁决由 Agent 完成。
- **D1（已批准）**：`chars:N` 改为目标体量，完整结构优先；单个不可拆块超限时保留整包并报告。相比当前“上限”描述，此项改变参数语义，不能静默上线。
- **D2（已批准）**：恢复增加“待复核”结果，不再把机械计数通过直接视为可复用。允许主 Agent 在当前源译文件上补齐独立复核后复用；复核证据不足不等于必须重译。
- **D3（已批准）**：合并增加当前源、拆分策略等全量依据；旧命令缺少依据时返回输入不足，不再沿用从实收包数推断范围的行为。Skill 与相关内部调用需在实施时一起更新。
- **D4（已批准）**：四类校验统一采用严格代码/公式/资源门禁；既有错误 PASS 将变成失败或待复核。合法模板转换必须逐项明确，不能靠隐式宽松比较。
- 不确定项是实际参考手册中的脚注/图题边界、历史公式包装和项目模板映射；用 A1–A2、A8–A11 与真实样例校准。不能处理时保留完整范围并报告，不能降级忽略。
- 不增加通用文档 IR、解析器注册中心、模型 SDK、调度器、数据库、自动语义评分或通用出版框架；不改术语裁决优先级、独立目录默认、PDF 默认排除与出版边界。

## 6. 评审与授权边界

本文与对应设计共同覆盖 G1–G5。V1.3（2026-09-12）已有原八阶段实现与验收记录（含 cuSPARSE 13.3 第 3 章真实交付），已完成计划按仓库生命周期清理，可通过 Git 历史追溯。

2026-09-13 后续复审确认 R5 仍有合法 SVG 被依赖识别误拒绝的问题；用户已同意“替换依赖识别层、固定成对验收矩阵”的收敛方案。该收敛修订（V1.3）已实施并按设计 7.3 S1–S5 矩阵验收通过，本节与设计的实施前基线描述保留为历史记录，不得按历史描述撤销已实现能力。

同轮复审另确认两项未验证缺口（G6、G7，均属 R5）：含 `xml-stylesheet` 处理指令的 SVG 被静默放行（目标样式表不同、缺失或被替换仍 ALL PASS），以及 CSS 组件值与 `@import` 参数中的解析错误（如 `url(foo bar)` 的 bad-url token）被忽略。两项已按设计 7.2“不能可靠解释且会影响资源核验的结构报告未验证”的合同修复并验收：处理指令与解析错误均明确报告未验证并阻断完整通过，资源身份记为不可用，显式映射与恢复证据均不能绕过（行为记录见 `CHANGELOG.md` V1.3）。

本轮不改变 R1–R5、D1–D4 或 A1–A13 的要求；具体方案及验收细化见对应设计第 7.1–7.3 节。
