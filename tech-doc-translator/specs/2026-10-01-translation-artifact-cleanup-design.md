## 1. 问题陈述

翻译任务结束后，项目留下快照、工作包、草稿、缓存、脚本、报告和说明。用户希望删除无用内容，让交付便于阅读和维护，同时仍能直接重新导出、恢复翻译工作区，并回查验收证据。

按文件名或目录整体清理无法可靠区分垃圾与必需资产：图片可能有间接依赖，源包参与恢复，源快照和人工裁决支撑核验，证据搬移也可能改变路径解析。清理必须保证翻译输出效果；凡可能影响输出或其他保留能力的文件，一律保留。

## 2. 解决方案

将清理作为每次翻译任务完成原有交付验收后的收尾步骤：识别保留资产与候选，归位证据，自动删除已确认无用项，再验证实际交付的阅读、重新导出、恢复和证据状态，提供完整清单与交付说明。未知或有潜在影响的文件保留，不要求目录清空，不生成归档。

主 Agent 依据文件内容、实际消费者与现有交付合同作判定，使用已有文件操作、资源核验、导出和恢复工具。清理规则集中在一份按需读取的参考说明，主入口负责在正常翻译收尾时触发；详细导出和恢复语义继续由已有规则维护。

## 3. 用户故事

1. 作为读者，我希望清理后的译文与成品 PDF 内容不变，以便继续使用已验收的翻译结果。
2. 作为读者，我希望图片、公式、代码、目录和链接仍正常显示，以便清理不会损害阅读效果。
3. 作为读者，我希望间接使用的 SVG、CSS 和图片资源也被保留，以便依赖没有直接写在 Markdown 中时仍可呈现。
4. 作为导出执行者，我希望直接使用清理后的项目重新导出，以便无需从归档或已删除文件取回输入。
5. 作为导出执行者，我希望原输入顺序、视图声明、映射、配置和必要资源仍可用，以便重新导出的内容和呈现效果不退化。
6. 作为译者，我希望清理后仍能恢复翻译工作区，以便继续使用原有翻译、恢复、合并和核验流程。
7. 作为译者，我希望已复核工作包仍具有原来的复用资格，以便清理不会使有效成果变成缺失或待复核。
8. 作为译者，我希望同版本源快照、PDF 裁决、golden 和必要项目脚本仍可用，以便无需重新翻译、重做已丢失裁决或重新抓取变化的源。
9. 作为译者，我希望单篇说明中的独有口径和未解决项得到保全，以便后续处理有准确依据。
10. 作为验收者，我希望证据集中且能从交付说明访问，以便回查当前交付的真实结论。
11. 作为验收者，我希望搬移记录解释证据的原位置、现位置和角色，以便消费者和说明仍能定位正确内容。
12. 作为验收者，我希望历史证据与清理后验证分开记录，以便旧 PASS 不被当作当前状态的证明。
13. 作为项目维护者，我希望每次翻译验收后自动清理已确认无用的文件，以便无需逐次批准删除清单。
14. 作为项目维护者，我希望看到全部候选的处置、理由和实际结果，以便了解删除了什么、保留了什么及原因。
15. 作为项目维护者，我希望未知或无法排除影响的文件保留，以便缩减体积不会优先于输出与恢复能力。
16. 作为项目维护者，我希望文件名只用于寻找候选，以便同名“草稿”或重复资源仍被使用时不会误删。
17. 作为项目维护者，我希望仍有保留用途的目录允许存在，以便清理不以目录清零为完成标准。
18. 作为项目维护者，我希望只有已证实能由保留资产重建的非直接输入才可删除，以便恢复不依赖备份或重新作出人工决定。
19. 作为项目维护者，我希望文件变化或验证缺口使相关删除停止，以便执行不会继续使用过期判定。
20. 作为项目维护者，我希望无候选时如实报告无需删除，以便结果不被删除数量左右。
21. 作为项目维护者，我希望清理只处理本项目和本任务拥有的产物，以便其他项目及范围外文件不受影响。
22. 作为用户，我希望最后的说明分别给出翻译、清理、阅读、导出、恢复和证据状态，以便知道实际完成项与剩余缺口。

## 4. 实现决策

### 4.1 职责与复用

新增一份清理参考说明，并在翻译交付主入口接入。同步导出、翻译约定、PDF 源规则及相关规格中受影响的完成条件、证据位置和说明引用；详细资源与恢复规则保持单一事实源。获准实施后，最终行为与限制维护在同一个未发布变更条目。

选择“现有工具加明确工作流”：主 Agent 判定项目内的文件用途与独有口径，既有入口验证结果。新增自动分类/删除工具仍需这些判断，会增加维护职责；只写一句“删除无用文件”又缺少必要判定与验收。旧知识库工具依赖固定库结构和归档，保留为历史依据。身份与复核资格继续由现有工具统一计算。

### 4.2 资产与消费合同

| 角色 | 决策 |
| --- | --- |
| 最终译文、成品 PDF、目录、术语表、原图、阅读与导出配置和全部依赖 | 保留内容和有效路径；不能通过改写最终译文制造“无引用” |
| 源快照、解析源、PDF 清单、golden、块映射、源/译工作包和必要项目脚本 | 按实际核验与恢复用途保留，允许原目录存在；没有分包的项目不新增工作包体系 |
| 验收报告、复核证据、交付身份索引、独有裁决及未解决事项依据 | 归入项目证据目录，保全关联、历史内容与真实身份 |
| 交付级图片映射 | 仍是导出输入，保持现有固定位置；不当作历史报告搬移，也不复制成第二份 |
| 图片与阅读资源 | 保持在资源目录，不进入证据目录 |
| 可读交付说明 | 沿用现有允许位置，补充清理结果和证据链接；旧说明只在独有内容及引用已完整保全后判断冗余 |
| 已确认无用的缓存、失败中间版和过期机械副本 | 无输出、恢复、证据用途及有效引用后直接删除；内容或用途不明者保留 |

候选判定覆盖所有实际消费者：Markdown 的图片、普通/引用式链接、wiki 链接与嵌入，SVG/CSS 后续资源，以及导出命令、配置、映射、校验和恢复入口。按实际消费者的路径基点解析；不支持或不可靠的引用不能以“零匹配”放行。有效引用与仅供历史说明的文字提及分别处理，不机械改写历史记录。

“可重建”仅适用于不承担直接阅读或导出输入的过程产物。删除前在库外临时目录，仅凭保留输入、已有工具和原口径实际重建并核对；不能借用待删文件、归档、变化的网络源或重新作出的人工裁决。不能证明时保留，不为增加删除量另建恢复机制。

### 4.3 收尾流程

1. **确认基线。** 原交付验收成立后，读取当前交付记录、项目命令和实际范围，固定交付文件身份、依赖、恢复状态与必要环境；失败、暂停或未完成任务不进入收尾清理。
2. **判定候选。** 从保留资产及其消费者识别保护范围，再逐项检查候选内容和用途。名称只用于筛选；同摘要不自动允许删除被使用的路径。未知、可能影响输出或其他保留能力、范围外的文件保留并说明原因。
3. **归位证据。** 新任务从产生时使用证据目录；存量证据搬移保留相对结构与历史内容，登记原/现路径和角色，同步当前命令及可读说明引用。检查内部相对路径与消费者读取；目标冲突不覆盖。变更触及绑定时按既有合同重新复核，不伪改历史 PASS 或自动补签。
4. **记录完整清单。** 列出全部候选的路径、用途、大小、身份、处置、依据及搬移目标。使用现有说明/报告形式，不建立另一套翻译状态；自动处理已确认无用项，交付时提供清单与证据，无须逐次等待用户批准。
5. **检查并删除。** 必需文件及依赖不在删除集合，必要重建验证已完成，归位后的交付与恢复入口可用。执行前重查候选身份及相关依赖；变化或不确定项退出本轮删除。仅对最终明确集合逐文件删除，目录只删除确认为空且无保留用途者，不归档。
6. **验收并说明。** 按第 5 节检查清理后的实际交付。必要检查失败则停止后续删除，报告已执行、保留和未完成项及实际影响，不声称存在归档回滚。最终说明分别列出翻译验收、清理、阅读、重新导出、恢复和证据状态；有阻断缺口时不宣称整体完成，已确认无用项仍未处理时不宣称清理完成。

## 5. 测试决策

### 5.1 最高层测试边界

主测试边界是“一个真实翻译项目完成收尾后的交付能力”。沿用已批准的项目交付、资源核验、PDF 导出/独立核验、工作包恢复/合并及源核验入口，不新增业务测试接口。

至少使用一个真实 HTML 分包项目和一个文字版 PDF 源项目验证主流程，最小反例补齐分支。样本先验证当前状态，不用历史 PASS 签正向基线；相同执行可支持多项验收。测试只观察实际文件处置、交付效果、恢复资格与证据可用性，不断言内部实现或指令措辞。

### 5.2 直接验收

| 需求验收 | 测试行为与成功标准 |
| --- | --- |
| A1 | 全部保留交付物清理前后内容一致；在实际阅读环境从实际路径检查图片、公式、代码、目录和链接，资源扫描与可见效果分别留证 |
| A2、A6 | Markdown 到 SVG/CSS 子资源、普通/引用式/wiki/嵌入依赖完整；仍被使用的同名候选、重复路径和源目录保留，不可靠解析时保留相关文件 |
| A3 | 从清理后的项目，以原输入顺序、视图声明、映射、环境及口径实际重新导出，候选放库外而不覆盖成品；完成独立核验与全部页面视觉检查，正文、标题、目录/页码、图尺寸、公式、代码、链接及未解决项不退化，不只比较 PDF 字节或退出码 |
| A4 | 运行既有恢复入口，清理前后可复用、缺失、失效、待复核状态及对应目标不退化；接续合并在库外验证，不能用原项目或已删除文件补输入 |
| A5 | PDF 源项目复跑原源与译文核验，裁决、golden、解析源、快照和映射可被真实消费者读取；没有分包的 HTML 项目用保留的同版本快照、解析口径和项目脚本恢复工作输入，不生成原本没有的包 |
| A7 | 从说明实际访问证据和索引，搬移后的消费者读取正确；独有口径和未解决项保全，历史与当前证据分明，图片未误入证据目录，交付映射位置保持 |
| A8、A9 | 已确认无用项实际删除，未知项与范围外文件保留；完整清单可查，无归档或逐次审批；变化、风险或验证失败停止相关删除且无虚假完成记录，无候选时如实报告 |

### 5.3 验证成本与证据

现有资源测试已覆盖 Markdown 引用语境、SVG/CSS 递归依赖和换子资源；恢复测试已覆盖有效/失效证据、源包只读和资源变化；交付证据及 PDF 源测试已覆盖搬移、身份绑定、缺依据和发布失败。按受影响范围复用这些检查，不能以其通过替代清理主流程实测。

纯规则用静态语义分析和最少行为试跑，依赖真实环境的阅读、导出、视觉与恢复仍须实测，不新增形式化评测平台或文案匹配测试。临时样本、候选 PDF、运行报告和测试结果放仓库外；运行已有适用静态检查，无工具时做针对性检查并说明局限。

证据必须描述清理后状态，区分机器、源对账、语义与视觉复核。计数不变、文件存在、清理前 PASS 或单篇随机抽查不能证明全部交付无损；临时重导出 PDF 的身份不得替换实际成品身份。无 PDF 的翻译项目实际验证其既定导出输入，但不新增永久 PDF 交付要求。

## 6. 非目标

- 改变翻译、解析、导出保真规则或人工复核资格；新增恢复/状态/身份体系。
- 全知识库扫描、无授权的存量项目清理；独立仅导出任务自动清理翻译工作区。
- 将未完成任务当作已验收任务清理；通过重新翻译、重做人工裁决或网络重抓补齐已删依据。
- 归档、固定体积目标、目录清零、Obsidian Sync 与配额管理。
- 安装或发布产品、升级产品版本、改动外部历史清理工具。

## 7. 补充说明

### 7.1 基线与机制重审依据

本轮重新读取权威需求、V0.1 设计和相关源码，确认下列接口与限制仍成立；本区域未发现另设的领域词汇表或 ADR。

| 基线模块 | 正常/失败场景与设计约束 |
| --- | --- |
| 翻译主入口与资源核验 | 使用同版本源和最终资源核对，递归摘要包含 SVG/CSS 子资源；只扫描 Markdown 会漏间接依赖，摘要完整也不表示业务文件用途已全部枚举 |
| 工作包恢复 | 从当前源重建预期，读取旧源包定位目标并检查复核绑定；删除旧源包会变为缺失，仅保留证据 JSON 不够，恢复资格与对应关系须保护 |
| PDF 源核验 | PDF、裁决、解析源、双快照、块映射、golden 和图片进入同一来源身份；缺输入会阻断核验，重算摘要不能替代人工裁决 |
| 统一交付核验与证据 | 支持显式证据目录和批次索引；源链、检查参数、资源、共享检查器和环境共同绑定，旧报告存在不证明清理后完整 |
| PDF 导出与图片映射 | 交付映射有固定位置，条目相对映射目录解析；搬 JSON 会影响定位与尺寸恢复，须区分消费输入和历史报告 |
| 历史知识库清理工具 | 使用固定库结构、文件名候选、归档与 Markdown 引用收集；不具备通用的消费者判定，历史成功记录不构成本需求实测依据 |

第 4 节按现有消费者保护资产，并在删除前排除上述失败场景。相较于继续给历史工具叠加保护名单，这使通用规则保持一处维护；通用依赖数据库也没有新增需求依据。

### 7.2 已确认口径与兼容性

- D1 为自动清理已确认无用项，交付时提供完整清单和证据；未知或潜在影响项保留。
- 证据位置为项目 `evidence/`，交付级图片映射保持 `export/images_display.json`；图片保持资源目录。源与工作包目录可因保留用途残留。以上为已批准的位置与消费合同，不是新增接口。
- 本次 V0.2 只重组和精简 V0.1，需求范围、流程顺序、删除强度和 A1–A9 完成标准保持，没有待批准的行为差异。
- 正常任务自动清理的授权不代替仓库实施门禁；执行计划 V0.2 已批准并获实施全部三张 ticket 的明确授权，2026-10-01 三张 ticket 全部直接验收项凭直接证据闭合（含新建真实验证样本的正向实证与脚本修复的独立双轴评审）。依据[项目人工门禁](../../docs/agents/issue-tracker.md)，Agent triage 保持 ready-for-human，待人工复核确认。

### 7.3 Karpathy 精简与自检
