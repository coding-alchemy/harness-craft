## 1. 问题陈述

用户希望复用论文翻译经验，可靠处理 LaTeXML 原始快照，并能解释数字与单位差异。当前参考手册链能够处理数学密集文档，但直接读取 MathML 的 `alttext`、多个子图、公式组及 LaTeXML 脚注的语义尚不完整。旧预处理还可能改写 TeX 或删掉无法识别节点；其后即使源译一致，也无法证明原文已完整进入翻译输入。

现行独立对账已核对多类结构及所属关系，但普通正文尚未形成完整的有序对应，源侧公式比较会去空白。数字、单位依赖主 Agent 回源复核，缺少跨源家族的逐项定位提示。二期要解决原始输入损伤与复核定位，不能借此新增论文流程引擎，也不能让转换器的统计结果为自己授予完整资格。

## 2. 方案

将 LaTeXML 作为参考手册家族的一种明确来源表示，在原始节点上直接适配。原始 HTML、已确认论文身份、具体转换依据和实际资源进入现有源声明；解析器生成候选，独立对账重新读取原始快照与实际 Markdown，逐项证明内容、顺序及所属保持，随后复用现有拆包、翻译、人工复核、恢复/合并与交付链路。

数字辅助由现有家族核验入口显式启用，扫描当前源、译文及确认范围，报告数字、百分比、数量级和单位的原值、位置与差异。主 Agent 逐项回源处理，在既有复核记录中登记结果；没有差异仍须独立语义复核，有差异但未处置不能完整交付。

业务顺序为：只读快照与身份确认 → 原节点适配候选及转换对应 → 原始快照独立对账 → 分派与翻译 → 硬检查、数字提示及回源复核 → 当前输入绑定的恢复/合并 → 实际交付核验与证据 → 原有收尾清理。获取快照保持可选；HTML 需同版本 PDF 补图时复用现有裁剪、目检和来源证明，不等待四期候选工具。

## 3. 用户故事

1. 作为论文提交者，我希望本地快照与独立确认的题名、论文 ID 和实际版本一致，以便收到的是指定论文的翻译。
2. 作为复核者，我希望取得时间、最终 URL、快照摘要与资源结果可回查，以便识别失败下载、来源回退和版本缺口。
3. 作为论文读者，我希望公式保留原 TeX、行内/展示类型、组结构、式号与顺序，以便逐式对照原文。
4. 作为读者，我希望公式里的尖括号、与号、竖线、换行及命令不被清理，以便表达式没有因转换而改变。
5. 作为译者，我希望没有可用 TeX 的公式被逐个定位，以便补齐依据后处理，而不会漏译或猜写。
6. 作为读者，我希望正文、图、子图、题注、表格、算法及代码的顺序和所属关系保持，以便内容不会被配到错误对象。
7. 作为读者，我希望同号不同内容保持独立，官方重复内容得到保存，以便图号或题注前缀不会触发误删。
8. 作为复核者，我希望脚注引用、标签、定义及所在内容一一对应，以便整对删除或归属错换都可发现。
9. 作为译者，我希望可核验的 HTML/SVG 资源直接复用，同版本 PDF 替换有区域和视觉依据，以便不引入无来源补图。
10. 作为复核者，我希望复杂表格沿用逐源格转换映射，以便跨格、空值、公式和代码仍可逐项回源。
11. 作为译者，我希望导航、页码、渲染错误和重复浮动体的处理有具体依据，以便装饰可排除、正文不会被静默丢掉。
12. 作为验收者，我希望原始快照直接对账实际源 Markdown，以便等数换公式、正文遗漏、乱序和错归属不能被下游一致性掩盖。
13. 作为论文读者，我希望题注、官方编号、References 和术语遵循项目口径，以便既能查证出处，也能保持译文一致。
14. 作为主 Agent，我希望在每个工作包及最终范围看到数字、百分比、数量级与单位差异及源译位置，以便集中核对高风险内容。
15. 作为复核者，我希望合法换算与双语重复能逐项记录依据，以便提示不会自动判错或擅改译文。
16. 作为验收者，我希望数字提示、硬失败、未检查和未解决项分别报告，以便统计解释不能覆盖内容损伤。
17. 作为译者，我希望来源、转换、资源或口径变化后只重新核对受影响包，以便旧成果能可靠复用而不会按行号误迁移。
18. 作为交付接收者，我希望当前交付重新核验来源与复核绑定，并能在清理后访问必要输入和证据，以便历史 PASS 不被当作本次完成。

## 4. 实现决策

### 4.1 职责、接口与最小方案

| 职责 | 决策与复用关系 |
| --- | --- |
| 参考手册解析 | 在原有本地快照、可选选区、输出路径语义上增加显式 LaTeXML 来源依据输入；适配原节点，复用代码保护、表格、资源和显示尺寸能力。未选择该表示时保持原参考手册行为 |
| 原始源独立对账 | 扩展现有原 HTML 对账的来源分支，读取全新原始 DOM；增加 LaTeXML 正文、公式组、浮动体及脚注所属事实，独立扫描实际候选，不消费解析器的 DOM 或漏项统计 |
| 数字提示 | 一份共享提取与差异能力，由单页、分页、参考手册、API/DSL 及 PDF 源的既有核验入口调用；不增加第五套 HTML 解析器或数字专用工作流 |
| 身份与复核消费 | 现有源预检、统一交付身份、复核绑定、待复核项消费和发布复查读取新增来源依据及实际检查口径；保留同一计算与投影职责 |
| 工作包及收尾 | 保持现行源切片、唯一目标、恢复/合并和清理流程；人工可按约定填写记录，证据生成器属于三期 |

两种满足同一保真与验收合同的可行方案为：①原节点直接进入既有渲染及独立原始源提取；②生成记录转换位置的中间 HTML，再经参考手册解析，但最终仍独立对账原始 HTML，并绑定两段转换。选择①：少一份持久正文和一段来源映射，资源基点、节点身份与失败定位都保留在原快照。②也能满足要求，但需要持续核对中间输入及两段位置，未带来本期必要能力。两者都需要独立原始源对账、有限转换依据及现有身份消费；不以只写注意事项或旧脚本直接移植作为可行备选。

接口提议均为待批准增量：参考解析入口与参考译文核验增加 `--source-adaptation`，前者只读已确认身份/裁决输入，解析时另以 `--adaptation-output` 明确候选对应输出位置；后者读取最终来源依据，用同一来源约束核验。安全拆包、片段检查、恢复与合并也显式读取同一 `--source-adaptation`，具体投影和漏参门禁见第 4.6 节。原位置参数与家族参数含义保持，输入、候选 Markdown 与依据输出不得互相覆盖。数字入口增加 `--numeric-review` 和可选 `--numeric-policy`，后者指向实际项目约定的 UTF-8 文件，不定义换算规则语言。各入口的真实参数解析是唯一解释来源，交付记录、恢复与合并不得另行猜测这些选项。未选择数字能力时明示该辅助项未检查，保留原有人工数字复核要求；新 LaTeXML 验收显式选择该能力。

### 4.2 来源依据与身份确认（R1.1、R1.6）

保留 `reference` 家族与交付记录主版本，在源条目新增可选 `source_adaptation` 文件引用。该文件只描述当前 LaTeXML 来源、转换与裁决依据，不承担任务状态；普通 HTML 不要求虚构该文件。文件使用有限的 `version: 1`、`format: latexml` 合同：

| 内容 | 权威来源及消费方式 |
| --- | --- |
| 快照位置、摘要、资源基点、选区 | 位置来自明确输入，摘要由消费者读取原始文件重新计算；资源按声明路径目录解析，文件身份另取 realpath，不用转换器提供的摘要作为独立证明 |
| `paper_identity` | 保存预期与实际题名、论文 ID、实际版本、最终 URL、取得时间和独立确认依据；主 Agent 对照已确认论文资料与快照的可见内容/内嵌身份核对，不只信 H1、文件名或请求 URL |
| `correspondences` | 原节点身份、内容类型、所属关系、实际 Markdown 字符范围及定界转换；只描述转换结果，原节点集合、原值与关系均由独立原始源提取重建 |
| `decisions` | 仅记录具体装饰排除、经证明的同源重复表示合并、歧义裁决及提取伪影处理，含原位置、依据和结果；不能声明“忽略全部错误节点/表格/公式” |
| `resource_substitutions` | 仅在实际替换时记录原资源、已确认同版本 PDF、页/区域、裁剪口径、产物及身份/视觉依据；没有替换时不生成第二套图片映射 |
| `unresolved` | 无 TeX、身份/版本无法确认、缺资源、归属歧义等逐项位置和原因；不是供解析器随意清空的完成标志 |

输入中的论文身份与裁决先由主 Agent 独立确认。顺序为：只读 `--source-adaptation` 的身份/裁决输入 → 在库外产生候选 Markdown 与 `--adaptation-output` 指定的候选依据（复制实际适用身份/裁决并生成 `correspondences`）→ 从原快照独立核对两个候选 → 主 Agent 完成必要回源裁决 → 保存新的当前源与依据，最终源声明和核验引用这一实际依据。输入里的旧 `correspondences` 不能免去本次重建与核对；输入文件、已有有效源和依据均不就地覆盖，候选失败保旧。候选未取得分派资格，不能因文件中的“确认”文字而绕过门禁。自动生成的摘要、位置和转换清单均须在消费时重新核对实际文件。不存在“原始摘要与转换表都由同一生成器提供，因此相互相等即通过”的路径。

快照取得不纳入强制前置：已有保留快照可离线执行；取得结果记录真实状态，缺取得时间或身份依据时说明缺口，不编造。缺元数据可由主 Agent 补齐可核查事实，未能确认的来源、版本、范围或实际资源仍停止相应分派和完整交付。若另行辅助获取，只覆盖用户已确认来源与缺失项，记录最终落地内容；不会自动尝试最新版、其他站点或不同版本 PDF。

### 4.3 原节点渲染与数学保真（R1.2）

适配器按直接子节点源序遍历，每个内容节点只消费一次；识别规则限于实际 LaTeXML 节点语义，不建立通用文档 IR。MathML 节点优先取实体解码后的 `alttext`，MathML 子树的渲染字符不替代 TeX。行内/展示类型由节点自身的显示属性及已确认公式容器共同决定，冲突定位为未解决项，不能从是否含换行猜类型。

原 TeX 作为受保护内容，不进入普通正文的空白、标点和标题清理。源 Markdown 中定界符只包装原表达式：新增包装换行与原表达式内换行有明确范围，独立对账精确比较解码后的原字符串。展示公式保留内部与首尾的原空白；不沿用源对账的去空白口径，不删除命令、替换竖线或按渲染等价接受改写。标准实体编码只在 HTML 读取边界解码一次；不要求私有码位，也不能把占位符留在最终源或译文中。

来源对应分别记录公式的定界区间、原表达式内容区间及实际新增包装文字，原始对账验证原 TeX 恰好占据声明内容范围。LaTeXML 来源的源译核验在同一 `compare_math_spans` 增加原节点限定的精确比较口径：只剥离已独立确认的定界/包装，表达式首尾空格与换行也逐字比较，不执行默认块级 `.strip()` 容差。包装外及没有原节点依据的内容不进入该口径；既有普通家族默认容差保持。合法表格管道表示仍按已有真实表格范围解码，其余字符与原表达式一致；删除原边界换行、把内换行登记成包装或在式号处借字符补公式都须失败。

公式组以原组节点关联成员顺序、类型、式号及所属内容；成员可以分别输出为既有数学跨度，但不得丢失组关系。式号保留为相邻的官方文字/引用目标，通过具体对应约束其位置，不擅自往 TeX 插入 `\tag` 或改写公式。转换依据描述组到实际连续区域，独立对账同时验证每个成员和组覆盖，等数替换、改类型/式号、拆错组或乱序均失败。

**限定数学扫描差异。** 当前默认扫描器不将跨行 `$…$` 当作行内公式，直接折叠 LaTeXML 行内 `alttext` 换行或改成展示公式会违反 R1。选择在一期共享 `scan_math` 上增加 keyword-only 的已确认数学上下文，`scan_math_spans` 仍投影同一实现：只对独立原始 MathML 对账已确认的多行行内节点启用，源与译文仍用同一个扫描器和严格比较。普通 Markdown 保持原行为，来源选项不能把任意映射范围注册为公式。

限定上下文包含原节点类型、所属内容与已验证源表达式范围；扫描仍排除围栏、行内代码、转义及货币，并从实际美元定界取得候选。译侧按原公式序和所属内容定位，不搜索原表达式子串来“找到正确公式”；全部真实内容仍参加覆盖与顺序核对，不能用扩大跨度吞掉中间正文。不能唯一确定定界或归属时定位为结构歧义，不能宣称该输入已满足保真。替代方案是只采用表示层实体编码恢复换行，但现有 Markdown 数学消费者没有证明该编码可还原原 TeX 与视觉结果；它尚不是满足同一验收的可行简化。限定接口及跨行兼容属于待批准 D2，并须以实际 CLI 正反例证明没有放宽普通 Markdown。

无 `alttext`、空 TeX 或无法解释的定界冲突逐节点进入 `unresolved`。可保留诊断候选供回源补齐，但不得删除该节点、猜写 TeX 或发布合格源包；补齐后重新对账整份适用范围。

### 4.4 正文、浮动体、表格、脚注和资源（R1.3、R1.5）

| 对象 | 规范转换与独立对应 |
| --- | --- |
| 正文与普通容器 | 保留所有内容性文本，段内 HTML 排版空白按现有口径处理；代码与 TeX保护区不归一。标题仅消费真实标题节点，普通文本的 `#` 使用一期已确认边界表示，不按文本过滤 |
| 图、子图、题注 | 遍历全部图内容及子图，按实际出现复用现有图片占位和题注表示；对应记录父浮动体、子图序、图片出现及题注范围。相同资源可共享文件，正文每次出现仍保留 |
| 算法与代码清单 | 真实代码由现有代码保护及围栏输出保持字符、空白和次序；题注保留官方编号并归属本清单。非代码算法正文保留其结构，不能为消除表格或未知节点门禁转成代码 |
| 简单/复杂表格 | 简单表复用现行格位及代码表示；跨行/跨列重建继续独立使用 `table_conversions`，逐源格核对内容、跨度、空值和格内事实。新来源对应只定位浮动体与表，不另复制逐格合同或提供通用转换器 |
| 脚注 | 从原引用目标与定义节点建立真实标签配对，保持引用出现及所属关系；转换为现有脚注引用/定义表示。命名标签不能通过提取数字变成同一个 `?`，含正文、代码或公式的定义仍完整处理 |
| 渲染错误、导航与重复表示 | 渲染错误节点的内容照常进入事实，不能整类删除。导航/页码等排除必须有具体装饰依据；只有无法确认内容、结构或归属的块定位未解决，普通未知容器可按现有递归保持内容及所属时，不因标签/类名未列举而阻断。同源重复表示仅凭原节点/资源/内容及上下文证明合并，官方重复内容保留；不能只按图号、题注前缀或字节相同去重 |

独立对账核对节点与父容器关系，不只比较分类多重集。同号异图保留独立内容身份，同一图片在不同位置各有独立出现记录。优先使用能读且身份可核验的本地 HTML 资源，沿用文件有效性、SVG/CSS 递归依赖、实际路径与显示尺寸规则。参考家族原先只取 basename 的输出遇同名异资源时须明确无冲突目标对应，不能覆盖；原始资源路径仍保留供身份核验。

HTML 中可用图片照常进入现有解析期和交付级映射。需要 PDF 替换时，由主 Agent 先核对同版本、对应区域、图内文字/图例和裁剪结果；替换依据进入本期有限来源记录，现有图片映射继续保存实际输出出现、尺寸和资源身份。原始 HTML 资源确实无法取得时记录缺失及获准替换，不伪造原资源摘要；完整身份同时包含原始引用与缺失事实、已确认 PDF和替换资源，核验按已证明的替换关系闭合，不用 `None == None` 放行。无法证明同版本或区域时不替换、不完整交付。

题注复用中英对应格式，图/表/算法官方编号及交叉引用保持。References 默认保留英文，项目明确覆盖时按该口径；术语选择以项目表为先，不导入单个 LLM 项目的普遍不译清单。提取伪影保留原值、原位置、依据及处置，原快照不改；未能定性时照录并记录，确定损伤仍阻断。

### 4.5 原始快照独立对账与安全恢复（R1.4）

对账端从原始文件重新建立独立 DOM，以快照内稳定节点定位、源序与原所属关系枚举真实内容。唯一官方节点 ID 可直接定位，无 ID或重复 ID 时使用原始文档序、节点类型与父容器关系；不能按 Tag 内容相等合并不同出现。图片继续使用排除 pre 内容后的原始 `img[n]` 命名空间，其他节点对应也不采用适配后 DOM 的序号。解析侧从实际 Markdown 重建标题、正文片段、代码、公式、表格/列表、图片、题注及脚注事实，来源对应只辅助解释具体转换。两侧不共用渲染遍历和“已经输出”清单；共享成熟 Markdown 扫描及资源规则不改变源事实的独立性。

新增正文流覆盖标题前置区、普通段落、浮动体说明、未知内容性文本及 References，按内容顺序与宿主关系比较。只归一既定 HTML 排版空白和已知 Markdown 表示，保护代码、TeX、内容性字符；两侧归一范围记录明确，不用全文字符集合或内容子串包含替代相等。分段合并由具体范围解释，合并后的完整正文必须一致。原始内容节点集合与实际输出覆盖都由消费者计算，声明漏节点、范围交叠、无解释的输出、错归属及无法解释重复均失败。

每个诊断指出原快照、选区、节点/容器、内容类型与实际源 Markdown 位置；摘要计数只供阅读。允许的组拆分、子图展开、逐表转换、装饰排除和重复表示合并须逐项解释且验证结果，不能把映射中的排除项从原始基准直接删掉再自证。

解析与重新解析均先在工作区外生成候选 Markdown、对应与映射，通过适用对账和资源证明后才接入实际源路径。失败保留旧源、旧映射、旧工作包与有效证据；更新时先保存新旧内容差异和受影响对应，再按现行恢复合同重建预期，不能先覆盖旧源包。通过源位置身份与内容判断包是否受影响，无法唯一对应时交主 Agent 明确处理，不按行号迁移译文。无关有效包仍须以当前事实复验后复用，不默认整篇重译。

### 4.6 当前交付身份与有限合同扩展（R1.6）

源声明中的 `snapshots` 始终指向原始 LaTeXML；不得把 clean HTML 当唯一原文。保留 `source_version`、`section_id`、多快照连续 `range`、`per_stem_map`、`table_conversions` 与 `covers` 含义；新增来源依据只补原接口缺少的来源表示、实际论文身份和具体转换。多快照每份均有自身对应与资源基点，不用首个页面替全部来源。

现有源预检须读取新增依据、独立核对原始快照/范围及论文身份、检查逐节点对应和未解决项；原始图片事实仍从原快照选区枚举。HTML 有效资源沿用既有身份；实际 PDF 替换依照第 4.4 节核对来源关系，并将其声明 PDF、裁决及资源读入同一事实。原 TeX、正文对应、表转换与资源替换任何确定损伤都不能由人工 `closed` 覆盖。

统一身份构造增加来源依据、实际适配器及有关检查依赖的当前内容身份；新增真实参数及其指向文件由各核验入口的实际参数解析纳入检查事实。`source-reconcile`、`semantic` 以及适用的导出前就绪检查从同一事实按实际目标覆盖投影，发布前重算同一身份。不给 `reviews` 增加另一种 LaTeXML 通过标志，不另建摘要计算器或漂移台账。新来源有必需依据却缺摘要时直接拒绝，完整记录也不能代替实际回源复核。

数学来源上下文必须贯穿全部消费者。拆包先通过当前源预检与原始快照对账，再将已确认的公式内容/定界范围交给同一共享扫描器建立安全切点，多行行内、组关联及现有脚注依赖不被切开。既有包正文仍为原源切片，frontmatter 仅附加 `source_adaptation` 引用，保留现有 `source_char_start/end` 和片段摘要；不把授权 span 列表复制到包内。片段检查、恢复、合并显式接收同一来源依据，重验其当前源对应后按包字符范围投影实际原节点/包装/类型，再以局部偏移调用同一扫描与精确比较。原范围落在两包、对应漏项或包声明此来源却漏参数/参数不符均拒绝，不降回默认扫描；最终装配从完整源范围重新核验全部事实。

当前 CLI 尚无这些参数，这是二期必须补齐的限定增量，不依赖三期生成器。主 Agent 可手工提供同一来源记录与新增参数完成拆包到交付；三期项目上下文只引用此记录，不能生成另一种数学授权。元数据引用及历史映射不是分派/复用证明，每次准入仍验证当前原始源与来源依据，失配先定位受影响范围。

限定形态参与 PDF 导出时也必须进入同一消费链。翻译加导出复用现有 `--translation-record` 的当前翻译就绪核验，按实际输入取得已经独立核验的 LaTeXML 来源上下文；独立导出与 PDF 核验可显式使用同一 `--source-adaptation` 引用，核对实际输入/范围，不自动搜索相邻记录。沿用现有 Markdown 渲染与 KaTeX，只让受来源约束的数学节点消费共享扫描事实及原类型，不由旧渲染分类的 `.strip()` 或环境启发式改写原表达式、把行内改成展示。导出报告保留实际原表达式、包装、来源类型和渲染条目；独立核验重读当前 Markdown与来源上下文，再对最终 PDF 数量、类型、实际绘制与视觉结果核对，不能仅信导出报告中已有条目数。运行期间依据漂移拒绝替换旧 PDF；未带来源的普通独立导出行为保持，存在新限定形态却未提供可核验上下文时不声称该形态已保真。

逐包证据继续使用当前源/目标/资源、检查器和 `review.semantic/unresolved` 合同；对新增能力，相关适配事实及规则进入待批准的公共 `check_policy` 扩展。它投影本包实际涉及原节点、转换/裁决、适配器与数字口径，原始整份来源对账是本次准入前置；不能把全篇快照或整份适配记录的摘要强塞每个包导致无关包失效。最终交付仍重验完整来源身份。二期人工可填写同一记录，三期只补生成与消费便利，不是二期验收前提。

完整交付按任务实际模式运行现有交付入口：分列硬不变量、原始源全量对账、语义复核及适用 PDF/视觉状态。证据按现行合同进入项目证据目录，交付级图片映射保持原固定位置，不扩大交付根允许清单。原交付成立后执行现行收尾，保护快照、源/译包、转换依据、独有口径与必要资源；清理后真实阅读、导出输入、恢复和证据消费均须保持。

### 4.7 数字与单位提取、处置和消费（R5）

显式启用的数字辅助读取当前家族已确认的源 Markdown 与译文，包范围只读包正文，最终范围来自实际核验有序输入；不能从缺失文件或实收包反推范围。共享扫描器提供代码、公式及结构区间，数字提取按这些真实区间标注上下文，检查结果不修改它们已有硬规则。代码/公式中的数字可以报告为受硬检查保护的事实，不把它们当可换算正文；URL/标识符中的数字单列上下文，不把所有阿拉伯数字都判作数量。

提取保留原始数值写法、正负号、小数/指数/千位形式、百分比符号、紧邻单位与数量级词，以及文件、行/字符位置、章节/格位/题注/脚注等已知宿主。使用有限的常见数字与单位写法作为定位规则，中文数量级、英文 magnitude 和符号单位均保留原 token；不能可靠判断的写法显示未检查或待确认范围，不宣称全自然语言单位识别。只用精确原值及明确词法形式进行统计，不自动计算换算、推断等价单位或扩大单位词典为规则平台。

输出同时保留完整位置清单和源/译差异多重集：差异项列出源缺失/译新增、数量级或单位相关上下文及相应位置；同值不同单位的 token 差异可提示，但相同 token 被调换归属可能仍无统计差异，须独立语义复核。逐字保留得到零统计差异，合法 `104 billion` → `1040 亿` 或双语题注重复仍有提示，主 Agent 依据项目数字口径回源说明，不为其建立自动豁免白名单。

`--numeric-policy` 指向本次实际适用的既有项目数字约定；工具记录路径、当前内容摘要与适用范围，作为复核上下文，不把说明文本执行成规则。未给出文件时使用明确的“保留原值、报告差异、不自动判换算”辅助口径；存在其他已确认项目口径时必须显式引用，否则不能把该口径用于关闭差异。相关约定或工具口径变化按当前绑定重新复核，历史说明不可补摘要追认。

每个本次差异生成定位 ID，内容包含检查实际源/译角色、确认范围、原值/单位、出现序号和当前源译位置；ID 来自本次扫描，不从主 Agent 的闭合清单反向生成。ID 用来逐项对应，不承担跨版本稳定状态。主 Agent 回源确认真实问题并修译后重跑，或在既有语义复核的 `items` 列出仍存在的合法差异 ID，并在 `note` 保存原值、位置、项目口径与处理依据。脚本只核对项覆盖和当前绑定，不解析 `note` 推断换算正确，更不能自动写 `closed`。

最终交付将这些 ID 进入已有待复核项容器的 `semantic` 分类，并把既有按目标、类别和次数的 `items` 消费从 PDF 扩展到实际译文输入：存在本次未覆盖项、非 `closed`、缺绑定或旧绑定不符均拒绝完成；别的目标、历史扫描或一条“全文已复核”说明不能代闭。数字零差异也不省略独立语义复核。包内未处置项进入现有 `review.unresolved`，主 Agent 全部实际复核后方可写 `semantic: done`，相关检查参数、项目口径及适用来源事实按第 4.6 节绑定；包资格不能代替最终逐项消费。

硬失败、未检查、未解决与统计提示分别输出。数字合法差异被处理不覆盖公式、代码、标题、图片、脚注或强 token 的失败；数值/单位已真实改错时必须改译文、重新检查和复核。脚本不承诺发现同数换归属、否定、条件或全部语义损伤，主 Agent 全量回源职责保持。

## 5. 测试决策

### 5.1 已确认主入口与先例

主验收复用“原始 LaTeXML 本地快照 → 参考解析与独立源对账 → 译文核验 → 当前交付”的现有 CLI。用户已确认该边界；只测试外部输入、实际输出、诊断、分派/复用资格和最终证据，不断言适配器私有遍历或自由文本措辞。底层用例只用于公式边界、归属和身份缺陷定位，复用现有公式扫描、结构不变量、参考手册、恢复/合并和交付证据测试。

数字辅助在所有现有家族的真实核验入口执行，并覆盖包与全量确认范围；PDF 用现有裁决后源 Markdown及 PDF 源校验，不另造文本权威。真实 LaTeXML 论文至少一份，在执行前固定可读路径、独立身份、版本和范围。已保留 DeepSeek 快照是候选，当前失败及历史 clean 输出不是正向 golden，须从原始内容完成实际复核。

## 6. 不纳入范围

- 网络抓取平台、批量论文检索、固定通道回退、站点限制绕过、OCR、LaTeX 源包构建或 PDF 公式自动提取/重建。
- 通用文档 IR、论文专用调度/状态库、第二套身份或复核记录、全局适配器注册及自动复杂表格转换器。

- 自动换算白名单、数字提示代替语义复核、按行自动迁移译文、包级/全局机器 PASS 授予人工完成。
- 三期生成器、四期 PDF 候选工具及其 D4 扩展；二期保持既有人工记录和同版本 PDF 资源处理即可独立验收。
- 自动修改外部论文项目、扩大根目录允许清单、迁移历史证据、增加产品版本或发布；本轮不写执行计划或实现代码。

### 7.2 机制重审与待批准差异

扩展来源记录与人工待项消费触发机制重审。留痕设计第 9 节已证明：正常多来源要按实际目标完整覆盖，局部补身份却不贯通绑定/发布会使第二来源、资源或口径变动沿用旧结论；全局绑定又会误撤销不相关目标。二期的新失败场景是适配后源一致而原 MathML/正文已丢失，或数字报告有未处置项却仍凭语义 `closed` 完成；根因是原始事实与新待项尚未进入现有消费者，不是需要另一套状态系统。

可行收敛方案是在当前源事实中补充 LaTeXML 对应，将有限新依赖进入统一身份，并将既有待项消费扩展到语义目标；也可在适配器、包恢复、交付和发布各自补检查并保持同步，但会重复来源/口径构造及项覆盖。选择前者。保持 source 与 semantic 独立回源复核；脚本只判断事实和记录资格，不把人工判断程序化或增加任意复核标志。

| 待批准差异 | 影响与兼容口径 |
| --- | --- |
| D1：有限来源依据及原始对账扩展 | 新 LaTeXML 来源必须提供 `source_adaptation`，对应 facts/资源/适配器身份进入同一绑定；record 主版本与 reference 家族不变，包只附加同一来源依据引用。普通已支持 HTML 不强制补该文件或参数。历史 clean 输入不能自动取得 LaTeXML 资格，可保留成果，但须补原始依据并实际重核受影响范围 |
| D2：LaTeXML 原 TeX 精确保持与限定多行行内扫描 | 新来源不沿用去空白、块级首尾 trim 或改类型处理；只有独立原始节点确认的范围可开启共享扫描器限定选项，贯穿安全拆包、片段检查、恢复/合并、最终核验及适用 PDF 导出/独立核验。普通默认跨行行内行为与既有家族保持。旧源因适配/检查口径变化须实际复验，不补签；无法唯一定位的输入仍有明确缺口，不声称全部支持 |
| D3：数字辅助与语义待项消费 | 各族能力显式选择，未选择则明示未检查并保持原人工数字职责，不以缺新数字字段拒绝所有存量项目。选择后本次差异 ID 须由同目标当前 binding 的 semantic.items 逐项闭合，既有 reviews 格式不变；普通 `closed` 或 note 不再能覆盖该能力发现的未处置项 |
| D4：适用包口径绑定 | 与三期 R6 共用最小 check_policy，数字真实参数/实际约定与 LaTeXML相关片段转换投影参与包资格。二期可人工填写，不依赖生成器；启用新能力而旧记录缺适用口径则待复核，不自动重译、不把全篇映射摘要绑定所有包。三期生成器不能重新定义该口径 |

以上均为设计提议，用户确认四期划分、编写设计及测试入口不等于批准这些行为与持久合同。真实样本身份与全面复核尚待执行时固定；旧下载政策与历史成功率未重核，不用作通用保证。本轮没有已实施的未经批准变化，批准需求和设计后才能编写执行计划，计划批准及明确实施授权后才能修改实现。
