## 1. 核心结果与评审边界

用户可以把论文实践中的通用能力用于当前 Skill：LaTeXML 论文不因预处理丢掉公式、浮动体或正文；合法公式与关键标识符得到可靠检查；任务上下文、复核证据和目录无需每个项目重新拼装；批量完成仍依据当前交付事实。

用户已确认四期划分，并要求分别编写需求。本文保存共同目标、评审依据、公共合同和范围边界；各期文档保存对应功能与直接验收的唯一正文。分期不削减原需求及验收强度。当前只编写需求，不追认素材中的历史授权，不把旧项目的 PASS 或命中率作为当前能力验收。需求与设计获明确批准后才能编写执行计划。

目标执行者是主流大模型及其宿主工具，脚本负责确定性处理，主 Agent 负责来源、语义、术语及视觉裁决。全部新增能力继续使用现有源家族、检查和证据链，不另建论文工作流引擎。

## 2. 当前事实与采纳依据

## 3. 必须保留的合同

1. 原始快照只读且可回查；解析只读本地输入。来源、版本、范围不能确认时停止；不自动换成最新版或其他来源。
2. 分派前独立核对源内容与结构；计数相等、源译相等或脚本 PASS 均不证明上游提取完整及语义正确。
3. 代码、公式、标题、图片、脚注和已裁决强 token 的既有硬检查保持；合法结构转换使用源位置与实际转换对应，不提供整类免检。
4. PDF 仍按勘察 → 主 Agent 裁决 → 物化 → 独立对账执行；候选不授予权威资格，OCR、位图自动提取和公式自动重建的现行边界按第 5 节处理。
5. 源、译文、资源、规则或检查口径变化后按既有绑定使受影响旧复核失效；不重算摘要后追认历史 PASS。不相关有效包继续按恢复合同复验复用。
6. 项目术语优先、共享库与预设显式选择、子 Agent 只写唯一译文目标、硬检查与源对账及语义/视觉复核分层、收尾清理与恢复保护继续适用。

## 4. 功能需求与直接验收

P0 表示已复现的内容漏检或误判；P1 表示有当前缺口的保真或高频辅助能力；P2 表示特定输入的复用便利。优先级和分期编号均不构成执行授权。

R3 的匹配边界、有效计数和源中未出现项告警属于一期；显式文件清单、合并去重及可选 PTX/ISA 预设属于三期，继续使用一期同一计数语义。

一期 R4 根据四类入口的实际位置参数角色澄清官方标题输入的互斥范围，该解释仍随一期需求待确认。

二期依赖适用的一期公式/标题核验，但可复用现有人工复核流程完成验收，无需等待三期证据生成器。三期的 LaTeXML 场景使用二期来源合同，已有源家族无需等待新增家族；四期沿用既有 PDF 勘察与人工裁决流程，不以二期 HTML 适配或三期工具作为硬前提。第三、四期的先后可按实际 PDF 使用频率调整；具体依赖和执行安排留待获批后的设计与计划。

各期均须在实际消费与交付链路完成适用回归和直接验收，不把集成验证集中留到最后。PDF D4 公式物化差异在第 5 节及四期文档单列，四期划分确认不等于该差异已批准。

## 5. 假设、待批准差异与不纳入项

- **新增范围待批准：** LaTeXML 的端到端来源链、辅助生成工具、数字复核及可选预设均为本次需求提议，不是当前 Skill 已具备能力。R1 的原始快照对账须进入既有交付身份和复验，不能只在预处理脚本中打印 PASS。
- **PDF D4 差异待批准：** 现行 [PDF 源需求](./2026-09-26-pdf-source-translation-requirements.md) 不承诺公式自动提取/重建。R8 的公式物化只建议扩展为“候选文本 + 人工裁决 + 独立对账”，不自动采纳或猜测修复；未批准前维持既有人工处理与 pending 合同。
- **兼容影响：** R2/R3 修正会改变部分公式切分、计数及硬检查结果；解析源或检查器身份变化后，沿用既有复核失效规则，不给旧证据自动迁移资格。新增便捷输入不取消原逐项参数，旧项目只按明确范围重新核验。
- **证据限制：** 旧抓取的站点政策、下载通道排序、固定 glyph 偏移、单栏命中率和已删除脚本只作为经验线索；不写成通用默认或验收事实。不需要新增网络获取能力来验证本次离线缺口。
- **不纳入：** 按行自动迁移译文、归档后清空半成品、固定重试两次转主 Agent、宿主错误码与额度调度、通用块回填/句式字典/增量计数平台、原文错误批量汇总、LLM 共享词库、全部输出行重排格式。已有恢复、代码回填、人工复核、证据与清理解决其必要部分，其余缺乏足够通用收益或安全对应证据。
- **待复现而不立项：** 嵌套括号标题问题。归一化副本图片核验已经有 `--image-map`/`--delivery-root` 路径，先使用现有独立来源证明，不增加免检参数或另一套归一化通道。

## 6. Karpathy 精简与自检

1. **基线：** 第 2 节保留已复现问题、已覆盖合同和历史经验的区别；各期对照其现行入口与限制，继续复用共享核验、原始源独立对账、PDF 清单、恢复/合并证据、交付身份、目录消费和术语读取。
2. **假设与差异：** 用户确认的是四期组织，各期需求尚待评审；新增能力、PDF D4 与证据失效影响仍在第 5 节显式列明。本次未实施行为变化，未复现问题和历史常数不升级为通用要求。
3. **最小方案：** 按核验、LaTeXML、工作流辅助、PDF 候选分开审阅和验收，复用现有入口；只写注意事项不能修复已复现漏检，复制旧整套流程会重复规则并沿用损伤。具体算法、接口及文件拆分由后续设计确定。
4. **删除审计：** 原 R1–R11 的功能和验收正文移到对应分期，R3 按核心计数与显式复用分属一期、三期；总览只保留公共合同、边界和入口，避免两份完整权威正文。原有撤回项继续不纳入，分期不降低保真、独立核验与完成条件。
5. **直接验收：** 分期文档保留各项正向结果、损伤反例及真实链路要求；核心证据仍是原始内容逐项保存、真实损伤被拒绝、当前复核资格可回查和实际链接可用。文档存在、格式正确、旧测试或旧项目 PASS 不能替代这些结果。
