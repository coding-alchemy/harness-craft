## 1. 用户结果与范围

下一次翻译 NVIDIA 这类结构密集的 API 文档（PTX ISA 单页手册、Tile IR 多页规范）时，执行者用共享安装就能把完整快照解析通过，不必复制组件改源码，也不必写运行时包装；对账失败时第一屏就能看到根因，并能看到被拒的解析稿；截断的快照在解析时就被拒绝。

现状：PTX ISA 9.5 全文解析报 177 条差异，全部来自 R1–R5 五处组件缺陷；Tile IR 13.4/13.5 共 28 页里 6 页因字面 `$` 阻断（R6），截断的 13.4 operations 页照常通过（R7）。两个会话分别复制 47 个脚本改源码、写运行时包装才往下走。

范围只含组件行为。改动落在 `_source_reconcile.py`、`_html_fidelity.py`、`_verification.py`，它们计入各核验入口的检查器身份（`verify_delivery.py:482-513`），重装后已闭合的复核要重新闭合。重新解析的 HTML 项目（API、单页、分页、参考手册四个家族），解析稿表格格内的 `|` 写成 `\|`，正文里紧贴标识符、不配对的 `$` 写成 `\$`；API 项目的列表项与定义条目里还会多出锚点行。旧译文要同步。LaTeXML 论文的解析与对账不变。批准本文只确定目标行为，不授权设计或实施。

## 3. 需求

### R1 定义条目有多段时不漏项（P0）

来源：问题记录缺陷 A。

- 现状：dd 里有两个以上段落时，解析稿在定义区里用空行把段落隔开，Markdown 写法正确。源对账读定义列表时，遇到第一个不以空格开头的行就结束定义区，空行也算（`_source_reconcile.py:1831-1833`），这个 dl 后面的术语全部漏读。有序比对从漏读处起逐项错位，PTX 全文的 157 条定义列表差异都由第 41 项 `sm_1x` 一处漏读引起。只要 dd 有两段就会触发，两段 dd 的最小样本同样报 2 项对 1 项。
- 要求：定义区里的空行不结束定义区；定义区照旧由非空且不缩进的行或结构标记结束。
- 验收：add 一节切片 8 项对 8 项通过；两段 dd 的最小样本通过；删掉 dd 第二段的损伤样本报定义列表差异。

### R2 列表项与定义条目里的带 id 表格写出锚点（P0）

来源：问题记录缺陷 B。

- 现状：解析在顶层块入口写对象锚点（`parse_api_html.py:148-149`）。锚点核对要求哪些对象有锚点，由 `source_anchor_ids` 认定（`_api_navigation.py:132-143`）：表格不论是否嵌在列表里都要锚点；段落嵌在列表项或定义条目里时不要求（`:47-49`），提示框只在嵌在列表项里时不要求（`:60-62`）。列表项和定义条目里的块由 `rich_container_lines` 输出，表格分支直接输出表格、不写锚点（`_html_fidelity.py:1087`），锚点核对报“缺来源对象锚点”，指向这张表的链接没有目标。PTX 全文 75 张带 id 的表格里，只有第 13 章 Table 75（`changes-in-ptx-isa-8-8-family-specific-features`）在列表项里，正文有 2 处链接指向它。
- 要求：锚点核对要求锚点的对象嵌在列表项或定义条目里时，同样写出锚点，位置紧接对象，链接能跳到对象。直接嵌在列表项或定义条目里、自身带 id 的 `<pre>` 除外（D2）：不写锚点，解析照旧报“缺来源对象锚点”，不静默通过。Sphinx 把代码块的 id 写在外层 `div.highlight-*` 上，这种代码块现行版本已写锚点。
- 验收：`changes-in-ptx-isa-version-8-8` 一节切片通过；把锚点挪到表格之后的损伤样本报锚点错绑；直接嵌在列表项里、带 id 的 `<pre>` 样本报“缺来源对象锚点”。

### R3 表格格内的 `|` 不破坏列界（P0）

来源：问题记录缺陷 C。

- 现状：普通 `[TABLE]` 行把各格文字用 ` | ` 拼成一行（`_html_fidelity.py:1301`、`:1309`），格内文字与行内代码里的 `|` 原样写出；源对账按 ` | ` 切格（`_source_reconcile.py:1731`），格数比源多。PTX 常量表达式规则表第 17 行的 `` `& | ^` `` 切出 6 格（源 5 格），lop3 表头的 `Oper 254 (ta | tb | tc)` 切出 11 格（源 9 格）。显式网格模式已把格内 `|` 写成 `\|`（`_html_fidelity.py:1338`）。只在解析端转义还不够：源对账按字面读 `\|`，格内代码 `& \| ^` 与源里的 `& | ^` 不一致。
- 要求（四个 HTML 家族，D4；LaTeXML 论文的表格写出与对账不变）：
  1. 解析稿表格格内的 `|`（文字与行内代码）写成 `\|`。
  2. 源对账读 `[TABLE]` 行时把格内的 `\|` 读作 `|`，再与源比较。
  3. 译文真实 Markdown 表格格内的 `|` 同样写成 `\|`，翻译约定（`references/translation_conventions.md:15`）从公式扩到行内代码与文字；PDF 里显示为 `|`。
- 验收：两张表的切片通过；含这两张表的样本译文导出后，PDF 显示 `& | ^` 与 `Oper 254 (ta | tb | tc)`；改动格内一个字符的损伤样本报表格差异。

### R4 只含代码的单列表格按单列表格读（P0）

来源：问题记录缺陷 D。

- 现状：格里只有代码时，解析稿把这一格写成一个空格，代码写在表后的 `[TABLE-CODE r=行 c=列#序]` 下。源对账读到首行的空格位时登记了这一行，但没有进入单列模式（`_source_reconcile.py:1710-1716`），读到第二行 `T1` 时就结束了表格（`:1744-1752`）。PTX `causality-axiom` 一节的 CoWR 表（1 列 4 行）因此只读出 1 行，表后 3 个格内代码标记找不到所属表格，报 3 条孤儿标记、行数 4 对 1 和 3 条格内代码归属不一致。同一节的双列 MP、SB 表不受影响。
- 要求：首行是空格位的单列表格按单列表格读，行数与格内代码归属与源一致。
- 验收：`causality-axiom` 切片通过；把 CoWR 表一个格内代码标记的行号改错的损伤样本仍报归属差异。

### R5 定义条目里的列表项有多段时不丢续段（P0）

来源：问题记录缺陷 E。

- 现状：dd 里嵌着列表、列表项有多段时，解析稿把续段写在列表标记的同一列（`_html_fidelity.py:1066-1068`、`:1138-1140`），与 dd 外的列表写法相同。源对账重建列表时，`[DEF-LIST]` 开启定义区（`_source_reconcile.py:1558-1566`）；列表标记的缩进比定义区深超过 2 格时不结束定义区（`:1567-1569`），之后的续段被当作定义内容跳过（`:1570-1576`），列表项只剩首段。PTX `warp-level-matrix-instructions-mma` 一节 5 条、`warp-level-matrix-instructions-sparse-mma` 一节 4 条，都是精度与整数运算说明列表，两节各自单独切出都能复现。
- 要求：dd 里列表项的续段计入该列表项；列表结束后的 dd 段落仍是定义内容，不并入列表项。
- 验收：两节切片通过；dd 里“列表后接段落”的样本，段落不并入列表项；删掉一个列表项续段的损伤样本报列表项差异。

### R6 HTML 正文里不配对的 `$` 按字面文字处理（P0）

来源：问题记录缺陷 F。

- 现状：数学扫描（`_verification.py` 的 `scan_math`）把同一行没有配对的 `$` 判为未闭合的行内公式，货币排除只认数字开头的金额（`_verification.py:435-447`）。源对账对 HTML 文本节点（`_source_reconcile.py:524` 的 `_literal_math_issues`）和解析稿都做这项扫描。NVIDIA Tile IR 规范在正文和链接文字里用单个 `$` 写元变量和操作名（`$pointerType`、`$value`、`cuda_tile.preview$call`），这些 `$` 都不配对，13.5 有 5 页、13.4 有 1 页因此在解析时被阻断。导出用同一扫描，遇到时拒绝导出（`export_pdf.py:2918-2921`）：知识库现有 Tile IR 译文 `06_Type_System.md` 有 1 处（L591 `$pointerType`）、`09_Operations.md` 有 10 处，现在重新导出会被拒。
- 要求：
  1. HTML 正文与链接文字里不配对、紧贴标识符的 `$`（`$` 之后至少两个字母、数字或下划线，或 `$` 之前紧贴其中之一，如 `$pointerType`、`cuda_tile.preview$call`）是字面文字，解析不因它阻断，解析稿写成 `\$`，源对账按字面 `$` 比较（D1、D3）。`$x` 这类照旧按残缺公式阻断；`$ 5` 在现行扫描中本就不视为数学候选，继续保持原样，不新增阻断或转义（D3，2026-11-22 澄清）。四个 HTML 家族同样处理（D4）。这与表格格内 `|` 写成 `\|`（R3）是同一种处理。
  2. 译文保留 `\$`，翻译约定加一条；导出后 PDF 显示 `$`。Markdown 里不带反斜线、又不配对的 `$` 照旧报未闭合，数学检查不放松。
  3. 配对完整的 `$…$`、`$$…$$` 与货币规则不变。
- 影响：知识库现有 Tile IR 译文有 11 处不带反斜线的 `$`，按本条规则仍报未闭合，重新导出前要补成 `\$`。
- 验收：Tile IR 13.5 全部页与 13.4 全部完整页不加包装解析通过；HTML 正文里的 `$x` 照旧阻断分派，`$ 5` 保持非候选现状、原样通过且不新增转义；保留 `\$` 的样本译文导出后，PDF 原样显示 `$pointerType`；删掉 `\$` 的反斜线，或删掉数学文档译文里一个公式的闭合 `$`，导出都报未闭合。

### R7 截断的整页快照在解析时被拒（P1）

来源：问题记录缺陷 G。

- 现状：Tile IR 13.4 `operations.html` 只有 81,920 字节（正好 80 KiB），截断在一段 `<pre>` 中间，没有 `</html>`。HTML 与解析稿截断在同一处，源对账通过，现行版本解析退出 0；页里的操作锚点只有 9 个，13.5 同一页有 110 个。解析入口读入快照后直接解析（`parse_api_html.py:284-285`），不检查快照是否完整；组件不负责下载。知识库与 `machine-learning.local` 里 397 个 HTML 文件（不含图片、证据与导出目录）中，以 `<!DOCTYPE` 或 `<html` 开头的完整文档 342 个，只有这一页缺 `</html>`；其余 55 个是片段，本来就没有 `</html>`：CUDA PG 项目生成的 52 个 `<article>` 选区片段，以及 cuTile Python 缺陷盘点里的 3 个片段样本。
- 要求：各 HTML 快照解析入口（`parse_api_html`、`parse_single_page_html`、`parse_paginated_html`、`parse_reference_html`）遇到以 `<!DOCTYPE` 或 `<html` 开头、却缺少 `</html>` 的快照时报截断，给出文件与字节数，不写出解析稿；片段输入照常解析。这四个入口的源码里都没有快照完整性检查。
- 验收：13.4 `operations.html` 解析报截断；另一个入口用截断的论文快照样本同样报截断；13.5 全部页、知识库现有完整快照与 CUDA PG `pagesite/` 片段照常解析。

### R8 API 解析对账失败时第一屏能看到根因（P1）

来源：问题记录 §4、§6。

- 现状：`parse_api_html` 对账失败时直接退出，不写解析稿（`parse_api_html.py:299-302`）。差异按事实流逐条打印，PTX 全文 177 条里 158 条是第 41 项一处漏读引起的错位，第一行是排在最前面的孤儿标记，不是根因。执行者只能自己拼代码重现解析稿，拼法与解析入口稍有不同，结果就不一样：问题记录给出的拼法生成的 CoWR 表首格是压平的代码文字，实际参与对账的是一个空格，照它找不到 R4 的原因。导出与 PDF 核验已把全部差异写进 work-dir 的 `reconcile_diffs.txt`（`verify_pdf.py:5626-5638`），API 解析入口没有。
- 要求：
  1. 对账失败时，第一屏按差异类别列出条数，每类给出第一条。
  2. 全部差异与被拒的解析稿写到旁路文件；解析稿文件名标明未通过，内容与参与对账的文本逐字节相同；原输出路径照旧不写。
  3. 拆包、合章与 API 核验拒绝把被拒解析稿当解析稿用。
- 验收：PTX 全文失败的第一屏不超过 40 行，定义列表一类的第一条是第 41 项 `sm_1x`；旁路解析稿与解析入口实际对账的文本逐字节相同；把它传给拆包被拒。

## 4. 决定

| 编号 | 问题 | 决定 |
| --- | --- | --- |
| D1 | Tile IR 这类文档正文里不配对的单个 `$` 怎么处理 | 2026-11-20：解析稿写成 `\$`，译文保留，Markdown 侧的数学检查不放松（R6）。不选放宽扫描：数学文档里残缺成 `$W_q`、`$QK` 这种只剩标识符的公式会查不出 |
| D2 | 直接嵌在列表项或定义条目里、自身带 id 的 `<pre>` 要不要写锚点 | 2026-11-21：不写，解析照旧报“缺来源对象锚点”（R2）。这种 `<pre>` 在列表里被换成围栏文本、没有留下节点，要写得改三处共用的块序列格式；218 页 API 快照里没有这种代码块 |
| D3 | HTML 正文里哪些不配对的 `$` 算字面文字 | 2026-11-21：只算紧贴标识符的，`$x` 照旧阻断（R6）。全部放行会把被 `<em>` 等标签切开的公式静默当成文字；Tile IR 两版的 19 处字面 `$` 都紧贴标识符。2026-11-22：实测确认 `$ 5` 在现行扫描中不产生 issue，用户批准澄清为保持非候选现状，不新增阻断或转义 |
| D4 | 单页、分页、参考手册 HTML 家族是否也写 `\\|`、`\$` | 2026-11-21：四个 HTML 家族都写，LaTeXML 论文不变（R3、R6）。对账读回 `\\|`、放行字面 `$` 的代码四个家族共用；只改 API 时，其他家族表格里的源文字 `a\\|b` 会被新对账器误报 |
