## 1. 问题陈述

R1/R3/R9 与此前 PDF 能力已合入 main；当前剩余增量主要为 R4 交付证据与 R7 布局检查。本轮针对身份覆盖、映射位置合同及对应失效文档口径完成重审，不重开已迁移机制，不把 R4/R7 已有实现等同于完成。基线为 `zn_dev` 的 `66609d8723f4bd0874e5bc11de11e41c8f5d858b`，main 为 `757dc89`。本轮具体决策、兼容差异与直接验收见 §9；原 R1–R9 与 A1–A28 合同保留。
## 2. 解决方案与现有边界

沿用“快照 → 解析 → 交付映射 → 导出 → 独立核验”，补充回补入口与最终留痕检查。用户仍取得原始 Markdown、原图和额外 PDF，交付说明明确尺寸状态并指向持久证据。目录规则并入现有交付记录与完成检查；分页只改代码渲染及对应核验，不增加目录迁移 CLI、分页配置系统或新的 PDF 后端。

## 4. 实现决策

### 4.1 公共数据与兼容规则

保留显示映射 `version: 1`，附加字段不改变已有含义。每次真实图片出现恰归一类：确定尺寸、源无约束、无法确定；未覆盖项由实际输入与映射差集生成，不能以 `undetermined` 掩盖漏图。

| 对象 | 保留的合同 |
| --- | --- |
| 解析期映射 | 源快照及摘要、节点、图片出现序号、宽度或原因；推导尺寸附计算依据 |
| 交付级确定项 | `markdown`、`occurrence`、`image`、`sha256`、`width`、`source`；来源含快照摘要与独立资源身份 |
| 交付级未确定项 | `undetermined` 保留同样的定位和身份，附 `reason_code`/`reason`，区分 `no-source-constraint` 与 `unresolved-size` |
| 未覆盖项 | 原因 `missing`；空映射及错章条目不能证明覆盖 |

路径仍相对映射目录解析；两类条目均核对出现、路径与摘要，重复冲突、未知主版本、非法类型或尺寸拒绝。`sha256` 保护交付字节，来源身份沿用递归覆盖 SVG/CSS 依赖的既有函数。来源身份为四元组（HTML 文件 realpath、快照摘要、资源解析上下文 `resource_base`、源节点）：文件身份与资源上下文职责分离——文件级符号链接别名是同一文件，但相对资源按声明路径的目录解析；`resource_base` 为声明路径目录的 realpath，只归一目录自身的符号链接与平台别名，目录别名即同一上下文。仅导出可继续使用旧有效映射，无来源说明不能反推“源无约束”；新回补必须有独立源证明。

### 4.2 解析保存与高度推导（R1、R3）

四类解析保留当前产物位置，有图即保存确定项或未确定项，无图不要求空映射。临时路径警告共用真实路径与宿主临时根包含检查，覆盖符号链接和平台别名，不用字符串前缀误判；警告不改变调试退出码。

有效宽度优先，保留百分比参照。仅在无有效宽度、无未解释布局冲突且源资源比例可靠时，由内联 CSS/HTML 高度推导宽度：px 原值，pt 乘 `4/3`，无单位 HTML 整数按 px；宽度为高度乘源固有宽高比。未知比例、非法值、外部布局或冲突明确未确定，不用交付图尺寸猜源约束。

普通翻译与 PDF 安装清单均保留 `Pillow>=12.3,<13`（Python ≥3.10），只读位图元信息；SVG 使用有效固有尺寸或 viewBox。不全量解码、不降采样；记录原高度及单位、固有比例、换算结果和源身份，已有 CSS/SVG 身份与离线安全检查保持。

### 4.3 回补入口与绑定（R3）

保留 `rebuild_images_display` CLI：接收 `--manifest`、`--output`、`--work-dir`；需要补抓时显式使用 `--fetch-missing`。默认只读本地输入，工作目录在工作区外。

回补清单是本次明确范围的输入，不是项目状态库：

- 清单版本、源版本、源家族、按权威顺序排列的页面/选区；每项包含快照位置、解析产物目标、最终 Markdown 归属与图片出现区间。
- 缺失快照/资源的已确认同版本 URL 与保存位置；可用时保存预期摘要。抓取仅覆盖清单声明的缺失项，不爬取新范围；重定向导致版本/来源不可确认时停止，完整快照不重抓，失败下载不覆盖旧文件。
- 沿用现有全局源到交付对应关系。无法由固定源序和目标区间唯一确定时，补充明确的“源节点/出现 → 目标出现”对应；工具不根据文件名猜范围。

流程为验证清单 → 复用或补齐快照 → 按源选区提取图片与尺寸 → 独立核对图片出现 → 绑定最终引用及独立身份 → 写候选映射 → 重读候选并原子替换目标。复用 `HtmlFidelity` 的尺寸提取、源节点定位和现有家族图片选择规则，不调用完整正文渲染或 `reconcile_html_to_markdown`，不生成中间正文。源未确定尺寸沿链路传递，不算回补失败，但必须保留原因。

图片检查直接读取原快照选区与实际交付 Markdown；保持四类家族的暗亮选择、引用改写及顺序，排除代码示例中的图片语法，核对每次出现及独立资源身份。不能用尺寸提取结果的数量自证完整。源图片本身漏项、错序、身份不符或无法唯一对应仍拒绝；无关正文中的复杂表格、脚注或代码排版不决定回补成败。仅当该结构使图片归属无法确定时，按图片歧义失败。回补成功只证明映射有效，不代替 R9 全文对账，也不解除真实样例 A16/A24 的原有缺口。

绑定使用规范化源位置、源出现顺序和资源身份共同确定。同一次出现同时保留原始源引用与交付引用：源资源相对快照目录解析，reference 的 `images/<basename>` 改写只用于交付匹配，不能覆盖原始路径。`left/plot.png`、`right/plot.png` 应直接命中各自源图；去掉先丢路径、再扫描整个目录树找 basename 的分支。历史映射缺路径时，仅可用已有独立源证明恢复，仍有歧义则拒绝。同图不同宽度按出现区分，跨章分别编号，暗亮选择跟随解析结果；数量、顺序或身份不符均定位拒绝。API 合并器复用这一绑定逻辑，保留未确定条目并在合并时同步重编号；分页及工作包装配沿用现有映射。

同输入重跑得到语义一致的映射；失败保存工作区外诊断，不触碰旧映射、正文或原图。完整回补需同版本源依据齐备，缺来源证明不能通过重算本地图摘要绕过。

历史身份核对在候选写盘前执行：每次出现的来源四元组与既有独立证明比对，证明来自旧交付映射带身份条目和清单可选 `parse_map` 声明的该页解析期映射（声明的快照摘要、来源文件与资源上下文均须与清单页一致，逐条合并、同键不同摘要即冲突、与记录顺序无关）；同一来源位置字节不一致即同路径换图，整单拒绝且旧映射不变，不以当前字节补签历史。旧版相对来源记录（基点不可确定）与含身份但缺 `resource_base` 的旧记录（上下文不可确定）明确失败保旧，重新解析/合并即得合规记录；无身份字段的旧条目不构成历史事实，按兼容边界重建。同一出现号内容冲突的重复确定项与输入顺序无关地拒绝，相同内容重复幂等。

### 4.4 导出预检、告警与严格模式（R2）

保留输入顺序、只读合同、显式映射路径及 `--require-display-map`；不将严格模式设为默认，仅在用户要求尺寸保真时启用。导出按“资源枚举和文件检查 → 全部映射验证 → 逐次覆盖及预算 → 出处门禁 → 内联/打印”执行；核验从实际输入与映射独立重建覆盖，核对报告、严格参数和映射摘要，不信导出统计自证。

- 普通模式：缺映射用 `images-display-absent`，无源约束/尺寸未确定用 `images-display-undetermined`，告警列章节、位置、原因、自然尺寸加版心上限的回退及补救办法。用户明确要求保真时暂停待回补或调整要求，不重复询问。
- 严格模式：任何未恢复出现均以 `images-display-required` 失败；无图豁免。显式路径缺失、坏映射、非法尺寸及身份错配始终失败，不能降为告警；不能通过省略核验严格参数改变导出政策。
- 报告保留旧字段含义，按出现次数记录总数、恢复数、三类未恢复数及明细，满足总数对账。已映射出现从最终 PDF 内容流实测，期望为 `min(显示宽度, 版心上限) × 0.75pt`，沿用 0.75pt 舍入容差，不放宽以容纳打印缩放。

### 4.5 图片预算（R5）

预检复用只读资源清单与 Pillow 元信息，同时报告按摘要去重和按出现累加的 `Σ(w×h×4)`；告警采用后者，初值 512 MiB。列出大图位置，GIF/WebP 多帧额外开销和 SVG 等未知部分不能记零。`image-decode-budget`、`image-budget-incomplete` 均在内联/解码前可见。

阈值是保守提示，不代表 Chromium 峰值或硬上限；用普通/资源密集样例校准，只调整常量，不新增配置系统。告警不改退出码、资源和合订范围；真实解码、字体、溢出及视觉检查照常执行，错误保留原始原因。

### 4.6 默认出处前置与独立核验（R6）

保留固定章首投影集合“原文/译例说明/来源/抓取日期”，政策单源并记入证据，不增加任意字段排除配置。导出与核验独立识别可删区间；正文、代码、表格、脚注和技术引用中的同名内容保持。

1. 从原始章首来源字段、已有目录出处读取来源文字、链接、源行区间及输入摘要。每章须能定位具体原文（URL/锚点或可回查快照及选区），并保留已知版本、日期和限定说明；不强求源未提供字段，不从正文猜测或编造。
2. 仅排版空白归一后完全相同的信息去重。优先复用目录中完整出处；标准“译自…”按 Markdown 块识别，自由格式用既有 `--provenance` 只读区间映射核对输入摘要、段落、章节与来源字段，映射不能补造来源事实。
3. 将完整出处置于第一章前，覆盖实际单篇/合订/分篇范围；无目录时生成导出视图中的独立前置容器，不改 Markdown、不新建目录。仅去重复出处块，其他说明和正文章序不变；前置内容不冒充正文章节，来源链接保留并遵循既有链接检查，页码纳入目录收敛。
4. 部分不足报 `provenance-incomplete`，完全缺失报 `provenance-unavailable`；所有模式均在内联和任何 PDF 生成前非零退出，定位受影响章节，保护旧 PDF，不以占位/告警放行。

核验独立重建来源和授权投影，拒绝未知集合、参数冲突及输入来源缺口；从最终 PDF 的页序和同页位置核对完整出处只前置一次、章首管理字段已排除，不能仅信报告或摘要。多来源、多行、目录跨页及前置与首章同页仍适用。

### 4.7 持久证据与交付完成检查（R4）

保留 `verify_delivery --record --evidence-dir`，记录继续声明模式、源家族/版本、有序输入输出、源与映射、检查参数、复核、尺寸决定及根目录文件角色。入口只完成“核对范围 → 本次核验 → 复核闭合 → 发布证据”，不承担任务调度或工作包复用资格。

**参数只有一个解释来源。** 沿用已提取的真实 CLI `parse_args`，保留原本接受的写法、位置顺序与错误语义；PDF 使用 argparse，翻译家族复用已有 `extract_*`。在执行检查前解析全部记录，获得实际输入、源、输出和核验口径；子进程仍以交付根为 `cwd` 原样传参，字面量不改写。路径按真实参数语义解析并规范化后用于绑定，不新增参数规格注册层。空 `checks`、未知工具、畸形参数、未声明输出和未覆盖输入在复跑前清晰拒绝；`rerun_checks` 各分支维持同一返回合同。

| 必要记录 | 内容与检查 |
| --- | --- |
| 源与映射 | `translation` / `translation+pdf` 的每份实际英文输入都能关联同版本原快照、选区及解析 Markdown；有图检查两级映射，无图免映射；`pdf` 模式不强制补英文源 |
| 当前产物身份 | 当前输入、源链、输出、映射、资源、相关检查器依赖和有效参数共用同一计算口径；变动使相关旧结论失效 |
| 机器检查 | 按模式调用对应已知校验入口，从最终路径复验并保存输出、退出码及检查参数；不执行记录中的任意 shell 命令 |
| 回源与人工复核 | 源全量对账、语义复核分别覆盖每个译文；PDF 逐个要求视觉复核，链接复核不能替代。绑定对应产物的完整检查上下文，并逐项闭合机器待复核项 |
| PDF 证据 | 导出报告、核验报告、最终 PDF 摘要、尺寸分类/严格参数、出处投影、预算、代码分页政策与逐块结果、环境与依赖版本；复核必须针对同一最终 PDF |
| 交付根目录 | 允许清单内文件与实际一级文件逐项相符；多余、缺失或角色不符均不能完成，映射与辅助文件遵循 4.8 |

**完整源链与身份只计算一套。** 沿用已存在的 `compute_delivery_identity`，使独立构造的检查上下文与复核绑定消费同一份完整事实（当前缺口与收敛方案见 §9）；这是一份本次运行的值，不是状态库。输入为交付记录及真实 CLI 解析结果，输出为完整依赖身份、逐产物检查上下文或可定位的问题：

- 源链沿用已有映射；交付记录的 `sources` 补足“解析 Markdown → 有序快照、家族/版本、选区”的明确关联，合并源使用已有页面/片段范围，不能按文件名猜测。选区保留家族默认根或指定锚点两种口径，不强制全文输入增加锚点。已有 per-stem 映射提供的快照信息可复用；无图仍须能声明源链。有图还须关联解析期与交付级映射，检查实际出现覆盖及独立源身份。缺快照、指定选区不存在、错版本或漏关联均在复跑前拒绝。
- 文件身份覆盖交付 Markdown/PDF、实际英文输入、原 HTML、两级映射、参与判断的来源/转换映射和导出证据。图片从两侧实际引用枚举，使用 `_verification.local_resource_digest` 等既有函数递归核对 SVG/CSS 依赖；按出现保留路径关联，文件摘要可去重复用。必需文件缺失或摘要不可得时失败，不能以两侧同为 `None` 判相等。
- 检查身份覆盖实际入口及影响结果的本地共享脚本，而非仅入口文件；沿用 `recover_work_packages._script_identity` 的显式依赖做法，在已知入口处维护有限依赖集合，不扫描整个仓库或构建动态依赖框架。记录有效参数、已有依赖版本及参与导出/核验的样式政策；临时目录和日志位置不作为语义口径。复用摘要原语，工作包资格与整套交付合同保持独立。
- 每个译文保留覆盖它的**全部检查及各自有序源输入、口径**，每个 PDF 保留其实际有序 Markdown 输入和核验上下文。不能只取首项、仅取来源并集而丢掉“哪个检查使用哪个源”，也不能因多个工具覆盖同一译文而一律拒绝。记录中的其他文件不能冒充实际被核验范围。

**只保存本次机器结果。** 通过预检后，原 HTML→解析 Markdown 调用 §4.10 的独立对账，并保存当前源链结果；译文按四类既有核验入口复跑；PDF 使用既有 `run_verification` 从最终路径读取成品。新机器结果须无失败、状态与退出结果一致且覆盖当前范围，缺结果不能用残留文件兜底。翻译入口保留原输出格式，必要输出与身份进入本次证据；不恢复旧 JSON 鉴真、不重写全部工具。导出报告仍为必要输入，缺政策须重导出，不能由新核验报告补签。

**复核绑定不能随报告一起重置。** 保留 `reviews` 的 `kind/target/status/sha256/items/note`；用一个 `binding` 保存上面按目标计算的完整上下文，替代新记录中零散的 `source_sha256/checker/semantic_args`。源对账与语义复核绑定译文及其全部源链和检查，视觉/链接复核绑定对应 PDF 的输入、资源、成品和口径；无关产物不进入该条绑定。`binding` 不含复核正文、交付记录自身摘要或本次生成报告，避免循环依赖。

机器检查可以给出待复核上下文及具体项，人工实际复核后才将对应 `binding` 和结论写入记录。新合同沿用交付 `version: 1`，旧记录缺 `sources` 必需关联或完整 `binding` 时定位失效，不自动补填或把历史结论重新签成通过；历史证据保留。按产物、类别、出现次数核对 `relaxed_matches` 和 `reviews`，不能跨 PDF 或跨检查代闭。语义、视觉结论仍来自实际复核；“不恢复尺寸”的用户决定不豁免资源身份。

**发布只切换索引。** 在复跑前捕获完整身份和交付记录字节摘要；核验及复核通过后沿用独立新批次写入、重读核对。批次完成后、原子替换 `delivery_index.json` 前，以同一函数重新枚举并计算完整身份，另查记录自身摘要；源、资源、共享检查器、范围或政策在期间变化均拒绝。不能只复查预先列出的旧路径，也不能把复制时的当前摘要重新当成基线。索引保存这份身份与本次检查结果，报告用相对证据目录的引用。失败或中断最多留下未引用的新批次，旧索引及全部引用文件不覆盖；不增加锁服务、数据库或自动历史清理。

持久目录不得位于系统临时根，默认在工作区外；工作区内位置仍须用户对具体内容和路径授权。源快照、成品在各自明确持久位置，必要机器报告（含导出证据）归档到本次批次，不复制整套项目。临时候选路径只作诊断，清理临时目录后索引不得依赖这些路径。无可用持久位置、必要引用失效或复核未闭合时，只报告缺口。

输出分别列出硬不变量、源全量对账、语义复核、PDF 核验、视觉复核及留痕状态；仅 PDF 模式的翻译检查为“不适用”。完整证据通过返回 0，任何必要缺口返回非零并定位。解析临时路径等普通告警保持原退出语义；R9 可证明的源解析损伤必须非零退出，证据不足阻断分派。导出/核验按 D6 将出处不足作为硬失败，尺寸回退与预算告警仍遵循原模式。本检查是 Agent 宣称交付完成前的统一入口。

### 4.8 交付目录与映射迁移（R7、D5）

布局作用于翻译交付项目，非 Skill 仓库。新产物按下表存放；既有项目须明确获得整理授权，未知文件不擅自删除。

| 位置 | 内容 |
| --- | --- |
| 根目录 | 目录、章节译文、成品 PDF、术语表；另允许 `导出前准备说明.md`、`PDF导出交付说明.md`，不强制新增或搬回 |
| `export/` | 交付级 `images_display.json`，回补仍写此处 |
| `docs/` | 其他过程文档、独立命令模板；机器报告仍需具体落盘授权 |
| 原有子目录 | `images/`、`scripts/`、`source/`、`translated/` 及归档保持原位，章节与原图不改 |
| 工作区外 | 临时候选、诊断、迁移备份；持久证据按 §4.7 |

§4.7 的记录按实际交付范围登记路径/角色；章节对应输入，PDF 对应已核验输出，术语表对应项目术语来源。枚举根目录所有一级文件，含隐藏文件和文件链接，逐项核对身份与角色，不按扩展名或“用户可读”放行；符号链接不能伪装目录绕过。额外文件或去向未定均阻断完成。两份说明不自动进入正文合订，术语表仍默认排除；说明内链接须可用。

迁移使用既有文件操作，不新增 CLI：记录旧映射及解析目标，在 `export/` 生成候选并重算顶层/条目的 `markdown`、`image`（含 `undetermined`），如 `../章节.md`、`../images/图.png`；同步来源定位、证据引用、文档链接和命令。不机械改 URL/绝对路径，不覆盖目标冲突文件，不动旧归档。

确认绑定命中原章节、来源和原图后移除旧根目录映射，两侧命令显式使用同一 `--images-display export/images_display.json` 并明确工作目录；回补沿用 `--output`。失败保留工作区外诊断/备份，仅回滚本次改动。保留旧同目录发现兼容，不递归搜索、不留根目录副本；漏参按普通告警/严格失败，不能凭退出 0 宣称整理完成。

迁移前后逐次比较身份、宽度/未确定原因、恢复状态及最终 PDF 实测宽度，并验证连续两次回补仍使用新位置。纯迁移使用相同打印政策；同时改变分页允许页码变化，但图片恢复不得退化。

### 4.9 代码分页与块内完整性（R8、D7）

**渲染与分类。** 在 Markdown 代码 token 与 `pre` 的收集边界建立逐块记录：章节、块序号、源区间、原始代码、逻辑行数及分页类别。覆盖围栏、纯文本、未知语言回退及既有缩进代码；不重新解析嵌套代码内容。仅统一 CRLF/LF 行结束，末尾单个终止换行不增行，内部及真实末尾空行计入，空块为 0 行。核验侧从原 Markdown 独立重建，不信报告中的行数。

10 行及以下对代码容器和 `pre` 保持 `break-inside: avoid`；超过 10 行在两层设置允许跨页，解除代码包装层造成的整体移页限制。分类在高亮之后统一应用，保留现有字号、行距、视觉折行、缩进和配色；不设置行号、续页标签、阈值参数或针对整本书的利用率指标。普通可见行是分页边界，长逻辑行折行后可在完整可见行间续排。

在打印宽度、字体已加载的视图中检查短块高度；连一整页都放不下时报告 `code-short-too-tall`，不私自拆短块。CSS 的 `avoid` 只是浏览器建议，最终 PDF 仍须验证短块没有跨页。短块整体移页产生的页尾空白明确接受；长块有可容纳完整代码行的页尾空间时必须利用，不能为保持整体挪到下一页。

**一份 PDF 绘制事实。** 在现有 `PdfFacts` 中统一收集页码、容器路径、页面/内容流作用域内的 MCID、绘制顺序、原始文字、字体和经变换的页内物理坐标。复用 `_collect_text_run_geometry` 的变换，原始 `tm` 仅在提取层联接内容标记；视觉行聚合与排序改用物理基线，CJK 基线容差也以物理 pt 计算，桶内保持绘制序。`line_first` 和缩进比较统一使用物理起点与字宽，折行、图片占用及分页使用同一坐标；不再把原始 `tm.x/y` 传给这些判定。沿用现有纸张、字体和受支持 Chromium 输出范围，不增加坐标适配框架。源 Markdown 预期与 PDF 实际内容仍独立提取。

**一个块对账核心。** 保留结构树候选归属及 `_consume_block_tokens` 严格对账，原输入有序块与 PDF 容器逐项对齐，结合相邻正文/表格边界、代码字体和几何范围定位；高亮 span 与跨页片段展开后仍保持块边界。已删除的 `_match_code_blocks_legacy`、桶搜索、固定 x 阈值与源码子串重定位不恢复。不能假设存在固定 `/Code` 标签或 HTML `id`，也不能只凭样式建立归属。

每个原始代码块必须独占一组实际绘制片段，顺序单调、一一消费；完整读取该组片段，不能仅找到源码子串就认为相等。邻接正文、表格及其他代码块的字符不属于本块；定位歧义或结构不足时记录候选页和区域，进入既有待复核流程。代码块记录与结构映射仅是定位依据，PDF 隐藏替代文本、导出报告中的源码或匹配摘要均不能代替绘制内容。

结构不足的每个块须列出源位置、候选页/区域及尚未证实的内容与分页项；无法缩小区域时列出完整章节范围，不伪造定位。人工须绑定当前 PDF 逐项核对字符、空白、块次数、顺序与布局，记录实际结论；未闭合时 `verify_delivery` 非零退出。能可靠归属的区域继续严格检查，已发现的硬失败不可由人工覆盖。若当前受支持 Chromium 正常产物普遍失去结构归属，应修复提取层，不把整份文档转人工视为精简成功。

**比较与交错处理。** 普通和跨页代码使用同一块内严格对账。非空白逐码位相等，行内空白按数量及缩进位置核对，不做 NFKC 替换或删空白比较。视觉折行必须有真实右界或相邻页底/页首位置依据；保留现有 `uniseg` UAX #14 软断点及下一不可拆片段宽度判定，不恢复标点白名单。制表位、字体切换的额外空白、折行尾未绘制空白及空行中无法从绘制内容确定的部分，逐块记入待复核；不得将行中空格删除或任意换行作为合法折行。

页面提取顺序中穿插的正文或表格，只有实际内容标记和区域证明其属于本块之外时才可剔除；记录被排除片段、页码、范围及归属依据。本块实际绘制的新增字符绝不视为噪音：`return 10;` 不能通过 `return 1;` 的检查。重复块必须有不同的已消费片段，缺一份、插字、删字、乱序及借邻文补齐均失败。禁止给代码调用任意字符子序列回退；归属不明的候选需现有复核记录逐项闭合，口头认可不能覆盖确定损伤。

**分页判断须解释前导内容。** 从最终 PDF 的代码片段与紧邻内容判断页尾能否容纳完整代码行，沿用版心、边框/内边距及实际行高。前一内容页取同章中按源序相邻的实际内容，不用前一代码块末页代替；章首强制分页和正常章尾保持既有规则。前页占用同时计入正文文字范围与绘制图片底边，不能只看文字。

长块位于后页时，检查其前方的标题、正文或图片与源顺序及实际区域的对应：

- 前页剩余空间能容纳必要间距与至少一完整代码行；本页若有随块移来的前导内容，还能容纳这些内容：报告 `code-page-gap`。增加一个 H2 不改变这一空间判断；标题不能使已确定的大留白转为通过或待复核。
- 上述所需空间确实放不下：该移页有依据。例如前导图片本身放不进前页，代码依源序排在其后，不能把代码挪到图片之前来要求填空。记录实际前导区域、所需空间及前页占用，不能凭“有前导内容”直接跳过。
- 源序或物理区域无法可靠对应：定位相关代码及前导区域，进入既有逐项复核；已有可靠证据的损伤仍失败。

以上只复用现有 Markdown 结构和 `PdfFacts` 的相邻区域，不建立整本文档排版模拟器。短块整体移页产生的空白仍明确允许；可见行间续排和接缝完整性继续检查。

已知代码损伤、短块实际跨页或长块整块移页缺陷均为失败。候选 PDF 完成目录页码收敛后调用同一代码检查，再决定是否复制到最终目标；独立核验从最终路径重读，不能只复用候选报告。待复核沿用既有状态，不新增宽松成功状态；交付检查要求内容与布局复核闭合。仅候选/诊断可留工作区外，硬失败保护旧 PDF；出处不足则依 4.6 在任何 PDF 生成前阻断。

### 4.10 项目脚本能力回流（R9，复用 R3/R7）

## 8. 机制重审（2026-09-18，依据 2026-09-18 实现评审与 AGENTS §5）

四个机制在补齐执行中连续多轮修补后仍有可复现反例，按下表完成重审；证据为评审探针（/private/tmp/translation-completion-review-20260918/）与持久验收副本重跑结果。结论：四个机制均收敛为“单一事实来源 + 严格对应核验”，不再按页面/报错逐项叠加例外。

### 8.1 列表归属（渲染 + 核验双侧）

- **根因：** 渲染端对列表项内块级内容（div 包装段落、嵌套列表、pre）的缩进输出不一致——围栏经 041360c 已按层级缩进，但 `div > p` 等段落仍落列 0；核验端 `child_noted` 单布尔只能记录一次子列表边界，父项代码经“未定围栏”规则被归给栈顶子项。两侧规则各自演化，同一结构在不同页面产生不同输出，逐页补丁不可持续。
- **方案比较：** ①继续按页特例（拒绝：三张真实页已证明会互相冲突）；②取消列表归属比较（拒绝：换父移动、标签越过代码为 §5.3 已批准验收，不可削弱）；③收敛：渲染端保证“列表项内一切块级内容（段落/围栏/表格标记行）一律按项层级缩进（2×level 空格）”，核验端以栈重建——缩进连续行归属深度不大于其层级的最近项、子列表边界可多次记录、缩进围栏属项内代码、列 0 内容结束列表。选③：单一缩进不变量同时消除三类误拒，且损伤例（换父、越代码）仍可检出。
- **Karpathy 自检：** 不新增标记语法或第二套列表解析；删除 `child_noted` 冲突状态；三正例（父项代码后置、双子列表、div 包装段落）与既有损伤例同入口验证。
- **补充缺口（实施核对发现）：** 2×level 缩进在 level≥2 时围栏标记行达 4+ 空格，而 `_verification.scan_code_fences` 沿用 CommonMark 顶层 ≤3 空格口径，扫描器漏认这些围栏，代码事实随之丢失（cpp-language-support 存在 5 处 depth≥2 的项内 pre）。该扫描器的全部输入为本管线渲染器形状（或其译文副本），缩进代码块不是受支持输出；`verify_pdf.raw_scan` 与 markdown-it 结构层本就按任意缩进识别围栏。因此统一放宽围栏标记行的缩进上限，误认场景在核验中表现为响亮失败而非静默放行。

### 8.2 表格转换映射核验

- **根因：** 内容检查用“源格文字 ⊆ 目标文字”子串判定（132→132000、附加文字放行），格内代码用全局排序集合比较（跨格交换放行）；均未按映射声明的格位做完整解释。
- **方案比较：** ①保留子串 + 局部修补（拒绝：确定损伤放行违反 §4.10）；②取消转换映射（拒绝：17 张表与未解释跨度阻断为已批准要求）；③收敛：逐输出格核验——非空输出格的文字按 `' / '` 分段后，必须与声明指向它的源格文字（行优先序、归一口径）一一相等，空段对应空源格；格内代码按源格（行,列,序）映射到声明目标格位的 TABLE-CODE 键逐一相等，输出表孤儿代码必拒。选③：表头/共享值展开由“多源格分段相等”自然解释，数值篡改与跨格移动均为确定性拒绝。
- **Karpathy 自检：** 复用现有归一函数与映射结构，不新增分隔符配置；映射生成端同步声明表头全部层级源格（父格须有目标）。

### 8.3 交付身份的目标投影

- **根因：** `compute_delivery_identity` 已计算 `resources.sources`（解析侧图片递归身份），但 `expected_review_binding` 只投影了译文自身资源；源图/SVG 子资源变化改变身份却不改变期望 binding，旧复核照常匹配（S5）。同类遗漏：两级映射必要性由“记录是否声明”而非实际图片出现决定（S4）。
- **方案比较：** ①另写源身份计算器（拒绝：两套口径）；②零散补字段（拒绝：评审已证明会漏）；③收敛：一切绑定/必要性判断均从统一身份与实际枚举投影——语义/源对账 binding 附该目标全部源链的解析侧资源（含递归依赖，缺失摘要即拒绝绑定）；两级映射要求由源链解析 Markdown 与交付输入的实际图片出现决定，交付映射还须按出现数覆盖。选③。
- **Karpathy 自检：** 不改 reviews 记录合同（仍是单一 `binding`），预检—绑定—发布同一投影函数。

### 8.4 合并源的快照范围

- **根因：** `run_source_reconcile` 对每个快照都比较整份解析 Markdown，合法 A+B 合并被误拒两次（S6）。设计 §4.7 本就要求“合并源使用已有页面/片段范围”。
- **方案：** `sources[].snapshots[]` 增加可选 `range`（解析 Markdown 的起止行，闭区间）。单快照缺省全文；多快照必须声明 range 且按序无缝覆盖整份 Markdown，预检拒绝缺口/重叠/乱序；对账仅比较各快照对应范围，选区锚点按快照各自生效。该字段是 §4.7 既有要求的实现，不是新行为；若后续发现需按标题等语义边界（而非行号）表达，另行按门禁处理。
- **Karpathy 自检：** 不放宽标题核验（范围内逐项），不为通过只取首个快照。

### 8.5 译文表格内公式的管道转义（2026-09-18 真实样例执行发现）

- **根因：** 解析侧表格以 `[TABLE]` 标记行表示，格内公式的 `|` 无需转义；译文按约定使用真实 Markdown 表格（`[TABLE]` 属译文残留标记），格内公式的 `|` 必须转义为 `\|`（否则破坏列界）。公式对账为逐字节比较，`$|x|$` 与 `$\|x\|$` 被判不一致——这是表示层的必然差异，不是译文损伤。
- **方案比较：** ①译文改用 `[TABLE]` 标记（拒绝：与译文残留标记门禁冲突）；②译文公式改写 `\vert`（拒绝：表达式仍与源不一致，且属改写源公式）；③比较侧仅在译文公式所在行为表格行（含 ` | `）时把 `\|` 归一为 `|` 参与比较：表格行内的 `\|` 语法上就是管道字符，与源 `[TABLE]` 行中的 `|` 是同一数学内容；表格外不归一（LaTeX `\|` 是合法的范数记号）。选③。
- **Karpathy 自检：** 归一仅作用于译侧、且限定表格行；不改变源侧提取，不掩盖公式遗漏/换序/其余字符损伤。真实样例（mathematical-functions 的 `|x|`、`\ln \|x\|` 等）正反例随实现验证。

以上重审结论随本轮修复一并验证：每个机制以评审给出的最小正常/失败场景进入既有测试，真实页面仅作集成样例。
