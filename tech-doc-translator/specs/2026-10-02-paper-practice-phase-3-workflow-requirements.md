## 1. 核心结果与范围

主 Agent 可以根据当前文件和项目口径生成自足任务、待复核证据与可消费目录，并核对一批项目的实际完成情况。没有主会话上下文的翻译 Agent 能准确定位输入与规则，只写自己的目标；硬检查通过、子 Agent 回报完成、状态表完成或历史 PASS 均不能替代当前独立复核与交付验收。

本文只定义三期需求，不规定新脚本名、参数格式、证据 schema 改造、内部算法或实施顺序。用户确认分期与并行编写不构成具体需求、设计、计划批准或实现授权。本文没有修改实现或外部翻译项目。

[总需求第 3 节](./2026-10-02-paper-practice-requirements.md#3-必须保留的合同)是公共来源、分派、硬检查、人工裁决、证据失效和写权限合同；[总需求第 5 节](./2026-10-02-paper-practice-requirements.md#5-假设待批准差异与不纳入项)是共同批准、兼容与非目标边界。本文细化三期结果，不另设替代门禁。

## 3. 分期边界与必要依赖

- [一期核验基础](./2026-10-02-paper-practice-phase-1-verification-requirements.md)负责 R2、R3 核心计数、R4 和 R9。三期的文件 / 预设必须使用已修正的同一计数语义；任务、证据和目录使用可靠的公式、标题和围栏事实，不能通过包装掩盖一期缺陷。
- [二期 LaTeXML 保真](./2026-10-02-paper-practice-phase-2-latexml-requirements.md)负责 R1、R5。三期处理 LaTeXML 时，须使用二期进入现有身份与复验的源链；数字差异的逐项处置进入既有复核记录。三期不复制来源适配或数字审查规则。
- 已支持的其他源家族，只要当前源对账与项目合同成立，即可使用三期能力，不人为依赖全部二期结果。三期不以 [四期 PDF 候选辅助](./2026-10-02-paper-practice-phase-4-pdf-candidates-requirements.md)或待批准公式物化为前置条件；既有 PDF 源仍按当前裁决合同处理。
- 工作包复用资格和最终交付资格保持独立：逐包复核不替代合并后的全量复验，工作包证据不直接冒充 `verify_delivery.py` 的整套交付记录。

## 4. 功能需求与直接验收

R6、R7、R10、R11 为 P1 辅助能力；R3 文件 / 预设为 P2 显式复用能力。优先级不授予执行资格。以下验收是待实现标准，本轮没有执行翻译或新增工具的运行验收。

### 4.1 R3：强 token 文件清单与 PTX/ISA 显式预设

来源：03 R3.9 的复用边界、05 R5.6 及 CUDA 审计附录；核心计数修正归一期。

1. 支持从显式文件清单读取强 token，与逐项参数合并去重；逐项、文件及合并输入使用一期同一匹配边界、计数、差异与“源中未出现，此项未检查”告警。原逐项参数继续可用，不能由便捷输入默默改变实际检查清单。
2. 提供可显式选择的 PTX/ISA 预设。预设的模式只从当前源生成实际出现的候选 token，交由主 Agent 确认适用口径后用于检查；保留候选到最终实际清单的对应关系。预设不是术语库，不能改变项目译法、优先级或处理方式。
3. 预设可复用指令、`.` 修饰符、`%` 寄存器等已知形态；普通缩写、数字小数点或正文词缀不能因形似自动成为强 token。不开放任意通用规则引擎，不按 URL、厂商、文件名或自动识别结果启用预设。
4. 任务书、证据生成、恢复、合并及最终核验使用同一份已裁决实际清单与适用口径；输入文件、预设或裁决变化影响实际检查时，按现有绑定使受影响复核失效，不重写摘要沿用历史结论。

**直接验收：**

- 对 `add.rn.f32 d, a, b; mov.u32 %r1, %tid.x; cvt.rn.satfinite.e4m3x2.f32 d, a;`，等价逐项与文件配置得到相同清单和结论；合并重复项不重复制造检查。`.rn=2`、`.f32=2`、`.satfinite=1`，删除实际命中项失败，缺席配置项有明确未检查告警。
- 显式选择预设后，候选均能回到实际源位置并经裁决进入清单；未选择时检查行为不变。`.rni` / `%tidy` 不替代 `.rn` / `%tid`，普通小数、正文缩写不自动入选。
- 以相同实际清单生成工作包证据后恢复 / 合并可消费；改动实际清单或检查口径，旧证据不能继续授予完成资格。缺失文件或无法确定预设 / 清单内容时，不声称相应项已检查。

### 4.2 R6：工作包复核证据生成

来源：04 R4.1。

1. 提供随 Skill 交付的证据生成能力，复用当前恢复 / 合并的全量预期、源片段与唯一目标对应、片段硬检查、正文与资源摘要及证据消费合同。不以实收到的译文数反推范围，不修改旧源包、译文或资源，不依赖固定用户安装路径。
2. 输入包含当前实际强 token 与适用检查口径；不能用空清单替代已配置项目项，也不能漏掉影响本次检查的已批准公式 / 结构转换口径。生成结果须被当前恢复与合并按同一事实解释，不另建宽松证据格式。
3. 硬检查通过只生成待复核记录。主 Agent 针对当前输入实际完成独立回源复核、明确登记相应包且无未解决项后，才能登记完成；翻译 Agent 自检、工具 PASS 或一个全局 `done` 参数不能替代逐包实际复核。二期数字复核的未处置差异仍阻断语义完成。
4. 源片段、目标正文、两侧资源、实际检查器或检查口径变化后，受影响旧证据失效；摘要缺失不能以双方为空认定相等。失败不能覆盖已有有效记录或替仍需复核的包写完成结论；无关有效包继续按现有恢复合同复验复用。
5. 恢复与合并自行读取当前文件并核对资格，不信任生成器先前的通过摘要。合并仍核对独立全量范围、唯一目标和最终路径内容；失败保留既有有效成品。

**直接验收：**

- 完成拆包 → 翻译 → 生成待复核证据 → 合并拒绝 → 主 Agent 针对每包实际回源复核并登记 → 恢复 / 合并接受的链路。一个包仅做自检或存在未解决项时不能随其他包取得完成资格。
- 分别制造代码 / 公式硬损伤、错目标、缺包和不可核验资源，定位实际原因；失败前后已有有效证据与成品摘要不变。
- 分别改变源、译文、图片及 SVG/CSS 依赖、检查器、实际强 token 和适用检查口径，受影响旧结论不能复用；未变化的有效包经独立复验可复用。补写新摘要而未重新实际复核仍不能完成。

### 4.3 R7：可独立执行的工作包任务上下文

来源：04 R4.3、R4.4、R4.8、R4.10 的有效部分。

由现有拆分元数据与显式项目口径生成每包自足任务书，保留 Skill 已有四要素：

| 要素 | 必须可直接读取或执行的内容 |
| --- | --- |
| 必读上下文 | 当前项目指令、适用翻译规则、项目术语或已选择子集；同构样例可引用，非同构样例须指出不能仿照的差异 |
| 唯一输入输出 | 唯一只读源与可写目标，`source_order`、小节 / 实例 / 片段、源范围及摘要；路径从任务环境可定位 |
| 输出合同 | 译文模板及当前公式、代码、图片、表格 / 占位结构等特殊规则；不得改源、其他包、全局目录、术语表或交付说明 |
| 完成合同 | 拆包脚本生成的实际计数和对应自检；返回新术语及首现位置、原文 / 解析问题、已执行检查和不确定项；任务回报不授予复核或合并资格 |

1. 任务书引用现有权威约定和真实检查参数，不复制成另一套全规则配置系统。明确 `[TABLE]` 等解析结构如何转为真实译文结构，保持公式、格位和内容；不能一边要求照留残留标记、一边用禁止残留的检查口径验收。
2. 四要素缺失、路径不可访问、源尚未独立对账或规则冲突时，不分派。计数来自脚本；确实不能可靠识别时报告不确定，以源内容为准并上报差异，不能手填计数覆盖源文。
3. 需要工具时给出可用解释器、Skill 位置和适用入口，优先复用已有环境；不依赖旧用户绝对安装路径，不固化落盘字数、重试次数、模型或并发数，也不为任务书增加环境管理平台。
4. 源或规则变化时，暂停受影响旧任务的完成认定，说明精确变化位置及前后内容，要求使用新输入复验并返回额外发现。消息已发送、Agent 表示收到或旧任务回报完成，都不能证明内容已同步；已有结果按当前恢复合同判断，不自动覆盖或迁移译文。

**直接验收：**

- 无主会话上下文的试读者能找到全部规则、术语、源和工具，理解表格标记与保真要求；在实际工作包试跑中只写唯一目标，返回完成合同，主 Agent 仍进行独立核验。
- 分别遗漏四要素中的一项、提供不可访问路径、未完成源对账或冲突标记规则，均不能分派；手工计数与源不符时不支配输出。
- Skill 安装位置变更后，按实际新位置生成的任务仍可执行。源或规则变化后，旧回报不能直接合并；受影响内容重新核验 / 复核后才可取得资格，无关包仍按当前事实复用。

### 4.4 R10：独立目录生成

来源：05 R5.7；既有独立目录默认见 PDF 导出需求第 3.5 节。

1. 从最终译文及独立确认的官方 TOC / 导航和交付范围，按官方顺序生成 `00_目录.md`；支持单篇、多章、现有章 / 节层级，保持官方原题、编号与译文标题对应。局部范围只链接已交付内容并标明范围；不能按文件名排序、译文目录或生成成功反推官方范围已闭合。
2. 标题识别、slug 和同章重复标题 `-N` 编号与实际 Markdown / PDF 消费一致，复用既有规则，不维护近似副本、不折叠现有保留的连续连字符；围栏里的 `#` 不计标题。同名章节按实际目标区分，不能借第一个同名标题消解其他条目。
3. 链接使用相对路径与正确锚点，以目录实际位置为基点，不回退 cwd；目标文件和片段可实际消费。生成不修改章节正文或资源，不在每章文末重复附全书目录，原文固有章内目录继续保留。
4. 保持翻译默认独立目录、用户明确不要时省略的合同；已有 Markdown 仅导出 PDF 且无目录输入时，不强制补建目录。PDF 的印刷层级、分篇过滤、实际页序和独立链接核验沿用既有导出合同。

**直接验收：**

- 单篇、多章和局部范围样例按官方顺序对应真实译文；覆盖同章重复标题、同名章、中文标点、连续连字符，以及长反引号 / 波浪围栏内伪标题，全部链接指向正确目标。
- 将目录放在明确输出位置并切换 cwd，从实际阅读器打开链接；同一目录进入实际 PDF 导出与独立核验，目标标题、页码和点击结果成立。围栏伪标题和范围外章节不进入交付目录条目。
- 错目标、坏片段或缺官方范围依据不能宣称目录交付完成；目录生成通过不替代源范围核对。独立导出既有无目录译文仍可运行且原 Markdown 不变。

### 4.5 R11：批量完成核对与后续变更留痕

来源：04 R4.6、05 R5.8。

1. 只处理显式项目清单，各项目明确当前范围、实际文件、交付模式和检查依据；按 `translation`、`pdf`、`translation+pdf` 复用当前 `verify_delivery.py`。不按目录遍历擅自扩大范围、不重建另一套交付判据，也不要求未请求的 PDF 或总结文件。
2. 分别定位缺产物、当前检查失败、复核缺失 / 未闭合、证据过期，以及状态表与事实矛盾。完成判定依赖当前文件与有效绑定，并执行适用的当前核验；固定七类文件、grep PASS、口头结果或状态表完成不构成资格。
3. 状态表只作辅助，无产物且无可信调度依据时报告状态不明；不能据此断言未分派或自动重派。仅 PDF 模式不被强加英文源、翻译语义复核或工作包合同。
4. 源修复、项目口径变更或补译后，在已有说明 / 证据位置保留日期、变化位置、依据与重新验收结果；历史记录和当前结论可区分，当前完成引用最新有效证据。项目修补脚本不能成为唯一记录，不增加状态数据库、调度器或独立变更台账。
5. 单项目交付及收尾清理保持现有顺序与保护合同；批量核对成功不自动触发未完成 / 暂停 / 失败项目的清理，不删除历史证据或恢复必需资产。当前报告不得掩盖已失效旧结论。

**直接验收：**

- 一个显式批次同时包含“状态完成但缺文件”“状态在途但无产出”“文件齐全且旧日志 PASS 但输入已变”三类反例：均不能算完成，各自原因可定位；第二类缺调度证据时为状态不明。当前范围及验收闭合项目被正确识别。
- 混合三种交付模式，各项目只执行其适用合同；翻译模式不被要求生成 PDF，独立 PDF 模式不被要求补英文源，范围外项目不被扫描或处理。
- 实际后续补译使旧复核失效；重新回源复核与交付验收后，说明可同时回查变化前历史与当前有效结论，引用在证据归位及清理后仍可访问。

## 5. 假设、兼容与非目标

- 新增的是辅助生成 / 核对入口及显式文件 / 预设能力，尚待批准；不追认旧素材中 `--semantic done`、固定任务步骤、就地建环境、自动覆盖重派或七类文件的行为。具体入口、清单格式和复核登记方式由获批后的设计确定。
- 保持既有逐项参数、源家族和项目优先级。新检查口径进入实际身份和消费合同后，相关旧证据须重新实际核验 / 复核，不自动补签；无关有效产物按现有恢复合同复用。新能力不授权批量修改存量项目。
- 人工复核不能由工具从计数推断。工作包证据与交付证据各履行现有职责，长期位置和收尾归位服从留痕 / 清理合同；本仓库评估与验证产物仍在工作区外。
- 不纳入按行迁移译文、通用块回填 / 固定句式翻译平台、全规则配置引擎、统一状态库或队列、额度 / 宿主错误码调度、固定重试 / 并发 / 模型、归档清空半成品、自动语义评分及 LLM 项目词库导入。保留必要独立核验，不用精简为由取消主 Agent 逐包回源复核。

## 6. Karpathy 精简与自检

1. **基线：** 第 2 节核对当前拆包元数据、四要素、恢复 / 合并、真实 CLI 计数、目录消费与交付身份，区分已有门禁和缺失辅助。沿用留痕设计第 8、9 节的统一事实及覆盖投影，不另建证据系统。
2. **假设与差异：** 第 3、5 节明确一期计数依赖、LaTeXML 适用条件及待批准能力；四期不是本期前置。没有实施行为变化，没有把“同意分期”解释为新增能力获批或执行授权。
3. **最小方案：** 保留现有人工流程作为可行基线，在既有入口上补生成与核对能力。仅加使用说明不能达到无需各项目重复拼装的结果；复制旧整套批量驱动会重复状态、计数及身份口径，因此只保留五组直接能力。具体算法和文件布局不提前写成设计。
4. **删除审计：** 合并素材中任务书、口径、变更同步和环境定位为 R7；批次扫描与追记归 R11；R3 只承接文件 / 预设，不重复一期计数实现。删除固定路径、全局 `done`、固定七类文件 / PASS、固定宿主调度、按行迁移和额外台账提议；未删除逐包独立复核、当前身份、失败保旧、目录实际消费或清理恢复保护。
5. **直接验收：** 第 4 节保留每组正反例和实际消费链路。核心证据是无主会话任务可执行、未复核 / 过期包被恢复与合并拒绝、目录在实际位置可阅读 / 导出、批次结果对应当前事实且后续历史可回查；文件存在、字段齐全和旧测试通过不替代这些结果。
