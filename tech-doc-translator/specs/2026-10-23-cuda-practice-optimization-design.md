### 2.2 随整体设计获批的方案选择

1. **表格格式 D2：**解析源和中间译包可保留受校验的 `[TABLE-CODE …]`；合并发布时转成可读的格位代码说明。成品不保留实际解析标记，旧中间包可重新核验后复用。

3. **并发默认：**每个新故障事件把当前上限减半并向上取整，最低为 1；停滞观测窗默认 10 分钟且至少两次宿主观察，冷却默认 60 秒，持续限流逐次延长，最长 10 分钟。更明确的宿主等待要求优先；用户可覆盖时间参数。下降后本次运行不自动回升。
4. **术语与风格 D4：**采用已有基础约定，CUDA 特定译法及风格留在项目规则和项目词表；补同构样例与任务传递，不把未经裁决的项目偏好升级为全局默认。

第 3 项是本方案提出并随整体设计获批的默认值，不是固定子 Agent 数量。第 1、2 项的新格式行为也已获设计批准；实施仍须满足完整计划批准及明确开始指令的门禁。

## 4. 最小方案与表格机制重审

### 4.1 可行方案比较

| 方案 | 能否满足同一要求 | 维护与选择 |
| --- | --- | --- |
| 保留项目适配层，并让组件正式支持它的挂接与核验 | 可行，但须维护解析、规则、核验及安装版本之间的外部耦合 | 不选；本次常见 Sphinx 行为应进入现有入口，继续分散修补容易再次出现阶段冲突 |
| 在现有入口收敛：补解析、扩展原表映射、合并时确定性转换、最终独立验收 | 可满足 R1–R11，并保留现有源家族与工作包 | **采用**；只新增缺失职责，不建立完整新流水线 |
| 建立统一 IR、调度器及重建服务 | 可以承载目标，但要求重接所有源家族、工具和证据 | 不选；现有块扫描、映射、资格及协作流程已承担大部分职责 |

更少改动的“只增加标记黑名单”无法保留代码归属，且拒绝合法中间包；“只补正则”无法同时保证块边界和多次写回位置；“原表映射 v1 不扩展”会强迫格内代码重复。它们不是满足同一需求的可行替代，不能借此缩小要求。

### 4.2 正常与失败场景、根因边界

正常操作应只改变声明的表示：生成分隔行、把标记变为可读说明、在表外补锚点后，逐格内容、顺序、代码所属及题注对应不变。当前源码可定位的失败机制如下：

| 当前证据 | 可确定的失败条件与原因 | 对方案的约束 |
| --- | --- | --- |
| `recover_table_data.py` 先扫描 `joined` 得到所有位置，再向 `bodies` 写回可变长度块 | 前表插入数据后，后表仍用旧位置；位置基线与当前内容不再一致 | 以不可变输入建立一次转换，完成后独立重读候选；不在变长内容上沿用旧索引 |
| 同脚本按此前出现过的题注决定表归属，并以列数 / 行数作为恢复依据 | 无题注表可能继承不属于它的题注；相同行列数不能证明源格或内容相同 | 回查同源表身份及逐格事实；没有可信旧内容时拒绝猜补 |
| `add_internal_anchors.py` 可在任何包含 `(#anchor)` 的行前 `insert` | 引用出现在表格数据格时，锚点落入数据区；本次实测当前表格读取配置将其读成额外行，污染格位 | 先定位原对象，再选择该对象的合法块边界；引用出现位置不是目标位置 |
| `_MarkdownFacts.table_records()` 对围栏清状态、跨后续块寻找未用围栏 | 第二个格代码丢失或标记跨过其他正文绑定到后表 / 非表代码 | 读取完整表格及相邻代码组；缺、重复、越界、跨组绑定均拒绝 |

### 4.3 收敛决定

组件负责从可信输入构造正确候选并拒绝损伤，不增加“对任意损坏文件猜测修好”的官方修表器。源表展开进入既有解析器；中间代码表示转换进入既有工作包合并；锚点生成进入解析 / API 合并；三者使用同一 Markdown 块与表格事实读取。原 HTML→解析源仍由独立源对账证明，译文含义仍由实际回源复核证明。

多处修改使用原输入的块范围一次性构造新文本，或使用从后向前应用且有重叠检查的等价方式；二者由实现者选择。不得在同一循环里一边改变长度、一边复用旧索引。候选重读检查通过后才替换目标；旧文件、来源和历史资格不作为临时缓冲。

## 5. 解析保真：数学与结构容器

### 5.1 数学口径（R1）

`render_inline` 先识别源数学节点并保护其序列化结果，再对非数学文本做标点整理，最后恢复受保护片段。沿用已有行内代码保护；代码、货币、转义与未解决定界仍由共享数学扫描区分。扫描失败必须定位，不能退回会改写公式的旧整理路径。

API 数学节点只剥除已匹配的最外层 `\(...\)` 或 `\[...\]`。源预期、解析输出及 Markdown 读取采用相同“外层定界转换”合同，保留原家族的行内 / 块级类型及既有允许的换行折叠；不对全文替换 `\[`，不额外压缩公式内部空格。源节点独立读取和实际 Markdown 解析仍分开，避免双方共用错误生成结果而同时通过。

### 5.2 容器及图片（R2）

API 复用 `rich_container_lines`、定义列表及图片选择 / 绑定能力，补充以下真实结构分派：

- 链接包裹图片：按图片节点提取资源与显示尺寸，保留链接语义和相邻文字；整个子树只消费一次。
- 富 `blockquote`、脚注列表及其他已定位结构容器：沿源顺序逐块递归，保留父属。纯文本容器继续原行内合同；未识别且可能丢结构的节点报告位置。
- `sd-tab-set`：每个标签和面板作为一个顺序单元，标签使用项目既有加粗约定，内容仍按原块类型读取。已有 `sphinx-tabs` 使用同一嵌套缩进出口。
- `details`、既有脚注分支不重复实现；定义项和列表中的递归结果，由父容器统一施加缩进，不能靠临时哨兵字符泄漏到产物或修改代码正文。

独立源事实同时检查容器所属、顺序、图片选择和代码 / 脚注关系；既有其他家族只接入共享修正，不机械改变其外部表示。

## 6. 表格完整链路（R3、R4、R5）

### 6.1 显式网格展开

`parse_api_html.py` 保留原位置参数，新增显式 `--expand-tables grid --table-conversions-output <JSON>`；两项配对使用。未启用仍拒绝不可直接表示的跨行 / 跨列结构。输出先进入候选，英文 Markdown、必要显示尺寸映射及表转换映射全部核对后才发布；任一失败不留下可被误认成功的新配套文件。

对每个源表按实际 DOM 行与单元格编号，另建二维覆盖网格；两种坐标均从 1 开始、包含表头。跨度须为可解释正整数，冲突、越界、嵌套表或不能保持语义的结构明确拒绝并定位。不得自动补造数据行或把未知空白填成“不适用”。

每个源格的文字、行内代码和数学投影到其全部覆盖位；格内围栏代码只在原点格位登记一次。输出是真实 GFM 表：首行作 GFM 表头，剩余源行按原序保留；多层表头保留各行和重复的分组标签，后续表头行中的 th 以加粗保留可读区别，不自动压缩或推断新字段。独立表事实保留 th / td 及表头所属；对应层级含义须实际回源确认。管道、反斜线与公式的转义以最终阅读字符不变为准。

无源格覆盖的网格洞保持空字符串，并与真实空源格区别记录于当前表事实；矩形结构不等于自行补值。无法在当前 GFM 表示中说明分组含义时，保持阻断，使用已有显式人工转换与复核通路。

### 6.2 转换映射 v2 与消费者

沿用现有 `locate`、DOM `row/col/rowspan/colspan`、表格 `targets` 的含义。新映射强制当前 `snapshot_sha256`；v2 限于本节的确定性网格展开，对含围栏代码的源格增加 `code_target: {table, row, col}`，必须为该源格的原点 target。无代码格不得虚报 code_target，格内代码按原顺序只投影一次，不按代码文本去重。旧 v1 的人工重组和 note target 能力保留原合同，不挪用到自动网格模式。

独立对账从原 DOM 的实际格位和跨度重建覆盖关系，逐项检查映射，不调用生成侧网格结果作为预期。含空源格的全部覆盖位必须声明；真实空源格、无覆盖洞、表头角色、格内容及代码原点分别核对。不能仅检查非空输出格有来源，就放过覆盖位漏声明或错位。

v1 继续按原合同读取，不能悄悄改变其“向所有 targets 投影代码”的解释；自动展开统一生成 v2。旧工具遇 v2 拒绝未知版本，不能把它当 v1 部分消费。v2 的新增语义、读取器身份及相关局部映射进入既有 `check_policy`，修改映射须重新回源。

交付源链新增快照级 `snapshots[].table_conversions`，路径仍相对 `delivery_root`；单快照可继续使用 `sources[].table_conversions`。两级并存必须指向同一映射；多快照的条目级旧声明只在其摘要唯一对应一个快照时归属，否则拒绝。每份快照只与自身映射及已声明 Markdown 区间对账，局部表序号不跨快照累加。

`verify_delivery`、项目上下文准入、拆包、任务生成、逐包检查、恢复与合并使用这份源记录。准入确认全源；逐包资格只绑定该包相关表与映射事实，避免无关表的编辑使所有包失效。`structural_conversions` 仍是已有的人类裁决说明，不能拿文本说明冒充机器逐格映射，也不增设“跳过此表”的开关。

### 6.3 格内代码的阶段表示（D2）

| 阶段 | 合法表示 | 核验与下一阶段 |
| --- | --- | --- |
| 解析英文 | 旧简单表 `[TABLE]` 或显式展开 GFM；格代码使用 `[TABLE-CODE r=R c=C#N]` 后接围栏 | 与原 HTML 逐格及代码归属独立对账；r/c 为该解析输出表坐标 |
| 翻译中间包 | 正文表为真实 GFM；保留并校验格代码坐标标记；工作包代码占位须先经已有 splice 入口还原 | 显式中间阶段检查；GFM 表、代码组和坐标一起核验，主 Agent 回源确认中文格义 |
| 最终页面 / 章节 | 标记转换为普通可读说明，例如 `本表第 2 行、第 3 列的代码 1：`，紧接原围栏 | 最终检查无实际解析标记；说明坐标、相邻表和围栏共同核对，不能仅比较代码集合 |
| PDF | 保留表格及可读格位说明，原代码不变 | 阅读和视觉复核能判断代码归属，无 `[TABLE-CODE …]` 泄漏 |

这里的“第几行”包含首行表头，不包括 GFM 分隔行；说明对应实际输出表格坐标，n 为该格代码出现序。说明不增加翻译含义，只替代原内部归属信息。它是本方案的可见格式选择，随设计一起批准。

中间阶段通过 `verify_translation.py --fragment --table-code-stage intermediate` 等对应真实入口显式选择；缺少阶段参数默认最终规则，禁止把交付检查切到中间模式。各家族最终核验均检查相同的最终表示。任务和 check_policy 携带真实参数及阶段规则，不从“文件名看起来像 draft”猜阶段。

工作包合并入口增加显式 `--finalize-table-code`，只对已通过当前源 / 规则 / 逐包复核的中间包构造最终候选；不覆盖中间译包。没有标记的旧最终格式仍按最终检查接受；旧包有合法标记时重新核验后转换，错误或已丢归属的旧包不能仅凭旧 PASS 自动迁移。单页结果也可使用现有合并入口与明确 scope，无须再加一支清理脚本。

### 6.4 输出事实、损伤检测与写回

输出侧按真实块结构读取表格及“相邻说明 / 标记 + 紧随围栏”代码组。空行可跨越，任意其他正文、标题、下一张表都终止当前代码组；不跨这些边界寻找下一个围栏。围栏内、行内代码中的同形标记是字面内容，不参与残留或归属判断。重复键、越界、缺围栏、多余围栏、孤儿说明和跨表代码全部定位拒绝。

原 HTML→英文解析源使用完整逐格内容比较；英文→中文在逐包与最终检查中，对照同源表或已批准转换后的格位、表头层次、代码、公式、图片和其他既有硬不变量，拒绝缺行、额外伪行、错列及错表，再加实际语义复核。不能以英文中文逐字相等作为译文门禁，也不能从链接完整或数字提示推断表格完整。中间中文→最终中文是确定性表示转换，必须逐表核对格值、顺序、列位、围栏字节与格归属完全不变，并验证只有预期标记行变成对应说明行。

表格分隔行由已识别表格事实序列化；最终输入若连表边界或数据都不能确认，直接拒绝，不尝试原地修复。锚点仅放在表外边界，题注与表归属不得变化。单纯总行数守恒或代码多重集相等均不能证明无损。

候选独立重读、语义硬检查及受影响表格渲染检查通过后，使用现有失败保旧的发布方式。单个最终 Markdown 原子替换；配套解析文件使用本次独立的新输出位置，不能逐个覆盖旧来源文件。全部验证完成后，主 Agent 才按既有准入流程更新来源记录的当前引用；中断最多留下未被引用的候选，不使旧有效记录指向一半新文件。显式展开模式须拒绝覆盖已存在的输出文件，并保护源文件、旧映射及其引用；普通旧 CLI 的未启用行为保持。身份变化后旧完成资格失效，不能只更新摘要。

### 6.5 计数与入口（R5）

拆包和任务计数消费同一表事实读取，识别 `[TABLE]` 与真实 GFM，排除代码示例；表及其格代码组保持原子拆包。列表信息计数共用实际有序 / 无序项口径，保留“提示、需解释”的级别，不新增计数相等硬门禁。

API 入口最少一个源文件，其余 manifest、独立官方 TOC、范围、顺序、资源和源内容核验保持；零源仍失败。项目文档示范调用现有 `export_heading_list.py`，不移入项目的简易 `heading_titles()`，也不将生成标题表当官方依据。

## 7. 任务规则与自动减并发（R7、R8）

### 7.1 规则变化和当前资格

分派前主 Agent 核对规则、样例、阶段和检查命令的关键行为，已知冲突写入既有 `rule_conflicts` 并停止受影响分派。生成任务必须引用当前实际规则选区、所选术语、输出阶段及对应命令；脚本检查结构化冲突声明，不承担任意自然语言裁决。

规则改变后保留旧任务实际正文及只读旧源包，以 `--previous-task` 展示精确变化。受影响旧任务不再授予完成资格，待其目标无旧写者后按当前口径复验与实际复核；无关有效包复验复用。只更新文档版本、发出消息或写“已同步”均不能解除漂移。

表格阶段、合法交付链接转换以及已裁决术语的示例直接进入既有上下文，不另建规则版本登记文件。最终合并后仍须整页 / 整章及交付级独立核验。

### 7.2 运行位置与可观测事实

自动减并发写入 Skill 的主 Agent 协作行为和工作流说明，由当前会话已使用的宿主子 Agent 工具执行；不新增跨宿主调度 CLI 或守护进程。宿主的运行、终止、失败、限流、进展与等待状态是依据。错误码按当前宿主解释，不硬编码 `1302` 为通用限流。

主 Agent 保留本次运行所需的少量会话事实：用户上限 U、当前分派上限 C、在途目标及所有者、最近进展与故障事件、冷却截止点。宿主硬上限参与取最小值；用户未给 U 时沿用宿主允许和当前任务已选择的初始并发。日志写到既有任务记录或工作区外，不建立持久调度数据库。

文件 mtime 单独不构成停滞。明确宿主停滞可直接触发；否则须至少两次状态观察，跨度达到停滞窗，且没有新的进展、完成或明确仍在执行的正常长操作依据。等待用户输入、已知长耗时操作及主 Agent 主动暂停不按停滞处理。仅状态不明时可以保守降并发，但必须继续保留旧写者所有权，不能声称其已失败。

### 7.3 自动动作与停止条件

| 事件 | 自动动作 | 不可越过的边界 |
| --- | --- | --- |
| 新停滞或新限流事件 | `C := max(1, ceil(C / 2))`，再与用户 / 宿主当前上限取最小；立即停止超出新上限的补派 | 不为达成瞬时人数目标强杀健康任务；在途超过 C 时等待其自然下降 |
| 同一故障被反复观察 | 只更新状态，不重复减半 | 事件以宿主事件身份或“执行者 + 同一次未恢复故障”去重；没有恢复事实不制造新事件 |
| 限流恢复前 | 遵守宿主 Retry-After；无明确等待值则从 60 秒冷却开始，新恢复尝试再遭限流时翻倍，最大 10 分钟 | 冷却中不提交新子任务；更长的宿主要求不得被本地上限截短 |
| C 已为 1 且仍限流 / 停滞 | 保持 1，暂停无效补派，报告当前故障及已有产物 | 不降为 0 后永远静默，不无限循环创建同一失败任务 |
| 用户设上限为 0、暂停或停止 | 按用户指令停止新分派 | 不用最低为 1 的算法覆盖用户停止指令 |
| 原执行者明确终止或已确认撤销写权 | 可按既有恢复入口核对 draft / target 和当前资格，再决定接续 | 状态不明不能启动同目标第二写者；不以文件存在作为完成 |

减并发首先改变分派上限；实际在途数量随完成 / 退出减少。确已停滞的执行者可按宿主取消能力请求停止，只有收到终止确认后才释放目标；取消未确认时保持占用。保留已完成健康包，本次运行不自动提高 C；用户可根据恢复情况明确调整上限。

以上没有给无人值守重试 / 重派授权。接续仍由当前主 Agent 在原任务授权内完成来源、规则、单写者和已有产物核对。会话恢复时先读宿主实际在途，不能从旧日志推断全部已退出；不能确认的目标冻结补派，其余目标可继续保守运行。

## 8. 合并与 PDF 交付（R6、R9）

### 8.1 来源目标到最终链接

翻译页面保留原链接目标；交付阶段才做获准的路径和命名空间转换。源对象身份为“规范化源页路径 + 原 id”，不能只有 id。解析时把被支持内容块承载的原锚点放在该块合法边界，表 / 图锚点放在对应对象前并留空行；不依据译文里引用字符串的位置反向猜目标。

API 合并从既有 source_record 的 snapshots 与 covers 取得源页→最终章节归属，显式 `--navigation-record <交付记录>` 指定；只读来源准入与声明，不要求候选最终章已存在。一个源页须唯一归属该次输出章；多义 covers 必须细化源链声明，不能选第一个。最终验收使用同一记录重建预期对象关系。

合并时为页内 id 加稳定的源页命名空间，编码由实现者选择，但须可重复、无歧义且检测冲突。原 `#id` 在合并前先解释为当前源页 id；`other.html#id` 先相对该源页解析。目标同章生成该章片段，跨章生成明确的相对 Markdown 文件加片段。指向源页本身的链接落到该页首个已确认内容目标；源页不在交付范围或对象无法映射时定位拒绝，不丢链接。

锚点归属通过来源块角色和已核对的标题 / 题注 / 图表出现对应确认；不能可靠定位的行内目标保持未解决，不一律提升到最近章节。题注尾部 `[#](#anchor)` 属于正常链接事实，适用同一转换。

API 最终核验比较转换前后的源对象身份，允许的链接变化只有上述确定映射；其他删除、改目标或错章仍失败。普通独立 Markdown 不要求补 API 导航记录。PDF 的 `resolve_fragment` 直接采用用户批准的本章限定，不保留旧跨章后备开关；明确 `other.md#id` 仍按文件与片段定位。

### 8.2 图片映射组合

复用 `rebuild_images_display.py`，新增与原 `--manifest` 模式互斥的可重复 `--compose-map <章映射>`，仍用 `--output <交付根/export/images_display.json>`。不改动 `merge_api` 既有单章基点合同，不另加只修一类路径的 `--markdown-base`。

每份输入必须仍能按自身所在目录解析。先把 markdown、image 及需要解析的来源引用解析为规范化实际路径，验证当前资源身份、出现位置和尺寸依据，再相对最终映射目录重写所有路径。不能先把原映射搬到新位置再猜旧基点；旧映射已被搬移时，用现有回补清单从原快照和最终 Markdown 重建。

出现序号属于一个 Markdown 文档，在组合多个章节时不全书累加；同文档相同 occurrence 的冲突或重复声明拒绝。不同章节可同名但不同实际图片；同一最终资源路径承载不同内容仍拒绝，不新增静默改名策略。确定项与 undetermined 一同保留，后者不能被错误变成已确定尺寸。

候选组合映射重读、全覆盖与实际资源核验通过后原子替换；旧成品及输入章映射不被覆盖。用不同 cwd 读取和实际 PDF 宽度复核证明基点正确。

### 8.3 脚注与译注剩余内容

导出建立整章脚注定义、引用出现顺序和显示编号上下文，原始视图与去译注视图分别实际渲染。`verify_pdf` 的剩余文字核验复用同一渲染配置及章级上下文，不再用无脚注环境的局部 CommonMark 渲染代替。

只排除批准的译注片段；根据源片段保留其外的文字、脚注引用和定义。脚注显示编号如因视图变化重排，用“标签 + 第几次引用 + 对应定义”的角色关系解释编号变化，不能直接把 label 当显示编号。代码中的 `[^label]` 仍是字面内容；重复引用、命名脚注及同行正文分别核对。

预期保留内容从原 Markdown 及批准的删除区间独立取得，实际结果来自候选渲染 / PDF。不能直接把删后 DOM 的文字再当作它自己的预期，从而掩盖连带删除。真实 PDF 还须阅读脚注标号、定义与同行文字，机器通过不代替视觉复核。

### 8.4 模式化依赖预检

在排版、浏览器启动及打印前，使用当前解释器检查本次路径实际消费的依赖和运行资源：核心 PDF 解析 / 渲染、候选代码核验的 `uniseg`、位图处理的 Pillow 及选定浏览器；视觉辅助启用时才检查 PyMuPDF。普通翻译不载入 PDF 依赖。

| 旧英文解析稿、旧锚点和当前修订 | 旧英文解析稿缺源 ID；当前章有缺失、重复或错绑锚点。第二章另有 4 个裸片段指向代码对象，其中两个锚点被放到同一段前；现有 `source_anchors` 未覆盖这些代码对象。双语题注还将同一个外链保留两次，而英文源只有一次 | 不能直接给旧文件补 `--navigation-record`、信任旧锚点位置，或用旧译页重新覆盖当前章；恢复不能删现存链接换取严格检查通过 |
| [`export_pdf.py`](../skills/tech-doc-translator/scripts/export_pdf.py) | 已纳入的 `.md#id` 和本章片段可消解；遗留 `.html` 被归为范围外，Chromium 将其写成临时目录 `file://`。复制候选前已有独立代码核验 | 转换在合章层完成；PDF 入口只读核对来源及成品，不再实现一份源 HTML 转换器 |
| [`verify_pdf.py`](../skills/tech-doc-translator/scripts/verify_pdf.py) | 已有 `/Link`、MCID、`/OBJR` 与真实 `/Annots` 绑定，显式锚点有部分逐实例检查；标题链接仍主要检查目标页。实测同页目标互换可通过 | 扩展既有逐实例检查到正文和全部内部目标；计数与页级存在性不能作为成功依据 |
| [`verify_delivery.py`](../skills/tech-doc-translator/scripts/verify_delivery.py) | 正式交付要求范围外待处置项闭合，并绑定实际检查依赖；本次仅证实独立机器门禁漏检 | 保留正式交付门禁，不宣称已证明它整体绕过；新增来源依赖进入原绑定和重跑路径 |

第 8 节与第 13 节已建立导航转换和来源身份约束，本轮继续增加恢复入口、扩大成品检查前，需重审其衔接：正常新任务拥有源锚点及逐页译文，适合严格合并；旧项目缺少锚点、未接导航且当前正文已有修订，直接重跑严格合并会拒绝或丢修订；即使输入链接正确，PDF 检查仍可能接受另一条链接或同页另一目标。根因分别落在接入、恢复基线及成品对应关系，单补 URL 正则不能覆盖。

| 满足同一需求的方案 | 取舍 |
| --- | --- |
| 在合章层恢复/转换导航，PDF 层共用逐实例核验 | **采用。** 正常和存量输入共用来源解析与目标命名；存量增加有限输入模式，PDF 保持呈现与成品检查职责 |
| 在 PDF 导出前构造来源投影，直接保留旧 Markdown，按来源改写临时 HTML | 可满足结果，但必须在导出、独立核验和正式交付中再处理旧页边界、锚点恢复及正文绑定，且 Markdown 导航仍坏；与合并器重复的机制更多，不选 |
| 单独建立存量修复工具，再交给现有正常合并 | 可满足结果，但仍需处理当前译文与源文链接出现差异，增加一个入口和恢复合同；现有合并器能容纳该输入模式，不选 |

仅把原 HTML 文件复制到导出目录会留下依赖本地文件的成品；只改 49 条 URL 无法处理源页起点、跨章、错绑锚点或漏检。它们不满足同一需求，不作为可行简化方案。

### 14.3 来源合同与正常流程

唯一来源依据继续使用 `source_record` 中已准入的原快照、解析范围及 `covers`。`load_navigation` 负责生成运行期页/对象索引；不按 basename、同名 ID 的首次出现或相邻文件猜对应关系。索引覆盖引用所需的源页，PDF 输入列表单独决定实际纳入章节，两者不混为一谈。

原页无片段链接指向该页内容在合章中的起点；有片段链接按原 DOM 的实际对象定位。扩展现有源对象读取和锚点验证，覆盖代码块/代码清单、有 ID 的段落及 Sphinx 注释，保留标题、表格、图和同对象的多个别名。页面入口使用既有 `namespaced(page, None)`，对象沿用源页与原 ID 的命名；同名 ID 在不同页互不冲突。无明确可渲染对象、缺失目标或同页 ID 歧义必须定位失败，不能绑定到附近标题。

新任务继续由现有解析器保存源锚点，译文保留锚点及原链接，合章时才转换。`merge_api` 和正常 `verify_api_translation` 发现源页或译页存在来源页内/页间引用时，导航记录为必需输入；缺失即失败。没有这种导航需求的输入不强加来源记录。原始源链接参与判断，不能靠译文删掉链接规避。工作流说明和正常命令样例同步传递同一记录，不能只改推荐示例而留实际入口静默降级。

合并仍使用 `target_for`：同章转换为带页命名空间的片段，跨章转换为目标 Markdown 路径及片段；外部 URL 保留。`verify_page` 独立从源 HTML/解析稿重建预期，核对目标及每次出现。已有源译链接严格一致、表格、代码、数学、图片和来源角色检查保持。

### 14.4 存量恢复：以当前合章为不可变基准

建议在 `merge_api` 增加显式恢复输入，例如 `--recover-navigation-from <current.md>`；同次必须提供 manifest、独立 official TOC、site root 和 `--navigation-record`，复用正常 API 核验的 TOC 口径。恢复读取当前合章，不读取旧 `trans_*` 作为正文。当前输入、候选及最终路径分别明确；原件只读，不能原地覆盖恢复基准。

恢复基准可为当前章的逐字节冻结副本，与输出使用相同资源基点但不同文件名；`covers` 绑定最终逻辑章路径，临时候选始终按该路径核验。真实验收在保留原章文件名和相对目录布局的项目副本中输出，新来源记录显式更新副本根路径。不能把基准快照名或候选临时名写成目标章，也不靠重新命名章文件改变已有跨章 Markdown 引用。

1. **准备可信来源。** 在工作区外从现有原 HTML 快照重新使用组件解析入口生成带源 ID 的解析稿，并沿用原来源记录的准入/对账方式建立当前记录。保留原解析范围和必要转换事实；旧解析稿不能因“只有锚点差异”而免核。来源准备不重新翻译正文，也不把旧无锚点解析稿当成正确对象位置。
2. **确定当前页范围。** 复用 `_split_pages` 的围栏外分隔规则获得候选范围，先核对 manifest 与独立 official TOC 的集合及顺序，再逐页校对来源归属和完整标题序列。页数相等本身不足；多余分隔、标题不匹配或范围重叠失败。按原始字节区间处理，保留当前分隔、空白及正文，不重新序列化整篇。
3. **恢复对象锚点。** 以原 DOM 的 ID→对象关系为真值，在对应当前页内确定同一译文对象。标题使用已核对的层级、官方原题/编号及上下文；代码用现有逐块代码对账，图片用资源身份，表格用现有逐格/转换映射。位置序号只能辅助，不能单独证明身份。段落等按已对应的页面、标题范围及原解析对象结构核对；仍不能唯一对应时停止，报告原 ID、当前候选位置及缺少的依据，不能自动猜补。现有语义复核记录不承担机器可消费的对象映射，人工 note 不能豁免这一失败；本次不新增持久对象声明或人工强制通过入口。正确锚点保留，已证明错绑的源锚点移至正确对象，冲突按源页消歧；没有来源依据的用户自定义锚点和链接不随意删除或重绑。
4. **转换当前每次引用。** 从当前页的真实 Markdown 链接 token 枚举，以当前页身份调用同一目标解析器。现存链接文字、顺序、数量及外链逐次保留，代码中的伪链接不参与。已有可用的 Markdown 链接、标题 slug 及脚注按现有作用域保留；只有能证实属于源 ID 的裸片段才随恢复后的对象改写。已正规化链接须验证后保持幂等，不能重复添加命名空间。
5. **独立证明只改导航。** 新增有限的恢复核验函数，由候选门禁和 `verify_api_translation` 的显式“仅导航恢复”模式共同调用。独立重读基准、候选和来源：逐实例重新推导合法 href；核对新增/移动/命名空间化的锚点确实落在相应对象；把这些已验证的编辑及锚点合法块边界必需的空行反投影后，必须与当前输入逐字节一致。检查不能直接信任生成侧的编辑清单。不得放行正文、可见链接文字、代码、数学、图表、资源引用或合章后修订的变化。

恢复模式不重复图片本地化或重建显示尺寸映射；沿用当前章的资源解析基点。候选最终位置须与当前章相同目录层级/资源基点，或在保留同一相对目录布局的副本中运行；本模式不承担搬移内容时的资源改写。

恢复核验只授予“导航正确且当前内容保留”的结果。正常源→译核验仍严格，不以当前基准豁免真实翻译缺陷。`verify_delivery` 在既有检查参数解析/重跑处拒绝把“仅导航恢复”模式登记成完整翻译 PASS，不增加长期资格类型或平行台账。独立 PDF 导出可以使用恢复后的 Markdown 与明确的来源导航记录；若申请完整翻译交付，仍须满足原有全部检查和人工复核。第二章现存双语题注外链重复必须原样保留，作为这一区别的真实回归用例。

### 14.5 PDF 入口、范围判定与依赖绑定

建议 `export_pdf` / `verify_pdf` 接受显式 `--navigation-record` 与配对的 `--site-root`，只读核验已经正规化的 API Markdown，不在这里恢复正文或转换 HTML 链接。现有 `load_navigation` 需要 site root，`source_record` 自身未存该值，不能从目录结构猜它。翻译加导出从 `--translation-record` 的现有就绪投影获得实际 API 检查消费的同一记录和 site root；显式声明与投影不一致即失败，不自动搜索邻近文件。同一合订输入可组合多个已核验的记录/站点根配对；同一源页或目标章出现冲突归属时拒绝，不能覆盖前一个。

现有就绪投影尚不足以重建全部源页/章关系，需在原投影补充每个 API 输入实际消费的导航记录引用、site root、来源身份及 `covers`。归一化检查事实（当前实现为 `verify_delivery._check_facts`）、依赖摘要、报告输入和独立重跑须绑定同一记录及其快照/解析稿依赖。改动沿用原记录体系，不另存一份可编辑的页→章真值；来源文件或范围改变即使旧资格失效。恢复基准进入恢复检查的文件依赖，不能只保存参数字符串或一次成功结论。

| 已确认上下文 | 处理 |
| --- | --- |
| 来源目标可定位，所属章在本次 PDF 输入中 | 必须对应当前 Markdown 的正确对象，最终为 PDF 内部跳转；残留源 HTML、缺锚点或错绑失败 |
| 来源目标可定位，所属章明确不在本次 PDF 输入中 | 报真实范围外，保留既有报告及正式交付逐项处置规则，不自动补章 |
| API 来源记录必需但缺失、源目标不存在、归属歧义、对象未对应 | 报解析/依据失败，带当前文件、行、链接文字、原 href 及缺失依据；不得当作范围外 |
| 普通独立 Markdown，无 API 来源上下文 | 保留原 `.md#id`、本章裸片段、外链、术语表投影及范围外待处置合同，不要求 API 记录；也不声称已证明它与某套 HTML 来源的对应关系 |

组件工作流已识别为 API/Sphinx 翻译项目，或翻译记录声明 API 来源时，必须走有来源的路径，不能通过去掉参数再运行普通 Markdown 导出取得成功。用户仅提供不带来源的独立 Markdown 时，工具不能凭 `.html` 后缀猜它是 CUDA 或 Sphinx；继续明确呈现原有待处置项，不能宣称它们已闭合。这一边界避免为修复 API 导航改变普通 Markdown 的既有行为。

### 14.6 PDF 逐实例与具体目标核验

核验器独立重读 Markdown、所需来源记录和实际 PDF，不采用导出器的成功计数作为证据。沿用当前 `PdfFacts`、结构树和绘制事实，完成以下对应关系。

1. **预期引用。** 逐次枚举实际呈现的链接，保留完整文字、输入行/块位置、出现序、目标章及对象；不以当前报告的 80 字截断文本作为身份。目录折叠、管理字段及术语表等既有投影仍独立复算；正常保留的正文引用逐条检查。
2. **该引用自身的注解。** 把 `_toc_link_instances` 中 MCID、`/Link`、`/OBJR` 与页面真实 `/Annots` 的归属检查推广到正文。保留内部、外部、坏目标及缺注解的实例槽位，按结构顺序、完整文字和所属块匹配，不能跳过坏实例后消费下一条同名链接。纯图片链接以自身图片绘制归属定位，不能因没有文字跳过。一次折行对应的所有绘制段均须被自身注解覆盖；重复文字、同页同名链接及跨页折行不能合并成一次。
3. **目的地身份。** 读取命名目标与直接数组目标的实际目的页、目的地类型和位置参数，统一成可比较事实；注解矩形的 `top` 只描述点击区，不能充当目标坐标。命名目标必须属于期望对象，直接数组必须落在同一对象的有效目的地；只比页码不通过。
4. **目标对象确实在该处。** 从当前 Markdown 锚点关联及来源对象独立定位 PDF 中对应的标题、段落、表、图、代码或源页首内容，结合结构树/绘制内容验证目的地与对象位置。当前 Chromium 的结构节点没有可直接消费的 HTML ID 或对象边框：使用已核对的对象顺序及 MCID 自有内容匹配；图片补充现有图片绘制读取的 MCID 归属和变换坐标，表格取对应 `/Table` 首片段，跨页代码取自身首片段。不能把 PDF 自己的命名表同时当预期和实际，以免目标表错绑自证正确。同页不同目标必须可区分；无法建立对象位置或实例对应时明确失败，不能退回页级/计数通过。

位置比较需采用当前打印布局的坐标换算与对象边界，而非要求目标坐标等于首字基线。现有真实 PDF 的命名目标与标题文字/大纲约有 55 pt 差异，其中实测版心上边距约 51 pt，另有行盒与字形边界差；不能把总差值设成通用容差。实施者须以实际 PDF 几何变换、打印页边距及小范围真实打印证据确定统一坐标，容差限于对象自身行盒与数值舍入，不得覆盖相邻目标。具体 Chromium 目的地坐标的一般换算仍待实现时验证；若无法独立判定，须报告实现缺口并重新审查该部分方案，不能以人工点击替代机器阻断要求。

保持现有诊断/报告体系，逐条输出预期目标和实际动作/目的地；汇总数只用于阅读。正式交付继续消费机器失败与真实范围外待处置项，前者不能通过人工关闭后转为成功。

### 14.7 候选发布与独立核验共用边界

把强化后的 `check_links` 接入现有候选检查：它已独立重解析 Markdown、读取 `PdfFacts`、计算标题及章范围，可在同次读取中完成代码和链接检查，再决定是否复制最终 PDF。可按实际职责重命名 `candidate_code_check`，不新增一套 PDF 比较器。

候选检查调用核验函数，不调用依赖已发布 `export_report` 和翻译就绪重跑的完整 `run_verification`，避免导出与核验循环。独立 `verify_pdf` CLI 在重读报告及真实依赖后调用同一检查。

保旧按各入口的写入边界保证：来源预检、恢复候选或 PDF 候选检查失败时不发布，旧有效 Markdown/PDF 不变；独立核验只读检查调用者指定的 PDF，失败时不改写该文件，也不覆盖此前成功证据。它不负责回滚已经发布或被外部修改的文件；本次不改为“完整独立 CLI 通过后才发布”的新事务流程。链接损伤由发布前同口径的独立候选检查阻断，事后损伤对照只操作副本。本次失败报告写入独立运行目录，带准确输入身份和失败状态，不能复用旧 PASS 标签冒充新运行。

### 14.8 影响范围与直接验收

| 组件 | 本次关系 |
| --- | --- |
| `_api_navigation`、API 解析及源对账 | 复用来源/目标解析；补代码、段落等明确源对象的锚点表示和核对，增加当前基准→导航候选的独立校验 |
