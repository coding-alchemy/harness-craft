## 1. 核心结果与授权边界

主 Agent 能从现有 PDF 勘察结果取得图区、表格行列、双栏阅读顺序及文本层字符缺陷的候选，直接回到原页核验其边界、内容与归属。候选保留原值、依据和不确定项，经主 Agent 实际回源裁决后，才进入现有物化、独立对账及交付链路；未裁决或有损伤的内容不能成为成品。

本文只拆分和细化需求，不是设计、执行计划或实施记录。用户同意四期划分并授权编写文档，不等同于批准新增能力、改变 PDF 源 D4 或授权实现。第 5 节编号公式候选物化是独立待批准扩展，未批准前不进入设计，继续现有人工处理与 `[PENDING-FORMULA]` 合同。

## 3. 范围与跨期依赖

- R8 基础图区 / 表格候选为 P1，常见双栏阅读顺序与字符缺陷辅助为 P2；全部保留在本期，不以优先级取消验收。具体算法、阈值、数据字段及内部文件拆分留给获批后的设计。
- [一期需求](./2026-10-02-paper-practice-phase-1-verification-requirements.md)的共享公式扫描与强 token 修正，是涉及相应输入的可靠硬检查前提。本期候选不能覆盖其失败或另建弱比较器；不把所有一期便利输入设为本期勘察的前提。
- [二期 LaTeXML](./2026-10-02-paper-practice-phase-2-latexml-requirements.md)不属于 PDF 候选的来源前提。[三期工作流工具](./2026-10-02-paper-practice-phase-3-workflow-requirements.md)也不是本期验收的硬依赖：既有人工裁决、复核记录、拆包 / 恢复 / 合并与交付入口可独立完成 PDF 流程。
- PDF 仍按勘察 → 主 Agent 裁决 → 物化 → 独立对账执行。候选补现有清单和页面证据，不授予权威资格；源对账、硬检查、语义及视觉复核继续分层。

## 4. R8：PDF 论文候选辅助

### 4.1 候选证据与不确定项（P1）

- 每项候选能回查当前只读 PDF、范围、页码与页面区域，保留原提取值、判定依据、实际参数、适用条件和歧义。沿用现有 pt、页面旋转及坐标转换口径，不把像素与页面坐标混用；对象编号仅在相同源身份下有效。
- 无法可靠定位、边界冲突或内容不清时明确待裁决，不猜测、不静默删除。候选类别为空只表示未找到候选，不能证明原页无该类内容。
- 机器线索与人工接受 / 修改 / 排除及处理依据保持可辨；未经实际回源裁决，不物化候选内容、不改变阅读顺序、不修改只读源，也不改变核验判定。机器成功退出不授予分派或完成资格。

### 4.2 图形区域候选（P1；来源 02 R2.1、R2.6）

- 在现有图题和页面对象依据上给出可回查的图形区域候选及图题对应，区分同页其他图、表格、代码、正文与装饰，支持单图、上下相邻及并排图的边界核对。
- 候选须包含所属图形、图内文字标签与图例；紧邻正文不能随图区一并吸收，其他题注及结构有各自归属。无大面积外框、区域重叠或疑似双栏时保留具体歧义，不以扩大裁框代替裁决。
- 同号或多次出现不凭图号合并，每次出现保留独立位置与所属依据。`pymupdf4llm` 的图区 / 伪表格经验只作候选线索：矢量图文字被抽为伪表格时可提示其图形归属，不能自动删除、折叠或作为第二条权威来源。
- 裁决后的提取继续按现有 `figure_region`、裁剪目检、资源身份和尺寸合同执行；候选区域本身不能证明裁图完整。

### 4.3 表格行列候选（P1；来源 02 R2.3）

- 对有页面区域依据的表格提供行、列及单元格文本与位置候选，供主 Agent 转录核对；保留列位置、空单元格位置、多行表头及所属关系，不把空值消失或展平词序视为表格保持。
- 参数和适用条件可回查；疑似列合并、错行或表头归属不明时明确待裁决。图内标签或伪表格不能因工具给出表格形态而自动成为正文表格。
- 输出仅作核对辅助，不自动物化为 Markdown 表格。经页面确认的表格重建继续使用现有裁决与转换对应，不能以候选数量、源译展平文本一致或转代码绕过逐格核对。

### 4.4 双栏阅读顺序候选（P2；来源 02 R2.4）

- 对论文常见单栏、双栏及含跨栏图的页面，补充有块 / 区域定位的栏区与阅读顺序候选、双快照差异依据、实际参数及歧义，帮助主 Agent 回到页面裁决。
- 跨栏标题、图形、图题和正文的所属及顺序不得由单一文本流决定；跨栏图不误切为两栏内容。不以一个 PDF 的固定空格数、页宽比例或字符分布推导全部论文的可靠顺序。
- 只提供候选，最终顺序与依据仍记录在现有清单；未裁决不改源顺序。调换块虽保持总字数，也不能通过独立源对账和页面复核。

### 4.5 文本层字符缺陷候选（P2；来源 02 R2.5）

- 对疑似字形映射缺陷、图内文字异常及代码 / 伪代码中的数学字母数字区字符等提供页面区域、原提取值、建议值（如有）、依据与不确定性，供主 Agent 复核。
- 单个 PDF 的固定 glyph 偏移或视觉相似性不能成为通用修复规则；证据不足不猜测字符，不自动 ASCII 规范化，也不削弱代码 golden 的字节合同。
- 主 Agent 按页面及较高保真证据确认后，将裁决值和必要译注要求登记在现有缺陷口径中；区分提取缺陷与原文异常。未裁决建议不改变源、译文或 `verify_pdf_source.py` 的核验结果。

### 4.6 再勘察、复验与完成边界

- 同源同范围再次勘察保留已有裁决值、排除理由、处理依据与阅读顺序；刷新候选不恢复未解决项的完成资格，不把已裁决区域再次变成新未裁决项。
- 源或范围变化继续按现有稳定区域对应合并候选，保留旧裁决并定位新增 / 消失 / 变化区域，进入现有漂移重核；不存在有效 revalidate 时，不能仅删除 stale、刷新候选或重算摘要后沿用旧资格。
- 已裁决候选进入现有清单、源 Markdown、块映射及相应资源事实，纳入现有独立对账和统一交付身份。相关输入、资源或口径变化使受影响旧复核失效；不相关有效包按恢复合同复验复用。
- 未解决素材或源 / 译仍有 `[PENDING-*]` 时，沿用完整交付门禁；机器候选的 basis 不充当 resolution_basis。源依据、清单与恢复所需映射继续受现有收尾保护，临时页面检查图及报告放工作区外。

## 5. 独立待批准扩展：编号公式候选物化

本节承接 R8 的待批准扩展（来源 02 R2.2），涉及[现行 PDF 源需求](./2026-09-26-pdf-source-translation-requirements.md)第 5 节 D4。只有用户明确批准该差异后，才可进入相应设计；批准其他候选能力、四期划分或本文编写均不解除此门禁。

现有回源人工处理与记录仍可按现行合同闭合；本扩展批准不是所有 PDF 交付的前提。以下 pending 要求约束尚未闭合的公式候选及拟新增物化路径。

- 在已有公式文本 / 页码 / 区域候选上，补公式簇、式号和唯一插入位置依据，由主 Agent 对照原页确认内容、行内 / 展示类型、式号、行列结构及所属位置后，经现有清单物化并独立对账。
- 不自动恢复 LaTeX，不按控制字符清理、视觉近似或“保真等级声明”放行内容损伤。矩阵列序交织、定界符缺失及多行关系丢失均须解决，不能仅照录并加说明后算保真。
- 重复 / 多义锚点、无法唯一定位、源身份变化、未裁决或未获此扩展批准时保持 `[PENDING-FORMULA]`；禁止按旧 Markdown 行号就地插入。位置证据必须对应当前源及裁决顺序。
- 补入公式后重新生成受影响源包、块映射和复核依据，沿用恢复 / 合并及交付的失效和复验合同；不采用按行自动迁移译文，也不自动追认已译包通过。
- 独立对账须发现内容、类型、式号与位置损伤，不能只比较生成器产物或公式计数。正式验收覆盖单行、多行、矩阵、重复锚点、未批准 / 未裁决及输入变化拒绝。

## 6. 直接验收

以下是待实现能力的标准，本轮编写文档不代表产品已通过。最小真实 PDF 页面覆盖各形态；至少一份真实论文 PDF 在实际项目路径完成回源核验及适用交付链路。执行前固定源身份、范围、清单与环境，不能用旧项目 PASS 或候选数量替代实际页面复核。

| 编号 / 范围 | 正向与反向场景 | 用户可观察的成功证据 |
| --- | --- | --- |
| A1 / 4.1–4.2 | 单图、上下 / 并排图、图内标签、紧邻正文、无大外框及同页其他表格；矢量图文字形成伪表格 | 候选可回原页，图区 / 图题 / 标签归属正确，邻接正文及其他结构不混入；歧义具体定位。删图内标签、错配图题或扩大至无关正文不得登记完整复核 |
| A2 / 4.3 | 规则表、空单元格、多行表头；同词数但移列、漏空位、错表头归属 | 行列和空位在候选中可辨，经逐格回源确认；损伤在物化 / 转录后的独立对账或页面复核中定位并阻断，不因展平文本一致放行 |
| A3 / 4.4 | 单栏、双栏、双栏含跨栏图；互换两栏块、误切跨栏图 | 双快照及顺序候选可回页，裁决后源顺序正确；反例不能以字数相等或某个文本流通过完成核验 |
| A4 / 4.5 | 疑似缺字形映射和数学字母数字区字符；同类字形但映射依据不同、无足够证据 | 原值、建议及依据有定位；未裁决时源及核验结论不变，证据不足仍待裁决。确认后裁决值 / 译注落实，代码字节合同保持，不能通用套用固定偏移或 ASCII 替换 |
| A5 / 4.1、4.6 | 仅生成候选、未裁决区域、机器 basis 加 resolved、未解决素材或遗留 pending | 候选不能直接取得权威 / 物化内容资格；未闭合项不能完整交付，定位原因与区域。当前有效裁决、独立对账及必要复核闭合后才接受 |
| A6 / 4.6 | 同 PDF 再勘察；随后改变 PDF / 范围 / 区域 / 口径，加入新区域，删除 stale 而无有效重核 | 同源不改已有裁决、不制造同区域重复 pending；漂移后保留旧依据并定位受影响项，旧复核不能被补摘要追认，新发现项不丢失；完成有效重核后可复验 |
| A7 / R8 基础 | 至少一份真实 PDF 经勘察 → 原页裁决 → 素材与源物化 → 独立对账 → 翻译 / 复核 → 当前交付及收尾 | 图区、表格、适用的阅读顺序和缺陷候选逐项可回查，原 PDF 摘要不变，当前证据闭合；加入未裁决或损伤项不能成品，清理后来源与恢复依据仍可用。未请求 PDF 导出不强制生成 PDF 成品 |
| A8 / 第 5 节，获批后适用 | 单行 / 多行公式、矩阵、式号及唯一位置；删字符 / 改类型 / 式号 / 列序 / 插入位置 | 经原页确认后保真物化，独立对账定位相应损伤；当前受影响源包及复核重新生成，旧证据失效。矩阵结构丢失不能靠声明放行 |
| A9 / 第 5 节门禁 | 重复锚点、未批准扩展、未裁决公式、源身份变化及旧行号 | 不猜插入位置、不改当前公式物化边界，相应公式保持 pending；拒绝原因能区分授权、裁决、位置与输入漂移，不能靠换标记或脚本成功完成交付 |

A1–A7 是 R8 基础候选辅助的完成标准；A8 是扩展获批后的额外标准。A9 中未批准时保持现状的边界必须保留，不因本期基础完成将公式扩展标为已实施或已验收。

## 7. 假设、兼容影响与非目标

- 候选只减少重复定位工作，不承诺任意 PDF 的全自动转换或全部缺陷自动发现；常见双栏论文是适用场景，不扩为通用多栏版面平台。无法确认的边界明确保留缺口。
- 新增能力及 D4 差异状态沿用[总需求](./2026-10-02-paper-practice-requirements.md)第 5 节。旧清单及现有调用继续按当前兼容合同消费，不自动补裁决、迁移外部项目或重签历史证据；新增候选不改变人工裁决的信任前提。
- 持久清单增量须进入现有来源身份和复核消费点，若设计需要改变记录合同，须单列兼容差异并按既有机制重审，不能只在候选脚本保存而旁路交付核验。
- 不新增 OCR、位图自动提取、自动 TeX 修复、通用字符替换、线性文本行号拼装或 `pymupdf4llm` 权威通道。不恢复旧按行迁移方案，不叠加独立状态库、证据台账或 PDF 工作流引擎。
- 四类 HTML 家族、现有代码 / 图片 / 脚注 / 强 token 检查、独立 Markdown 导出及清理保护保持；本期不发布或升级产品版本。

## 8. Karpathy 精简与自检

1. **基线：** 第 2 节依据当前 `prepare_pdf_source.py`、`_pdf_source.py`、`verify_pdf_source.py` 与现行 PDF 源规格，区分已实现的候选、双快照、图形提取、独立对账和漂移保护；[PDF 源设计](./2026-09-26-pdf-source-translation-design.md)第 7.3 节已有重审说明候选不能代替裁决、机器 basis 不能代替解决依据。
