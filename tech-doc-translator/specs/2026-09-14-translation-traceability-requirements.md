## 1. 目标与基线

用户能回查译文的同版本源快照、逐图尺寸依据和校验证据；链路缺失在交付前明确暴露，存量映射可在不重译、不改原图的前提下回补。交付根目录便于读者浏览，内部文件分类存放；PDF 默认集中前置出处，10 行以内代码保持整块并允许页尾空白，超过 10 行的代码按完整可见行跨页，禁止长块整体移页让前页仅有几行文字、大半页空白，同时保持代码完整。

依据为用户提供的《tech-doc-translator 留痕链路修复方案》《目录结构整理需求》《tech-doc-translator 代码块跨页拆分修复方案》及仓库提交 `502c8160b97c0eaa230b2b9d675be98a30798d28`（`zn_dev`）。另对照用户指定 CUDA 项目 `scripts/` 中实际存在的 8 个 Python 脚本，采纳范围见设计 4.10。附件及脚本说明中的批准、原型成功、页数和补丁操作不构成本次授权或验证结论。

## 2. 共同约束

- Markdown 与原始资源保持权威。尺寸走 `images_display.json` 旁路，不承诺普通 Markdown 预览器恢复尺寸；PDF 导出只读 Markdown、快照、图片和术语表。
- 导出离线进行；抓取与回补在导出前完成，只用已确认版本。仅导出旧译文不强制补英文源或翻译验收。
- 沿用四类源家族、独立目录、合订选择、默认排除术语表、内容保真、恢复/合并资格和实际交付路径复验，不另建状态体系；目录整理不改变这些选择。
- 尺寸回退与预算告警不改变 CLI 退出语义；显式映射路径缺失、损坏映射、身份错配、非法尺寸仍失败。出处信息不足在所有模式下阻断 PDF 生成；出处或严格策略检查失败时不得覆盖已有成功 PDF。
- 过程报告与临时验证产物放在 Git 工作区外；长期证据使用明确持久位置。项目内 `verify/` 等报告路径及内容须另获批准。
- 不在解析、回补或绑定层自动降采样，不改变合订范围。2026-09-19 获准的资源转换仅限导出层内联前重采样：位图（PNG/JPEG 单帧）长边超过 2600px 时重采样至界限内，只影响 PDF 渲染产物；交付原件字节保留，身份核对在内联前按原图完成，重采样清单记入导出报告并复验显示宽度。其余资源转换仍须另行获准，获准时保留原件、记录身份变化并复验，不能重算摘要后声称原图未变。

## 3. 功能需求

### R1：保存源与尺寸产物

- 新翻译留存同版本快照、解析 Markdown、有图时的 per-stem 及交付级映射，逐次关联源节点和最终图片。尺寸映射是交付资源，无图无需空映射；有图无确定宽度时保存 `undetermined` 原因。
- 沿用项目及源家族目录，不强制迁移 `pages/` 或改变分页解析接口。四类路线输出到系统临时目录时，醒目提示受影响产物及丢失后果，调试仍可成功；覆盖宿主临时目录及等价真实路径，避免名称前缀误报。
- 普通路径不代表链路完整，最终按 R4 检查可回查性。

### R2：明确尺寸回退与严格策略

- 导出前按真实图片出现核对覆盖，排除代码示例。无映射、空映射、仅含其他章条目、部分覆盖均须检出；区分缺失、源无约束和无法确定。
- 导出报告与终端告警列出章节、位置或出现序号、数量、原因、自然尺寸回退及补救方式。核验器从输入与映射重建覆盖并给出一致结论，不以是否满栏决定告警。
- 普通旧译文缺映射时，默认告警后继续并记录限制；明确要求尺寸保真时，暂停导出，待完成回补或用户调整要求后继续。已有决定不重复询问。
- 提供显式严格策略：每次图片出现均须有确定、有效的源尺寸，缺失、部分覆盖及 `undetermined` 均失败。无图不告警、不因缺映射失败；普通模式仍接受无源约束图片。
- 交付说明按出现次数列出总数、已恢复数、未恢复数及三类原因和相关决定，不按去重文件数统计，也不把导出成功等同于尺寸恢复成功。

### R3：回补存量尺寸映射

- 提供四类源家族共用的可重复回补入口，输入为已确认版本/范围、快照或同版本来源、交付 Markdown 与本地资源。优先复用完整快照；缺失先确认来源再补齐并持久保存，版本不明或不符停止，不无条件重抓或换成最新版。
- 复用解析器尺寸提取逻辑，保留有效宽度、百分比参照、暗亮选择和源节点；有依据的逐次恢复，无依据的记录未确定及原因。本期支持可靠纵横比下从 px/pt 高度推导宽度，已有有效宽度优先；比例未知、外部布局或约束冲突时不猜测，`basis` 标签不能代替依据验证。
- 源与交付按每次出现、路径及独立来源身份绑定，覆盖同名不同图、同图不同宽度和跨章复用。basename 与出现序只能定位候选；本地摘要不能自证源身份，须由快照资源或既有独立映射证明。无对应或有歧义时定位并失败。
- 不重译、不改正文和原图；同输入重跑绑定语义一致，失败不覆盖旧映射。回补后可离线导出并核对 PDF 逐次实测宽度。

### R4：交付证据可复查

- 完成前核对源快照、解析期映射、交付级映射和最终校验证据；无图免映射，有图须解释每次未恢复。新翻译默认保留尺寸链路，“不恢复尺寸”的明确决定须记录范围与原因，不能替代图片身份及离线验收。
- 证据关联当前输入身份、执行参数和校验口径，分别记录硬不变量、源全量对账、语义复核；PDF 另含导出/核验、最终 PDF 身份、尺寸及字段投影口径、视觉复核、未解决项与用户决定。复用既有恢复/合并资格，输入或口径变化后旧证据失效。
- 交付说明引用可访问的持久证据，清理临时目录后仍能回查。仅有目录、空记录、口头 PASS 或退出码不足以完成；检查失败、证据缺失、产物不可回查或无可用持久位置时，只报告进展与缺口。

**本轮细化（已批准，落实上述身份合同）：** 源图片须覆盖每份声明快照的实际选区及其资源解析上下文，保留原始源引用，不能以合并 Markdown 的首个目录或 reference 改写后的 basename 代替。实际核验所读的映射、出处及导出证据、有效参数、本地检查依赖和环境/样式政策均进入相应身份；预检、人工复核绑定、发布前重读必须使用同一事实口径。任一相关项变化使旧复核失效，运行期间变化不得替换旧证据索引；不能因摘要缺失或上下文不可确定而静默缩小范围。只影响其他产物的变化不应使本产物复核失效。仅 PDF 模式仍不强制英文源。

### R5：预检图片解码压力

- 全量内联/解码前估算图片负担，展示口径、阈值及主要大图位置；超阈值告警并写入导出结论。重复资源、未知尺寸与非位图处理须明示，未知不能记零。
- `Σ(宽×高×4)` 仅为候选位图估算，不代表实际峰值或必然失败。阈值与计数口径由设计结合样例确定；仍执行真实解码、溢出及页面检查，保留错误原因，不将异常统一归因内存或称为伪性失败。可建议调整范围或另行处理资源，实际改变须获授权。

### R6：出处前置与字段投影一致

- 出处最低标准：每章均能定位其具体原文，保留已知版本与日期；源本身未提供的字段不强制补齐，也不编造。只有文档名称或网站首页而无法定位对应原文，不算满足；可定位原文但源未提供版本或日期，不因此阻断。

- 所有 PDF 默认集中前置出处，无需另行启用：在第一章前完整交代实际范围的出处一次，各章默认排除“原文/译例说明/来源/抓取日期”管理字段。不同来源、版本及快照日期的差异必须在集中说明中保留，不能只取首章。
- 仅过滤获准章首管理字段及合法续行；正文、代码、表格、脚注和技术引用中的同名词保留。字段参数在导出与核验间单源并写入证据；核验独立从原输入判定可删位置及剩余完整性，未知字段或参数冲突不能扩大授权。
- 优先复用 `00_目录.md` 中完整的出处说明；没有目录或前置说明时，依据已有来源信息在导出视图中集中呈现，不强制新建目录或改写 Markdown。合订、分篇和单篇均按实际输出范围处理。
- 出处信息不足或完全缺失时，必须在 PDF 生成前报告受影响章节与缺口并失败退出；普通模式、旧译文和无目录输入均不豁免。不得生成候选或最终 PDF，不得覆盖已有 PDF，也不得宣告交付完成；补齐并重新通过检查后才能继续，不能用告警、占位出处或删尽来源字段放行。

### R7：交付根目录面向读者

- 翻译交付根目录仅允许目录文件（如 `00_目录.md`）、章节译文、成品 PDF、术语表（如 `术语表.md`），以及面向用户的 `导出前准备说明.md`、`PDF导出交付说明.md`。后两份说明允许放根目录，不要求为凑齐清单而新增或搬回；它们不因位于根目录就进入正文合订输入，术语表仍默认不进入 PDF。清单之外的文件不得留在根目录，不因已有文件、由其他模型生成或使用隐藏文件名而豁免；子目录本身不计入文件清单。
- 内部元数据、其他过程说明、日志、独立命令模板及其他辅助文件须从生成时就写入相应英文命名子目录或获准的工作区外位置。已有额外文件须在获准整理时归位；无法确定去向或尚未获准处理时，报告未完成项，不擅自删除，也不得把根目录验收判为通过。
- 交付级映射放入 `export/images_display.json`；上述两份用户说明可留根目录，其他过程文档和独立命令模板归入 `docs/`。这是翻译项目的产物布局，不是把本仓库规格移入 `docs/`；两份用户说明的位置授权不扩大到机器报告、日志或其他证据，未获准保存在项目内的证据继续放工作区外。
- 保持章节 Markdown、原图及 `images/`、`scripts/`、`source/`、`translated/` 和已有归档原位；章节内 `images/...` 引用不改。既有项目只在获得整理授权后迁移内部文件，不因新增默认布局自动搬动用户项目。
- 映射迁移后，`markdown` 与 `image` 使用相对映射目录的完整路径；例如根目录章节和图片分别经 `../章节.md`、`../images/图.png` 定位。同步所有受迁移影响的源定位、证据引用、过程文档链接和命令模板，不能只移动 JSON；归档中的同名文件不得被串用。
- 导出、核验和回补输出明确使用同一映射位置，两侧命令显式传入 `--images-display`；保留旧项目同目录自动发现兼容，不新增递归搜索或根目录映射副本。忘参按 R2 告警/严格策略处理，普通模式退出 0 不能证明整理成功；整理后逐次映射、恢复状态和实测宽度不得退化，重复回补仍写入新位置。

**本轮细化（已批准，落实上述位置合同）：** 最终交付检查核对记录声明、实际核验参数与 `export/images_display.json` 的同一位置关系；只匹配文件名、把映射放在 `other/` 或归档目录不能通过整理验收。无图无需新增空映射。此要求不取消独立导出/核验的旧同目录发现兼容，也不授权自动搬迁既有项目。路径等价判断与旧记录处理见设计 §9。

### R8：短代码保持整块，长代码跨页且不放宽完整性

- 以 **10 个逻辑行**为分界：10 行及以下不允许分页，超过 10 行允许按完整可见行跨页。末尾换行不额外算一行，真实空行计入；视觉折行不改变逻辑行数。长块须利用当前页可容纳完整代码行的剩余空间，后续行续到下一页，不因“下一整页能放下”而整体移页。
- 10 行及以下的短块允许整体移至下一页，因此产生的页尾空白可接受，不作为缺陷或阻断原因。超过 10 行的长块严禁因整体移页造成前页仅有几行文字、大半页空白。若短块视觉折行后连一整页也放不下，须报告无法满足不分页要求，不擅自拆块、缩字或裁切。
- 有效语言高亮、纯文本及未知语言回退采用一致规则。分页发生在完整可见行之间，不出现半行截断；缩进、字符、逻辑行顺序以及等宽/高亮/背景样式保持。不得通过删代码、改写 Markdown、缩小到不可读字号或截断来提高利用率。
- 核验必须同时接受正常跨页及“跨页代码与同页表格/正文提取交错”的正确成品，并检出字符改动、插入、遗漏、乱序及重复代码块缺失。检查限定于对应章节和实际代码块，不能借相邻正文、其他块或前一重复块补齐字符。
- 提取不连续只能按可定位、可解释的非代码噪音处理，记录块、页码、范围及依据；无法可靠归属时进入待复核，不能自动判完整。附件建议的任意字符子序列回退不作为既定方案：其可把 `return 10;` 当作 `return 1;` 命中，违反既有代码保真要求。
- 成功标准是在保真前提下消除长代码整块移页导致的上述留白，不强求固定总页数或页面利用率。真实验收分别验证短块留白可接受、长块利用页尾续排与跨页接缝；正常章尾空白不算缺陷，目录页码、链接、出处及图片宽度仍须复验。续页“续”标记、行号和可调阈值界面不纳入本期。

### R9：吸收项目脚本中的通用解析与预检能力

- 按能力并入现有四类路线，不新增 CUDA 专用解析入口或复制整套流程。优先修复受保护代码在高亮及嵌套容器中漏出、Pygments 行号混入代码、Sphinx 脚注定义未保留；段落、代码、列表、提示框、details 和定义项按源顺序且仅输出一次。
- 行号和标题链接装饰只能按已识别 HTML 节点排除，不能删除代码自身的数字、字面量 `<span>`、反引号或标题 `C#`。行内代码保持代码语义与文字；含代码表格保留单元格、表头、说明和代码的对应关系，不以无定位的展平替代原结构，无法表示时明确报告并回源处理。
- 将已有分派前 HTML→解析 Markdown 独立对账要求做成可复用检查：从原快照独立提取标题、图片、代码、公式、脚注及表格/列表等结构，与解析结果逐项核对位置、顺序和内容。计数只作摘要；无法解释的缺失、重复或顺序变化阻断分派，不能仅打印差异后成功退出，也不能拿解析器自己的漏项清单自证完整。
- 草稿预检复用源围栏回填及现有源家族硬检查；先在工作区外候选中回填代码，再核对标题、公式、脚注、图片及残留标记，原草稿不改。占位数量或 `$` 数量相等不构成通过，仍须保留最终路径全量复验和既有恢复/合并资格。
- 项目绑定脚本只提供 R3/R7 的逐次映射参考；错引用、源图身份未验证、任一章节失败时不得输出部分成功映射或覆盖旧映射。拆批、装配、页面闭合及官方排序优先复用现有能力，不引入项目硬编码列表、固定用户安装路径或自动降采样。
