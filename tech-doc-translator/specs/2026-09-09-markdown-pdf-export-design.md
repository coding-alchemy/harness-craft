## 1. 基线与约束

本次以仓库中的 [SKILL.md](../skills/tech-doc-translator/SKILL.md) 和 [翻译约定](../skills/tech-doc-translator/references/translation_conventions.md) 为实现基线，而不是本机已安装的旧版 Skill。仓库现已支持单篇/合订 PDF；完整章节 Markdown 默认独立。本轮只修订用户于 2026-09-11 指出的五项行为。

| 现有接口或行为 | 对导出设计的影响 |
| --- | --- |
| `merge_sections.py` 将首文件视为章节头、后续标题降级并删除面包屑 | 不直接复用为跨章合订，否则会改变完整章节结构 |
| `merge_work_packages.py` 要求 `source_order/section_id/fragment_index` | 完整章节不必具有工作包元数据，不能强加该合同 |
| `merge_api.py` 针对页面清单和快照图片，同名不同内容时报错 | 保留其现有职责；PDF 组合按来源身份引用图片，无需集中覆盖文件名 |
| 翻译要求代码和公式保留，合并需重新校验 | 导出只改变表示与布局，不写回正文；生成新 PDF 后重新核验 |
| 运行时资产已收拢至 Skill 目录 | 新资源通过 `<SKILL目录>` 定位，不依赖模块外绝对路径 |
| 翻译与 PDF 依赖已分别声明 | 保持按模式安装，普通翻译不强制下载浏览器 |
| `translation_conventions.md` 要求头部“原文 / 来源 / 译例说明”，多页文末附官方目录 | 保留 Markdown 头部溯源；PDF 过滤指定字段；全书目录改为独立 00_目录.md |
| 四类 `parse_*_html.py` 仅输出图片引用或 IMG 占位，未输出尺寸 | 新解析需保留显示尺寸，不能只补 PDF 样式 |
| `export_pdf.py` 使用 `html=False`；`inline_images()` 只解析路径和内联资源 | 不引入任意 HTML 执行，不把 width 属性追加为 Markdown 字面文本 |
| `style.css` 为 A4、左右各 16mm，图片 max-width:100%、height:auto | 版心约 672.76 CSS px；454px 在此约为 67.5%，不是报告的 35% |
| `parse_chapter()` 注册标题及链接，`page.pdf(outline=True, tagged=True)` 单次打印 | 目录复用确定性目标，增加带占位目录的探测与回填 |
| `verify_pdf.py` 重读原文、原始扫描与共享解析交叉核对，并检查结构树章区间与大纲 | 排除元数据和新增目录需同步调整预期；不得只改导出后放宽核验 |

## 2. 最小方案与分工

保留一个对外 Skill。在入口区分“翻译”和“已有 Markdown 导出”；PDF 专属规则放入按需读取的 `references/pdf_export.md`。翻译加 PDF 的任务在 Markdown 验收后调用同一导出流程。

内部采用一个导出入口，按输入列表逐文件解析，组合 HTML 后由 Playwright Chromium 打印；一个独立核验入口检查 PDF。阶段可用内部函数组织，不必按参考报告机械拆成四个 CLI。

既有导出边界均位于 `skills/tech-doc-translator/` 内：

- `scripts/export_pdf.py`：预检、解析、组合、渲染及机器检查；
- `scripts/verify_pdf.py`：以原始输入及有序列表为依据核对最终 PDF，独立重读输入，不只相信导出器统计；
- `references/pdf_export.md`：模式路由后使用的规则与人工检查口径；
- `assets/pdf/`：默认打印样式与离线数学渲染资产，保留第三方许可；
- `requirements-pdf.txt`：PDF 可选依赖，与现有翻译依赖分离。

回归入口遵循模块已有测试组织方式；测试输入在工作区外临时目录生成。本轮扩展这些既有文件，并在四类解析器及图片路径重写环节传递显示尺寸；入口与翻译约定增加独立目录的交付规则。不承诺仓库外稳定 API。

脚本负责解析、来源映射、渲染和确定性检查；Agent 负责输入范围、布局诊断、页面复核和未解释差异的裁决。不得用自动计数替代 Agent 的成品检查。

## 3. 输入合同与组合

### 3.1 输入与只读保护

Agent 按需求第 3.4 节先决定导出模式与排除术语表：多章意图不明时询问并等待，明确模式则直接执行。脚本不模拟交互，也不能用默认合订代替 Agent 的询问。

同一入口接收一个或多个明确有序的 Markdown 路径和一个 PDF 目标。规范化路径后检查缺失和重复，不自行扫描补章。源文件及资源只读；临时 HTML、资源清单、PDF 候选和检查结果写入工作区外临时目录。

前置读取确认支持的语法和资源。使用 Markdown 解析 token 处理围栏、公式、引用与脚注，不靠 `$` 奇偶或全文正则判断正确性：代码内的美元符号不是公式，转义符和货币文本也不得误算。

### 3.2 章首字段的导出投影

在 Markdown token 层定位每章标题前后、首个技术正文之前的模板管理字段，保存原始行号，生成仅用于导出的视图。仅去掉带“原文”“译例说明”标签的字段及其明确续行；遇到下一个字段或正文边界即停止。“来源”独立字段保留。混合引用块重建保留部分，代码围栏、列表/表格中的技术内容和正文同名词不参与过滤；边界不清的真实模板须明确定位后解决，不能做全文关键词删除。

来源链接可能在被移除字段内，应在建立链接/公式/图片预期前完成投影。原文文件摘要仍针对完整输入；导出证据记录排除的行区间、标签和原因。核验器独立检查这些区间确属获准章首字段，并对剩余内容执行原有硬检查，不能直接信任导出器给出的排除清单。没有目标字段的文档维持原有内容路径。

术语表排除在 Agent 组装输入时完成；显式术语表导出请求覆盖默认。被默认排除术语表的文档链接转换成保留文字的非链接节点，作为固定投影记录；仅针对已识别术语表目标，其他范围外链接不套用此规则。

### 3.3 逐章解析、统一 HTML

每章独立建立标题、显式锚点、图片、公式、脚注与引用式链接定义的映射，保留文件和行号来源。只使用解析器 token 与导出需要的映射，不建设跨源家族通用 IR。

合订为每章分配确定性的独立标识前缀。先建全部章节目标映射，再重写 HTML 的 ID、片段链接和脚注回链；本地相对文档链接以发出链接的 Markdown 目录解析。解析前保留每章引用定义作用域，避免同名定义被全局合并。

标题文字和编号保持；原章内标题相对层级保持，组合容器不新增正文标题。默认各章从新页开始，首章不制造空白首页。页码连续；PDF 大纲按可表示的标题层级生成，并验证目标。超出 HTML 标准层级的既有标题需明确映射并保留文字与相对关系，不能被解析为普通段落后静默丢失。

没有通用且唯一的 Markdown 标题锚点算法。优先保留显式 ID，对输入实际使用的标题片段建立可验证别名；歧义或找不到目标时报告，不能猜测或删除链接。纳入范围的跨章目标改为内部链接；HTTP(S) 外链保留，不把联网可达性作为离线导出门禁。范围外本地文档链接交由 Agent 明确处理，不自动加入文档。

### 3.4 资源与原样内容

图片从各章来源目录解析并内联到临时 HTML，或复制到隔离资源目录后以唯一身份引用；同内容可复用，同名不同内容必须独立。保留可打印 SVG，不强制将所有图转成位图。外部图片需先本地化，转换阶段不能依靠网络。

代码文本由原 token 直接输出，高亮仅包裹样式；视觉折行不插入源字符。公式从 token 进入本地 KaTeX，不对整篇正文再次自动扫描。未知命令、数学渲染错误和未覆盖定界符均显式暴露。保留现有普通引用提示块及已出现的 admonition 表示，不以样式统一为由改正文。

### 3.5 图片尺寸的最小数据链

保留标准 Markdown 图片语法与原始高清文件，新增项目交付资源 `images_display.json`。四类解析器都从已确认版本快照的实际选中图片提取显示宽度：优先可解析的内联 CSS width，再使用 HTML width；保留值、单位和源节点定位。像素宽度及百分比可明确表达，百分比必须记录其参照容器；外部 CSS、复杂表达式或仅高度约束无法直接确定宽度时，报告并从同版本源解析有效显示尺寸，不凭图片像素猜测。

映射最少包含：源快照身份与节点/出现序号、交付 Markdown 相对路径与图片出现序号、交付图片相对路径及资源摘要、宽度值/单位与尺寸依据。源条目先被提取，翻译/合并时由主 Agent 根据既有全局图片身份映射绑定最终路径和出现次序；`merge_api.py` 的重命名/复制同步更新路径，分包恢复与合并保持对应关系。按图片出现位置标识显示策略，使同一资源在不同位置可以使用不同宽度；不以 basename 为唯一键。

导出器按明确提供的映射文件，或每个输入 Markdown 同目录的映射文件读取，不递归猜测项目根；跨目录共享映射可显式指定。相对路径均以映射文件目录解析。先验证资源摘要与出现位置，再给生成 HTML 的对应图片注入受限尺寸属性，不把源 style 整段复制到 HTML。像素宽度使用原值，百分比使用可确定的参照关系；最终受版心最大宽度限制并保持图片比例。映射无命中时维持原回退并报告；已命中但资源错配、尺寸无效时失败，不能忽略损坏映射后宣称恢复成功。

映射是随译文交付的必要资源，不是临时验证报告。仅导出时只读映射，临时尺寸证据仍写到工作区外。旧译文补映射属于导出前准备，优先读同版本快照；当前任务不修改外部 CUDA 项目或自动抓取新版本。通用 Markdown 预览器不消费映射，相关限制已随 V0.2 批准。

### 3.6 独立目录及两遍打印

翻译阶段由主 Agent 根据已经对账的官方顺序与实际交付文件生成 `00_目录.md`：官方章/节标题及对应中文标题、指向译文的相对路径和锚点。以实际翻译范围闭合，不改变正文交叉引用“不造链接”的既有规则；目录导航是专门生成的交付结构。全书目录集中输出，章内固有目录保留。

PDF 使用显式目录角色识别 `00_目录.md`，不把任意标题为“目录”的技术章节当成导航。翻译加合订默认把目录文件列在正文之前；旧译文无目录输入仍走现有无目录路径。目录输入按原文重读、验证链接顺序和目标，印刷目录默认选章级条目；选择一级节时仅加一层。分篇模式从目录选取本篇目标，不能生成指向其他 PDF 的伪内部链接。

目录用独立导航容器呈现，复用已建立的章节目标，不重复作为正文 Chapter 打印或混入正文标题统计。正文的章区间、标题覆盖与书签大纲仍逐章验证；目录的标题、条目及目标使用独立预期核对，不能因为增加导航而放松正文核验。用户自有目录文件含有列表以外的说明时保留说明，或在无法无损增强时报告，不能整文件覆盖成自动目录。

1. 先以最终目录条目、字体、行宽、固定页码列生成占位目录，与正文一起打印探测 PDF。点线使用边框/布局实现，不依赖 CSS `leader()`；长标题在标题列换行，页码列不换行。
2. 从探测 PDF 的实际内部链接目的地和目标标题位置获取从 1 起算的页序；不假定 Chromium 一定输出命名目的地，也不凭 DOM 高度推算分页。重复标题通过章标识及链接目的地消歧。
3. 回填页码，保持目录布局条件不变，再打印候选 PDF。全部目录页计入实际页序，不采用正文重置或罗马页码体系。
4. 核验最终 PDF 每条可见页码、链接目标页和目标标题位置一致。若发生分页漂移，允许根据最新结果再回填并打印一次；总计最多三次打印（探测一次、首次回填一次、修正一次），仍不一致则 FAIL。固定列宽只能降低漂移风险，不能证明必然收敛。

无目录时仍单次打印；带目录时最终候选经过全部既有检查与新增目录核验才允许发布。不要求无目录 PDF 逐字节一致，验证内容、布局和链接语义不变，避免把时间戳等 PDF 元数据误当行为回归。

## 4. 渲染与布局

使用 `markdown-it-py` 及实际需要的扩展解析，Pygments 处理代码样式，Playwright Chromium 打印，PDF 提取工具核对正文与链接。具体版本组合在代表样例上验证后锁定；不沿用参考报告的 Python 下限或浏览器体积结论。

默认 A4 纵向、中文正文与中英等宽代码字体回退。检查字体实际可用性和字符覆盖；`document.fonts.ready` 只表示加载完成，不证明每个字符有字形。先等待图片解码、字体与公式全部完成，再检查错误、溢出和被隐藏的内容。

长代码允许视觉折行，表格允许单元格换行并保留列关系；超出一页的块允许合理分页，不统一设置整块禁止分页。长公式、复杂表格不能用无限缩小来获得表面“未溢出”；需在导出样式层选择可读布局并重新检查。确需横向页面等额外策略时按实际样例收敛，不预建通用配置系统。

默认样式不加载远程字体、脚本或 CSS。只有资源齐备后才承诺离线可用；首次安装浏览器与取得字体属于环境准备。原 Markdown 中的脚本不作为执行入口，所需 HTML 结构需保留可见内容并检查转换差异。

## 5. 验证与失败闭环

| 层次 | 验证内容 | 不作出的推断 |
| --- | --- | --- |
| 输入与组合 | 每章内容块与顺序、代码/公式原文、资源身份、脚注配对、所有内部目标 | 解析 token 数量不能独立证明解析器无损 |
| 浏览器 | 图片解码与实际显示、公式逐项成功、字体覆盖证据、打印布局溢出 | 就绪信号不能证明渲染成功；屏幕布局不能证明分页正确 |
| 成品 PDF | 逐章标题与正文顺序、代码及关键文本覆盖、链接目标与大纲目的地、可提取性 | XObject 数量不等于图片出现次数；文本存在不等于可见 |
| 页面视觉 | 全页布局，以及图片、代码、公式、宽表、脚注和跨页接缝细节 | 缩略图抽看不能证明细字与公式正确 |

核验从原始输入及第 3 节明确允许的投影建立预期，与组合 HTML 和 PDF 互相核对。图片检查增加逐次绘制的实际宽度及比例，与映射换算到 PDF 点数后的预期比较（1 CSS px = 0.75pt，容差仅吸收打印舍入，实施时以测量确定并记录）；目录检查从最终成品读取可见页码并核对真实目标，不能只核对中间 JSON。PDF 文本提取允许记录有依据的排版空白差异；公式等不能可靠文本对账的内容，使用原公式到渲染节点映射并逐项视觉复核。无法解释的差异标记为需复核，不直接判成功，也不为了通过而放宽内容守恒。

自动检查已确认缺失或错误时返回失败；自动检查通过但视觉复核未完成时只能报告“机器检查通过、成品待复核”。诊断应包含输入文件、章节或行号，能定位时附 PDF 页码。修复后重跑受影响检查，最终对实际交付路径复验；失败候选不替换既有成功文件。

内容缺失、图片串用、错误跳转、公式失败及不可读布局未解决时不交付。保留有效 Markdown，只重做导出；若问题实际来自译文，则报告并按翻译任务的授权处理，不能在导出器中偷偷修正。

## 6. 直接验收安排

按[需求第 4 节](./2026-09-09-markdown-pdf-export-requirements.md#4-验收与交付)逐项验证 A1–A14。真实样例覆盖单篇与跨章，临时对抗样例覆盖重复标题/脚注/图片名、坏引用、公式失败和长内容。

检查所有最终页面的整体布局，并放大检查内容密集页与跨页处；若自动检测覆盖不足，扩大视觉检查，不能缩小核心验收。对照有序输入逐章确认开头、结尾及正文覆盖，实际点击代表性跨章和脚注链接。验证后核对所有输入摘要未变化。

V0.1 的 PDF 导出已实现；本轮只完成源码与文档基线核对，尚未运行新增行为的 PDF 实验。模板边界、目录真实目的地提取、分页漂移与图片尺寸测量均需在实施阶段闭合，不能把参考报告中的 CUDA 页数或占比当成当前验证结果。

## 7. Karpathy 精简与自检

### 7.1 最小方案比较

更简单的“拼接 Markdown 后打印”无法保留各章资源目录、引用定义作用域和重复脚注，可能让同一链接跳到错误章节，不能满足 A3。逐章独立导出再合并 PDF 虽然容易复用单篇输出，但需要另行修补全局内部链接、大纲和页码；本次保留逐章解析及统一排版；只有带印刷目录时增加必要的探测打印，减少 PDF 拼接后修补链接。

采用单 Skill、一个导出入口与独立核验入口，保留必要映射；不建立新平台、通用 IR、公共 API 或多后端。

针对新增需求，更简单的“只补 Prompt 和 CSS”可以规定询问，却无法找回已丢失尺寸，也无法证明目录页码准确；“手改译文 HTML 图片”会破坏现有 html=False 管线与输入只读合同；“只改导出器”会让核验器把合法排除视为缺失，或诱使后续放宽检查。采用规则路由、图片尺寸旁路映射、受限导出投影及带最终核验的两遍打印，复用现有入口和目标映射，不新增通用出版框架。

### 7.2 删除审计

相对参考报告，移除“任意 Markdown”“只有浏览器保真”的过强承诺、四层配置继承、四个固定阶段 CLI 和定制页眉页脚；将公式/字体/图片就绪统一为打印前条件。拒绝用图片资源数、美元符号奇偶或中文抽样替代保真验收。

本轮删除参考材料中自动修复外部 CUDA 项目、降采样、补丁登记和上游发布的执行性建议；合并目录方案里两套相冲突的默认粒度与页码口径，去掉“链接永远正确”“页数稳定、必然收敛”和逐字节回归等无依据保证。不采用 basename 映射和固定 35% 占比。保留目录、尺寸、输入保护与全部原有保真要求。

逐节映射：第 1 节约束既有行为；第 2 节限定实现边界；第 3 节对应需求 3.1–3.6；第 4 节落实可读离线渲染；第 5、6 节落实 A1–A14；本节记录方案取舍与评审边界。未增加仅用于显得完整的运行平台或未来扩展配置。

### 7.3 假设、不确定项与状态

Markdown 为权威译文，PDF 为额外交付；过滤只作用于导出视图。默认 A4、章间分页与连续页序沿用原实现。需求第 6 节集中列出已批准取舍：目录默认粒度和页码口径、旁路映射不改变通用 Markdown 预览，以及来源字段、术语表链接和分篇目录的处理边界。

不确定项是实际章首模板续行边界、源 CSS 尺寸解析、Chromium 目的地结构及最终 PDF 尺寸测量；这些均有直接验收 A9、A12–A14，不以实现文件存在或检查退出成功替代。需要真实输入校准时仅按已授权路径读取，验证产物放在工作区外。

V0.1 已批准并实现；V0.2 已于 2026-09-11 获用户明确批准并继续编写计划。未修改运行时行为，没有已实施的未经批准差异；执行计划获批并获得执行授权后才实现。
