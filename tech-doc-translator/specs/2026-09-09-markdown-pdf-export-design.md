## 1. 基线与约束

本次以仓库中的 [SKILL.md](../skills/tech-doc-translator/SKILL.md) 和 [翻译约定](../skills/tech-doc-translator/references/translation_conventions.md) 为实现基线，而不是本机已安装的旧版 Skill。现有入口只承诺中文 Markdown；完整章节默认独立，明确要求才额外合并。

| 现有接口或行为 | 对导出设计的影响 |
| --- | --- |
| `merge_sections.py` 将首文件视为章节头、后续标题降级并删除面包屑 | 不直接复用为跨章合订，否则会改变完整章节结构 |
| `merge_work_packages.py` 要求 `source_order/section_id/fragment_index` | 完整章节不必具有工作包元数据，不能强加该合同 |
| `merge_api.py` 针对页面清单和快照图片，同名不同内容时报错 | 保留其现有职责；PDF 组合按来源身份引用图片，无需集中覆盖文件名 |
| 翻译要求代码和公式保留，合并需重新校验 | 导出只改变表示与布局，不写回正文；生成新 PDF 后重新核验 |
| 运行时资产已收拢至 Skill 目录 | 新资源通过 `<SKILL目录>` 定位，不依赖模块外绝对路径 |
| 当前依赖仅 `beautifulsoup4` | PDF 依赖按导出模式安装，普通翻译不强制下载浏览器 |

## 2. 最小方案与分工

保留一个对外 Skill。在入口区分“翻译”和“已有 Markdown 导出”；PDF 专属规则放入按需读取的 `references/pdf_export.md`。翻译加 PDF 的任务在 Markdown 验收后调用同一导出流程。

内部采用一个导出入口，按输入列表逐文件解析，组合 HTML 后由 Playwright Chromium 打印；一个独立核验入口检查 PDF。阶段可用内部函数组织，不必按参考报告机械拆成四个 CLI。

预期新增边界均位于 `skills/tech-doc-translator/` 内：

- `scripts/export_pdf.py`：预检、解析、组合、渲染及机器检查；
- `scripts/verify_pdf.py`：以原始输入及有序列表为依据核对最终 PDF，独立重读输入，不只相信导出器统计；
- `references/pdf_export.md`：模式路由后使用的规则与人工检查口径；
- `assets/pdf/`：默认打印样式与离线数学渲染资产，保留第三方许可；
- `requirements-pdf.txt`：PDF 可选依赖，与现有翻译依赖分离。

回归入口遵循模块已有测试组织方式；测试输入在工作区外临时目录生成。上述文件仅是设计边界，尚未创建。最终内部参数在获批执行计划中收敛，不承诺仓库外稳定 API。

脚本负责解析、来源映射、渲染和确定性检查；Agent 负责输入范围、布局诊断、页面复核和未解释差异的裁决。不得用自动计数替代 Agent 的成品检查。

## 3. 输入合同与组合

### 3.1 输入与只读保护

同一入口接收一个或多个明确有序的 Markdown 路径和一个 PDF 目标。规范化路径后检查缺失和重复，不自行扫描补章。源文件及资源只读；临时 HTML、资源清单、PDF 候选和检查结果写入工作区外临时目录。

前置读取确认支持的语法和资源。使用 Markdown 解析 token 处理围栏、公式、引用与脚注，不靠 `$` 奇偶或全文正则判断正确性：代码内的美元符号不是公式，转义符和货币文本也不得误算。

### 3.2 逐章解析、统一 HTML

每章独立建立标题、显式锚点、图片、公式、脚注与引用式链接定义的映射，保留文件和行号来源。只使用解析器 token 与导出需要的映射，不建设跨源家族通用 IR。

合订为每章分配确定性的独立标识前缀。先建全部章节目标映射，再重写 HTML 的 ID、片段链接和脚注回链；本地相对文档链接以发出链接的 Markdown 目录解析。解析前保留每章引用定义作用域，避免同名定义被全局合并。

标题文字和编号保持；原章内标题相对层级保持，组合容器不新增正文标题。默认各章从新页开始，首章不制造空白首页。页码连续；PDF 大纲按可表示的标题层级生成，并验证目标。超出 HTML 标准层级的既有标题需明确映射并保留文字与相对关系，不能被解析为普通段落后静默丢失。

没有通用且唯一的 Markdown 标题锚点算法。优先保留显式 ID，对输入实际使用的标题片段建立可验证别名；歧义或找不到目标时报告，不能猜测或删除链接。纳入范围的跨章目标改为内部链接；HTTP(S) 外链保留，不把联网可达性作为离线导出门禁。范围外本地文档链接交由 Agent 明确处理，不自动加入文档。

### 3.3 资源与原样内容

图片从各章来源目录解析并内联到临时 HTML，或复制到隔离资源目录后以唯一身份引用；同内容可复用，同名不同内容必须独立。保留可打印 SVG，不强制将所有图转成位图。外部图片需先本地化，转换阶段不能依靠网络。

代码文本由原 token 直接输出，高亮仅包裹样式；视觉折行不插入源字符。公式从 token 进入本地 KaTeX，不对整篇正文再次自动扫描。未知命令、数学渲染错误和未覆盖定界符均显式暴露。保留现有普通引用提示块及已出现的 admonition 表示，不以样式统一为由改正文。

## 4. 渲染与布局

使用 `markdown-it-py` 及实际需要的扩展解析，Pygments 处理代码样式，Playwright Chromium 打印，PDF 提取工具核对正文与链接。具体版本组合在代表样例上验证后锁定；不沿用参考报告的 Python 下限或浏览器体积结论。

默认 A4 纵向、中文正文与中英等宽代码字体回退。检查字体实际可用性和字符覆盖；`document.fonts.ready` 只表示加载完成，不证明每个字符有字形。先等待图片解码、字体与公式全部完成，再检查错误、溢出和被隐藏的内容。

长代码允许视觉折行，表格允许单元格换行并保留列关系；超出一页的块允许合理分页，不统一设置整块禁止分页。长公式、复杂表格不能用无限缩小来获得表面“未溢出”；需在导出样式层选择可读布局并重新检查。确需横向页面等额外策略时按实际样例收敛，不预建通用配置系统。

默认样式不加载远程字体、脚本或 CSS。只有资源齐备后才承诺离线可用；首次安装浏览器与取得字体属于环境准备。原 Markdown 中的脚本不作为执行入口，所需 HTML 结构需保留可见内容并检查转换差异。

## 5. 验证与失败闭环

| 层次 | 验证内容 | 不作出的推断 |
| --- | --- | --- |
| 输入与组合 | 每章内容块与顺序、代码/公式原文、资源身份、脚注配对、所有内部目标 | 解析 token 数量不能独立证明解析器无损 |
| 浏览器 | 图片解码与实际显示、公式逐项成功、字体覆盖证据、打印布局溢出 | 就绪信号不能证明渲染成功；屏幕布局不能证明分页正确 |
| 成品 PDF | 逐章标题与正文顺序、代码及关键文本覆盖、链接目标与大纲目的地、可提取性 | XObject 数量不等于图片出现次数；文本存在不等于可见 |
| 页面视觉 | 全页布局，以及图片、代码、公式、宽表、脚注和跨页接缝细节 | 缩略图抽看不能证明细字与公式正确 |

核验从原始输入建立预期，与组合 HTML 和 PDF 互相核对。PDF 文本提取允许记录有依据的排版空白差异；公式等不能可靠文本对账的内容，使用原公式到渲染节点映射并逐项视觉复核。无法解释的差异标记为需复核，不直接判成功，也不为了通过而放宽内容守恒。

自动检查已确认缺失或错误时返回失败；自动检查通过但视觉复核未完成时只能报告“机器检查通过、成品待复核”。诊断应包含输入文件、章节或行号，能定位时附 PDF 页码。修复后重跑受影响检查，最终对实际交付路径复验；失败候选不替换既有成功文件。

内容缺失、图片串用、错误跳转、公式失败及不可读布局未解决时不交付。保留有效 Markdown，只重做导出；若问题实际来自译文，则报告并按翻译任务的授权处理，不能在导出器中偷偷修正。

## 6. 直接验收安排

按[需求第 4 节](./2026-09-09-markdown-pdf-export-requirements.md#4-验收与交付)逐项验证 A1–A7。真实样例覆盖单篇与跨章，临时对抗样例覆盖重复标题/脚注/图片名、坏引用、公式失败和长内容。

检查所有最终页面的整体布局，并放大检查内容密集页与跨页处；若自动检测覆盖不足，扩大视觉检查，不能缩小核心验收。对照有序输入逐章确认开头、结尾及正文覆盖，实际点击代表性跨章和脚注链接。验证后核对所有输入摘要未变化。

本设计尚未进行真实 PDF 渲染；字体、复杂数学、深层标题、打印大纲与 PDF 文本提取的表现均是实施中必须闭合的证据，不是当前已验证能力。

## 7. Karpathy 精简与自检

### 7.1 最小方案比较

更简单的“拼接 Markdown 后打印”无法保留各章资源目录、引用定义作用域和重复脚注，可能让同一链接跳到错误章节，不能满足 A3。逐章独立导出再合并 PDF 虽然容易复用单篇输出，但需要另行修补全局内部链接、大纲和页码；本次采用逐章解析、一次排版，减少后处理。

采用单 Skill、一个导出入口与独立核验入口，保留必要映射；不建立新平台、通用 IR、公共 API 或多后端。

### 7.2 删除审计

相对参考报告，移除“任意 Markdown”“只有浏览器保真”的过强承诺、四层配置继承、四个固定阶段 CLI 和定制页眉页脚；将公式/字体/图片就绪统一为打印前条件。拒绝用图片资源数、美元符号奇偶或中文抽样替代保真验收。

逐节映射：第 1 节约束既有行为；第 2 节限定实现边界；第 3 节落实单篇/合订与输入保护；第 4 节落实可读离线渲染；第 5、6 节落实 A1–A7；本节记录方案取舍与评审边界。未增加仅用于显得完整的运行平台或未来扩展配置。

### 7.3 假设、不确定项与状态

假设 Markdown 为权威译文，PDF 为额外交付；默认 A4、章间分页和连续页码是本稿明确提出的排版选择。真实语法样本、字体供应方式与版本组合尚待验证。发现无法保真的既有结构时须解决或提出待批准差异，不允许以“首版”名义静默排除。

用户已于 2026-09-09 批准本设计及对应需求，并授权编写执行计划。尚未修改运行时行为，没有已实施的未经批准差异；计划获批并获得执行授权后才实现。
