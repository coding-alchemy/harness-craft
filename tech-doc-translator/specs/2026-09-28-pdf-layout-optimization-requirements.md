## 1. 目标与边界

让所有导出的技术文档 PDF 具有整齐、可读的正文、纯中文总标题和准确的连续页码；PDF 不显示译者添加的前置出处或非原文说明。`torch.fx` 译文用于验证本次目标，不把该文的标题、图号、页数或具体文本硬编码成通用导出规则。

以现有导出器生成的 PDF 为基线，保留既有的正文与资源保真、可检索复制、图片尺寸、印刷目录、链接、脚注、代码分页和视觉复核合同。样本初译稿中的审阅高亮、批注、占位符不进入新成品。排版优化不构成改写译文语义或跳过翻译验收的授权。

本文件规定用户可观察的结果及验收证据，不指定 CSS、浏览器页脚模板或 PDF 后处理等实现手段。输出页数随实际排版确定，不以 18 页或与旧版逐页同位作为合格条件。

## 2. 需求

### R1 正文段落两端对齐（P0）

1. 导出 PDF 中的普通正文段落两端对齐；最后一行自然结束，不强行拉满。中英混排、行内代码和链接仍可读，长标识符与 URL 可以在必要时折行，但不得越出版心或引起整本缩印。
2. 作用范围是正文叙述段落。标题、代码块、表格单元格、图表题注及印刷目录保持其各自的排版规则；不得因通用段落样式误改这些区域。
3. 译文字符、标点、链接目标与代码内容不因对齐方式改变。

### R2 非原文说明的 PDF 呈现（P0）

1. 所有 PDF 默认不显示译者添加的前置出处信息：既包括由章首“原文／来源／抓取日期”等管理字段生成的集中说明，也包括目录文件中仅为交代来源而写的“译自……”段落。输入 Markdown 中的可定位来源及既有来源门禁保留；参考文献条目、正文引用和属于原文内容的来源信息仍须保留。这个可见内容变化取代现行“来源集中前置显示”合同，见第 5 节 C2。
2. 对**已标识且已确认不是原文内容**的译者导览说明、翻译过程说明及译注，PDF 导出视图一律排除。不得按“出处”“译注”等关键词全文删除；原文脚注、图表题注和正文中同名技术词必须保留。无法确定某段是否属于非原文说明时须定位并报告，不能猜测后删除。
3. `torch.fx` 样本至少排除第 1 页前置“出处”框、参考文献标题下的“本节为文献引用数据……”及 URL 还原译注；保留该 URL 的正确目标、参考文献条目、附录原文脚注 `[^1]` 与图 5、图 6 等图题。URL 译注的 PDF 排除与现行 PDF 源验收合同存在差异，见第 5 节 C4。
4. 对 PDF 排除的每一处文字，应能回查原 Markdown 位置及排除原因，并独立验证其余正文完整。交付 Markdown 保持原样；导出与核验须以**同一获批投影政策**建立预期，不得把 PDF 与 Markdown 的差异默认为通过。

### R3 总标题与 PDF 元数据（P0）

1. 所有 PDF 的文档总标题在导出视图中显示中文题名；原题已有可信中文译名时使用它，只有外文题名时自动翻译。中文题名允许保留 `Torch.fx`、`Python` 等专有名词。PDF 元数据 `Title` 与该可见总标题一致。章节标题按输入保留文字、层级、编号和链接目标；原本中英双语的标题仍中英双语，不把纯中文要求推广到各级章节标题。
2. `torch.fx` 新成品的文章总标题显示为 `Torch.fx：Python 深度学习中的实用程序捕获与变换`，不得带英文原题；在既有 A4 版心内以一行呈现，保持可读字号，不通过整页缩印达成单行。文章各级章节标题仍按当前中英双语译文呈现，如 `Abstract（摘要）`、`1. Introduction（引言）`。
3. 输入 Markdown 的 H1 与原题保留原样；仅 PDF 导出视图改变总标题和元数据。合订本缺少书名时，基于已确定的有序输入范围与章题自动生成中文合订标题，不把 `00_目录.md` 的“目录”或第一章标题冒充全书标题；生成依据写入导出证据。若原题和输入主题都不足以形成可核对的题名，定位缺口并停止生成，不能用无依据的占位题名继续。现有 PDF 源校验要求译文 H1 保留英文原题，本需求不改变该输入验收规则，见第 5 节 C4。

### R4 每页页脚页码（P0）

1. PDF 每页页脚底部居中显示 `当前页 / 总页数`，例如 `3 / 18`；页序从 PDF 第一页算起，包含封面页、印刷目录页与正文页，跨章不重置。页脚文字采用约 8–9 pt 的低对比灰色，但须清晰可读。
2. 实际页序与总页数以**最终 PDF**为准。页脚不得遮挡正文、脚注、表格、图片或代码，不使既有正文版心变窄或底部内容被裁切；与既有印刷目录页码口径一致。
3. 单篇、带目录的单篇及跨章合订均适用。成品无页眉；本需求不加入书名、章节名或其他页脚文字。

### R5 `torch.fx` 样本交付验证（P0；已实施）

`torch.fx` 样本交付验收由 ticket 07 承担并已于 2026-09-29 完成，成品按当时的 R1–R4 与第 4 节逐项复核通过且交付 Markdown 摘要不变。后续通用目录出处规则及导航漏检已修复，直接验收及实施后两轴复审通过；这些修复未改变该样本成品。下列条款为样本验收时的执行口径留档。

1. 用 2026-09-27 交付版作为内容与排版基线，导出新的 PDF 并按 R1–R4 和第 4 节复核；2026-09-22 初译稿仅用于参考对齐、紧凑度与标题效果，不能继承其审阅痕迹。
2. 样本 Markdown 保持原样；仅在 PDF 导出视图中按 R2、R3 排除或调整可见内容。不能仅为让 PDF 文本搜索“零命中”而误删原文脚注或参考文献链接。若后续任务另行修改已验收译文 Markdown，旧翻译验收身份失效，须按现有交付护栏重新完成受影响验收后再导出。
3. 新 PDF 的目标文件名、旧版保留方式及实际交付路径在执行前确定；需求来源中的“默认覆盖 `交付_译文.pdf`”不视为本仓库对外部项目目录的执行授权。
