## 1. 问题陈述

合法论文和技术文档中的相邻行内公式、公式后数字及 PTX 指令修饰符目前可能漏检；普通段落行首 `#` 会被误写成标题，合法输入反而被独立对账拒绝；现行推荐的项目术语表表头也有读取缺口。用户需要正确输入可处理、确切损伤被拒绝，并能确认检查实际覆盖了哪些内容。

一期沿用既有四类 HTML 家族、源独立对账、拆包、恢复、合并和交付检查。源译计数相等只作摘要，不代替有序内容比较和人工语义复核。本文记录获批设计及合同内修复决策；实施已验收，执行计划按生命周期删除。

## 2. 方案

在现有共享核验层修正公式定界和指定 token 边界，所有实际消费者采用相同事实及未解决诊断。HTML 渲染只对来自普通文本节点、会误触发标题的输出位置作必要 Markdown 转义；真实标题继续按独立来源核对。四类译文入口增加一个官方标题文件输入，独立官方基准与解析工作清单分开。术语读取只增加已确认目标列别名和可定位的读取来源，不改变词条身份及裁决。

事实链保持为：只读原始快照及确认范围 → 解析候选与独立源对账 → 安全拆包 → 适用范围硬检查 → 主 Agent 实际回源/语义复核 → 恢复、合并及最终路径复验。共享检查器、实际参数或来源变化沿用现有身份绑定使受影响旧证据失效，不补签历史 PASS。

## 3. 用户故事

1. 作为翻译负责人，希望相邻行内公式分别保留类型、表达式、顺序和位置，以便正文翻译不误伤数学内容。
2. 作为复核者，希望公式闭合美元后紧接数字仍参与检查，以便删除或改动任一公式都能被定位发现。
3. 作为技术文档译者，希望真实块级公式、货币、转义美元及代码得到正确区分，以便正常输入不会被错误拒绝。
4. 作为主 Agent，希望无法解释的公式定界明确进入未解决状态，以便不完整结构不会被拆包或冒称核验通过。
5. 作为维护者，希望拆包、源对账、译文及工作包检查共享公式事实，以便不同入口不会对同一损伤作出相反结论。
6. 作为项目负责人，希望显式配置的点修饰符与百分号寄存器按完整形态计数，以便紧贴指令名的真实命中不遗漏、较长标识符不冒充命中。
7. 作为复核者，希望源中未出现的配置 token 明确标为未检查，以便源译均为零不会被误报成检查成功。
8. 作为现有项目使用者，希望原逐项参数、强 token 位置参数与增加项告警保持，以便兼容修正不改变其他输入角色或扩大失败条件。
9. 作为 HTML 文档译者，希望普通文字和代码注释中的 `#` 保持原语义，以便输入可正常处理且真实标题不被批量删掉。
10. 作为复核者，希望纠正存量伪标题时依据原节点及具体出现位置重新核对，以便同名真实标题得到保留且旧证据不能自动复用。
11. 作为主 Agent，希望四类 HTML 核验可读取官方原题文件，以便用独立权威清单发现解析源与译文共同遗漏的标题。
12. 作为项目使用者，希望标题文件的空行、内容字符及参数互斥规则明确，以便错误文件不会悄悄降级成无官方基准。
13. 作为主 Agent，希望可导出排除围栏内注释的标题工作清单，以便准备任务上下文，并知道它不能证明自身解析完整。
14. 作为论文译者，希望已知术语表别名与规范表头得到相同有效词条，以便复用项目经验时不改写原表或重新裁决译法。
15. 作为术语维护者，希望每个可识别行有读取结果或明确错误，映射可回查，以便未知/歧义表头和破损行不会静默丢失。
16. 作为项目负责人，希望项目覆盖、语境选择、来源和原表摘要保持，以便兼容表头不会污染共享库或改变术语权限。
17. 作为交付接收者，希望受影响旧复核失效、重新实际复核后可恢复资格，以便检查改进仍依赖当前源和产物，而非历史报告。

## 4. 实现决策

### 4.1 基线与职责收敛

上述变化只修正本期已确定职责。需要同步消费的原因是已确认的语义缺口：只改共享扫描而消费端仍先删定界、丢类型或忽略未解决状态，不能满足 R2；只修计数但报告仍把零命中写作全部通过，不能满足 R3。相关源码及测试证据在第 7 节列出。

### 4.2 D2：按上下文识别公式，保持共同诊断

**扫描与接口。** 在共享层增加最小结果入口 `scan_math(text)`，一次取得有序 `spans` 和 `issues`；每条 issue 只保存原偏移、行号、定界原文和原因，不增加通用解析 IR。保留 `MathSpan` 和 `scan_math_spans(text)` 的切片接口，后者仅投影同一次扫描定义的有效跨度。安全拆包、源对账、四族译文、恢复、合并及适用 PDF 检查须消费完整结果，不能只取跨度而忽略 issues；工作清单等只读调用不授予完整通过资格。

先复用等长代码掩蔽：较长反引号、波浪线围栏及行内代码覆盖区不参与公式；转义美元按所在文字语境识别，链接标签中的合法公式继续参与，链接语法转义不变成数学定界。保留换行和偏移，`expr`、`raw` 总从原输入切片取出。

扫描在未进入数学和已进入数学两种上下文按原偏移推进，不先全局抓取 `$$`：

1. 未进入数学时，合法 `$$` 或家族支持的 `\[` 开启块级；单个 `$` 开启同一行的行内候选。行内内容首尾非空白的既有约束保持。
2. 已进入行内时先消费一个闭合 `$`。紧随的另一个 `$` 由外层继续处理，因此 `$x$$\sim$` 是两个行内公式，不会被其中间 `$$` 抢作块级起点。闭合字符后的数字不再否定该公式。
3. 已进入块级时，只用匹配的块级定界闭合，内部单美元属于原表达式。单行 `$$x$$`、多行 `$$…$$` 及既有 `\[…\]` 保持块级；不把块内美元另记为行内。
4. 货币排除独立于“闭合后数字”判断：先检查能否构成同一行、内容首尾非空白的完整公式跨度，`$5$`、`$5 + x$` 等数字开头的合法表达式优先作为公式；只有无法构成这种跨度的金额片段才按普通货币排除。`costs $5 and $10`、现有中英文价格样例及单个 `$100` 不制造公式或未解决项。金额与不完整数学确有两种合理解释时定位 issues，不靠屏蔽所有数字开头表达式避免误扫。
5. 非货币、非代码/转义的候选无法闭合，或定界结构无法按上述规则解释时，定位 issues；行内不跨行寻找闭合来吞入正文。只把确切跨度交给比较，未解决项仍阻断分派及完整核验，不能用剩余跨度相等消除它。

**消费与允许转换。** Markdown 侧统一使用上述类型、顺序、原表达式。原 HTML 侧继续直接读取原始选区：字面数学使用共享扫描；已识别数学节点按现行家族的行内/块级表示生成独立预期，保留节点顺序和归属。源提取不读渲染器输出清单。对于 DOM 已确认的包装去除、实体解码及行内格式空白序列化，只在对应源节点的 HTML→Markdown 边界描述其确定结果，不以全文 `_norm_math` 删除所有空白。源与解析、源与译文的比较不再把类型拍平成同一个 `math` 或对原表达式作任意归一；块级首尾排版空白、真实 Markdown 表格行的竖线转义和获准包装/逐项译注继续由既有比较合同限定。LaTeXML 原 TeX 提取不在本期。

拆包把共享公式覆盖区间与现有原子块/依赖范围合并，候选切点不得位于跨度内；不完整数学先阻断，不用更小片段规避问题。无缺口、不重叠及按序逐字还原自检保留。

适用 PDF 导出的数学识别也消费同一定界定义：在既有 Markdown 数学规则的识别边界使用共享扫描结果，渲染回调、公式 DOM、历史包装、KaTeX 和打印流程仍各履原职责。不能只打开“允许相邻数字”而取消货币排除，也不能在导出侧保留另一套抢占相邻 `$$` 的识别。未解决数学拒绝导出就绪；独立 PDF 核验仍从实际输入和产物重读，不用渲染器报告替代真实公式保持。

**最小方案比较。** 调整现有正则、再在外层按区间解决 `$$` 与行内冲突也可满足要求，但仍需同一上下文判定及未闭合诊断；按偏移消费定界直接避免候选互抢，维护点更少，选择后者。使用两套扫描再对失败做豁免不能保证拆包与各核验入口一致，不是满足同一要求的方案。结果对象仅为必要的“跨度 + 未解决项”，不扩展为整份文档模型。

### 4.3 D3：按显式 token 的形态计数

继续由 `count_token(text, token)` 提供计数、`strong_token_report` 提供失败/告警，不屏蔽代码，也不根据厂商、文件名或正文自动启用 token。配置仍为实际字面 token 清单；一期不读文件或预设。

| 显式 token 形态 | 匹配边界 |
| --- | --- |
| 普通词形标识符 | 保留现有完整词边界，`kernel` 不由 `subkernel` 满足 |
| `.` 加标识符修饰段 | 匹配完整点分段，右侧标识符续字符使命中无效；点分链允许指令名及其他修饰段紧邻，故 `add.rn.f32` 两段分别命中；左侧必须为文字边界或包含标识符字母的点分链，不由数字小数部分制造命中 |
| `%` 加寄存器名 | `%` 属 token 本身；左侧不能附在另一词形/百分号内，右侧不能继续该寄存器名；后接点分字段允许，故 `%tid.x` 满足 `%tid`，`%tidy` 不满足 |
| 无词字符的既有 token | 保留原字面计数，如 `<<<`；不借形态识别改变其他项目 token |

点分段与寄存器名的词字符范围由同一计数函数处理，大小写及字面字符不改写。形态识别只决定已配置项的边界，不从普通缩写或小数中生成待检查项；验收以实际配置 `.rn`、`.f32`、`.satfinite`、`%r1`、`%tid` 对应的正反例为依据，不把词法命中声称为 ISA 合法性裁决。

对每项同时计算源与译文次数：译文少于源为硬失败；多于源保持既有增加告警；源为零另外明确“配置项源中未出现，此项未检查”，即使译文也为零亦如此。未配置清单保留原 `diffs=None` 及未配置告警。家族汇总只说实际检查了哪些非零源项，缺席项独立列出；API、恢复和合并中现有丢弃告警的调用也须传播本期未检查提示，不把空差异打印成所有配置项通过。

现有逐项 `--strong-token` 和参考家族的旧位置参数继续合并为实际清单；本期不重解释路径或官方标题。最终交付与工作包复验沿用同一函数及真实清单，不能传空清单绕过项目配置。

**最小方案比较。** 对每个项目手工使用不同正则也能计数，但每个入口/项目都须维护相同边界。有限形态分支在现有函数中即可复用，选择后者；不为三个已确认形态建立可配置语法或 ISA 数据库。只删通用左词边界会让长标识符冒充命中，不能满足要求。

### 4.4 D4：普通文本转义只在原节点的输出位置发生

HTML 家族渲染继续分别处理真实标题、普通块与受保护代码。在普通块写出前，检查该块每个可能成为 Markdown 行首的普通文本位置；若将被 `heading_entries` 识别为标题，则只在第一个 `#` 前加反斜线。例如普通 `# define data` 输出为 `\# define data`，阅读文字仍为原文。此操作由原节点类型及正在输出的具体块决定，不在整份 Markdown 上做事后“标题修复”。真实 `<h1>`–`<h6>` 与深层既有标题路径不调用普通块转义；行内代码及围栏正文逐字保持，不转义代码注释。表格单元格只有其实际输出行首会触发伪标题时才处理，不删除管道或内容。

转义动作在现有共享 HTML 保真层提供一个普通块输出助手，各家族只在对应普通块出口调用；`render_inline` 的公式、代码、链接序列化保持。独立对账在输出侧普通文本解码这一 Markdown 转义后比较内容，不能在源侧/代码/公式里全局删除反斜线。源侧真实标题仍从原 DOM 读取，输出标题仍从实际 Markdown 扫描；含管道标题与和代码注释同名的标题不豁免。

存量项目优先从只读快照重新生成解析候选，核对原节点顺序和具体输出出现，再限定纠正受影响源范围。需要保留项目已有合法转换时，沿用该项目现有转换依据和主 Agent 回源核对，记明快照摘要、选区、节点出现、目标行及转义前后文字；这份本次转换说明属于现有源复核依据，不新建长期标题映射库。映射不能唯一确定则继续待复核，不能按标题文本批量替换。受影响源重新独立对账，旧复核按身份失效。

**最小方案比较。** 在各家族的普通块出口各自转义也能满足需求，但会复制相同 Markdown 边界规则。复用共享输出助手只增加必要职责；不统一四个家族渲染器。按含管道、注释同名等文本全局过滤会丢真实标题，不采用。

### 4.5 D5：官方标题文件与工作清单保持不同来源角色

拟定内部 CLI 为四类 HTML 译文检查统一增加 `--official-headings-file <文件>`，仅接受一份文件。共享选项提取保留原位置参数顺序，真实 `parse_args` 返回路径角色 `official_headings_file`；共享加载器在 CLI 的实际基点读取内容后提供 `official` 有序原题。独立调用以调用方 cwd 解析相对路径，交付复验以明确交付根解释；不在 `parse_args` 阶段依当前进程 cwd 读取文件，避免交付入口解释与子进程不同。

文件使用 UTF-8：按行读原题、移除行结束符及首尾排版空白，忽略空行，内部字符和顺序保持；不设置注释、编号或 Markdown 层级语法，行首 `#` 是原题内容，重复原题不去重。缺文件、不可读、编码错误、空清单、选项缺值或重复声明均清楚失败，不能降级为未提供官方基准。文件内容代表已确认本次范围，不能按解析结果删减不匹配项。

| 家族 | 既有位置参数角色 | 文件输入的组合与核验 |
| --- | --- | --- |
| 单页 | 译文、源文之后的逐项官方原题 | 文件与这些逐项官方原题互斥；旧逐项写法继续有效 |
| 参考 | 译文、源文之后的强 token | 文件可与旧强 token 并存；不把它们解释为标题 |
| 分页 | 合并译文之后的有序源路径 | 文件可与源路径并存；保留有序页面范围及既有装配层级映射 |
| API | manifest、official TOC、site root 及源路径；TOC 每行是页面相对路径 | 官方标题文件是额外原题基准；原 TOC 继续独立核对页面集合与顺序，必需输入及完整范围不能被标题文件替代 |

**互斥解释（已批准）。** 原总需求“与已有位置参数同时提供时拒绝”如理解为任何位置参数，当前接口必需路径亦为位置参数，会导致新输入无法使用。已随需求确认：互斥仅限同角色的官方原题输入，其他路径及强 token 保持角色。

官方原题按实际确认范围与源序、译文序逐项对照。层级仍由原 HTML→解析及源→译文的独立有序检查证明，纯原题文件不假装包含层级。分页/API 的生成章节头、已批准层级降级按现有具体装配映射处理，不能把全部标题降级或用模板跳过真实标题；片段使用其确认范围，不套整篇 H1 唯一性。未提供文件的既有官方输入/告警行为保持，新增文件不扩展 PDF 权威入口。

标题工作清单通过单一内部入口 `export_heading_list` 读取显式源 Markdown，复用 `heading_entries` 输出每行一个原题到显式独立路径，不覆盖输入源；沿用较长反引号、波浪线及未闭合围栏规则，未闭合围栏明确诊断，不把隐藏后半篇的清单声称为完整。结果仅是任务准备数据，不能自动当成官方文件；官方基准须来自已确认权威原始来源，不从译文或当前解析产物反向自证。

标题文件作为实际依赖进入现有 `_check_facts`：登记规范化路径及内容摘要，登记加载后的有效原题及确认范围口径，再由 `compute_delivery_identity` 和 `expected_review_binding` 投影；修改同路径内容使相关旧源/语义复核失效，不仅记录参数字符串。不增加独立标题证据格式或第二套参数注册表。

**最小方案比较。** 各入口分别加载文件也可满足要求，但语法、错误与绑定要复制四次；共享小型加载/选项助手加既有真实参数解释是必要最小组合。不把所有入口改为一套新 CLI，不把 API 页面 TOC 重定义为标题表。工作清单导出复用已有事实函数，不另写标题识别器。

### 4.6 D6：目标列别名只读映射

在当前目标译法列别名集合中增加 `中文译法/保留`、`直译`，与 `中文译法`、`定稿译法`、`中文译法/保留形式` 映射到同一 `chinese` 角色。继续使用既有表头清理规则；有限集合显式列出，不模糊匹配、不由模型猜测列义。

对已识别为术语表的表头收集每个必要角色的匹配列：目标角色出现多个候选列即表头歧义，即使两列当前内容相同也不选择首列；必需角色缺失或无法识别则报告表头和受影响数据行。已批准的明确保留/暂定处理等既有特殊分支保持原职责，不能借 `直译` 自动推导“中文”或覆盖处理方式；新增别名不生成缺失字段。普通表未含英文原词角色仍不收为术语输入。

有效记录在现有读取来源元信息中附原目标表头、表头行号及列号，选择/整合的说明可回查该映射；这些字段不参与“英文原词 + 语境”身份，不改变项目优先级、处理方式、语境选择或来源聚合。读取和选择不改写输入表或共享库；不导入 LLM 项目词库。

表格继续逐表逐行核算。分列仅去掉真正的最外层 Markdown 分隔符，保留首尾空单元格，不能通过去掉所有首尾管道使缺值错列；行宽、必要值和处理方式按当前表头角色检查，无法可靠解释的行报文件、行号和原因。每个可识别数据行恰为有效记录或错误；歧义表头下的数据行亦有去向，不因整表提前退出而漏计。已有返回结构 `records, errors, count` 保持，错误会使选择/完整核算失败，不交付一个静默缺行的子集。

**最小方案比较。** 让用户先手工复制并改名表头可以得到可读取副本，但无法直接只读复用现行推荐表；在既有集合增加两个明确别名即可满足正常路径。为符合歧义及逐行错误合同，必要角色查找从“第一个匹配”改为“唯一匹配”，无须通用 Markdown 或术语 schema 引擎。

### 4.7 D7：身份、复核及跨期合同

不新增复核状态或证据格式。现有有限检查器依赖集合须覆盖本期实际参与判断的共享扫描、计数、HTML 转义/源对账、术语读取/选择和标题加载；实际 token、原题及相关项目规则/术语仍随适用身份绑定。对每个受影响包/产物执行既有复验：检查器身份、源、标题文件、项目术语或规则变化即需当前复核；不重算摘要保留旧 closed 结论，不因为缺记录强制重译。非相关有效包继续恢复复用，失败保护原译文与历史证据。

| --- | --- |

## 5. 测试决策

### 5.1 入口、先例与成本

用户已确认沿用现有最高行为入口：四类真实解析 CLI → 原始源独立对账 → 各家族译文 CLI，以及术语选择/整合 CLI；工作包与交付用现有恢复、合并、`verify_delivery` 完成适用闭环。不增加验收平台。扫描偏移、形态计数和文件语法等纯规则只补必要已有底层行为测试，预期由原输入含义独立列出，不从被测输出生成。

沿用公式/结构不变量/围栏测试、四类 shell 回归、术语回归，以及拆包、恢复、合并、交付身份测试的成对损伤方式。只读真实术语表用于兼容核算，项目路径和 121 行不写成产品依赖或固定成功数。普通翻译不为本期增加浏览器/网络依赖；共享改动确实影响 PDF 路径时，用既有 PDF 源核验及最小实际消费样例验收，保持裁决/pending 合同；不为每种词法反例重复导出 PDF。

### 5.2 需求—决策—直接验收追踪

| 需求原子合同 | 设计决策 | 直接验收与必要反例 |
| --- | --- | --- |
| R2.1 相邻、数字邻接、类型/顺序/表达式/位置 | D2 上下文扫描、原始切片 | 原需求两个相邻样例分别得到四个、三个准确行内跨度；`2$\times$3 and $\sim$10` 得到两个；删任一、等数换内容、换序或改类型均因具体差异失败，正文翻译无误报 |
| R2.2 排除代码、货币、转义及未知定界 | D2 掩蔽与 issues | 单/多行块级和块内单美元保持；`$5 + x$` 保持行内公式并可检出损伤；价格样例、转义美元、长/波浪围栏、行内代码不制造公式；无法闭合的非货币候选及金额/数学歧义有位置并阻断完整通过，不能靠剩余跨度相等通过 |
| R2.3 共同消费与安全拆包 | D2 消费侧、原子区间 | 同一反例经适用源对账、四族译文及工作包入口结论一致；切点不入公式、原包按序还原与输入逐字相同；未解决结构不产生可分派包 |
| R2 适用 PDF 消费 | D2 导出数学识别 | 相邻及数字邻接公式进入既有真实 PDF 导出与独立核验，类型、顺序和原内容可对照，价格不被渲染成数学；删式或漏渲染均不能通过。只需最小实际样例，不逐项重复打印全部词法反例 |
| R2.4 既有合法转换 | D2 适配限定及原比较 | 真实表格内合法竖线转义、块级首尾排版空白、一致历史包装、获准额外译注可验；表外范数改变、包装扩大及译注遮蔽源公式仍拒绝；HTML 合法实体及家族序列化正例保持 |
| R3.1 形态边界及正文/代码 | D3 有限形态计数 | PTX 原样例 `.rn=2`、`.f32=2`、`.satfinite=1`，显式 `%r1/%tid` 被计入；删真实项失败，`.rni/%tidy` 不充数；普通缩写、小数不自动成为配置或命中，正文与代码同口径 |
| R3.2 缺席与告警语义 | D3 报告消费 | 源中不存在的配置项逐项“未检查”，空清单明确“未配置”；增加项保持告警不升级硬失败，汇总不能声称缺席项已检查 |
| R3.3 旧角色与复验 | D3、D7 | 四类原传参继续有效，参考位置 token 与显式 token 并存；恢复/合并/交付使用实际清单，遗漏在最终路径复验仍失败 |
| R4.1 普通/真实标题及存量定位 | D4 | 段落、表格和代码注释文字完整且不生伪标题；含管道/注释同名真实标题保留，删标题、改层级、整篇重复 H1 仍拒绝；存量纠正有原节点具体出现及新对账，旧证据失效 |
| R4.2 官方文件语法与角色 | D5 | 单页文件与逐项原题得到同结论；其他三类文件可与其必需旧位置参数并存；空行忽略、`#` 内容保留；缺文件/坏 UTF-8/空清单/缺值/重复文件/同角色并用清晰失败；API TOC 页面漏项仍被拒绝 |
| R4.3 工作清单与独立官方基准 | D5 | 长反引号/波浪线围栏注释不导出，未闭合围栏有诊断；从解析源和译文同时删真实标题，独立原题基准仍发现遗漏，不能用导出的清单自证 |
| R4.4 既有标题/PDF边界 | D4、D5 | 无编号、H7/H8、内容性字符、中文后缀与分页降级保持；片段不误套整篇 H1；PDF 权威仍为裁决清单，新 HTML 文件不能取代它 |
| R9.1 别名等价与只读来源 | D6 | 两别名与规范表头在同源、方式、语境下选择结果相同；可回查原表头/行列且输入摘要不变；`直译` 不改方式 |
| R9.2 权限、语境及必需字段 | D6 | 项目覆盖共享、同词多语境显式选择及来源保持；缺必需值有错误，不从列名猜译法；未选语境仍拒绝，共享库不改 |
| R9.3 完整读取与错误去向 | D6 | 多表及真实项目表的每个可识别行均有效或定位错误；未知/双目标列/缺值/列宽损伤不能静默跳过；非术语表不误收，样本行数非固定标准 |
| 需求第 4 节身份与兼容 | D5、D7 | 已有有效基线后，分别改变源、目标、标题文件内容、适用规则/术语或共享检查器使相关旧证据失效；无关包可复用；重新实际复核可恢复，失败不覆盖原译文/证据 |

### 5.3 实施后完成门禁

上表正反结果均须在实际适用入口取得，失败须归因于目标差异，不能以另一处偶发错误充当验收。四个 HTML 家族分别验收，不用一族 PASS 代替全体；选择/整合实际输出与原表摘要同时核对。保留机器检查、独立源对账及语义复核的分层；当前证据完整、适用工作包可恢复合并、最终路径复验通过，才能声明一期产品完成。

本节为设计时（2026-10-02）制定的完成门禁，现行有效；一期实施、合同内修复及独立复评已完成，2026-10-08 用户确认收尾并要求删除已完成计划、提交改动。既有回归绿、文档覆盖表、格式/链接检查不能证明产品能力。本期不要求等待后三期辅助生成器，可用现有人工复核和证据输入完成实施验收。

## 6. 不纳入范围

R3 文件/预设、LaTeXML TeX 提取与浮动体、数字统计、复核/任务/目录生成器、批量状态核对及 PDF 候选物化分别由后三期设计；本期标题工作清单不生成最终目录。不新增代数等价、整类免检、标题文本豁免、通用文档 IR、规则引擎、厂商自动选择、公共 SDK、数据库或新状态体系。不回写外部项目、批量改译文、改原始快照、导入 LLM 共享词库或发版。[总览第 5 节](./2026-10-02-paper-practice-requirements.md#5-假设待批准差异与不纳入项)继续适用。

## 7. 进一步说明

### 7.1 假设、兼容差异与批准状态

执行者为主流大模型及现有宿主；确定性脚本只处理已明确语法和事实，主 Agent 继续负责来源、术语、语义及 PDF 裁决。文件格式是既有 Markdown 与 UTF-8，不新增环境或网络获取要求。

R2 可靠扫描及消费侧收敛会使相邻/数字邻接损伤、类型/内容损伤或未解决定界从漏检变为失败/待复核；适用 PDF 数学识别同步这一语义，不能保留忽略合法公式的旧导出结果。R3 有效计数会拒绝此前错误通过的 token 遗漏，并显式显示缺席项；R4 普通文字转义和便利文件输入、R9 表头兼容为本期能力。源解析与检查身份变化使相关旧证据失效，历史原件保留。D5 互斥解释已随需求确认；标题文件的来源权威不能由脚本判定，主 Agent 须在现有源范围合同下确认。

上述差异均已按批准实施。本段审批记录为设计时（2026-10-02）事实：当时用户仅确认四期划分、编写设计及既有验证入口，其后需求、设计与执行计划均已获明确批准并授权实施；合同内修复重审见 §7.4–§7.7。不把 `ready-for-human` 当作可执行状态。

### 7.4 修复重审（2026-10-07）：序列化与阅读事实收敛（R1–R3）

一期实施后连续三轮评审修复（首轮 8 项、A2/A3 标题事实与对账口径、F1/F2 表格阅读保真与标题尾部 `#`），2026-10-07 评审又确认三个正确性缺陷（R1 代码与伪数学保护区重叠重复拼接、R2 表格链接语法转义被再次加写且漏过对账、R3 真实标题字面反斜线序列化与事实读取不匹配）。同一机制（行内序列化的反斜线处理）连续多轮出错，按 AGENTS §5 在改动前重审，本节为重审记录与方案裁决。

**根因：四种文字在同一字符串上失去区分。**

1. **源字面与生成的语法转义混淆（R2 根因）。** `render_inline` 为链接标签生成 `\[ \]` 语法转义后，`escape_cell_backslashes` 在整段序列化字符串上按阅读语义加写，把生成语法当成原文字面再次加写（`A\[B\]` → `A\\[B\\]`，实际阅读多出原文没有的反斜线）。字符串层面两者不可区分。
2. **第二套美元分类规则（R1 根因）。** `_protected_inline_spans` 用独立正则 `_MD_MATH_SPAN_RE` 在含代码的整段文本上识别“公式”区间，与 `scan_math` 的代码感知扫描口径不同；代码区间与其内部美元区间只排序不去重，消费函数按序拼接时游标回退，代码内容被重复输出。
3. **标题编码与解码职责不同步（R3 根因）。** `escape_heading_tail_hash` 只在尾部 `#` 前加一个反斜线，不按阅读语义处理原有字面反斜线；而 `heading_entries` 的 `resolve_backslash_escapes` 按阅读语义解码整段标题。任意数量字面反斜线的合法标题因此编码后阅读失真并被独立对账误拒（旧版已有阅读损失，本轮新增的是误拒）。
4. **对账重复解释（R2 漏过原因）。** `_norm_text` 先 `resolve_backslash_escapes` 解码全部反斜线、再解包链接并手工删除 `\[` 转义，同一反斜线被解释两次，双重加写的损伤产物仍与源字面“相等”。

**方案比较。**

- 继续局部修补（按链接、金额、反斜线数量追加豁免表或正则特例）：保留上述分裂，每类新样例都需要新豁免，维护点持续增加，且无法证明阅读保真；不采纳。
- 新建通用转义平台、IR 或规则引擎：超出本期已确认需求（第 6 节非目标）；不采纳。
- **收敛方案（采纳）：** 在既有节点出口区分源字面与生成语法——`render_inline` 在序列化前对源文本节点（代码与已识别数学元素之外）按阅读语义加写反斜线，保护区复用代码感知的 `scan_math` 事实；生成的链接语法、代码定界与数学定界在加写之后产生，不再被二次加写。对账端按同一阅读语义单次解释：链接解包先于反斜线解析，标签转义由阅读解码一次完成，删除手工二次替换。真实标题序列化与事实读取共用同一阅读语义：标题文字经同一文本节点加写，尾部 `#` 关闭标记转义保持；`heading_entries` 的 H7/H8 扩展路径同步按阅读语义解码。

**复用、新增与删除。**

- 复用：`scan_math`/`scan_math_spans`（既有代码感知公式事实，删除第二套美元正则后为保护区的唯一公式来源）、`parse_inline_code_spans`、`resolve_backslash_escapes`、`_escape_segment_backslashes`、`render_inline` 既有代码哨兵与链接职责、`heading_entries` 的 markdown-it 实际解析语境。
- 新增：`render_inline` 的 `escape_backslashes` 形参（节点出口处的源文本加写开关），仅表格格位与真实标题两个既有出口启用；普通段落、列表、提示框、图题与表题不在本轮范围。
- 删除：`_MD_MATH_SPAN_RE` 第二套美元分类；`escape_cell_backslashes` 的整段字符串加写（职责移入节点出口，函数按源文本节点级加写保留并更名 `escape_text_backslashes`）；`_norm_text` resolve 路径中链接解包后的手工 `\[`/`\]` 替换（重复解释）。

**兼容影响（字节级）。** 解析产物字节变化仅限：含字面反斜线的真实标题行、含链接或字面反斜线的表格格位——这些输入此前或被误拒（R1/R3）或已存在阅读损伤（R2 及 R3 旧版阅读损失）；不含反斜线、链接方括号与尾部 `#` 的既有产物逐字节不变，由既有四族回归验证。源解析与检查口径变化按 D7 使受影响旧复核证据失效，需重新实际复核后恢复。

**选择理由。** 满足同一合同（R2.2 代码排除、D4 内容保持、R4.1 真实标题保持、正常输入不误拒）下维护机制更少：一套美元规则（`scan_math`）、一套阅读解码（`resolve_backslash_escapes`）、一个加写点（源文本节点出口），替代重叠区间、双套美元规则与双向字符串补丁。

**独立核验保留。** 源侧 DOM 独立预期不消费渲染输出；markdown-it 实际阅读断言与损伤反例（保护区重复拼接、链接双重加写、标题字面反斜线丢失）保持定位拒绝；不以两端同样归一后的相等代替真实阅读。

### 7.5 修复重审补充（2026-10-07）：标题阅读事实与链接标签字面标点（F1/F2）

§7.4 收敛实施后经终审确认仍有两条未收敛路径：标题链接标签的字面反斜线阅读文字被二次解释导致合法输入误拒（F1）；表格链接标签的字面星号在阅读中丢失，且删除损伤被两端同样归一放行（F2）。同一机制第四轮出错，按 AGENTS §5 在改动前补充重审；两例在修复前快照同样存在，属本轮保真合同未闭合，不是新增回归。

**根因。**

1. **标题阅读事实进入第二次语法解释（F1）。** `heading_entries` 已按阅读语义解析反斜线，title 是“阅读文字 + 链接语法”；`_MarkdownFacts` 随后用 `_norm_text` 处理时，其中无条件的 `\[`/`\]` 剥离把阅读文字中的字面反斜线当作生成语法删除。该剥离的唯一正当职责是撤销源侧 `_headings` 里 `render_inline` 对链接标签生成的转义；对已解释的阅读文字是第二次解释，输出事实丢失字面反斜线，与独立 DOM 预期不符，合法输入被误拒。源侧纯文本标题的字面 `\[` 也被同一剥离删除（两端归一掩盖）。
2. **强调定界在三处失守（F2）。** 序列化：`escape_text_backslashes` 只加倍反斜线，`\\*` 中裸露的 `*` 仍是活动强调定界，成对后实际阅读丢失星号（`A\*B\*`、`A\**B\**` 阅读均为 `A\B\`）。输出侧：标签事实只用反斜线解码冒充完整 Markdown 阅读，被强调吃掉的星号仍被“看到”。源侧：`_norm_link_label` 对 DOM 字面文字应用 Markdown 粗体剥离（`_MD_BOLD_RE`），源预期先丢星号，两端同样归一使“删除产物全部四个星号”仍通过对账。

**方案比较。**

- 继续补分支（按字符、数量或链接/标题上下文追加豁免表或针对性剥离）：每一新字符组合都需新豁免，且仍以归一相等冒充阅读；不采纳。
- **收敛方案（采纳）：** 序列化在 `escape_text_backslashes` 既有职责内把源字面强调定界（`*`/`_`）一律转义为 `\*`/`\_`——定界不论数量与位置同一处理，不设例外表，转义后的定界对 markdown-it 惰性；输出侧链接标签事实复用 markdown-it 实际行内阅读（renderInline 取文本），删除“反斜线解码 + 代码/粗体语法剥离”的重复解释组合，脚注引用与数学记法归一保持；源侧标签是 DOM 字面文字，删除 Markdown 粗体剥离，节点转换（代码/脚注/数学）归一保持；标题事实区分已解释与待解释：`_norm_text` 的 `\[`/`\]` 剥离加开关，标题路径（已解释的阅读文字）关闭，源侧 `_headings` 复用 `_MD_LINK_RE` 仅在链接标签内撤销一层生成转义，链接目标身份保持。

**复用、新增、删除与兼容。**

- 复用：markdown-it 实际行内阅读（替代表格链接标签的解码+剥离组合）、`_MD_LINK_RE`、`escape_text_backslashes` 既有节点出口职责、`_norm_text` 既有归一骨架。

- 删除：`_norm_link_label` 输出侧的 `resolve_backslash_escapes` + 代码/粗体语法剥离组合（由真实阅读一次完成）；源侧标签的 `_MD_BOLD_RE` 剥离；标题路径对阅读文字的全局 `\[`/`\]` 剥离。
- 兼容影响（字节级）：含字面 `*`/`_` 的表格格位与真实标题的产物字节变化（这些输入此前阅读已损伤）；标题中字面 `\[` 的对账事实由两端归一删除改为两端保留（合法输入保持通过）；受影响旧复核证据按 D7 失效，重新实际复核后恢复。

### 7.6 修复重审补充（2026-10-07）：公式链接误拒与内容星号删除放行（P2 两项）

§7.5 收敛实施后经独立评审（tdt-f1f2-convergence-review）确认仍有两项既有合同缺口：链接标签内公式被无数学规则的普通阅读器解释，四族合法输入由通过变为误拒（P2-1）；真实标题、标题链接标签与非链接表格格位的内容性星号仍被两端剥离，删除损伤通过独立源对账（P2-2，修复前快照同样漏拒，属既有缺口未闭合）。同一机制（受保护/字面事实被再次按 Markdown 语法解释）连续多轮出错，按 AGENTS §5 在改动前补充重审。

**根因。**

1. **标签阅读器无数学保护（P2-1）。** §7.5 把输出侧链接标签事实改为 markdown-it 真实行内阅读（`_HEADING_FACTS_MD.renderInline`），但该实例只有 CommonMark/table 规则：标签中 `$a*b*c$` 的 `*b*` 先被强调规则消费，其后的 `_MD_MATH_RE` 去定界无法恢复已被吃掉的内容，标签阅读事实由 `a*b*c` 变为 `abc`，与源侧 DOM 事实不符，四族正常输入误拒。事实丢失层在核验投影，不在序列化或交付渲染：产物中的 `$a*b*c$` 表达式与链接目标字节保持，真实交付数学消费者（`export_pdf.build_markdown` 的公式条目与 `data-tex`）同样保持 `a*b*c`。
2. **字面内容被当作生成粗体语法剥离（P2-2）。** `_norm_text` 无条件应用 `_MD_BOLD_RE`，作用于三类本不含生成粗体的角色：源侧真实标题的 render_inline 序列化（源文本节点的字面 `*` 不经标题事实出口加写，保持字面）、已按阅读语义解释过的输出标题事实、源/输出表格格位文字。两端预期同被归一为 `AB`，删除产物全部四个内容星号的损伤与正常产物“相等”而放行。调用职责核对结论：解析器从不为 `<strong>`/`<em>` 生成 `**`（`render_inline` 走 `get_text`，行内格式标签在序列化中消失，实测 `<dd>`/列表项/段落内 `<strong>` 的产物均无定界符）；产物中仅有的生成 `**` 是定义列表术语 bullet、提示框/图题/页签结构标记，全部由结构性正则或前缀在 `_norm_text` 之前消费。`_MD_BOLD_RE` 因此没有任何合法的生成语法输入，是纯二次解释；定义列表的合法转换（bullet 生成与 `terms()` 结构提取）不经过它，删除不受影响。
