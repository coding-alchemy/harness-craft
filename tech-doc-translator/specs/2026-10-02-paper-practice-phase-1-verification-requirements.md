## 1. 用户可观察的结果与范围

用户能处理含相邻公式、公式后紧接数字、PTX 指令修饰符及正文行首 `#` 的合法输入：公式和已指定强 token 不被漏检，普通文字不会变成标题，项目术语表采用已知表头别名仍可读取。删除或篡改公式、遗漏强 token、删除真实标题及破损术语行均有明确诊断；正常输入和既有合法转换不被误拒绝。

本期只定义上述核验基础需求，不增加源家族或翻译编排机制。本文沿用上游 R 编号；R3 的文件清单与 PTX/ISA 预设属于三期，不构成本期完成条件。P0 表示已复现核验漏项，P1 表示当前合法输入处理缺口；优先级不授予实施权限。

本需求及其兼容影响、R4 互斥澄清已获用户批准；一期实施及合同内修复已验收，执行计划按生命周期删除。最终实现决策见[一期设计](./2026-10-02-paper-practice-phase-1-verification-design.md)，主要行为与兼容影响见 [CHANGELOG](../CHANGELOG.md)。

## 3. 功能需求与直接验收

### 3.1 R2：相邻及数字邻接公式的可靠扫描（P0）

来源：素材 03 R3.1、R3.2。

1. 正确区分 `$…$$…$` 的相邻行内公式与真实 `$$…$$` 块级公式；合法公式的闭合美元后紧跟数字不能造成漏扫。公式的类型、顺序及原表达式保持，位置可回查，不把相邻公式之间的正文纳入表达式。
2. 货币文本、转义美元、代码围栏和行内代码继续排除。无法判定的数学定界必须定位上报，不能静默忽略或默认为可通过；不完整结构不得被拆坏后继续分派。
3. 拆包、HTML/PDF 源对账及译文检查在各自已确认范围内采用一致公式事实；拆包不切入新识别的公式。比较仍按类型、顺序和原表达式，不做代数等价推断，不以事后忽略“伪块级”失败修复误扫。
4. 真实表格行内竖线的既有转义归一、块级公式首尾排版空白、源译一致的历史数学包装告警，以及显式获准译注的逐项处理保持；不得把这些规则扩展为整类公式豁免，获准译注不能替代或遮蔽源公式。

**直接验收：**

| 场景 | 必须观察到的结果 |
| --- | --- |
| `gain $x$$\sim$ noise and more prose here $y$$\le$ bound end` | 按顺序得到 `x`、`\sim`、`y`、`\le` 四个行内公式；只翻译正文不误报公式变化 |
| `speedup of 2$\times$$\sim$3 over baseline and $a$ ok` | 得到 `\times`、`\sim`、`a` 三个行内公式，不吞正文 |
| `2$\times$3 and $\sim$10` | 得到两个行内公式；删除或修改任一个均失败且可定位；同数量换内容、换顺序或改类型同样失败 |
| 真实单行/多行块级公式，`costs $5 and $10`，转义美元、围栏与行内代码 | 块级公式保持；其余非公式文本不参与预期。未知定界有具体位置及未解决状态，不能冒称完整通过 |
| 表格内转义竖线与表外范数、历史包装及获准译注 | 既有合法转换仍可验；新增、扩大或改变历史包装仍失败，表外不套用表格归一 |
| 含上述公式的安全拆包、源对账及四类 HTML 译文检查 | 同一公式的范围、类型及内容结论一致，包按序还原不改源；删除反例经适用入口及最终路径复验均被拒绝 |

### 3.2 R3：强 token 核心计数（P0）

来源：素材 03 R3.9、05 R5.6 及 CUDA 审计附录清单；本期只覆盖匹配边界和有效计数。

1. 项目显式配置的 token 按其形态匹配，覆盖紧贴指令名的 `.` 修饰符与 `%` 寄存器；不能将 `.rn` 当成 `.rni` 的一部分，或用 `%tidy` 替代 `%tid`。普通词缀、正文缩写和数字小数点不能被误认作独立指令修饰符。
2. 对正文和代码中的命中采用同一计数语义。源中存在的指定 token 被译文遗漏时失败；源中未出现的配置项明确告警“此项未检查”，不能以源译均为零声称已检查该项。清单整体未配置时的现有告警和译文增加项的现有报告语义保持。
3. 继续接收现有逐项参数，不改变源文件、官方标题及旧强 token 位置参数的角色。恢复、合并和最终交付使用实际项目 token 与同一核验口径，不能用空清单或另一个匹配标准绕过本期修正。

**直接验收：** `add.rn.f32 d, a, b; mov.u32 %r1, %tid.x; cvt.rn.satfinite.e4m3x2.f32 d, a;` 的 `.rn=2`、`.f32=2`、`.satfinite=1`，并能计入配置的 `%r1`、`%tid`。删除任一真实命中项失败；`.rni`、`%tidy` 不满足对应期望，普通缩写和小数点不制造命中。对源中不存在但已配置的项以及未配置清单，分别明确“未检查”；不能把告警写成全部强 token 已核对。四类 HTML 入口及现有工作包复验保留正确样例、遗漏反例和既有传参行为。

### 3.3 R4：真实标题与普通文本的边界（P1）

来源：素材 03 R3.3–R3.5。

1. 普通段落、表格文本及代码注释的行首 `#` 不得成为 Markdown 标题；真实 HTML 标题保持其层级、内容性字符和顺序。存量源需要纠正时，从原始节点到具体出现位置建立转换依据，重新核对受影响源及复核证据；不能按含 ` | ` 或与注释同名，在源译两侧一律排除标题。
2. 四类 HTML 检查均支持 UTF-8 官方标题原题文件：每行一项，忽略空行，保留标题中的 `#` 等内容，不设置注释语法。官方标题文件与既有逐项官方标题输入互斥，同时提供时拒绝；缺文件或空清单报错，不回退为未提供官方基准。其他既有位置参数仍按原角色解释，不把源路径或强 token 当标题。
3. 标题清单导出复用围栏感知规则，排除较长反引号及波浪线围栏内的注释，结果只作为工作清单。独立官方基准必须来自已确认权威源，不能从译文反推，也不能用自己的解析产物证明自身无漏项。
4. PDF 继续以主 Agent 裁决清单提供权威标题；本期文件便利输入不增加 PDF 平行权威入口。标题文件及导出的工作清单均不能放宽独立源对账、标题硬检查或完成门禁。

**直接验收：**

| 场景 | 必须观察到的结果 |
| --- | --- |
| 普通 `# define data`、表格文字及围栏内注释 | 内容保持普通文字或代码语义，不增加标题，不靠删除原内容获得通过 |
| 含管道的真实标题、与代码注释同名的真实标题 | 真实标题保留并参与检查；删标题、改层级或重复整篇 H1 仍失败 |
| 等价官方清单文件与逐项官方标题输入 | 结论相同，空行忽略，含 `#` 标题保留；文件缺失、清单为空或两种官方输入并用均明确失败 |
| 较长反引号及波浪线围栏中的标题样式 | 工作清单导出不计入；已确认权威清单不受解析源漏项影响 |
| 从解析源删去一个真实标题，或纠正存量伪标题 | 前者被独立官方基准发现；后者有原节点与具体出现位置依据，受影响源重新对账，旧证据不自动恢复资格 |

既有原题中文后缀边界、深层标题、分页装配、片段范围与 H1 约束保持；片段不会被错误套用整篇 H1 唯一性要求。嵌套括号问题未复现，不立新的豁免或修复项。

### 3.4 R9：已知项目术语表表头兼容（P1）

来源：素材 05 R5.5。

1. 只读识别已确认的 `中文译法/保留`、`直译`，与现有规范目标译法列作等价映射；映射结果可回查到原表头和位置，不改写原表。列名 `直译` 不授予处理策略，不能据此覆盖现有处理方式。
2. 既有处理方式、项目优先级、语境、来源及词条身份语义保持；项目表仍覆盖显式选择的共享默认值，同词多语境仍须明确裁决。缺字段不得补造值，程序不猜测译法，不自动启用共享库。
3. 已识别术语表的未知或歧义目标表头明确报错；所有可识别行进入读取结果或逐行给出文件、行号及原因。不能因兼容而吞掉破损行，普通非术语表不被当作术语输入。不将 `Papers_LLM` 词库并入 Skill。

**直接验收：** 两种别名与等价规范表头在同一源文、处理方式和语境选择下得到相同有效词条，映射可追溯且原文件摘要不变。真实 LLM 表全部可识别行均进入结果或有逐行明确错误；121 行只描述现有样本，不构成固定成功条数。未知/歧义表头及破损行不静默跳过；项目覆盖和同词不同语境的显式选择仍正确，未裁决语境仍拒绝，原共享库不被修改。

## 4. 兼容影响与证据有效性

- R2/R3 修正会改变部分公式分组、计数及硬检查结论，既有错误 PASS 可能变为失败或待复核。这是已批准的兼容影响，不能通过扩大容忍规则保留错误结果。
- 解析源、规则、项目术语、官方清单或检查器身份变化，按现有绑定使受影响的源对账、工作包及交付复核失效。新增文件输入必须以实际内容和有效参数参与现有身份核对；只记录文件路径不能证明口径未变。
- 对存量项目，仅在明确范围内修复和复验；不批量重写译文、术语表或快照，不重算摘要后追认历史 PASS。不相关有效包继续按既有恢复合同复验复用，缺记录不直接等同于必须重译。
- 硬检查通过仍不等于正文完整、术语正确或语义复核完成。不得将本期校验改进解释为自动完成语义复核或扩展 PDF 权威来源。

## 6. 非目标

本期不增加强 token 文件清单/预设、通用规则引擎、自动厂商选择、LaTeXML 转换、数字统计、证据/任务/目录生成器、批量状态核对或 PDF 候选物化；这些能力分别由后续阶段定义。也不增加代数等价、整类免检、标题文本豁免、按行迁移译文、LLM 共享词库或新的状态体系。[总需求第 5 节](./2026-10-02-paper-practice-requirements.md#5-假设待批准差异与不纳入项)的排除项继续适用。

本期需求及第 4 节兼容影响已获批准；具体内部参数名称、共享模块改动及算法由获批后的设计决定。未知定界和未知表头必须显式暴露，不能借设计待定新增静默容忍。无未经批准的实现行为变化。

**R4 互斥范围（已确认）：** 原总需求写“与已有位置参数同时提供时拒绝”，但当前四类入口的位置参数分别承载官方标题、源路径或强 token。本期按实际接口确认：互斥仅针对同属官方标题的逐项输入，源路径和强 token 不受牵连。

## 7. 本期完成标准

本期实施后的完成证据须同时证明第 1 节核心结果和第 3 节各项正反验收。共享能力在实际适用入口运行，安全拆包还原、现有恢复/合并及最终路径复验保持；受影响旧证据被正确拒绝、复核后可重新取得资格。四类 HTML 的代表样例分别验收，不用一个家族的 PASS 代替全部；共享变化影响 PDF 检查时验证其适用路径，保持已裁决标题及 pending 合同。

既有适用回归、格式与链接检查是辅助证据，不能替代合法输入得到正确结果、损伤被定位拒绝和原始术语表保持只读。一期实施、合同内修复及独立复评已完成；2026-10-08 用户确认收尾并要求删除已完成计划、提交改动，按生命周期关闭本期计划。后续项目仍须按现行合同完成各自的语义及 PDF 视觉复核。

## 8. Karpathy 精简与自检

1. **基线：** 第 2 节依据当前共享扫描、源独立对账、四类参数解析和术语读取/选择列出真实缺口；完整性、留痕及术语裁决仍为既有权威合同，不复制四套核验规则。
2. **假设与差异：** 面向主流大模型及现有内部脚本；R2/R3 会改变错误核验结论，R4 增加便利输入，R9 增加只读别名，均在需求评审范围内。没有把四期划分确认当作行为批准，也没有实施未经批准变化。
