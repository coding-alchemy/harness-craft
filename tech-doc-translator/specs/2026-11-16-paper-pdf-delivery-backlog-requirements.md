## 1. 用户结果与范围

目前一篇论文的翻译加 PDF 交付要 6–7 小时 agent 时间，用户无法接受。下一次翻译 LaTeXML 论文并交付 PDF 时，执行者不必改共享安装或写一次性补丁，就能让合法译文通过核验；失败时第一屏就能看到根因；agent 时间达到 §6 的整体目标。

W2 的基线：agent 时间 5h43m，其中脚本执行只占 3.7%，模型读输出与生成占 87.5%，上下文压缩占 8.7%；修导出占 2h39m（锚点 1h08m、链接目的地 38m、KaTeX 宏 53m）。优先级按能省的时间排：P0 是 R1、R2、R3、R5、R15。

本文收录经验文档里组件还没有实现的条目，按问题合并。已实现的条目已从经验文档删除，不在本文重复（见 2.1）。批准本文只确定目标行为，不授权设计或实施。

## 3. 需求

### R1 PDF 文本核验接受数学穿插与跨页接缝（P0）

来源：E1 A.2、D.3；E2 R9；E3 §8、§9。

- 现状：`verify_pdf.py:2996` 的 `subsequence_in_window` 只在 `4×片段长+60` 字符内放宽同页穿插（`:3002`）。KaTeX 字形副本在页末批量绘制，长度常超出预算；句子跨页时片段被劈开。两种情况都以 `text-missing` 硬失败，而 PDF 版面正常。
- 要求：一个片段在 PDF 中两种情形下按 relaxed 登记、交视觉复核：被数学字形串打断但各段逐字连续且有序；被页缝分为两半且两半各自逐字连续。缺字、换字、乱序仍失败。报告写明穿插长度或页缝位置，不再要求执行者用改写译文或插分页把片段挪开。
- 验收：AutoInt 第 7/8 页、HSTU 第 34/35 页的原始译文通过且登记 relaxed；删一个字或调换两段的副本失败。

### R2 译注剩余文字核验覆盖含数学的段落和表格单元格（P0）

来源：E1 H.4、B.3。

- 现状：`verify_pdf.py:1715` 要求剩余文字整串出现在同一 PDF 文本对象里（`if remainder in text`）。含行内数学的块会穿插 KaTeX 字形；跨页段落被拆成多个对象。两者都报 `translator-note-collateral`。
- 要求：剩余文字按数学位置分段，各段在对象中按序出现即通过；对象内不完整时，以本章页文本做有序分段核对。真实连带删除仍失败。
- 验收：Hiformer 含数学的译注段落、cuSPARSE 表格单元格内的 21 处译注通过；删掉剩余文字中一个词的副本失败。

### R3 译文不需手工放置锚点，目的地判定不误报（P0）

来源：E1 A.1、D.2、H.2、H.3；E2 R12；E3 §10；W2 §2.2、§6.2。

- 现状：
  - `parse_reference_html.py:423` 能列出锚点目标，`references/latexml_source.md:54` 写了锚点该放在哪里，但把锚点放进译文靠执行者手工完成。W2 中执行者自写 `patch_export_anchors.py`、改三轮，补 65 个锚点用了 1h08m。
  - `verify_pdf.py:4976` 以页面上最近的上方基线限制目的地窗口，宿主段首行的数学上标也算在内，独立锚点段放在含上标的释文段前无论怎么摆都失败。跨页长段的独立段锚落在续页首行，同样超出窗口。W2 修 22 项 `internal-link-target` 用了 38m。
- 要求：
  1. 执行者不再手工放置锚点：锚点按导出与核验要求的写法出现在译文对应对象上（公式锚并入式号行或作为式号行后的独立段，图锚独立成段并与图片行空一行，脚注锚放在定义体内，段锚并入段首）；放不上的锚点列出位置和原因。设计时优先复用 API 家族已有做法：解析稿自带锚点行、译文照写（见 CHANGELOG“未发布”中带 id 引用块的锚点），再考虑其他方式。
  2. 目的地窗口上界不计宿主自身的字形。
- 验收：ULTRA-HSTU 的译文不经手工补锚点，导出的内部链接检查一次通过；Hiformer 式号后释文段、ULTRA-HSTU 的 S1.p3.1 与 S5.p1.2 用独立锚点段通过；删除锚点、改写法、调换顺序或挪进其他锚点所在块的副本失败。锚点挪到相邻、原本没有锚点的块时不保证检出。

### R4 长代码块随标题移页不判失败（P1）

来源：E1 B.3。

- 现状：`verify_pdf.py:4482` 的 `code-page-gap` 只看前页尾部空白。“标题 + 长代码块”因标题不孤行整体移页时也失败。
- 要求：代码块前同页紧邻标题时记 relaxed 交视觉复核；没有标题粘连的整块移页仍失败。
- 验收：cuSPARSE 对应页通过并登记 relaxed；去掉标题的同构样本仍失败。

### R5 KaTeX 不支持的命令在导出前暴露并有受支持的适配（P0）

来源：E1 D.1、D.5、H.1；E2 R33；W2 §2.2、§6.2。

- 现状：确认数学按原 TeX 逐字渲染，`\textsc`、`\penalty\ `、`\lx@text@lbrace`、行内 `split` 等在 KaTeX 渲染时才失败（`export_pdf.py:4780` 的 `katex-error`），一次只报每式第一个错。导出器不提供宏映射（仓库无 `macros` 选项）。执行者只能改快照或改共享脚本；W2 为 `\textsc` 一个宏改 `export_pdf.py`，转义层数来回 17 步、7 次回滚，用了 53m。
- 要求：
  1. 提供只渲染数学的预检，一次列出全部失败公式、位置和原因，翻译轮即可运行。
  2. 提供受支持的宏映射输入（如 `\textsc→\text`），只改交给渲染器的字符串，`data-tex` 与核验基准不变，映射写入导出报告。
- 验收：DIN 的 155 个公式、ULTRA-HSTU 的 `\textsc{SLWeight}` 预检一次列全；带映射导出通过，公式对账不变；未登记宏仍失败并给出建议。

### R6 PDF 中链接标签不在词中断开，带链接的图片不与图注分页（P2）

来源：E1 D.4；CUDA PG 13.5 视觉复核（图 42 的图注孤零零出现在页首，共享安装 `style.css` 被就地修改）。

- 现状：
  - `assets/pdf/style.css:61` 对所有链接设 `word-break: break-all`，引文标签被拆成 `Covington et al., 2|016`；CUDA PG 第 121 页的英文链接同样被拆。
  - 图片与图注不分页的规则（`style.css:54`–`:56`）只匹配直接含图片的段落；API 家族的图片包在链接里（`<p><a><img></a></p>`），不受约束。
- 要求：
  1. 短链接文字按正常词边界断行，长 URL 仍能断开、不溢出版心。
  2. 带链接的图片段与紧随的图注段同页，约束与不带链接的图片相同。
- 验收：DIN 四处引文标签不再拆词；含长 URL 的样本不溢出；CUDA PG 图 42 与图注同页。

### R7 LaTeXML 解析不带出列表圆点；题注回显的转义规则（P2）

来源：E1 H.5；E2 R5 第 3 项。

- 现状：`_latexml_source.py:766` 只去掉与序号相同的有序列表标签，无序列表的 `•` 留在正文，Markdown 变成 `- • `，PDF 出现双圆点。翻译约定只写了表格内 `|` 的转义（`references/translation_conventions.md:15`）。
- 要求：无序列表的 CSS 标记不进入正文；翻译约定写明双语题注回显中 `*`、`^`、`_` 的转义。
- 验收：Hiformer 11 行列表不再有 `•`；含 `r_*` 的加粗题注在 PDF 中强调完整。

### R8 批准的图片适配有受支持的声明入口（P1）

来源：E2 R24；E2 §4 “结构性大片空白”。

- 验收：MTGR 方案 A 用一条声明完成并通过核验，还原后与原始字节一致。

### R9 失败诊断与输出（P1）

来源：E2 R17、R19、R21、R27、R34、R3；W2 §3.3、§5.2。

- 现状：
  - 当前导出证据缺文件时，核验报出 `provenance-evidence-missing`、`image-display-evidence-mismatch` 等十余类“导出 None”不符，ULTRA-HSTU 一次 33 项，根因只有一个：work-dir 里没有 `export_report.json`。
  - `export_pdf.py:3967` 的 `file_uri` 对相对路径直接 `as_uri()`，相对 `--work-dir` 抛 `ValueError`；核验侧接受相对路径。
  - 对账只给前 3–5 条差异（如 `_source_reconcile.py:2190`、`:2543`），STCA 的表格失败直到第 9 次导出才露出。
  - 全绿复跑也整段打印全部明细。W2 中 bash 输出累计 827k 字符，9 次上下文压缩共 30m，其中 5 次紧跟大输出或大文件读取。
- 要求：
  1. 证据缺位时先报一条根因（缺什么文件、期望路径、应在同一 work-dir 先导出），不再逐类报内容不符。
  2. 导出入口把 work-dir 规范为绝对路径。
  3. 失败输出第一屏按检查类别计数并给样例，全部差异写入文件并打印路径。
  4. 默认只打印失败、告警和计数，明细需显式请求。
  5. `references/` 写明大输出先落盘再读摘要。
- 验收：ULTRA-HSTU 缺证据场景只报一条根因；相对 work-dir 导出成功；STCA 表格失败在第一次运行出现在类别计数里；全绿复跑输出不超过一屏。

### R10 检查器变化后的恢复路径与首跑误报（P1）

来源：E2 R1、R29、§2.1。

- 现状：检查器文件变化后，记录绑定和导出证据同时失效。执行者只重建记录不会通过，正确顺序（重建记录 → 重新导出 → 重跑复核链）没有写进文档。STCA 的 `--prepare-reviews` 首次运行报“候选准备期间依赖身份变化”，原样重跑即通过，原因未定位。
- 要求：`references/workflow_helpers.md` 写明检查器变化后的恢复顺序和每步的检查点；定位首跑身份变化的来源并消除，消除前报错要指出是首跑。
- 验收：按文档在改过检查器的项目上一次恢复；STCA 首跑不再误报（若无法复现，记录为待定位，不改为常规重跑两次）。

### R11 数字复核候选在格式修复后保持闭合（P1）

来源：E2 R18。

- 现状：候选以行号定位。HSTU 只做拆段、移锚点、加分页后，165 项中 115 项落点失效，需要整体重新闭合。
- 要求：候选以数字与相邻上下文作定位键，行号只作展示；内容未变的候选继承原结论，只重审新增或变化项。
- 验收：HSTU 格式修复前后，只有真实新增或变化的候选待审；新错误数字不继承旧结论。

### R12 交付文书的机械部分由组件生成，严格参数在导出前把关（P1）

来源：E2 R14、R15、R31；E3 §2、§6。

- 现状：交付说明、外部文件记录、`00_目录.md`、视觉和链接复核备注里的摘要、路径、清单和计数靠手写，曾出现“41 vs 42”“83 vs 85 个锚点”等不符。J 轮漏传 `--require-display-map` 时导出照常完成，核验才拦下。
- 要求：
  1. 从交付记录与证据渲染上述文书和复核备注的统计部分，执行者只补判断和例外；交付根一级的说明文件在渲染时登记。
  2. 记录要求的严格参数与本次导出参数不一致时，导出在开始前失败。

### R13 无图像能力时的视觉复核（P2）

来源：E2 R11；E3 §11。

- 现状：`--visual-aid` 只提供定位统计，`SKILL.md:32` 明确它不构成视觉复核。HSTU、J、ULTRA-HSTU 的会话或子代理没有读图能力，各自用“程序化检查 + 关键页清单交用户”的方式闭环，写法和标注各不相同。
- 要求（D1）：会话和子代理都没有读图能力时，程序化检查加用户抽查关键页算视觉复核完成。统一最少检查集、关键页清单和固定标注词；用户的抽查结论写进复核记录之前，视觉复核保持未闭合。
- 验收：无图像会话在 HSTU 上产出同格式的复核记录，标注与实际做的检查一致；用户抽查结论写入前，交付校验不放行。

### R17 PDF 图片在版心内水平居中（P1）

来源：用户 2026-11-18 查看第 2 批验收的 PDF。

### R18 SVG 插图在 PDF 中清晰（P1）

来源：用户 2026-11-18 指出 HSTU 交付 PDF 第 6 页的图 3 打印或放大时发虚。

- 现状：
  - 绑定了显示宽度的 SVG 由导出器在离线浏览器里渲染成 PNG 再嵌入 PDF，渲染倍率固定为 1：PNG 宽度取显示宽度与 SVG 自身宽度中较大的一个（`export_pdf.py:3784`、`:3805`）。SVG 自身不比显示宽度大时，嵌入位图只有 96 dpi：HSTU 图 3 显示宽 321.7pt，嵌入位图 429×493 px。
  - 工作区现有 21 份导出报告里有 38 张 SVG 派生位图，分布在 HSTU、ULTRA-HSTU、MTGR、STCA、DIN 五篇论文，其中 26 张不到显示宽度的 1.5 倍像素。CUDA PG 13.5、cuBLAS、cuSPARSE 的插图都是 PNG，没有 SVG 派生位图。

  1. SVG 派生位图的像素至少是显示宽度的 2 倍（D5）；PDF 里图片的显示尺寸、位置和分页不变。
  2. 核验仍按导出时的参数独立重建位图并逐像素比对；没有记录倍数的旧导出报告和旧 PDF 重新核验时照常通过。

## 7. 最终验收结论（2026-11-17）

第 1 批（R1、R2、R3、R5、R9、R16）于 2026-11-17 完成真实样本最终验收，已知限制见 [CHANGELOG“未发布”](../CHANGELOG.md)。逐项结论：
