## 1. 目标、边界与本轮工作项

让同类论文沿组件正常入口完成，减少重复适配、整链重跑、手工录入和无进度排障；保留能独立发现错误的核验、真实语义裁决及适用视觉保障。需求的全部 R1–R16 均在范围内，优先级不用于削减或推迟要求。

采用现有来源家族、来源依据、裁决清单、交付记录和核验入口。在相应职责内部补缺口，跨环节只共享当前事实与明确的运行结果。不建立持久缓存、通用 DAG 调度器、第二套状态库或质量规则引擎。

本轮工作项分别为：基线与证据核对；具体设计及兼容差异；**Karpathy 精简与自检**；独立 builder check 与文档验收。这不是实施路线图，不创建 tickets 或改变产品版本。

本文中的接口及方案由 Agent 提出，已于2026-11-08随整份设计获批。后续计划及实施遵守仓库既定流程。

## 3. 交付调用与记录机制重审

### 3.1 根因、正常路径与失败路径

正常职责应是：原生源独立对账 → 译文硬检查与当前语义复核 → 翻译就绪 → 导出 → PDF 独立核验与视觉 / 链接复核 → 当前交付发布。最终交付会重读当前事实，但翻译就绪不依赖尚未生成或正在核验的 PDF。

当前 readiness 接受 `translation+pdf`，把完整 `checks` 交给 `rerun_checks`；后者调用 PDF 核验，PDF 核验又因导出报告中的 `translation_readiness` 回到 readiness。只跳过 `verify_pdf` 仍不够：runner 末尾按原 mode 要求 PDF 覆盖，会把合法就绪报成缺 PDF。目录也同时被源链、检查覆盖和复核类别三处当成正文。

双记录暂时切断循环，却使同一来源、输入和复核事实要重复生成；O.7 再提示不能靠反复重建记录稳定身份。它的历史根因未确定，本设计只修当前已证实的职责耦合，并要求区分无关文件、真实依赖和报告变化，不新增猜测性的“漂移自动修复”。

### 3.2 满足同一目标的方案比较

| 方案 | 能解决什么 | 选择 |
| --- | --- | --- |
| 保留两份记录，由共同模板生成 | 可避免当前循环，旧项目已使用；能减少手抄 | 作为兼容路径保留，不作为新任务必需；两份完整声明仍须同步，且未修复允许输入形成循环的入口 |
| 只在 readiness 跳过 PDF 调用 | 局部消除直接重入 | 不足：PDF覆盖、目录角色、当前数字待处置仍不一致；不是完整方案 |
| 现有 runner 按职责执行，单记录逐步完善 | 同时消除循环、重复声明和迟发现的就绪缺口 | **采用**；复用现有事实 / 绑定，无新持久状态 |
| 通用依赖图、跨调用缓存或版本台账 | 可编排更一般任务 | 当前没有此需求，增加失效与迁移职责，不采用 |

### 3.3 runner 的明确执行范围

`rerun_checks` 增加内部执行目的 `translation` / `full`，默认 `full`，不提供可让用户关闭必需检查的 CLI 开关。

- `translation`：源链预检、原生来源独立对账、全部覆盖正文的家族检查，以及对应 source-reconcile / semantic 复核闭合；含当前 NUM 多重集处置。目录单独按§4验证。不要求 PDF 存在、PDF checks、visual 或 link。
- `full`：按记录现有 mode 执行全部必需职责；`pdf` 保持不强加英文源；`translation+pdf` 必须同时完成翻译、目录和 PDF。只有顶层发布入口能切换证据索引。
- 抽出当前复核检查的“适用目标 / 类别”选择，供 readiness 和 full 共用同一闭合规则；不能继续让 readiness 丢弃 `_pending`，到最后才发现数字差异未处置。
- 原始检查顺序号和实际 CLI 参数解析保留。先完成翻译职责，再进入 PDF；PDF 核验需要就绪时使用本次已验证的同一翻译事实，不能反向启动 full。

同一顶层调用可携带短期运行上下文，键由检查职责、真实工具参数和完整适用依赖身份构成；只有已完成结果可复用，输入身份重读后不相同则拒绝复用。独立源对账与译文硬检查不是同一职责，不能互相替代。该上下文不落盘、不跨调用、不代替发布前身份复查；不新增缓存锁、持久失效协议或后台调度。

### 3.4 单记录生命周期与旧记录

新任务使用同一路径的 version=1 交付记录：先是 `translation`，含正文检查与实际闭合复核；导出通过该路径的 `--translation-record` 取得只含翻译职责的身份投影；随后变为 `translation+pdf`，追加 PDF 输出、检查及复核，不重排既有翻译检查。现有 source / semantic binding 不含 mode 或其他 PDF 输出，因此无须为追加 PDF 重新签同一翻译事实。

导出就绪身份仅包含正文与目录的当前依据，不纳入后续 PDF 输出；记录文件整体摘要继续用于当前调用的防漂移 / 发布保护，不能混作翻译事实身份。若实际翻译、规则、环境或来源变化，正常失效，不因路径相同而复用。

旧双记录和仅翻译 / 仅PDF记录继续可读，不自动合并或迁移。合法混合记录应能成功就绪；真正循环 / 范围冲突给定位失败，不能把所有混合记录拒绝当作递归修复。

### 3.5 进度与候选复核记录

现有入口默认向 stderr 输出并及时 flush：阶段开始、对象 / 检查序号、完成或失败及耗时。源对账、家族检查、PDF机器核验、人工复核缺口和发布各有事件；stdout 的既有结果语义保持。进度不伪装百分比，不加后台心跳服务。执行者连续无推进先结合阶段耗时与已有经验定位，不能只看进程存活或连续 sleep。

`verify_delivery.py` 增加 `--prepare-reviews <候选.json>`，与正式发布互斥；该模式不要求 `--evidence-dir`，不写索引。复用同一 runner / identity，输出原记录结构及各适用目标的 pending reviews、完整当前 binding 和逐项待处置清单。候选必须是显式新路径，不覆盖输入记录、旧证据或产物；硬失败明确报告，不能生成 closed。

主 Agent 实际回源 / 目检后在候选中登记已有 `note/items/status`，正式入口再核对。候选中的完整 items 是待办清单，不是已经处置的声明；status 仍为 pending。旧 closed 条目只有当前完整绑定相同且所需处置仍覆盖时才原样保留，否则生成 pending。无需新增第二套 register 引擎；工作包继续使用专属 `build_review_evidence.py`，不把单篇塞进工作包模型。

## 4. 目录角色与有序输入

保留 `inputs` 为本次导出的完整有序输入，保留 `files[path]="toc"/"chapter"`。增加可选 `toc_manifests`：键为目录相对路径，值为已有 `build_toc` manifest 的路径，仅用于显式目录参与记录驱动导出的场景。

共用 `input_roles` 投影同时用于 `check_source_chains`、`rerun_checks`、`check_reviews` 和 readiness。chapter 仍须翻译源链、家族检查及 source-reconcile / semantic；toc 走下述独立验证。PDF 输入范围仍包含全部目录与正文并保持有序，不能从翻译输入过滤的结果反推导出范围。

目录验证复用 `build_toc.build` 的官方依据、scope、entries、真实标题出现和阅读核对，提取只读消费部分，不写文件也不重新生成目录冒充实际内容。逐项验证“官方条目 → 真实标题出现 → 实际目录标签与 href”的有序一一对应，不能只独立比较标签序列和合法目标集合；交换两个合法 href 也须失败。manifest、官方依据、目录正文和引用章节身份进入现有依赖构造及写保护。

生成区间外仅接受已识别的目录管理文字，以及经现有投影规则 / `view_declaration` 明确确认的非原文说明；未解释文字定位拒绝目录豁免，不能仅凭 `toc` 标签接受夹带正文。旧手写目录可在不改内容的前提下补已有格式的官方 manifest 与范围对应：有 START/END 时按原区间读取，无标记时检查整个文件中的目录条目，并对剩余内容沿用同一管理字段 / 明确排除规则。无法唯一对应则定位报告，不要求重写目录、覆盖用户说明或增加另一份 manifest。没有目录的旧导出保持原行为。

本变化只取消目录的虚假翻译覆盖要求，不取消官方范围、目录内容与实际导航；术语表、用户交付说明和任意附加文件不获得同样豁免。

## 5. 来源准备与机械装配

### 5.1 LaTeXML 在现有适配器内处理

在原节点身份冻结后扩展分类 / 写出与独立 DOM 阅读：object 的 `data` 按真实图片资源解析，保留 width / height / id；enumerate 按原有序条目和嵌套输出；出版注从题名内容中分出一个有对应关系的正文块，保留完整注文本和原顺序。相应独立源流按原 DOM 结构解释转换，不能调用适配器生成文本构造预期。

普通段落现有软换行处理继续使用，只补版权块、混合行内节点等真实触发的回归；不新建 `normalize_latexml_snapshot.py` 通用前置层。原快照不改，来源依据继续声明原节点到实际输出的具体转换。

修正 `_source_reconcile._latexml_md_stream` 的 cross 路径：对完整语义段落中的全部已扫描数学 / 图片跨度先保护，再读取剩余 Markdown 叶子，最后按原偏移合成有序流。跨行式前后的单行式不能直接送给 Markdown 解释。复用 `SourceMathContext`，不修改 alttext、不新增宽松公式比较，不放开未确认的普通跨行数学。

### 5.2 一份非权威准备清单

`parse_reference_html.py` 增加只读 `--inspect-output <候选.json>` 模式，与正文 / adaptation 输出模式互斥。候选包含当前快照摘要、选区、未支持结构、图片准备问题、被内部链接引用的原 ID 清单，以及复杂表转换草稿；它是一次任务的派生工作材料，放库外，不进入第二状态体系。

锚点项包含原节点、对象角色、来源片段和可粘贴的空锚点。译文段落锚点行内附着，表格单元格锚点放格内，图表及文献锚点放相应对象。不会按译文首个相同文字自动插入；不直接把全部锚点塞进解析源并改动精确范围。机器从原DOM独立核对目标集合、重复次数、宿主角色及顺序，实际语义归属与导航继续由源 / 译复核及PDF检查证明。

表格草稿复用已有网格的跨度 / 占位算法，序号按本次选区实际输出含简单表的全局表序分配；多快照仍按各自依据范围计数，合并时沿用已有范围平移，不改成全书共享编号。全部源格、空位、多层表头与原 node 引用保留。主 Agent 确认后写入已有 `table_conversions`，无新映射 schema 或自动裁决。跨度矛盾定位源表 / 格，不擅自补列；分组行表达按原分组含义裁决，不固定全部“跨列占首格”的版式。

引用清单保留 Cited-by 各次回链及年份字母后缀。reference 家族按当前来源依据消费，不为通过不适用的通用锚点检查删除目标。候选清单无论多完整都不能代替独立原生对账。

### 5.3 PDF 裁决与表示

修正 `_pdf_math.render_content` 的普通文本序列化：字面方括号采用不会成为 `\[…\]` 的可逆阅读表示，例如 `&#91;` / `&#93;`；实际阅读仍是原字，角色为 text。代码、真实数学、链接标签等各走已有保护路径，不全局替换扫描器规则。

run-in 标题由现有原页区域 / fragments 分开登记标题与同行正文，不增加版式分类器。标题中的物理行分属独立 text 片段，标题输出按阅读关系连接，不能让裸换行形成第二个 Markdown 块；数学和代码内换行不折叠。materialize 前复用 rawdict / fragments 做每个应覆盖字形恰好归属一次的检查，分别报告遗漏、重复及明确排除；归属和语义仍须回页确认。

注入 / 物化继续用当前数学 ID、origin 的字形片段、owner / slot 和转换说明，不用 `(块,出现序)` 或同文字首项替代身份。结构变换后重建受影响对应并验证字面与原页出现，重复文本要消歧；任何脚本级注入模板只准备候选，不修改已确认清单后伪签原复核。

字形坐标、区域高清图及可取得的同版本 LaTeX 可作为裁决辅证，PDF 原页继续是权威；不新增必须下载源包的步骤。

### 5.4 同源复用与数学装配

PDF 同源复用采用明确的文档流程：核对 PDF sha256、范围、提取环境与未解决项，复制已有源层及依赖到新位置，记录供体和必要路径字段变更，随后调用现有 `verify_pdf_source` 独立核验。供体只读；清单中 PDF 路径、相对资源基点和 source / blocks 引用逐一核对，不能批量替换任意字符串。源变化时走已有再裁决 / 局部资格规则，不新建迁移工具。

增加单职责 `splice_math.py`，与代码围栏装配工具并列：输入来源、已确认上下文、含 `⟦mN⟧` 的草稿及显式候选输出；用 `scan_math` 的完整原始序列逐字回填，拒绝缺失、重复、乱序、未知占位与未解决定界，回填后再核完整序列和类型。输出不能覆盖输入，最终源家族硬检查和语义复核仍执行；不负责翻译、工作包分派或源裁决。

这比每项目重写装配脚本可复用，也比把数学确认强塞进仅处理代码围栏的工具少职责耦合。无占位需求时不强制使用。译写模板提前说明图表 / 题注 / 段落 / 列表相对位置和源数学顺序；题注回显不增加来源外公式，strong token 增加仍只告警。

## 6. 数字复核与默认工作指导

保留 `_numeric_review` 的完整 tokens / diffs / 当前ID及既有多重集闭合。增加派生展示分组：明确管理字段、标题 / 交叉引用、同一原值 / 单位候选及其他项；每组展开到原位置和全部ID。分组不合并语义、不删除差异，也不自动执行单位换算。

§3.5 的候选生成自动写出待办 items，主 Agent 可以对有同一真实依据的一组逐项确认并批量登记，但新项、未处理项和口径变化仍为 pending。最终记录继续是现有逐项 items，不增加组级免检字段或数字裁决数据库。包级处置沿用已有接口，不把包 done 自动升为最终 closed。

SKILL 和对应 references 只维护适用步骤与合同，各类示例就近放入现有 LaTeXML、PDF源、导出、数字和清理说明，不复制到多份“优化手册”。新任务完整扫描当前及同目录姊妹项目的交付说明和过程经验；持续失败超过十分钟先回看既有教训，再诊断；源码与运行矛盾先核对补丁落点和真实入口。

默认阶段进度、可定位错误和合法结构处理不要求开关。工具回传当前判断所需片段及定位，保留必要全量来源阅读与全页覆盖；小论文按现有单篇路径，实际需要才拆包。无 root 采样、错峰和模型档位仅按需资料，不变为新任务必跑步骤或自动改变用户执行时机。

## 7. PDF 导出与独立核验

### 7.1 打印几何与数学

将当前 CHECK_SCRIPT 的数学渲染与几何量测分开：完成实际 DOM、字体、图片、KaTeX 渲染后，使用 print media 和实际版心重新量测；目录两遍打印及任何内容布局更新后，最终打印前均以当前DOM重测。屏幕1280px下的结果不能复用为打印结论。

超宽项报告所属输入、块 / 公式 / 表格及实际宽度；不允许 Chromium 通过整篇缩印容纳。核验检测到全篇比例异常时先报共同缩放原因，同时保留逐图尺寸事实，不要求用户逐图修八个假象。

不引入 `render_tex` 第二公式源。PDF确认TeX若未表达原页多行 / 对齐，按既有裁决修订确认内容，使用明确的 KaTeX 支持结构，再物化并重核受影响译文；LaTeXML 原TeX精确保留。裸换行不自动变成 `\\`，`data-tex`、确认序列和独立核验保持同一权威事实。

公式及式号依照来源依据 / 裁决中已确认的关系组成同一展示单元，包含原来作为独立段输出的式号；不按任意“(数字)”启发式吸附。留出实际编号空间并约束分页，先保证语义与可读性，不以缩小整篇或叠字换取同页。遇到单个单元大于可用页面时明确定位无法满足，不删除命令或更改数学类型。

### 7.2 表格、锚点与图块

使用现有真实表格网格和 DOM 单元格角色，在打印负载中识别完整数字 / 正负号 / 百分比 / 单位组合，数值单元不任意逐字符折行；文本 / 引文列可自然换行。检测分组长文本撑首列时先核对转换映射，不压缩引文或删除单位试凑宽度。表头采用词 / 语义组合的可读折行，输出仍须在版心内；无法同时满足则定位表格并进入已有显式排版裁决，不悄悄整页横转或缩印。

段落行内锚点不制造空段；图题、表题和相应对象保持现有分页依赖。图块整体移页的必要留白可接受；只清理空锚点等造成的无意义布局障碍，不为填空裁图、改来源尺寸或任意拆分图题。

### 7.3 管理字段与译注

PDF源译文的 leaf host 读取复用 `project_management_fields` 的合法位置和字段范围，在读取正文结构前生成等长掩码，保留行号 / 字符坐标；原源内容、任意首块和正文同名词不排除。纯文本和带链接 / 代码的合规管理块得到同一正文结构。

译注连带删除检查以已确认投影位置和对应文本对象为边界，定位源Markdown位置及实际PDF页 / 对象；保留当前可解释的提取空白处理，不再加全局归一或任意子序列回退。先用正常折行、真实删除 / 改字 / 串段对照确认缺口，已有行为正确则只补定位和针对性回归，不因历史报告声称必需更宽容差。

### 7.4 图片资源与必要派生位图

来源和交付原图仍使用现有资源注册与递归身份；不改快照引用、不为核验在两个目录重复复制相同资源。源图片由原始来源 / 显式映射定位，译文图片按其实际目录定位，以身份关系对应；基点不一致报实际解析路径，禁止同名猜测回退。

对确需可量测位图才能满足尺寸合同的 SVG，允许在**导出内联负载**中转换，保留来源 / 交付SVG原字节。复用现有离线浏览器、资源注册和图片预算，转换记录包含该次出现、原递归资源摘要、派生位图摘要 / 像素、渲染条件与原CSS显示尺寸。其他可正确消费的资源保持原路径，不对所有图一律转位图。

像素准备按显示尺寸与既有嵌入预算决定，不能把像素数当物理宽度；清晰度不足、子依赖不可还原或呈现不可靠时定位失败，不改原图求通过。独立核验重读源依赖和转换事实，在临时目录按相同渲染条件重建参考像素，与对应成品图片解码像素及显示宽度核对；不拿导出器自己的派生摘要自证正确。仅有 `converted` 标志或相同basename不够。原图 / 成品视觉核对继续保留。本条扩展现行仅PNG/JPEG内联重采样的转换范围，已随设计获批，尚未实施。

### 7.5 复杂中文题名与来源依据继承

保留 version=1 的 `document_title.chinese` 纯文本含义。复杂题名使用 `view_declaration` version=2，在同一 `document_title` 中增加可选 `chinese_markdown`，与 `chinese` 互斥；只允许文本、强调、代码、公式及链接的行内结构，不允许图片、任意HTML或新块。新工具继续接受 version=1 旧声明；不将新字段写入 version=1，因为旧工具会静默忽略它并回退到 H1。旧工具现有版本检查能明确拒绝 version=2。此处为声明格式版本设计，不是产品发版。

新题名保留原题公式的内容 / 类型 / 顺序，以及链接目标和所在题名对象；出版注已由来源层分离，不与真正题名数学混用。导出和独立投影共同核对允许变化的文本与保留节点，元数据 Title 取同一题名的可见纯文本。无法可靠对应时拒绝，不把所有旧纯文本突然当Markdown解析。

`verify_pdf` 默认从指定 `work-dir` 的实际导出报告读取有序 source-adaptation 依据集合，再重读当前依据与源；显式参数必须与其一致，冲突、缺失和漂移拒绝。旧报告无声明时仍可显式提供，来源约束已声明而依据不足不能回退普通数学。单 / 多来源共用同一提取逻辑，同时供 `normalized_check_facts` 构造实际路径、摘要与参数身份，不能只有执行端继承而绑定漏掉依据。该集合还须与翻译就绪声明一致，不新增邻文件搜索。

## 8. 持久证据、清理与视觉复用

### 8.1 只持久保留实际核验输入

当前 `verify_pdf.run_verification` 使用 work-dir 的唯一输入是 `export_report.json`，不读取 `combined.html` 或临时渲染图。新流程在生成 PDF 复核绑定**之前**把最终报告原字节固定到获准的持久证据子目录，并将现有 `verify_pdf --work-dir` 指向该目录；导出临时工作目录仍在库外，可按清理合同删除。

不新增 `--export-report`、报告恢复状态机或全工作目录归档。当前记录的消费者始终指向同一持久报告位置，`publish_evidence` 继续复制该报告到不可变批次供历史回查。原始临时目录与核验报告输入目录在文档中明确区分。

存量记录迁移时按旧依赖的实际变化重核，不重算 binding 追认；目录重命名和新报告字节变化均显式定位。旧批次只在确认无当前、历史及恢复用途后清理，不能只按“未被当前索引引用”删除。

O.7 后续验证分别固定“纯核验”“仅删除无关渲染图”“报告或其他依赖真的变化”；设计不增加自动重绑、重复尝试到成功或每次连跑两次的规则。真实缺陷若无法由本方案解释，先重审证据再修改，不累积补丁。

### 8.2 显式视觉复用状态

保留 version=1 和 `kind=visual`，新增 `status=reused` 与 `reuse` 证据；不把未再次目检的结果伪写成 `closed`。source-reconcile、semantic、link 仍仅接受实际 closed。旧校验器遇到 reused 会因非closed拒绝，避免忽略附加证据后静默放行。

`reuse` 引用最初实际 closed 的视觉记录、旧PDF、旧导出报告及其摘要，不允许复用链递归。当前记录仍有正常完整 binding 和当前 PDF 摘要，旧记录原样保留；新机器核验必须实际通过。同路径重导出时，旧PDF可从预先保留的副本读取，以旧摘要证明其身份；旧 binding 和报告仍记录历史导出路径，不为副本位置改写历史事实。

仅在以下条件全部成立时接纳：

1. 旧真实视觉复核可回查且完整覆盖相同页面范围；原 / 当前文件可读取，页面数、尺寸、旋转相同。
2. 使用同一渲染器、版本、参数和足以覆盖原实际目检细节的分辨率，对两版全部页面渲染；逐页像素及尺寸完全相同。原复核渲染条件不可确认、依赖不可用或差异页非空，均回到实际目检。不固定72dpi为通用标准，不用文本 / 页数 / 书签计数相等代替。
3. 原 / 当前完整 binding 逐字段比较，仅允许各自PDF路径 / 摘要和导出报告路径 / 摘要不同；两份报告必须校验自身摘要，并逐字段比较，仅允许 `pdf_sha256`、`candidate`、`output_target` 三个产物定位字段变化。output_target按各自历史 / 当前导出身份核对，不要求旧字段等于保存副本路径；副本须匹配相应摘要。其余已知及未知字段一律相同，不笼统忽略“时间戳”或整份报告。
4. 来源、输入、映射、样式、检查器和环境等其余事实不变；旧视觉处置 items 仍按当前待处置项多重集完整覆盖。新待处置项或无法对应的项目须实际复核。
5. 链接注解与目标仍独立核验并完成适用实际导航；像素等价不能取得 link 复核资格。

使用现有视觉辅助的渲染器加载能力，可选依赖不升级为普通翻译必装。没有复用资格时正常人工目检仍可完成，不新增全局失败。初次真实视觉复核宜记录所用渲染条件，便于未来复用；没有该记录的旧项目不因此失去原已完成身份，只是不自动取得新复用资格。
