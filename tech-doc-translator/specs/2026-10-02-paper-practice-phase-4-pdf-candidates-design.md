## 1. 问题陈述

现有 PDF 勘察已提供原始页面事实、双文本快照及结构线索，也已具备裁图、物化和独立对账。主 Agent 仍需逐项目整理图区边界、表格空位与列归属、双栏顺序和异常字形位置。只看到一条图题、一串表格文本或通读顺序，无法快速判断标签是否漏裁、空格是否代表空单元格、跨栏图是否被切开。

用户需要可复用的定位辅助，并保留原页裁决和现有来源资格。候选找得多、展平文本一致或机器通过，都不能证明内容、结构和归属正确。

### 1.1 影响方案的基线

| 已有接口、行为与限制 | 本期约束 |
| --- | --- |
| `inspect` 记录 PDF 摘要、范围、环境、页尺寸及旋转，生成保版面与通读快照、候选和一份 version=1 清单 | 扩展该入口的候选，不另建 PDF 驱动；文本层不可用继续按原分类与授权处理 |
| 结构候选已有标题、图题、表题、脚注、位图及公式文本 / 页 / 区域；通读排序已有栏感知辅助 | 只补本期四类信息；不声称当前公式检测或阅读顺序不存在 |
| `extract-figures` 消费已裁决 `figure_region`，固化资源摘要、区域对象普查及物理显示宽度 | 新图区仍须逐图裁决和目检，dpi 不充当显示宽度，不改普查与资源核验规则 |
| `materialize` 消费清单 blocks 与人工顺序，输出源 Markdown 和块区间；`verify_pdf_source` 独立重读 PDF | 新候选不自动写入 blocks、替换原提取值或排序；候选生成与独立核验继续分开 |
| 表格区域目前按逐词相等对账；缺陷译文硬检查当前专门覆盖 URL 裁决值 | 不宣称机器已能逐格证明表格、自动检查全部字符裁决；本期结构与字符落实仍有明确的原页复核 |
| 再勘察按稳定区域对应保留 pending，继承已裁决 classification、`adjudicated_against`、stale 与 revalidate | 新候选更新不得覆盖裁决或吞掉新增 / 消失区域；删除 stale 不能消除绑定冲突 |
| 交付身份已包含 PDF、整份清单、双快照、源 Markdown、块映射、golden 与图片；完成门禁只认素材 `resolved: true` 和人工 `resolution_basis` | 新字段进入原清单即受现有身份保护；机器 `basis` 永不授予解决或完成资格 |

本区域未发现另设领域词汇表或 ADR；沿用“候选、裁决、源对账、硬检查、语义 / 视觉复核、统一身份”的现行含义。

## 2. 方案

用户沿用“勘察 → 主 Agent 原页裁决 → 素材及源物化 → 独立对账 → 翻译 / 复核 → 当前交付”。一次勘察补出四类定位信息，主 Agent 可直接回到对应页面，确认、改框、改归属或排除，并把实际裁决登记在已有清单。

候选为主 Agent 减少定位工作。最终图区、表格、顺序及字符处理仍由当前原页证据决定：歧义不清就留下明确缺口；机器候选不自动改源、不生成已闭合复核、不签发分派资格。基础候选的验收可用现有人工证据链独立完成，无需等待二期 HTML 适配或三期助手；涉及一期已确认公式 / token 缺陷的输入仍使用其可靠共享核验。

## 3. 用户故事

1. 作为主 Agent，我希望每项候选指向当前 PDF、范围、页和区域，以便直接核对原页。
2. 作为复核者，我希望看见原提取值、机器依据和实际参数，以便判断线索是否适用。
3. 作为复核者，我希望旋转页面的坐标空间明确，以便框选和裁图对应同一物理区域。
4. 作为主 Agent，我希望单图有图区与图题对应候选，以便不从图题文字重新猜框。
5. 作为主 Agent，我希望上下相邻、并排及同号图保留独立位置，以便不合并不同出现。
6. 作为读者，我希望图中文字标签和图例包含在完整区域内，以便裁图保留含义。
7. 作为复核者，我希望紧邻正文、表格和装饰有独立归属，以便避免扩大裁框吸收无关内容。
8. 作为主 Agent，我希望无大外框或图内文字被识为伪表格时仍有具体线索，以便回页裁决。
9. 作为主 Agent，我希望表格候选保留行列、位置和空单元格，以便按格转录。
10. 作为复核者，我希望多行表头和疑似合并格保留所属歧义，以便不把一行词序当作表格结构。
11. 作为读者，我希望同词数移列、漏空位或错表头归属仍被发现，以便数据关系不改变。
12. 作为主 Agent，我希望单栏和双栏候选展示实际块顺序及双快照差异，以便核对通读结果。
13. 作为读者，我希望跨栏标题、图形和图题保持整体及所属顺序，以便不被分成两栏内容。
14. 作为复核者，我希望顺序无法确认时保留原值和冲突位置，以便不采用机器默认裁决。
15. 作为主 Agent，我希望异常字符带原码位、区域及建议依据，以便区分提取缺陷和原文异常。
16. 作为读者，我希望没有可靠映射时不自动替换字符，以便视觉相似字符不被改错。
17. 作为复核者，我希望确认后的裁决值和必要译注在当前译文落实，以便处理结论可查。
18. 作为维护者，我希望代码 golden 固化后仍逐字节比较，以便字符辅助不放宽代码合同。
19. 作为主 Agent，我希望未找到候选显式显示为空，以便不误认为页面不存在该内容。
20. 作为主 Agent，我希望再勘察保留已裁决类型、块、排除项和顺序，以便机器刷新不推翻人工判断。
21. 作为复核者，我希望源或范围变化保留旧依据与新发现区域，以便重核不丢项。
22. 作为用户，我希望没有有效重核时旧证据继续失效，以便删除 stale 或重算摘要不能追认完成。
23. 作为用户，我希望真实 PDF 当前链路通过且原 PDF 不变，以便辅助能力交付保真结果。
24. 作为用户，我希望清理后仍能回源、复验和恢复，以便定位依据不随临时报告删除。
25. 作为用户，我希望未批准的公式扩展维持现状，以便基础候选设计不越过 D4 审批边界。

## 4. 实现决策

### 4.1 职责与入口

| Module | 决策及复用关系 |
| --- | --- |
| PDF 勘察与候选 | 复用 `inspect` 的 PDF / 范围 / 输出参数和 PyMuPDF 页面对象；新增四类候选列表及其证据，保留既有类别、双快照和显式空标记 |
| 单一裁决清单 | 复用 blocks、rejected、pending、reading_order、conventions；新候选仍在 candidates 内，人工裁决采用既有字段，不增加状态库或资格文件 |
| 素材与源准备 | 复用 `extract-figures`、代码 golden、`materialize`；输入是当前已裁决清单，不接受候选作为替代 |
| 独立源核验与当前交付 | 复用 PDF 原页重读、共享硬检查、统一身份和当前复核 / 发布；新信息帮助页面复核，不改比较器为弱比较 |

不新增公共 CLI、后端注册层或 `pymupdf4llm` 依赖。图 / 表 / 顺序共享同一份页面对象，提取一次供候选使用；独立对账仍重新打开 PDF，不复用生成器缓存证明正确。

### 4.2 候选数据与裁决映射

拟增加 `figure_regions`、`table_cells`、`reading_orders`、`character_defects` 四类列表。每个列表继续有显式 empty 标记，表示该次勘察未发现候选，不能解释为源中无相应内容。四类列表及 parameters / applicability / ambiguities 为新增诊断字段；page / rect / 原文本 / basis 的含义复用既有候选口径，source_sha256 与 scope 引用已算出的来源事实，旋转与空间声明复用 source 的坐标口径。共同证据如下。

| 字段 / 内容 | 合同 |
| --- | --- |
| `source_sha256`、`scope` | 对应本次清单 source 与实际范围；独立候选副本仍可确认来源，不产生第二套身份计算 |
| `page`、`rect` | 1 起页号与 pt 区域；沿现有口径区分未旋转文本提取空间与旋转后显示 / 裁剪空间，记录实际页旋转及转换依据，不把旋转后 page.rect 尺寸当成未旋转文本边界；不能可靠定位时保留页及定位缺口，不伪造矩形 |
| 原提取内容 / 对象定位 | 文本保留原值；绘图、文字块、位图的对象序只在当前 PDF 身份下有效；同号、同字不替代位置 |
| `basis`、`parameters`、`applicability`、`ambiguities` | 机器为何提出候选、实际工具 / 策略 / 数值、适用页面条件及未解决冲突；没有建议值时明确缺失 |
| 各类结构信息 | 图区与题注关系；表格行列和格位；栏区、块序及快照差异；异常原码位与有依据的建议值 |

各类条目只补所需定位：图区含对象定位清单、题注矩形及备选关联；表格含表区域、1 起行列、格矩形、原文本与表头归属备选，空文本格与无可靠边界格分别表示，不能用缺项表示空格；顺序含栏区、完整块定位及提取 / 建议序列、跨栏锚点与双快照对应；字符含原文本、码位、字形矩形、上下文、可缺省建议值及其证据。人工修正不覆盖这些原值。

候选字段全部为诊断输入，不写 `resolved`、`resolution_basis` 或人工 accepted 状态。接受或改正后的图映射为现有 `figure_region`；表格映射为 `table_region` 与逐格回源裁决；顺序写入现有 reading_order 及 blocks 顺序；字符处理写入 conventions.defects，并在实际复核中登记落实。

排除项在 rejected 中说明页面和理由。无法解决的结构 / 字符问题留在现有源对账或语义复核的未闭合记录，不新造当前消费者不识别的 pending kind，也不把全部启发式建议自动变成阻断项。已有素材 pending 保持其原门禁。实际裁决证明某区域有内容但尚未处理时，不得删除该区域或闭合复核。

### 4.3 图区与表格候选

图区先以现有图题、绘图及位图位置形成对象组：相交 / 连续绘图、邻近文字行与图题关系提供区域建议；空间关系以当前页对象、字号 / 行距和栏区为依据，实际取值入 parameters。保留组内绘图、文字及备选题注，支持无大外框图。组之间或与正文 / 表格冲突时输出重叠对象和备选边界，不用扩框自动闭合。

每次出现独立按页 / 区域记录。图号仅是关联线索，不能合并同号图；并排或上下图要分别说明所属。文字标签、图例未能确定归属时明确列出缺口。即使表格工具把图内标签识为格，也同时保留图形归属歧义，不消失性过滤任何页面对象。裁决后沿现有裁图、对象普查、资源摘要、尺寸映射及原页 / PNG 目检执行。

表格复用现有 PyMuPDF 的 `find_tables`，实际探测并留存策略及调用参数：存在规则边框时用线段策略，缺边框但存在重复文字列对齐时用文本策略，表题和局部区域限定提供关联线索；两种结果有冲突就保留备选，不自动挑选正确表。保留二维格位、每格位置与原文本，区分空字符串格、无可靠边界格及疑似合并格；多行表头保留原行和所属备选，不自动扁平化。API 缺失或识别不可靠时明确记录检查缺口，主 Agent 仍可按当前页面区域人工重建，不升级成全局不可用或自动安装依赖。

不自动生成 Markdown 表格。主 Agent 对原页逐格确认行列、空位、表头与单元格归属，将结论记入该块裁决和当前源 / 语义复核。现有逐词对账继续证明区域文本覆盖；同词数移列与空位损伤必须由独立原页逐格复核发现并拒绝闭合，不声称展平比较能够承担该证明。

### 4.4 阅读顺序与字符缺陷候选

顺序候选复用栏感知排序，把此前隐含的块矩形、栏区、跨栏锚点、提取顺序与建议顺序显式列出，并标明双快照中的对应及差异。已有启发式的实际参数照实报告，不升级为所有论文的可靠阈值。跨栏标题、图形和图题作为整块供裁决，遇到与两栏正文交织、区域重叠或不支持的版式就明确歧义。候选不更新清单人工顺序；最终 blocks 与 reading_order 由原页裁决确定。

字符候选读取原文字和字形位置，定位替代字符、异常控制字符、数学字母数字区字符、图内文字及代码 / 伪代码中的疑点。记录原码位和上下文，异常命中只是线索；数学 Unicode 字符也可能是正确原文。建议值仅在当前 PDF 的映射、内嵌信息或较高保真证据足以解释时给出，并注明证据限制。禁止固定偏移、无依据 ASCII 规范化及通用 glyph 修复。

未裁决时源、译文、golden 和核验结论均不变。确认后的缺陷按现有 conventions.defects 留原值、页 / 区域、较高保真证据、裁决值与译注要求：正文源区域仍接受当前独立原文重读，不用修正值绕过源对账；译文采用已确认值并由回源语义复核核对落实。代码字符须在 golden 固化前完成原页及较高保真证据确认，记录一致的裁决值、提取取舍与最终基准，候选不能直接改 golden；固化后源 / 译文与 golden 保持逐字节一致。后改基准须重新回源确认及复核，不能只更新摘要保留旧 review，也不能以候选归一化放行。既有 URL 硬检查保留，其他字符不冒称已受该机器规则完整覆盖。

### 4.5 再勘察与当前证据

同源同范围再勘察刷新诊断 candidates，保留 blocks、rejected、conventions、人工 reading_order、已裁决 classification 类型与依据。新候选不写回裁决；稳定 `(page, rect)` pending 对应及无 rect 的既有退回键保持，不把可变 kind 加入身份。真正新区域追加、旧区域未再发现仍保留待回源处理，不能静默删除。

PDF 或范围变化按原机制保存旧裁决和绑定，加入新发现项、定位变化 / 消失区域并冻结待重核；区域或口径改动也须完成受影响回源复核。materialize 与独立校验继续检查 stale 及 `adjudicated_against` / revalidate 覆盖，直接删除 stale、重算摘要或刷新候选不能获得资格。主 Agent 完成实际重核后记录有效迁移依据，才可重新物化和复验。

清单的候选字段、裁决、范围、映射及固化资源继续由原 `compute_delivery_identity` 消费，源对账 / 语义 / 适用视觉复核沿既有投影绑定；清单或检查口径字节变化使受影响旧绑定失效。再勘察保留裁决内容不等于保留旧交付复核资格，不重签旧 PASS。不相关包仍按现有恢复入口重读当前事实判断复用。

### 4.6 持久增量的机制重审与最小方案

正常场景是候选帮助主 Agent 作出一次裁决，后续同源勘察能复查线索且不改变裁决；失败场景是将机器刷新覆盖人工分类、把机器 basis 当作解决依据，或只在外部候选报告存定位而交付身份看不到变化。这些与现行 PDF 设计 §7.3 的根因相同：候选事实、裁决和资格混用，而非缺少另一份状态。

两种可满足同一合同的方案：①另设候选证据文档，给清单、源预检、身份、复核和清理分别接入关联与摘要；②在既有 candidates 中增四类诊断字段，裁决映射到当前清单字段，整清单身份覆盖继续生效。选择②，只有候选生成与展示增量，无第二份关联和状态同步机制。仅给旧报告加注意事项不能输出图区、格位及定位，是不满足新增辅助要求的下界，不充当可行替代。

清单 version 保持 1，四类字段为可选诊断增量；旧清单缺新字段仍按现行来源 / 裁决合同消费，不补造候选或自动追认裁决。候选刷新改变清单摘要的保守失效行为保持，不另造“候选变化免重核”投影。无需新增裁决字段或改变现有信任前提：由主 Agent 维护的实际裁决不能靠机器鉴别其真实性，伪造整套人工记录不以本设计新增历史台账解决。新候选合同及其辅助行为仍随本文待批准，本轮未修改产品行为。

## 5. 测试决策

### 5.1 已确认的主要入口与先例

用户已确认“PDF 勘察 → 人工裁决 → 物化 → 独立对账”的现有 CLI 验证入口，适用交付继续调用当前交付检查。测试观察页面内容、结构、候选定位、物化产物、当前证据资格及拒绝原因；不断言内部聚类函数或字符串措辞。仅为定位必要的确定性问题补现有底层测试，不新增测试平台。

现有勘察测试已有真实 PDF、双栏、位图全量枚举、裁决继承及连续生命周期；图形测试已有无大框图与同页表格、删标签 / 换图 / 换序反例；源对账测试已有区域遗漏、换块与 pending；代码、译文及交付测试已有字节基准、URL 裁决、来源绑定与完成门禁。复用其 fixture 与入口，覆盖本期差异。

### 5.2 直接验收

下表是获准实施后的验收合同，本次文档核验不代表产品通过。最小真实 PDF 页面覆盖各形态；至少一份真实论文 PDF 经过当前项目链路，固定源摘要、范围、环境和裁决，正向与损伤副本成对，所有临时产物在工作区外。

| 需求验收 | 直接观察及正反证据 |
| --- | --- |
| A1 / 图区 | 单图、上下 / 并排、同号图、无大框、图内标签 / 图例、邻接正文及同页表格；候选回到原页，裁决与裁剪归属正确。删标签、错配题注、扩大到正文或伪表格自动归类不能闭合复核 |
| A2 / 表格 | 规则表、空格位、多行表头逐格可定位；同词数移列、漏空位、错表头在独立源对账或原页逐格复核定位并阻断。记录由哪一层发现，不能以展平相等签正例 |
| A3 / 顺序 | 单栏、双栏、跨栏图的双快照和候选定位可查，人工裁决后源顺序符合页面；互换两栏块、误切跨栏图不能以字数一致完成 |
| A4 / 字符 | 原码位及证据定位可查；同类字形不同映射、有建议及无足够证据成对验证。未裁决时输入和结论不变，确认后裁决值 / 必要译注落实，代码仍按固化 golden 比较；固定偏移或 ASCII 替换不能自动采纳 |
| A5 / 资格 | 只生成候选不能直接进入 blocks 或产生闭合复核；机器 basis 加 resolved、未解决素材、遗留 pending 不能完整交付。有效回源裁决、独立对账和必要复核闭合后接受 |
| A6 / 生命周期 | 同源再勘察保留类型和裁决、不制造同区域重复 pending；改变 PDF / 范围 / 区域 / 口径后旧依据、新旧区域均可查，删 stale 无有效重核仍拒绝。真实重核后重新物化、复验可接受 |
| A7 / 实际链路 | 至少一份真实 PDF：勘察、原页逐项裁决、素材及源物化、独立对账、翻译 / 复核、当前交付与收尾。原 PDF 摘要不变，实际译文与资源可读；加入未裁决或损伤项不能成品。清理后源、清单、快照、golden、映射及恢复依据由真实消费者读取 |
| A9 / 现状边界 | 未批准的 D4 扩展不生效，现行未知公式继续 pending，脚本退出成功或改标记不能闭合交付；现行回源人工闭合路径保持可用，不强制全部项目等待扩展批准 |

候选为空、定位失败及旋转页必须有针对性检查：旋转页正例从文本 pt 区域经当前转换能在显示页 / 裁图中定位同一内容；漏转或混用旋转后尺寸的反例须在原页 / 裁图复核中定位并拒绝闭合。不以某个无关报错代替相应损伤的拒绝证据。仅翻译项目不强制新增 PDF 成品；明确请求导出时沿既有翻译就绪、独立 PDF 核验及真实视觉复核。纯身份与记录规则使用最低成本检查，页面布局与提取使用真实 PDF；旧项目 PASS、候选数和测试数量均不替代此表。

## 7. 进一步说明

### 7.1 假设、兼容与批准边界

适用场景为有可靠文字层的常见单栏 / 双栏论文；候选不保证发现任意 PDF 的全部缺陷。本轮本地 PyMuPDF 1.28.2 环境确认表格发现 API 存在，运行仍须记录实际兼容性和缺口；未发现内容由全范围回源复核补充，不能记为零。

本设计提出新增候选字段与辅助流程，尚未批准；没有已实施的未经批准行为变化。用户确认的是验证入口，未批准新合同、D4 扩展或实施。全文不设计该公式扩展，不把它作为现行人工 PDF 交付前提。旧清单及旧调用按 §4.6 兼容；候选、裁决或口径变化后的复核失效不能自动迁移为通过。

### 7.2 可核查基线

本轮已读取并核对：

### 7.3 Karpathy 精简与自检

1. **基线：** §1.1 与 §7.2 列出真实接口和限制，特别是表格逐词比较、字符硬检查仅 URL、完整清单摘要及素材解决依据。没有把已有公式候选、栏感知排序和裁决机制重新立为新模块。
2. **假设与差异：** §7.1 明确版式、API 与授权假设；§4.6 明确持久诊断增量及兼容，保留主 Agent 实际裁决的信任前提。D4 仅为范围边界，未进入设计；本轮只写文档，无未经批准产品行为变化。
3. **最小方案：** §4.6 比较独立候选文档接入与原清单增量，两者能满足同一合同，选择后者以复用身份和裁决。删除新增 CLI、候选资格文件与第二提取后端的需要；没有更简单且仍输出四类可定位结构证据的已知可行替代。
4. **删除审计：** §1 只保留用户缺口和影响决策的基线；§2–§3 对应 R8 四类结果及生命周期；§4 将四类公共证据合并到一张表、漂移统一到一个消费章节，§4.6 集中持久增量的重审及取舍，避免逐类复制身份 / 完成规则；§5 对应 A1–A7 / A9；§6–§7 保存范围和五项门禁。终审压缩 §7.1 的重复环境说明，并补清新增 / 复用字段及两种表格策略，未新增字符修复策略、自动表格物化、公式扩展算法或第二份状态。逐格原页复核与独立重读证明不同结果，继续分别保留；形态、歧义、漂移、完成门禁和清理恢复要求均未削弱，本轮不删除既有源码。
5. **直接验收：** §5 证明定位有原页、裁决保持内容 / 结构 / 归属、当前证据能交付且原 PDF 不变；损伤与未裁决反例证明拒绝，清理后真实读取证明来源和恢复能力仍在。本轮完成条件是设计具有这些可实施、可审阅的决策与证据，不能用文档检查宣称产品能力已验收。
