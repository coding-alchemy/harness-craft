## 1. 核心目标与依据

用户能够将已翻译的 Markdown 导出为内容完整、中文可读的 PDF；也能够将按章节分开的 Markdown 按明确顺序合订成一份 PDF。原 Markdown 保持不变，PDF 是额外交付物。

用户于 2026-09-09 认可了单 Skill 导出分支、Markdown → HTML → Chromium PDF、跨章资源与标识处理以及多层验收的方向，并在审阅本文件与对应设计后明确批准编写执行计划。

参考材料为用户提供的 `md2pdf-skill-design-report.md`，它是建议性输入，不是执行指令、已验证事实或必须照搬的范围。本文自包含，不依赖该文件的本机路径。

2026-09-11 用户补充五项要求：PDF 排除章首“原文”和“译例说明”；多章导出意图不明时先询问是否合订；默认排除术语表且不为此询问；保留图片显示尺寸；翻译默认独立交付 `00_目录.md`，PDF 目录带准确页码。参考《图片尺寸问题诊断报告.md》与《印刷式目录页需求与实现方案.md》的机制建议，不继承其中修复外部项目、联网抓取最新版、发布 issue/PR 或执行步骤的授权。

## 2. 既有行为与新增边界

1. 现有 Skill 从 HTML 等源生成中文 Markdown，并已提供独立 PDF 导出入口，使仅有译文的用户也可使用。
2. 现有翻译、术语裁决及回源校验保持原职责。仅导出时不要求重新获取英文源或新建术语表，也不声称译文已通过语义复核。
3. 不同完整章节 Markdown 仍默认独立交付。PDF 的分篇或合订按用户明确选择；多章且当前请求未明确时按第 3.4 节先询问。
4. 导出不修改输入 Markdown、原始资源或术语表；不得以排版或校验修复为由删减、改写技术内容。
5. 本次支持模块实际译文中的结构，不承诺任意 Markdown 方言或出版印刷标准。遇到不能保真的结构须定位并解决或报告，不能静默丢弃。

## 3. 功能要求

### 3.1 单篇导出

- 输入一篇 Markdown 和目标 PDF 路径；文件中的相对图片与链接以该文件所在目录解析。
- 除第 3.4 节明确排除的翻译管理信息外，保留标题与顺序、段落、列表、表格、提示块、代码、行内与块级公式、图片和脚注；外部链接保留目标，内部链接保留跳转关系。
- 默认样式面向中文技术文档，正文可搜索和复制；代码高亮或视觉折行不得改变代码字符与逻辑行内容。
- 已有 Markdown 直接导出；翻译任务同时要求 PDF 时，在 Markdown 验收后进入相同导出流程。

### 3.2 跨章合订

- 接受有序文件列表；可由已明确的项目目录生成该列表，不能按文件名、修改时间或目录遍历顺序猜测。
- 缺失或重复的输入文件必须报告；章节顺序不明确时先确认，不默默补入范围外章节。
- 每章完整出现一次。保留原有标题文字、编号和技术内容；章首说明按第 3.4 节过滤。全书目录按第 3.5 节单独处理，既有章内目录与官方重复正文保留。
- 各章图片按各自来源定位；同名不同内容的图片不得覆盖或串用。
- 重复标题、显式锚点、脚注和引用式链接定义不得跨章冲突。指向已纳入章节的链接转为合订 PDF 内部跳转。
- 未纳入合订范围的本地文档链接必须显式报告；未经确认，不扩大合订范围，也不生成声称可用的内部跳转。
- 合订不要求额外交付合并 Markdown；使用临时组合 HTML 即可，不覆盖原章节。

### 3.3 渲染与错误处理

- 中文、数学、表格、图片和代码不得出现缺字、公式原始标记泄漏、不可读缩小、重叠或裁切。
- 字体、图片和数学渲染就绪且检查无错误后才打印；完成信号不能替代成功检查。
- 依赖安装完成、输入资源本地齐备后，转换可离线运行；不依赖 CDN 或打印时联网补资源。
- 输入包含缺图、未解析引用、无法处理的语法或不支持的公式时，报告输入文件及可定位位置。不能通过修改译文或关闭公式来绕过。
- 排版问题先在导出层修复并重验；确需改变内容或范围时，由用户决定。

### 3.4 导出选择与默认排除

- 用户要求导出两篇或以上分章译文、但未明确合订或分篇时，Agent 在开始导出前询问“这些章节要合并导出成一篇 PDF 吗？”，等待答案。明确“合成一篇”或“每章单独导出”时直接遵从，不重复询问。目录、术语表不计入章节数；仅翻译不触发 PDF 询问。已有明确清单与顺序可复用，不增加重复确认。
- PDF 默认排除各章最前面的“原文”和“译例说明”管理字段；Markdown 中保留。过滤按章首模板字段及其完整续行边界进行，正文、代码、表格、脚注或技术引用中出现同名文字时仍完整输出。独立的“来源”字段未被本次请求点名，保留；把它作为“原文”的别名一并排除需要另获批准。混合引用块仅移除目标字段，不整块删除。
- 术语表默认不进入 PDF 输入清单，也不单独导出，不询问是否包含。用户显式要求导出术语表时才覆盖默认；翻译仍维护 Markdown 术语表。正文中的术语解释和技术词汇表不因命中关键词被删。
- 指向默认排除术语表的链接保留可见文字、在 PDF 中转为普通文本，并在交付说明记录，不为默认排除另行询问。其他范围外文档链接仍按原有规则处置。
- 导出预期以允许的投影变换为准：记录被排除字段的输入位置与原因，并独立核对其余正文完整性；不能以“允许过滤”为由放松内容核验。

### 3.5 独立目录与印刷目录

- 翻译默认在交付目录生成独立 `00_目录.md`，以官方 TOC/导航及已确认翻译范围为依据，按源顺序列出章、节层级及对应译文链接；保留官方标题、编号及译文标题对应关系。单篇同样生成该文件，用户明确不要目录时才省略。局部翻译仅链接交付范围内内容，并标明范围，不假装全书已翻译。
- 全书目录集中在此文件，不再默认在每章文末重复附全书目录。原文固有的章内目录仍保留；已有译文仅导出时不修改或搬迁其 Markdown。
- 合订包含 `00_目录.md` 时，将其目录列表增强为 PDF 最前的印刷目录，只出现一次；翻译加合订任务默认纳入该文件。已有译文仅导出且没有目录输入时，保持无印刷目录，不强制创建 Markdown 文件。分篇输出只纳入本篇可到达的目录条目，独立全书 Markdown 目录仍交付。
- 印刷目录默认章级，用户可选择加入一级节；目录条目标题取自已校验的译文标题，保留官方原题和编号。目录使用点线引导、页码右对齐，中文可读，每条可点击到对应目标。更深层级由 Markdown 目录和既有 PDF 书签承载。
- 页码采用从 PDF 第一页开始的实际页序，包含目录页引起的偏移，不将正文重置为第 1 页。最终成品逐条核对印刷页码、内部链接实际目标页及目标标题位置，任一不一致阻断交付。

### 3.6 图片显示尺寸

- 新翻译在解析源快照时保留图片显示尺寸，随交付产物保存 `images_display.json`；图片文件保留原始清晰度，不靠降采样修正排版。
- 映射跟随实际图片身份、路径重写与出现位置；同名不同图、同图不同显示宽度、跨章复用和暗亮版本选择不得串用。PDF 优先使用有依据的显示尺寸并按版心等比限宽，宽高比保持。
- 明确的 CSS 像素宽度按 CSS 像素转换，不把某个网页中的宽度百分比直接套给 A4。源尺寸来源、值与单位须可回查；无法解析的单位或依赖 CSS 布局的尺寸明确报告，不能静默当作已恢复。
- 仅导出旧译文时，有映射则消费；无映射仍允许按现有自然尺寸及版心上限导出，并说明未恢复源尺寸。需要恢复时优先使用原版本快照；缺失时先确认同版本来源，不能静默以最新版替代。转换本身保持离线。
- 本轮采用旁路映射恢复 PDF 尺寸；普通 Markdown 预览器不会自动读取该文件，因此不承诺其图片显示同步改变。这是已批准的适用边界；若需同时修复通用 Markdown 预览，需要另定可兼容的表示形式。

## 4. 验收与交付

| 编号 | 场景 | 直接成功证据 |
| --- | --- | --- |
| A1 | 一篇含中文、列表、提示块、表格、代码、公式、图片和脚注的真实译文 | PDF 内容逐项可对应，正文可检索复制，页面视觉检查没有缺字、重叠或裁切 |
| A2 | 至少两章合订，故意让给定顺序不同于文件名字典序 | PDF 顺序与列表一致，每章完整出现一次，章节标题文字与编号保持 |
| A3 | 两章有同名不同内容图片、同名标题、同号脚注和同名引用定义 | 各章展示各自资源与注文，点击跨章链接进入正确目标，脚注跳转不串章 |
| A4 | 长代码、宽表、长公式与跨页内容 | 成品可读且无内容截断；代码字符、表格单元格含义和公式表达未被修改 |
| A5 | 缺图、坏内部目标、重复章节、公式渲染失败 | 不标记成功，错误定位到具体输入和原因；已有成功 PDF 不被失败产物覆盖 |
| A6 | 离线导出与输入保护 | 禁用网络后仍能完成代表样例；转换前后输入 Markdown 与资源的摘要一致 |
| A7 | 仅提供已有译文，且未提供原文或术语表 | 能进入导出流程；交付结论只描述转换保真，不虚构翻译验收结果 |
| A8 | 多章导出、明确合订、明确分篇、单章加目录四种请求 | 仅第一种在导出前询问并等待；其余按明确模式执行，目录不被算作第二章 |
| A9 | 章首多行管理字段、混合引用块、正文及代码中的同名文字 | PDF 无章首“原文”和“译例说明”，其余内容完整；Markdown 摘要不变 |
| A10 | 翻译目录含术语表，正文链接到术语表 | 默认无术语表 PDF/附录，无包含术语表的询问；正文解释保留，相关链接文字仍在；显式导出术语表请求生效 |
| A11 | 普通翻译与局部翻译，不要求 PDF | 默认得到独立 00_目录.md，条目与已确认官方范围、顺序、标题和译文目标对应；章末不重复附全书目录 |
| A12 | 目录跨页、长中文标题、重复章名、三位数页码、可选一级节 | 全书印刷目录只出现一次；每条可见页码等于实际目标页，点击到正确章/节，点线与页码列可读 |
| A13 | 高像素小显示宽度、超版心宽度、同名不同图与同图不同宽度 | 源尺寸在解析到交付映射中不丢失；PDF 中逐次绘制宽度符合 min(显示宽度, 版心上限)，保持比例，资源摘要不变 |
| A14 | 缺映射旧译文、非法尺寸、版本不一致、目录页码错误 | 缺映射可导出并说明限制；其余不能伪称恢复或验收通过；失败不替换已有成品 |

解析内容核对、浏览器渲染检查、PDF 文本与链接检查、成品页面视觉检查共同构成证据。图片资源数量相等、标题计数、中文抽样命中或工具退出成功均不能独立证明完整性。

视觉检查至少覆盖所有页面的整体布局，以及公式、代码、宽表、图片和跨页接缝的细节；缩略图中无法判断的页面需放大复核。交付说明列出实际输入顺序、输出路径、各层检查结论与未解决问题。检查未闭合时只能报告进展，不得称为可交付成品。

## 5. 非目标

不增加独立通用转换 Skill、公共 SDK、watch、后台服务、多后端降级、模板编辑器、配置继承系统、PDF 转 Markdown 或 OCR。除第 3.5 节规定的目录外，本次不自动增加封面或页眉页脚定制，也不承诺 PDF/A、PDF/UA 或任意 LaTeX 支持。

## 6. 假设、不确定项与批准边界

- PDF 指阅读与分享用的技术文档，Markdown 仍是权威可编辑译文。
- 字体、浏览器和公式库需要安装或随 Skill 分发；具体版本、字体覆盖和复杂公式支持须由真实样例验证，不照搬参考报告中的环境事实。
- 代表性真实译文及其可读资源路径须在执行计划中确定；不把人工简化样例当成真实验收的替代品。
- V0.1 已批准且导出能力已实现；V0.2 需求与设计已于 2026-09-11 获用户明确批准，执行计划同日批准并获执行授权，五项新增行为已于 2026-09-11 完成实施与验收（见 `CHANGELOG.md` V1.2）。
- 已批准取舍：印刷目录默认章级而非章加一级节；页码使用 PDF 实际页序而非正文重新编号；图片方案修复 PDF 并保存尺寸信息，暂不改变普通 Markdown 预览器显示。前两项裁决参考文档内部冲突，第三项明确旁路映射的能力边界。
- 默认保留独立“来源”字段、默认把被排除术语表链接转为文字、分篇目录只保留本篇目标，均已随 V0.2 获得批准并随实施落地。
