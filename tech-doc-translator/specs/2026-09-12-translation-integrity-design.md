## 2. 最小方案与责任

保留现有四个源家族、拆分/恢复/合并入口和主 Agent 编排。扩展共享扫描和硬检查的小函数，源家族适配器负责从原有表示生成比较预期。共享的是代码、公式、标题、脚注和资源事实，不是统一文档 IR 或新工作流引擎。

数据与责任按以下顺序闭合：当前源与已确认范围 → 安全拆包及源位置 → 译文硬检查 → 主 Agent 源全量对账/语义复核 → 恢复可用性判定 → 全量合并候选 → 最终路径复验。脚本从实际输入重新读事实，主 Agent 负责无法机械证明的内容和批准转换。

辅助证据仅在明确的工作区外目录产生；包正文及必要源映射属于任务输入，不作为本模块运行日志写回仓库。`images_display.json` 继续是既有交付资源。无任务队列、中央状态 JSON、数据库或后台进程。

## 3. R1：可还原的结构边界拆分

### 3.1 扫描和切点

为拆包及校验共享可保留原始偏移的 Markdown 扫描函数。扫描器只返回结构类型、源区间、原文及必要关联，不翻译、不重排、不渲染。保留原始换行和字符切片，不能先 `splitlines()` 后重组导致无法证明原文一致。

按实际支持的 Markdown 结构识别三反引号、较长反引号和波浪号围栏；闭合必须匹配字符与长度，代码内的短围栏、标题、公式和图片语法不参与外部统计。代码/行内代码、转义和数学上下文互斥。深层标题按照现有参考手册源家族语义保留，不截到 H6 后丢弃。

候选切点只在顶层真实小节或完整块之间。一个列表连同嵌套子项、引用容器、表格、段落、定义、公式和图题关联区域作为整体；脚注及引用式定义按引用依赖扩大包范围，必要时合并相邻包。不复制正文或定义到多个包。不能识别的依赖维持较大连续范围并报告，不凭空白行猜测其独立性。

`h2` 优先小节边界；`chars:N` 先保完整小节，超限小节才在安全块边界细分。N 是目标值：单个块/依赖闭包超限时整体交付并报告实际长度、范围和原因，不截断也不无限递归。这是已批准 D1。

### 3.2 包映射与计数

保留 `source_file`、`target_file`、`source_order`、`section_id`、`fragment_index`。增加包的源区间与源片段摘要，用位置区分同名小节；记录拆分策略，避免恢复时猜测。标题等任务上下文只放元数据，续片正文保留真实源切片，不注入重复 H2。

摘要针对实际包源内容，整份源摘要仅用于定位基线变化，不能让一处变化迫使全部包重译。重拆后依靠源范围身份与内容验证旧包；无法唯一对应时交主 Agent 明确映射，不按文件名猜测匹配。

基于同一扫描事实生成 headings、paragraphs、list_items、tables、code_fences 等计数。切分结束后独立按源区间验证不重叠、不留洞，并比较正文按序还原结果与输入原文。未完成此检查不分派。源和目标路径相同或互相覆盖时失败。

## 4. R4：统一事实检查，保留源家族口径

### 4.1 范围适配与内容比较

四个 `verify_*_translation.py` 都调用共同硬检查，但各自建立完整文档/页面/片段预期：完整文档执行项目 H1 约束，片段只验证其预期标题；分页合并、模板头部、生成目录和标题降级由具体源到交付位置映射描述。没有映射的变化不能被忽略。

- 标题按有序 `(层级, 官方原题)` 比较，包含无编号和深层标题。中文后缀必须与源原题边界对照后识别，不能无条件截断第一个全角括号，也不能把弯引号等内容性字符归一化后漏报。
- 代码按出现顺序逐块比较开启行、正文、关闭行，保留语言标签、空格、空行和内部换行。换行编码如需标准化，只能在源快照到源 Markdown 的明确边界进行；译文比较不新增隐式归一化。
- 公式扫描排除代码、转义美元和普通货币文本，提取行内/块级原表达式及位置，按类型与顺序比较内容。既有源 Markdown 的 `$…$`、`$$…$$` 和历史包装按源家族已确认表示处理；不为了“修公式”改变源内容。一致历史异常报告告警，新增或变化失败。
- 脚注按源到目标的引用/定义关系检查，包含数字和实际出现的命名标签；完整删除一对也由源预期检出。片段存在跨包引用时按第 3 节依赖范围检查，不把片段内没有定义直接误判为整篇缺失。
- 项目指定强 token 沿用集中设置的列表，向四类入口显式传递，不只硬编码 CUDA 两个 token。无项目指定 token 时明确标记未配置，不声称已检查全部 API。

源范围缺失、文件不存在或模板口径不明时报告输入不足，不把空源当成无需比较。未知残留、源全量对账与语义复核门禁保留。

### 4.2 差异和人工复核

硬损伤返回失败；列表、段落、表格重建差异按章节/源位置报告，不以统一百分比阈值推断语义丢失。共同结果只需区分硬失败、待定差异和机器通过；“机器通过”不是最终交付通过。

合法转换仅描述已批准的具体源位置、目标位置和变换，例如某节标题降一级。映射必须验证范围和结果，不能提供“忽略公式”“跳过图片”“接受全部告警”等开关。额外译注也必须与源正文区分，不能吞掉或替换源中的代码/公式。

原始 HTML 到源 Markdown 的独立统计与代表内容检查仍由主 Agent 完成；共享扫描只证明 Markdown 层，没有增加一个同源算法互相证明的假闭环。已有正确 fixtures 与实际模板同时用于检查误报。

## 5. R2：以源、译文与复核证据恢复

### 5.1 判定顺序

1. 只读旧源包和目标文件，从当前源及明确策略在临时目录重建预期。比较源片段、唯一目标和映射；源已变化的包标为失效，缺目标标为缺失。
2. 对存在且源一致的译文运行适配范围的共同硬检查。代码、公式、脚注、图片等失败即不可复用；仅剩标题而源含正文等确定损伤直接报告。
3. 普通正文覆盖、表格含义或结构重建差异不能被确定性检查证明时进入独立回源复核。主 Agent 核对当前源与译文，不用字符数、段落数或目标文件非空替代。
4. 硬检查通过且源全量对账、语义复核证据对应当前文件时才输出可复用；否则输出待复核，不自动重译。复核发现实际缺失后补全受影响包，再重新验证。

恢复读取文件，不能改写译文、旧源包或先前有效成品。不同源家族的检查必须在包范围合法适配，不通过删除 H1 等现有整篇约束来兼容片段。

### 5.2 可重建的最小复核证据

仅凭机器代码不能证明一个中文段落是否漏译，所以允许主 Agent 把已完成的复核写成工作区外的逐包记录，并显式提供给恢复入口。记录最少绑定源片段、目标正文、实际资源、检查口径与具体转换映射的摘要，以及源全量对账/语义复核结论和未解决项。检查口径包含实际使用的校验脚本身份和项目强 token；相关术语或规则口径改变时重新复核，不能沿用旧结论。

记录由主 Agent 在独立复核后产生，不由翻译 Agent 自检直接授予，也不由脚本因计数通过自动生成“语义通过”。恢复重新计算摘要并重新执行硬检查；目标改一个字、源改一个数字、资源被替换或口径变化后旧记录不能继续授权复用。记录不证明模型绝不会误判，只防止旧检查结果被错误套给新文件。

没有记录的旧译文仍可在当前调用中完成复验并提供新证据。记录丢失只增加复核工作，不损失译文、不强迫重译、不要求状态迁移。不能独立验证时继续待复核；不得将“未验证”打印成 OK。这落实 D2，并保持文件事实恢复边界。

## 6. R3：当前源决定合并范围

`merge_work_packages.py` 增加当前源、拆分策略和源包映射的必需输入；根据它们重建预期，逐一对照译文实参。具体内部 CLI 拼写在执行计划确定，但不得保留无全量依据的“完整合并成功”模式。

对照内容包括源身份、范围、包顺序、小节实例、片段位置和唯一目标，比较完整集合而非实收包的 1…N。末包或末片遗漏、额外包及同名异源都在写出前失败。局部翻译先把确认的局部源范围作为依据，不从缺失实参猜测。

只有身份、范围及包验证证据齐备的输入才能进入交付合并；逆序实参按权威序号排序。装配用源区间和明确模板映射，保留正文原始切片；包之间不默认注入改变列表/公式语义的分隔线。分页/API 必须保存实际页面边界或按预期内容范围验证，不能靠全文中的裸 `---` 切页。代码内的图片字符串、标题和分隔线不参与重写。

先在工作区外产生候选与必要映射，资源解析明确使用最终 Markdown 路径和交付根目录；候选通过完整检查后才替换目标，再从实际路径复验。为最后复验失败保留原成品并恢复，首次输出失败则不留下声称有效的成品。包的验证记录不能替代合并候选的全量检查与回源复核。

## 7. R5：按来源与出现位置核对资源

原始快照及主 Agent 已确认的暗亮选择构成图片预期。每条预期最少包含源快照/节点或出现序号、选定源资源身份、目标文档/出现序号、交付相对路径和资源摘要；源 `[IMG:…]` 与标准 Markdown 图片由源家族适配器转换为同一比较事实。重命名不能只比较 basename。

已有 `images_display.json` 中可用的身份字段直接复用，尺寸未知不等于图片不存在；无尺寸映射的项目也能提供最小身份映射，不强迫创建 PDF 尺寸配置。图片预期不能从待验译文自身反向生成；原始源独立图片对账仍必须完成。

共同检查在最终 Markdown 目录解析引用，支持现有内联图片和实际使用的引用式图片，排除代码示例。相对引用必须落在明确交付根内；根默认 Markdown 目录，跨章共享资源时主 Agent 显式指定共同交付根。不尝试 cwd 回退，不接受热链或机器绝对路径。搬迁整个交付树后按新根复验。

读取实际文件并比较选定源资源摘要，验证魔数或 `file` 类型；已有可靠解码工具可作补充，魔数通过不等于视觉完整。SVG 须验证实际 SVG 文档及离线依赖，不能因扩展名或含有字符串 `<svg` 就接受 HTML 错误页。未知类型与无法读取的文件报告未验证并阻断最终通过，不引入联网兜底。

合并保留每次出现的有序映射，同资源复用副本但不去掉正文出现次数；同名不同内容继续拒绝覆盖，主 Agent 明确重命名后重验。显示尺寸条目同步绑定到新位置，宽度、比例和来源约束沿用既有 PDF 规格，不修改导出默认行为。

### 7.1 SVG 收敛修订：当前接口与最小改动

当前 `_css_resource_refs` 用正则从字符串提取引用，`_svg_resource_refs` 对所有属性进行扫描，导致 CSS `content: "url(example.png)"` 和 SVG `data-example="url(example.png)"` 被误判为真实依赖。源译使用同一份合法自包含 SVG 也会被拒绝。修复目标是同时接受这些合法输入、拒绝真实依赖损伤，不仅让原错误样例变绿。

保留 `_dependency_fails` 的离线遍历、`resource_identity_digest` 的依赖身份计算，以及四类校验、恢复、合并入口；它们继续消费同一份有序依赖识别结果。保留 `local_resource_digest` 的共同入口、不可核验返回 `None`、无效证据待复核且不强制重译的规则。依赖识别结果修正后，遍历和身份计算必须同步采用，不能出现同一资源一侧忽略、一侧计入的情况。

XML 继续使用现有解析器；CSS 使用 `tinycss2` 的语法节点区分字符串、注释、URL 函数与 `@import`，不再用整段正则猜测语法。该库已加入普通翻译依赖 `requirements.txt`，不借用 PDF 的可选环境。版本与兼容环境已经实施验证：`tinycss2>=1.5,<2`（当前 1.5.1，包元数据 `Requires-Python >=3.10`）于 Python 3.12 隔离环境通过本节矩阵，普通翻译依赖的兼容下限为 Python 3.10；安装命令用目标解释器的 `python -m pip`，避免 pip 与运行解释器不一致。新增依赖是用户已同意的小范围方案，普通翻译仍无需浏览器。

### 7.2 识别合同与兼容边界

- CSS 按所属语境解析：样式表与 `<style>`、`style` 声明列表、展示属性值。真正的 URL 节点及 `@import` 的字符串/URL 参数产生引用；普通字符串内部的 `url(...)` 文本、注释不产生引用。保留已有嵌套样式与导入链的静态资源识别，不计算 CSS 布局、选择器匹配或视觉等价。
- SVG 按元素和属性的资源语义取引用。保留真实资源 `href/xlink:href/src`，以及 `fill`、`stroke`、`filter`、`clip-path`、`mask`、`marker`、`marker-start/mid/end`、`cursor` 等展示属性和样式中的资源引用；不得对任意 `data-*`、说明或标识属性扫描 URL。属性集合以现有使用路径和资源语义为依据，不用一份过窄名单偷偷删掉原有支持。
- 两类输入统一输出按文档顺序的依赖；重复出现不随意去重，导入不重复计数。相对路径以实际所属 SVG/CSS 文件为基点；内部片段、自包含数据、合法共享和循环继续沿用已有规则。
- 正确识别出的依赖同时用于存在性与内容身份核验。顶层文件相同而子资源变化仍失败；缺失、不可读、外部及越界依赖不能完整通过。保留现有映射 JSON 格式与摘要合同，不新增摘要版本或转换配置；若纠正识别使某条旧证据不再对应当前事实，定位到该条目补验，不重译全文。
- 不能可靠解释且会影响资源核验的结构，应报告具体位置及未验证原因，不默默当作零依赖：CSS 组件值、嵌套函数/块与 `@import` 参数中的解析错误（bad-url、eof-in-string 等错误 token）进入 `_PARSE_ERROR` 诊断路径；`xml-stylesheet` 处理指令声明的样式表关联尚未实现，按所属文件报告结构类型与未验证原因，阻断完整通过且资源身份记为不可用。普通 XML 声明、XML 注释与转义文本中形似处理指令的内容不误拦截；不以禁止全部 SVG 或全部 XML 声明实现拒绝。超出现有约定且存在行为分歧的构造先明确差异；不默认引入新禁令，也不以“矩阵外”为由忽略已证明违反 R5 的问题。

### 7.3 固定成对验收矩阵

以下是需求 A10–A12 及恢复 A3–A5 的 SVG 细化，不替代或缩小 A1–A13。样例优先扩展现有图片、恢复、合并测试；预期引用由样例含义独立指定，不由被测解析器生成。

| 行 | 合法输入必须通过 | 损伤输入必须拒绝 | 直接证据 |
| --- | --- | --- | --- |
| S1 语法区分 | CSS 普通字符串、注释、SVG `data-*`/说明属性中的伪 URL；真实 URL 的合法单双引号、空白与转义写法 | 真正 URL 或导入指向缺失资源 | 同份合法源译 CLI 通过，负例定位真实引用；不存在虚构依赖 |
| S2 依赖范围 | 展示属性、样式、两种 `@import` 及多层 SVG/CSS 链，根内跨目录共享 | 缺失、不可读、外部及越界依赖 | 每类引用正负成对；诊断包含所属文件和引用，切换 cwd 无变化 |
| S3 内容身份 | 相同依赖树、合法顶层改名、自包含 SVG/位图保持已有摘要 | 顶层相同但直接或多层子资源换内容 | 自动源依据和显式映射均正确拒绝换图；不是凭数量比较 |
| S4 循环与搬迁 | 合法循环、共享、重复出现及整个交付树搬迁 | 循环或共享链中一个资源损坏 | 不挂起，搬迁身份稳定，每次出现仍可核对 |
| S5 业务门禁 | 四类校验正确样例、有效复核后的恢复和完整合并 | 旧证据下源/译依赖被修改、缺证据、合并后资源损坏 | 无误复用/误放行；失败不覆盖有效成品，修复补验后可继续 |

阶段验收先运行相关成对用例；全部变更稳定后集中执行完整测试、六组业务回归及 PDF 回归。不在代码未变化且已有结果通过时反复重跑全套。测试数量不是完成标准，S1–S5 必须各有真实行为证据；发现新的实质问题时按需求处理并补充对应行，禁止为了收尾忽略它。

## 8. 直接验收与回归边界

需求 A1–A13 是唯一完成矩阵：A1–A2 对应 R1；A3–A5 对应 R2；A6–A7 对应 R3；A8–A9 对应 R4；A10–A11 对应 R5；A12–A13 覆盖端到端交付。每个反例先在基线重现，再验证实现后的具体拒绝原因；不能用其他报错碰巧非零作为修复证据。

四类源家族的正确样例与同数量损伤样例逐一成对验证。特别检查正确模板不会因增加 H1、页分隔线或历史数学包装误报；反例包括只改返回值、公式顺序、整对脚注删除、外链/伪图、尾包遗漏以及已复核文件被改写。

执行时沿用六组非 PDF 回归，并补充拆包还原、恢复和最终目录搬迁实验；共享图片/尺寸代码受到变更时运行相关 PDF 回归，避免凭未触及浏览器就跳过间接影响。真实文档范围在执行计划评审时固定，直接检查中文产物、代码内容、公式、图片与源的对应及中断前后复用结果，不只检查测试退出状态。

原八阶段实施与后续复审修复统一归入 V1.3。第 7.1–7.3 节 SVG 收敛修订已按本节 S1–S5 矩阵实现并通过验收；行为记录见 `CHANGELOG.md` V1.3。

## 9. Karpathy 精简与自检

### 9.1 假设与取舍

假设是单 Skill、内部脚本、现有四类 HTML、文件恢复和 Agent 语义复核继续有效。D1–D4 集中在需求第 5 节，已随用户指示编写计划进入批准基线；实际脚注/图题边界、历史公式及模板适配仍需代表样例确认。没有已实施的未经批准差异。

### 9.2 最小方案比较

更简单的“只补 Prompt 和计数”无法拒绝源 32→64、同数量代码/公式篡改和尾包缺失，所以不能满足 A3、A6、A8。只加源摘要也不能发现源未变而译文删正文；只保存完成标志又会让改过的文件沿用旧结果。采用源片段对照、重新执行硬检查以及与当前文件绑定的可重建复核证据，保留 Agent 判断边界。

另一方案是所有恢复一律重译，虽然省去复核设计，却违反有效译文复用的既有要求。通用 IR、状态机和中央清单服务增加新运行系统，也不解决语义是否复核的问题，全部不采用。

### 9.3 删除审计

- 将标题、代码、公式、脚注和 token 检查归并到第 4 节，图片只在第 7 节定义，避免四套源家族复制同一规则。
- 将全部验收条件集中到需求 A1–A13，设计只映射，不另建一套完成标准；没有把必要边界降成“建议人工注意”。
- 不增加固定包大小、自动调度、术语平台、正式版本号、通用转换配置和免检开关；恢复记录不作为状态数据库或迁移要求。
- 指导文档只修正当前能力、回归入口与下一期链接；不重复粘贴本期详细设计，不把未来五项能力带入本期。

逐节映射：第 1 节是接口/限制基线；第 2 节是所有权和最小边界；第 3、5、6、4、7 节分别落实 R1–R5；第 8 节落实直接验收；本节记录取舍与审阅边界。没有只为文件完整性而添加的架构层。

### 9.4 直接成功证据与批准边界

核心证据是源包无损还原、旧译文正确拒绝/复用、全量包无遗漏合并、代码/公式损伤被检出，以及搬迁后的真实中文交付仍可离线阅读，并完成逐节源对账与语义复核。格式检查、链接有效和回归成功只是辅助证据。

V1.3 的八张任务已有实现与验收记录；2026-09-13 用户批准第 7 节收敛方向并明确授权实施，SVG 兼容缺口已按 S1–S5 矩阵关闭（V1.3）。
